## Observe days and months

```python
from analysis import mv, session, revenue, amount, region, august
```

{/* example: calendar-query */}

```python
days = august.by(mv.grain("day"))
daily = session.observe({"revenue": revenue}, by=(days,)).compute()
sum_of_days = daily.reduce({"sum_of_days": daily["revenue"].sum()}).compute()
sum_of_days.show()
monthly_source = session.observe(
    {"revenue": revenue}, by=(august.by(mv.grain("month")),)
).compute()
monthly_source.show()
```

Calendar buckets retain their nominal starts when the first or last bucket is
clipped. Empty buckets remain present, and sparse selections retain only their
selected periods. Builtin calendars use native calendar operations; certified
custom calendars use a unique date-to-period mapping from the frozen snapshot.
Neither route enumerates one SQL branch per bucket. Custom calendars still
require one period per date and continuous, non-overlapping periods.

{/* example: metric-window-query */}

```python
from datetime import timedelta

rolling = session.observe(
    {"revenue": revenue.window(mv.trailing_duration(duration=timedelta(days=7)))},
    by=(days,),
).compute()
month_to_date = session.observe(
    {"revenue": revenue.window(mv.to_date(grain=mv.grain("month")))}, by=(days,)
).compute()
rolling.show()
month_to_date.show()
```

{/* example: period-comparison-query */}

```python
current_days = session.time_scope(start="2026-08-01", end="2026-08-04").by(mv.grain("day"))
prior_days = session.time_scope(start="2026-07-01", end="2026-07-04").by(mv.grain("day"))
current_daily = session.observe({"revenue": revenue}, by=(current_days,)).compute()
prior_daily = session.observe({"revenue": revenue}, by=(prior_days,)).compute()
comparison = current_daily.compare(
    {"reference": mv.baseline(prior_daily, match=mv.ordinal())}
).compute()
comparison.show()
```

{/* example: shifted-period-comparison-query */}

```python
months = session.time_scope(start="2026-08-01", end="2026-08-20").by(mv.grain("month"))
current_progress = session.observe({"revenue": revenue}, by=(months,))
previous_progress = session.observe(
    {"revenue": revenue},
    by=(months.shift(mv.offset(periods=-1)),),
)
progress = current_progress.compare({"mom": mv.baseline(previous_progress)}).compute()
progress.show()
```

## Interpret windows and correspondence

August's total is 800. At the end of August 5, trailing seven-day revenue is
100; month-to-date through August 15 is 200. A trailing window can reach before
the displayed range, so include the required lookback history in the source data.

`trailing_duration` measures elapsed time: seven days is 168 hours. Civil
periods follow calendar boundaries and can span different amounts of elapsed
time around daylight-saving changes. Each window ends at the bucket's actual
right boundary; `to_date` resets at the start of the selected period.

Ordinal matching pairs positions in compatible, complete periods. The daily
scopes `[August 1, August 4)` and `[July 1, July 4)` each contain three days and
pair by position. Shifting the monthly prefix `[August 1, August 20)` back one
month compares it with `[July 1, July 20)`, excluding July 20 midnight and
later. The example compares 200 with 300, a change of -100. A missing target
date remains absent instead of moving to a nearby date.

`mv.offset(periods=n)` counts steps of the consuming axis's grain, not visible
rows or fixed-day durations: on daily data, `-7` is seven days; on weekly data,
`-1` is one week; and on monthly data, `-1` is one month. Built-in calendar
offsets require grain `count=1`; subday offsets are unsupported.

Summing result rows is a statistic on those rows. For a monthly ratio or
distinct count, observe the original `Metric` at monthly grain instead. Prepare
and certify a [fiscal or named-activity calendar](/docs/latest/modeling/dates/#business-calendars)
before using it as a grain.

Source parsing and report timezones are separate: set a parser timezone for
naive time-bearing source values; aware timestamps already identify an instant,
and date-only encodings do not use a timezone. For raw local timestamp columns,
filtering and calendar assignment around daylight-saving transitions follow the
source timezone's wall-clock order: repeated clocks resolve to the later
occurrence, and skipped clocks to the transition instant. The first occurrence
of a repeated reporting hour can therefore be empty. Projected timestamps keep
the backend's native conversion; use aware/UTC timestamps or another identity
field when both repeated instants must remain distinct.

`ms.hour_prefix(date_field)` uses the source timezone context of its date prefix.
Changing the report timezone does not reinterpret that source timestamp.

## Time means and sample coverage

`sample_interval=(1, "hour")` declares source cadence without rounding timestamps
into hourly buckets. All TimeField sample reducers use represented timestamps,
allow missing clocks and never implicitly fill them with zero or NULL.
NULL, empty-input and weighted valid-pair policies remain reducer-owned.
An explicit `Population` still selects its declared sample coordinates.

In the six-order example, first average order amounts per date, then average
the represented dates within each region. Only dates with orders participate,
and each date has equal weight; when order counts differ by date, this can differ
from an order-weighted mean. August gives 100 for east and 600 for west; adding
zero to each daily mean leaves those results unchanged.

```python
order_date_entry = session.catalog.get("time_dimension:sales.orders.order_date")
assert order_date_entry.kind == "time_dimension"
order_date = order_date_entry
samples = amount.mean(time=order_date).per(order_date)
sample_mean = session.observe({"average": samples.mean()}, by=(august, region)).compute()
# Arithmetic does not add a clock-coverage requirement.
adjusted = session.observe({"average": samples.mean() + 0}, by=(august, region)).compute()
sample_mean.show()
adjusted.show()
```

`samples.quantile(0.95)`, min/max and first/last share the same missing-clock
policy as means. Declaring cadence triggers no complete-coverage check and
requires no finite observation period; windows and calendar samples retain their
own period requirements. Represented NULLs still follow `nulls`. Results describe
the observed samples and do not prove completeness of the whole period.


Qualified source-backed samples finish at the source: each timestamp's child
Metric completes before the outer mean, quantile or other reducer. Compatible
summaries share the inner calculation. For example, `amount.sum(time=order_date).per(order_date).quantile(0.95)` computes a quantile of completed daily sums.
Explicit sample domains and calendar grids retain their own completion rules.
Native arithmetic and Decimal rounding follow the backend; unsupported type or
algorithm combinations retain their existing local route. A native failure does
not trigger local recomputation. Completed Frames continue to use captured data.

## Fold Metrics over calendar cells

Use a Grain in `Metric.per` to fold completed daily values without declaring
another TimeDimension. The observation supplies the finite scope and timezone;
each source component uses its own declared time field. A weekly mean of daily
revenue includes all seven days, with zero for an empty day's sum.

{/* example: calendar-sample-fold */}

```python
weekly = august.by(mv.grain("week"))
daily_average = revenue.per(mv.grain("day")).mean()
folded = session.observe({"daily_average": daily_average}, by=(weekly, region)).compute()
folded.show()
```

For a completed `daily_p95`, use `daily_p95.per(mv.grain("day")).median()`
under the same weekly axis. Empty ratios and quantiles remain NA and follow the
sample reducer's existing NULL policy. Calendar grids retain every cell;
TimeField samples continue to use represented timestamps and allow missing clocks. Inner grains must nest: day in week/month is valid; week in month is
rejected. Certified calendar grains use their captured snapshot's containment.
Nested Grain layers are supported. With a plain TimeScope the grid tiles the
whole scope. Partial edge cells clip to actual scope bounds and each counts once,
without duration weighting. Pass the Grain to `per`, and the CalendarAxis or
TimeScope to `observe(by=...)`. Help: `semantic.metric.per`.

Semantic Grains from `ms.calendar_grain(...)` bind to the Session's current
certified calendar snapshot. Declared calendar folds require calendar
certification. Windows inside calendar samples and windows wrapping calendar
folds currently raise a typed error. Observe the windowed Metric directly on a
CalendarAxis and explicitly reduce the captured Frame values instead.
