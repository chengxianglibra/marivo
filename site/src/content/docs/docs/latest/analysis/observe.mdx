`session.observe(...)` captures a metric calculation over a selected output
domain and returns a pending `AnalysisFrame`. Call `compute()` to evaluate it,
or `persist()` to complete and publish it.

Choose a report range with `where=scope` and an output grain with
`by=(grain,)`. A range alone selects contributions without adding an output
axis. A Grain alone produces the time buckets that actually occur. Together
they define a finite report bucket domain. Ordinary Dimensions and Groupings
can share the `by` tuple with one Grain, or use a complete Population as `by`.

Each source reduction fixes its contribution time when it is defined, either
explicitly with `time=field` or by inheriting its Entity's `default_time`.
A report range or Grain requires every branch of every Metric to have a
contribution clock. Composed Metrics can use different fields across branches.

For example, `amount` is a loaded Measure and `booked_at` and `paid_at` are
loaded TimeDimensions:

```python
import marivo.analysis as mv

scope = session.time_scope(start="2026-11-01", end="2026-12-01")
booked = amount.sum(time=booked_at)
paid = amount.sum(time=paid_at)
frame = session.observe(
    {"booked": booked, "paid": paid, "difference": booked - paid},
    where=scope,
    by=(mv.grain("day"),),
).compute()
```

Use `where=(scope, status == "paid")` to conjoin one report range with a row
predicate. `where=paid_at.within(scope)` is a fixed source-field predicate and
can filter a Metric that has no contribution clock. Window endpoints come
from the report time context. If a branch lacks a clock, repair that branch's
definition or omit report time from the observation.

See `marivo.help("semantic.metric.define")` and
`marivo.help("analysis.session.observe")` for the exact contracts.

See the [observe section of Analysis DSL](/docs/latest/analysis/dsl/#observe-metrics) for the full guide and example.
