`session.observe(...)` captures a metric calculation over a selected output
domain and returns a pending `AnalysisFrame`. Call `compute()` to evaluate it,
or `persist()` to complete and publish it.

For a complete minimal example, start with `marivo.help("analysis")`. In a project
with authored Metrics, search by business meaning:

```python
import marivo.analysis as mv

session = mv.session.get_or_create("revenue-trend", timezone="UTC")
catalog = session.catalog
catalog.search("revenue", kind="metric", limit=5).show()
```

Inspect the candidates and choose the Metric matching the question, rather than
automatically taking the first hit. The following assumes the confirmed ID is
`metric:sales.revenue`; use an actual returned ID. An already known exact identity
can skip search. Adjust the dates and timezone to the question, and reuse an
available Session when continuing the same analysis.

```python
revenue = catalog.get("metric:sales.revenue")
assert revenue.kind == "metric"
period = session.time_scope(start="2026-08-01", end="2026-09-01")
result = session.observe(
    revenue,
    by=(period.by(mv.grain("day")),),
).compute()
result.show(n=31)
```

The range includes August 1 and excludes September 1 in the Session timezone.
Every Metric branch needs contribution time. This computes and displays daily
values without requiring persistence; the range does not certify source completeness.

Use `where=scope` for a range-only total, or `by=(scope.by(grain),)` for
finite time grouping. A CalendarAxis can share the tuple with ordinary
Dimensions and non-time Groupings. Bare Grain inputs reject. If by carries
time, omit a report TimeScope in where, even if both selections are equal.
Custom calendar axes require one complete certified period and a captured Grain.

`by=P` retains P's complete output keys, including keys without facts; it does
not filter contributions. P must cover all necessary output keys. Use
`where=mv.in_population(P)` to restrict contributions explicitly. If P already
carries report time, omit a separate TimeScope in `where`.

Each source reduction fixes its contribution time when it is defined, either
explicitly with `time=field` or by inheriting its Entity's `default_time`.
A report range or CalendarAxis requires every branch of every Metric to have a
contribution clock. Composed Metrics can use different fields across branches.

For example, `amount` is a loaded Measure and `booked_at` and `paid_at` are
loaded TimeDimensions:

```python
import marivo.analysis as mv

scope = session.time_scope(start="2026-11-01", end="2026-12-01")
booked = amount.sum(time=booked_at)
paid = amount.sum(time=paid_at)
difference = booked - paid
difference.show()
total = session.observe({"difference": difference}, where=scope).compute()
frame = session.observe(
    {"booked": booked, "paid": paid, "difference": difference},
    by=(scope.by(mv.grain("day")),),
).compute()
```

`difference.show()` reports captured branch clocks when they can be determined
without a receiving scope. For a published Catalog Metric, inspect
`metric.definition.time_bindings` or call `metric.show(section="definition", max_output_bytes=None)`
to read all captured bindings. Clock availability does not certify a particular
grain or the source's physical types.

Use `where=(scope, status == "paid")` to conjoin one report range with a row
predicate. `where=paid_at.within(scope)` is a fixed source-field predicate and
can filter a Metric that has no contribution clock. Window endpoints come
from the report time context. If a branch lacks a clock, repair that branch's
definition or omit report time from the observation.

For an existing `metric` whose time capability is not known, inspect a rejected
observation's complete structured details before deciding how to repair it:

```python
try:
    pending = session.observe({"value": metric}, where=scope)
except mv.MetricContributionTimeError as error:
    print(error.output)
    for missing in error.missing:
        print(missing.path, missing.metric, missing.root, missing.reason)
```

`reason` distinguishes a source reduction without an Entity default from a
fixed Population count. Do not assign a clock to a fixed Population count;
keep it outside report time operations.

See `marivo.help("semantic.metric.define")` and
`marivo.help("analysis.session.observe")` for the exact contracts.

See the [observe section of Analysis DSL](/docs/latest/analysis/dsl/#observe-metrics) for the full guide and example.
