`session.observe(...)` captures a metric calculation over a selected output
domain and returns a pending `AnalysisFrame`. Call `compute()` to retain a fixed
Frame, `to_pandas()` to evaluate and export isolated values, or `persist()` to
complete and publish it. Export does not cache or save the result.

For a complete minimal example, start with `marivo.help("analysis")`. In a project
with authored Metrics, search by business meaning:

```python
import marivo.analysis as mv

session = mv.session.get_or_create("revenue-trend", timezone="UTC")
catalog = session.catalog
catalog.search("revenue", kind="metric", limit=5).show()
```

Inspect the candidates and choose the Metric matching the question, rather than
automatically taking the first hit. The following assumes the confirmed ID is
`metric:sales.revenue`; use an actual returned ID. An already known exact identity
can skip search. Adjust the dates and timezone to the question, and reuse an
available Session when continuing the same analysis.

```python
revenue = catalog.get("metric:sales.revenue")
assert revenue.kind == "metric"
period = session.time_scope(start="2026-08-01", end="2026-09-01")
result = session.observe(
    revenue,
    by=(period.by(mv.grain("day")),),
).compute()
result.show()
```

The range includes August 1 and excludes September 1 in the Session timezone.
The revenue branch uses its declared contribution clock; independent branches retain their scope. This computes and displays daily
values without requiring persistence; the range does not certify source completeness.

Natural calendars use `mv.grain(...)` and explicit `scope.by(grain)`. Fiscal periods, holidays and working days use ordinary business fields; the harness chooses authority, ranges and pairing. See [dates and time](/docs/latest/modeling/dates/).

Ordinary `by=(axis, ...)` does not fill missing time buckets. It returns the union
of complete keys supported by actual contributions, including real zero and all-NULL
contributions. At a row supported by another Metric, absent sum/count is zero and
mean is NA. Adding a Metric can therefore add rows and change current-row means.
Independent branches broadcast only over established complete keys. Time grouping
without a clocked branch or compatible time-bearing Population count rejects;
use an explicit output Population or a range total.

For a business question requiring every date, request a complete domain:

{/* example: complete-time-domain */}
```python
axis = period.by(mv.grain("day"))
unit = mv.coordinates(by=(), keys=((),))
complete = session.observe({"revenue": revenue}, by=mv.product(axis, unit)).compute()
```

`by=P` retains P's complete output keys, including keys without facts; it does
not filter contributions. P must cover all necessary output keys. Use
`where=mv.in_population(P)` to restrict contributions explicitly. If P already
carries report time, omit a separate TimeScope in `where`.

Each source reduction can fix its contribution time when it is defined, either
explicitly with `time=field` or by inheriting its Entity's `default_time`.
A report range or CalendarAxis filters only clocked branches. Omission without an
Entity default and explicit `time=None` both make a branch report independent.
Independent branches retain their business conditions, reduce first, then repeat
only along already established report coordinates. Composed Metrics can use different clocks;
a shared calendar bucket does not identify a shared cohort.

For example, `amount` is a loaded Measure and `booked_at` and `paid_at` are
loaded TimeDimensions:

```python
import marivo.analysis as mv

scope = session.time_scope(start="2026-11-01", end="2026-12-01")
booked = amount.sum(time=booked_at)
paid = amount.sum(time=paid_at)
difference = booked - paid
difference.show()
total = session.observe({"difference": difference}, where=scope).compute()
frame = session.observe(
    {"booked": booked, "paid": paid, "difference": difference},
    by=(scope.by(mv.grain("day")),),
).compute()
```

`difference.show()` reports captured branch clocks when they can be determined
without a receiving scope. For a published Catalog Metric, inspect
`metric.definition.time_bindings` or call `metric.show(section="definition", max_output_bytes=None)`
to read all captured bindings. Clock availability does not certify a particular
grain or the source's physical types.

Use `where=(scope, status == "paid")` to conjoin one report range with a row
predicate. The comma creates the AND tuple; `&` and `|` combine predicates and
boolean literals from the same stage. A TimeScope is a report selector, so
`scope & predicate` and `predicate & scope` fail at expression construction.
An explicit field comparison such as `where=paid_at >= start` filters
a fixed source field and can filter a Metric with no contribution clock. It stays
in force throughout window evaluation, including history before the report range.
Window endpoints come from the report time context or an enclosing calendar
sample. Independent branches retain their scope at each valid endpoint.

See `marivo.help("semantic.metric.define")` and
`marivo.help("analysis.session.observe")` for the exact contracts.

See the [observe section of Analysis DSL](/docs/latest/analysis/dsl/#observe-metrics) for the full guide and example.


Given an already selected Population `members`, a fixed denominator can participate in report time and windows: `session.observe({"per_member": revenue / members.count()}, by=(scope.by(mv.grain("day")),))`. A window reevaluates revenue and uses the fixed denominator once. Read `frame.schema.value_time_semantics` for each column's branch clocks, report effects and windows. Derived facts describe fixed inputs and do not imply a new source observation.
