---
title: Population
description: Choose complete member and coordinate domains, separate output keys from contribution filters, and count selected members.
---

Population is a finite set of complete coordinate tuples, such as orders, customers, regions, or correlated combinations of axes. It describes the domain for an analysis; an observation supplies measured values for its members. A field such as `customer_id` is not by itself a Customer identity: an identity contains every ordered primary-key component. A field value of `NULL` can be a category, while Entity identity components must be non-NULL.

Complete the [quick start](/docs/latest/start/python/) and save the [DSL shared example](/docs/latest/analysis/dsl/#complete-example-and-shared-inputs) as `analysis.py`. In the project root, save this page’s untitled code blocks as `population.py` and run `.venv/bin/python population.py`. Population definitions are lazy: `session.frame(P).compute()` materializes the complete keys, while `session.observe({"count": P.count()}).compute()` computes the domain size.

```python
from analysis import mv, session, revenue, region, august, current

orders_entry = session.catalog.get("entity:sales.orders")
assert orders_entry.kind == "entity"
Orders = orders_entry
```

## Literal coordinates: `mv.coordinates`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `by` | Yes | — | Ordered fields or identity groupings; each position defines one coordinate axis. Use `mv.product` to combine a time domain with other axes. |
| `keys` | Yes | — | Complete tuples with one value per axis. For an identity axis, each value is the complete primary-key tuple, even for a single-column key. Duplicate tuples count once. |


```python
requested = mv.coordinates(
    by=(mv.identity(Orders),),
    keys=(((4,),), ((5,),), ((6,),), ((999,),)),
)
requested_count = session.observe({"members": requested.count()}).compute()
assert requested_count.to_pandas()["members"].tolist() == [4]
```

`requested` includes order 999, although the tutorial source has no such row. A literal Population records the requested keys; source presence is a separate question. `keys=()` is empty; for `by=()`, `keys=((),)` is the one-element zero-axis domain.

Source-backed populations follow the identity, relationship-cardinality, and version-grain declarations in the semantic model. Use an explicit [online validation check](/docs/latest/modeling/semantic-layer/#load-and-validate) to test data conditions such as uniqueness or relationship cardinality. If a scalar lookup finds no matching row, `session.read` and `P.classify` keep the requested identity, with `NULL` for the missing attributes.

These declarations and actual set/grouping operations can establish complete-key
uniqueness without another duplicate scan. Ordinary members, read, classify and
Top are not source-quality audits. Literal Frame data and unknown relations keep
their ingress key checks; NULL identity and operation-specific coverage checks
remain independent.

## Identity grouping: `mv.identity`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `target` | Yes | — | Entity for a direct identity axis, or an `mv.path(...)` for a role such as buyer or seller. |

Membership time belongs to `session.members(..., at=...)`. Direct identity axes
from different snapshots of the same Entity can participate in set operations.
Choose explicit field or Path anchors when reading versioned attributes later.

## Source members: `session.members`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `entity` | Yes | — | Resolved Entity from this Session’s Catalog. |
| `at` | No | `None` | Exact version-selection instant for a versioned Entity; omit for an unversioned Entity. Choose it separately from the observation period. |
| `where` | No | `None` | Optional source-field or Population-membership filter; omit it to keep all source-represented identities in scope. |


```python
east_orders = session.members(Orders, where=region == "east")
east_count = session.observe({"members": east_orders.count()}).compute()
assert east_count.to_pandas()["members"].tolist() == [4]
```

These are orders 1, 2, 4 and 5 across both months. Choose membership time separately from the `Metric` observation period. For a snapshot or validity Entity, supply `at=session.instant(...)` explicitly.

To compare two snapshots of a versioned Customer Entity, select each
membership explicitly. The intersection keeps customer identities present in both
snapshots. The region field below is read as of the September snapshot.

```python title="Versioned customers model"
august_time = session.instant("2026-08-01")
september_time = session.instant("2026-09-01")
august_customers = session.members(Customers, at=august_time)
september_customers = session.members(Customers, at=september_time)
retained = august_customers.intersection(september_customers)
report_region = customer_region.at(september_time)
classified_customers = retained.classify(by=(report_region,))
```

## Output domain versus contribution filter

`by=P` selects the complete output keys. To restrict contributing facts to those members as well, use `where=mv.in_population(P)`. After filtering, the output domain must cover every required contribution key or evaluation raises a coverage error. Keep correlated axes together as complete tuples; separate axis values do not preserve their combinations.

### Membership predicate: `mv.in_population`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `population` | Yes | — | Complete selected domain used to test membership. |

A source predicate containing time coordinates matches the contribution clock
jointly with the ordinary coordinates. A time interval uses its inclusive start
and exclusive end. A report Population can contain one interval or be empty.
If source or Frame keys determine the selected interval, Marivo checks the
actual output domain before reading dependent Metrics.


### Cartesian product: `mv.product`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `factors` | Yes | — | At least two ordered `Population`, `TimeScope` or `CalendarAxis` factors with distinct axes; owned factors must belong to the same Session. If any factor is empty, the product is empty. |

```python
domain = mv.product(august, requested)
observed = session.observe(
    {"revenue": revenue}, by=domain, where=mv.in_population(requested)
).compute()
assert sorted(observed.to_pandas()["revenue"].tolist()) == [0, 100, 100, 600]
```

Order 999 remains with revenue zero because it has no contributions. An order with rows whose amounts are all `NULL` instead has an unknown sum. `mv.product(*factors)` includes every combination of its factors, so use it when the full Cartesian domain matches the intended output.

## Classify, project, and count

### `P.classify`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `by` | Yes | — | Single-valued fields or identity groupings to append. Existing coordinates are reused, and `()` leaves the domain as is. |
| `on` | No | `None` | Existing identity Grouping to read from. Omit when only one identity role is eligible. |

Classification preserves the complete input tuples. Missing scalar attributes
are NULL. Appending an identity role requires a complete non-NULL identity for
every input tuple.

### `P.project`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `by` | Yes | — | Axes already in the Population to retain or reorder. Projected tuples are deduplicated; use `classify` to add attributes first. |


```python
all_orders = session.members(Orders)
classified = all_orders.classify(by=(region,))
selected = classified.where(region == "east")
order_keys = selected.project(by=(mv.identity(Orders),))
regions = selected.project(by=(region,))
counts = session.observe(
    {"orders": order_keys.count(), "regions": regions.count()}
).compute()
assert counts.to_pandas()["orders"].tolist() == [4]
assert counts.to_pandas()["regions"].tolist() == [1]
```

`P.count()` returns a lazy `Metric` that counts distinct complete tuples, including `NULL` field categories and requested identities without source rows. The selected domain above contains four order identities and one region. Use `Entity.count()` to count source contributions and `mv.row_count()` to count rows in a Frame. `P.axes` lists coordinate rules; use `P` itself when you need its selected member set. A Population count is report independent. Report ranges and windows do not reselect its members; it repeats along a missing report time coordinate and matches any compatible time coordinates already captured in P.

## Set selection and relationship mapping

### `P.where`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `predicate` | Yes | — | A row predicate over existing coordinates. Compare fields, use `isin` or `isnull`, and combine with `mv.in_population(...)` using `&`, `\|` and `~`. |

Only True retains a tuple. Classify a missing coordinate before filtering on it.
`session.members(..., where=...)` and `session.observe(..., where=...)` can read
source attributes to evaluate predicates on their own domains.

### `P.union / P.intersection / P.difference`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `other` | Yes | — | Population with compatible complete bound axes. Results preserve the left Population’s axis order. Use `union` to combine domains, `intersection` to keep common tuples, and `difference` to remove matching tuples from this domain. |

### `P.image`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `via` | Yes | — | Directed `Path` from `mv.path(...)`. |
| `on` | No | `None` | Existing source identity Grouping. Omit when only one role qualifies. |

### `P.preimage`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `targets` | Yes | — | Selected direct target identity domain. |
| `via` | Yes | — | Directed `Path` from `mv.path(...)`. |
| `on` | No | `None` | Existing source identity Grouping. Omit when only one role qualifies. |


```python
present_requested = requested.intersection(all_orders)
missing_requested = requested.difference(all_orders)
set_counts = session.observe(
    {"present": present_requested.count(), "missing": missing_requested.count()}
).compute()
assert set_counts.to_pandas()["present"].tolist() == [3]
assert set_counts.to_pandas()["missing"].tolist() == [1]
```

An image returns distinct direct target identities. A complete foreign key can
supply an identity whose target row is missing. A preimage retains every full
receiver tuple that reaches at least one target. If a receiver tuple reaches
several targets, taking its image again may also return targets outside the
original selection.

Use `mv.path(relationship, source_at=anchor)` to read a versioned source, and
`relationship.at(anchor)` as a step when its target needs a version lookup.
A terminal anchor requires a target row read. To test target existence at a
given instant, use `session.members(Target, at=anchor)` as the target domain.

Use `P.identities(on=grouping)` to keep only the complete identity values on an
existing axis, remove its path role, and deduplicate them on the direct Entity
axis. Use `P.project` to keep the identity role and any other selected axes.

## Continue from Frame selection: `session.population_from`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `frame` | Yes | — | Frame from this Session; its represented ordinary keys supply the selected domain. |
| `on` | Yes | — | Explicit FrameAxis-to-field or Entity pairs that declare the business correspondence. Projection deduplicates complete selected keys. |


```python
chosen = current.top(1, by=current["revenue"]).compute()
chosen_regions = session.population_from(chosen, on=((chosen.axes[1], region),))
chosen_count = session.observe({"regions": chosen_regions.count()}).compute()
assert chosen_count.to_pandas()["regions"].tolist() == [1]
```

Because `current` is the completed August result, `population_from` records its selected region. Pass `chosen_regions` as `where=mv.in_population(chosen_regions)` in a later observation to keep west selected without ranking it again. Use `session.frame(P)` to compute Population keys. `session.read(P, fields, on=...)` preserves all input keys and adds named scalar values. Specify the existing identity Grouping when multiple roles can supply the fields. Use the owning Session to create and consume each Population. Exact references: `analysis.population`, `analysis.coordinates`, `analysis.session.members`, `analysis.session.population_from`.

For a versioned field, an unanchored target can carry values from its matching direct, unanchored field axis. Use `field.at(session.instant(...))` to declare a new versioned field binding.

### Filter fixed coordinate values

Capture a classified key Frame and map its axes back to their explicit business
bindings. The example uses the axis order from the earlier classify call.
The final filter uses the captured region values and can run with the source
offline.

```python
fixed = session.frame(classified).compute()
captured = session.population_from(
    fixed, on=((fixed.axes[0], Orders), (fixed.axes[1], region))
)
east_keys = session.frame(captured.where(region == "east")).compute()
assert len(east_keys.to_pandas()) == 4
```
