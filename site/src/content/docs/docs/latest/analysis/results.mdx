Run the [analysis DSL example](/docs/latest/analysis/dsl/#complete-example-and-shared-inputs), which persists its comparison as `saved`. Use `compute()` for a completed Frame you will keep in the same Python process. Persist the result when you need to reopen it in another process.

## Save the result identifiers

In `analysis.py`, add these lines after `saved = change.persist()` and run the producing script:

```python
print(saved.session_id)
print(saved.artifact_id)
```

Keep both IDs for the next process. Rerunning the producer performs the source observations again and may read changed data or publish another result.

## Reopen the saved data

Save this as `reopen.py` and run `.venv/bin/python reopen.py SESSION_ID FRAME_ID` from the same project, replacing the placeholders with the IDs you saved. It reopens the committed Frame without repeating its source observations. The final line writes `comparison.csv` in the current directory and overwrites it if it already exists.

```python
import sys
import marivo.analysis as mv

session_id, frame_id = sys.argv[1:]
session = mv.session.resume(session_id)
reopened = session.persisted_frame(frame_id)
rows = reopened.to_pandas()
assert rows["reference.absolute.revenue"].tolist() == [-100, -100]
reopened.show(n=0)
rows.to_csv("comparison.csv", index=False)
```

The two absolute changes remain -100 because this reads the saved comparison. Continue with supported Frame operations on `reopened`; call `persist()` on a derived Frame if you want to save another result. To use fresh source values, build and run an explicit source observation with the required definitions.

`to_pandas()` returns an isolated flat table with readable coordinate and value names and separate presence columns. CSV is useful for sharing values but does not preserve typed analysis metadata or frozen time interpretation; keep the Frame for typed analysis. Check units and keys before joining exported tables.

## Find a saved Frame when its ID is lost

Recover the intended Session first, then inspect its committed Frame directory:

```python
session = mv.session.resume(session_id)
page = session.persisted_frames(limit=20)
page.show()
```

Each `page.items` entry provides `artifact_id`, `committed_at`, `description` and
`schema`. Use the description, output columns and axes to identify candidates;
open a selected ID with `session.persisted_frame(artifact_id)`. Inspect its
`lineage` or saved evidence when needed. If candidates remain ambiguous, ask the
caller to select rather than automatically choosing the newest result.

Add a purpose when producing a result, when useful:

```python
saved = change.persist(description="Monthly revenue comparison")
print(saved.description)
```

`description` is optional and defaults to `None`; text is saved unchanged in the
same atomic commit. Missing descriptions are shown explicitly. They are caller
claims, not verification of business meaning. A saved Frame retains its
immutable description on repeated `persist()` calls; passing a different
non-None description fails. A new commit requires a new explicit description.

Discovery reads only current-generation Session metadata, without result files,
models or sources. Recover the Session before checking an uncertain publication
outcome. Continue with `session.persisted_frames(limit=20, cursor=page.next_cursor)`
when `page.has_more` is true; retain the same limit. Limits are 1..100. Pages do
not freeze concurrent history; start from the first page to discover new commits.
Older generations remain independent and require a compatible environment.

## Read evidence in context

An `AnalysisFrame` may be a pending expression, completed in-memory data, or a saved result. `compute()` completes a Frame in memory; `persist()` saves the completed result. `show()` is a bounded preview, while `to_pandas()` exports complete fixed data.

On a saved Frame, `session_id` and `artifact_id` identify the committed result. `show(n=0)` displays metadata and audit summaries without reading result rows. Use `findings()` to read committed Findings and `evidence()` to read saved Evidence. A plain observation's saved audit records source and evaluation facts; it may have no Findings. Supported contribution analyses retain their method explanations in `method_facts`.

Source read, evaluation, and commit times are distinct. Check the recorded source scope and times when judging freshness: a later observation may read changed data. The recorded scope describes the period, filters, and source constraints used for the read; it does not show that sources contain every relevant row or share a consistent snapshot. A contribution breakdown explains how the selected method allocates a change; it does not establish what caused that change.

## Inspect semantic column origins

Every Frame exposes `lineage`, including pending expressions. Reading it does not
execute the analysis or read business rows. It remains available after saving and
independent recovery without the original models or source connection.

```python
lineage = saved.lineage
lineage.show()
lineage.values["reference.absolute.revenue"].show()
origins = lineage.values["reference.absolute.revenue"].value_origins
for origin in origins:
    print(origin.kind, origin.path, origin.definition_id)
```

`value_origins` records semantic declarations and inputs used for the value.
`context_origins` records filters, grouping, time, relationships and row matching.
A filtered column retains its filter dependencies after projection. The `axes`
directory uses `frame.axes[i].token`; `presence` uses complete presence names.
Named Measures used in filters remain context origins, including inside a Metric.
Coordinates also retain row selection context. In weighted-mean attribution,
the denominator takes value origins from weights; valid-pair selection contributes
context origins from both values and weights. Valid-pair counts have context origins only.
For direct ratios, each component retains its own named Metric origins.
These are static logical dependencies, including all declared conditional branches;
they do not prove row-level contribution, successful reads, or causation. Display
is bounded; typed mappings and origin tuples retain the complete captured facts.

## Inspect structure and read pages

`schema` describes captured fields, exact types, units, complete axis keys and the
default export layout without reading result files. It is available even before
execution; pending fields may have an explicit unresolved type.

```python
schema = saved.schema
page = saved.read_page(columns=("reference.absolute.revenue",), limit=1000)
assert page.input_id == schema.input_id
rows = page.to_pandas()
if page.has_more:
    page = saved.read_page(
        columns=("reference.absolute.revenue",), limit=1000, cursor=page.next_cursor
    )
```

Pages keep every complete axis key in `coordinates`, keyed by schema slot ID,
and readable coordinates before selected fields. Use full value/presence names;
`columns=()` reads coordinates only. Limits are integers 1..10000, excluding bool.
Repeat the same limit, columns, axis aliases and `time_details` with a continuation cursor. Saved
cursors can continue after reopening the same commit with the same Runtime
version; memory cursors belong to the same fixed input in the current process.

`layout` explains the actual export columns. Page exports are isolated copies
with empty attrs; the page retains no full parent table. `read_stats` counts
inspected data/coordinate rows and receipt hashing bytes, not all disk I/O or
peak memory. Receipts and coordinate lookup may scan whole files. A page validates
selected data and necessary coordinates; full `to_pandas()` additionally validates
complete keys, data and mappings. Reading never executes or saves a pending Frame.

Evidence and Findings each return `items`, `input_id`, `session_id`, `artifact_ref`,
`limit`, `total_count`, `has_more` and `next_cursor`. Their limits are 1..100,
default 20; repeat the same limit to continue. Each collection is read independently.
A result can have saved Evidence and no Findings. Resolve record coordinate slots
through the matching `schema.slots`; slots do not identify rows across results
or automatically locate a unique row.
