## Select complete identities explicitly

{/* example: explicit-identity-read */}

```python
Orders = session.catalog.entities.get("sales.orders")
fixed_orders = mv.identities(Orders, keys=((4,), (5,), (6,)))
attributes = session.read(fixed_orders, {"region": region})
east = attributes.where(attributes["region"] == "east").population()
selected = session.observe(
    {"revenue": revenue}, during=august,
    members=east, by=(mv.member(),),
)
selected.execute().show()
```

`session.members(entity_ref, where=...)` selects existing source identities; `identities` captures explicit references, including unconfirmed keys. The Entity passed to `identities` must already be resolved; a bare Ref is a catalog lookup key. Composite keys keep all components in declared order. Population stays lazy: use `session.query(population).execute()` to save keys. `session.read(population, fields)` is the only attribute-read entry and always uses an explicit Session.

`query.coord(axis)` is a scalar value locator. A composite identity cannot become one quantity: execute preparation rejects it before Run admission or business compilation/reads. Keep its complete output/export keys and use Population tuple predicates for identity selection, or choose an existing single-field axis for a scalar Column.

For a versioned attribute, pass a resolved field with `.at(session.instant(...))` in that mapping. Its exact version is independent of the observation period. Missing required profiles or duplicate mappings fail, while a valid source Null remains NA. Computed Measure expressions belong in observe. Population has no read alias or execution method.

## Keep exact calendar boundaries

{/* example: calendar-query */}

```python
days = august.by(mv.grain("day"))
daily = session.observe({"revenue": revenue}, during=days)
monthly = daily.reduce({"sum_of_days": daily["revenue"].sum()}, by=(days.coarsen(mv.grain("month")),))
monthly.execute().show()
```

Acquire time scopes and exact instants through `session.time_scope(...)` and `session.instant(...)`; there are no module-level aliases. Dates and offset-free strings use the Session or explicit boundary zone; aware inputs preserve their instant. Naive Python datetimes and ambiguous/nonexistent wall clocks reject. Scope bounds are half-open. Each CalendarAxis keeps original nominal buckets, actual clipped intervals, order and timezone. DST civil days can contain 23 or 25 hours.

`coarsen(grain)` constructs a candidate calendar. reduce/share/rollup consume it only when every fine nominal and actual bucket has one lawful coarse image. A clipped cross-month week cannot become a month. Reduce uses represented day values; original rollup recomputes the original Metric under its own sufficient-information and additivity constraints.

## Attach the window to the Metric

{/* example: metric-window-query */}

```python
from datetime import timedelta
rolling = session.observe(
    {"revenue": revenue.window(mv.trailing_duration(duration=timedelta(days=7)))},
    during=days,
)
month_to_date = session.observe(
    {"revenue": revenue.window(mv.to_date(grain=mv.grain("month")))},
    during=days,
)
rolling.execute().show(n=5)
month_to_date.execute().show(n=5)
```

Each endpoint evaluates the complete Metric over its own W(t). The display start does not clip earlier window input. `trailing_duration` uses elapsed time; `trailing_periods(count=...)` uses complete calendar periods. `since(start=...)` freezes an exact start; `all_history()` has no lower bound. To-date selects the reset period ending at the evaluation boundary, and calendar buckets must have unique containment.

Windowed original rollup retains the same time axis and endpoints and may perform only qualified spatial rollup. Construct a new observe to change the window or evaluation calendar. Calendar certification does not prove business source completeness.

## Pair completed endpoints

{/* example: period-comparison-query */}

```python
current_days = session.time_scope(start="2026-08-01", end="2026-08-04").by(mv.grain("day"))
prior_days = session.time_scope(start="2026-07-01", end="2026-07-04").by(mv.grain("day"))
current_daily = session.observe({"revenue": revenue}, during=current_days)
prior_daily = session.observe({"revenue": revenue}, during=prior_days)
paired = current_daily.compare(prior_daily, match=mv.ordinal())
paired.execute().show()
```

Ordinal requires compatible Grain, timezone and complete nominal buckets. Filters preserve original bucket ordinals. exact requires equal bucket counts and complete key pairing; outer can retain a longer tail with independent presence.

`period_offset(-1)` moves one true calendar position; on a day axis it means yesterday. `previous_year()` supports builtin day/month/quarter/year same-name periods. Daily February 29 has no counterpart: exact rejects, outer keeps the missing side. Complete February can still pair with last year's complete February. Week/subday and retail 53-week calendars have no automatic year mapping.

Both endpoints complete their own windows before pairing. Default paired output preserves both calendars; `time_axis="current"` requires a real current date on every represented row. A baseline-only row cannot be discarded or assigned a fabricated current date.
