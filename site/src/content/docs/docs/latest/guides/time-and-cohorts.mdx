## Declare source time and sampling

A TimeField owns its optional `sample_interval`; parse owns only encoding and
source clock interpretation. For a native naive timestamp, declare
`parse=ms.timestamp(timezone="UTC")` and, separately on the field,
`sample_interval=(1, "hour")`. Aware timestamps already identify instants and
must omit parser timezone, even when it equals their physical timezone.
Date-only `ms.strptime("%Y%m%d")` must omit timezone. Native DATE/timestamp
fields may use `parse=None`; strings and integers need explicit parse.

Sampling uses the frozen source clock: naive parser/reader authority or UTC for
aware values. Report timezone clips the same source points to actual contribution
intervals; it never changes their phase. Missing expected samples fail coverage;
present samples with NULL retain the reducer's null policy. Without cadence,
only represented samples are evaluated. Same-time facts reduce spatially first.

DATE time roles require day-or-coarser output/reset, whole-24-hour duration
multiples and actual finite boundaries at business midnight. Across DST, an
elapsed 24-hour window can fail that boundary check; use complete civil periods.
A plain `field.within(scope)` keeps its midnight-point predicate meaning.

Snapshots require `ms.snapshot(partition_field=day, timezone="Asia/Shanghai")`.
The field owns the date encoding; snapshot is always daily. Label D is effective
from D midnight. An end-of-day file D must be explicitly authored as effective
D+1 when those values apply only the following day. DATE validity requires its
business timezone. Timestamp validity rejects that parameter: move naive source
localization into the field parser, or remove duplicate timezone for aware data.
`valid_from`, `valid_to`, `interval` and `open_end` remain required.

## Select complete identities explicitly

{/* example: explicit-identity-read */}

```python
Orders = session.catalog.entities.get("sales.orders")
fixed_orders = mv.coordinates(
    by=(mv.identity(Orders),), keys=(((4,),), ((5,),), ((6,),)),
)
attributes = session.read(fixed_orders, {"region": region}).compute()
chosen_orders = attributes.where(attributes["region"] == "east").compute()
east = session.population_from(chosen_orders, on=((chosen_orders.axes[0], Orders),))
selected = session.observe({'revenue': revenue}, by=mv.product(august, east)).compute()
selected.show()
session.frame(east).compute().show()
```

Coordinates captures explicit complete references without proving source presence.
Each identity value is a complete primary-key tuple, even for a one-column key;
`mv.identity(Orders, at=instant)` also captures an explicit version anchor.
read requires one Entity
identity domain and nonempty named fields. The bridge maps that exact result's
complete identity axis to an explicit resolved Entity; a Field cannot be promoted
to identity. `on` is required, with legal on=() for zero axes. Empty projected
domains remain empty constraints. Population stays lazy; frame binds general keys.
Attribute `.at(anchor)` is independent of the observation period. coord accepts
only a single-component FrameAxis; composite identity stays a complete key.


A TimeScope directly in by supplies one interval coordinate; even a single period
retains that axis. Use `by=mv.product(august, east)` to retain every selected
identity, including those without facts. `east.count()` is a lazy Metric over that
captured identity domain and counts absent identities; fact conditions do not
reselect its denominator. Combine field and member leaves in one native Deferred
condition, for example `(region == "east") | mv.in_population(east)`, in
observe, eligible Metric.where or members. Both sides retain their checks and
dependencies; nullable fields keep three-valued boolean semantics. A condition
does not acquire window endpoints or attribute anchors. See
`marivo.help("semantic.predicate")` for the source grammar.
Only-count observations reject conditions/windows with no fact effect.
A domain without time broadcasts the same selected tuple count across the requested
time axis. To count selected identities by a new attribute, retain identity explicitly:

```python
classified = east.classify(by=(east.axes[0], region))
by_region = session.observe({"orders": classified.count()}, by=(region,)).compute()
by_region.show()
```

Projecting classified to region alone before counting would count distinct regions.

## Keep exact calendar boundaries

{/* example: calendar-query */}

```python
days = august.by(mv.grain("day"))
daily = session.observe({'revenue': revenue}, by=(days,)).compute()
sum_of_days = daily.reduce({"sum_of_days": daily["revenue"].sum()}).compute()
sum_of_days.show()
monthly_source = session.observe({'revenue': revenue}, by=(august.by(mv.grain('month')),)).compute()
monthly_source.show()
```

The scalar sum_of_days consumes represented rows; monthly_source requests new
source computation. They are different questions even when this additive demo
has equal totals. There is no Frame calendar coarsening or CalendarAxis.coarsen.
Session instant/time_scope freeze exact boundaries; dates/offset-free strings use
the chosen zone, aware inputs retain their instant, and naive Python datetimes or
ambiguous/nonexistent clocks reject. A CalendarAxis keeps original nominal and
clipped actual buckets; civil days can last 23 or 25 hours. Grain has no ordering
operators. Subday count must tile a nominal day and use one spelling: 60second,
120second, 60minute and 24hour reject; 90second and 90minute are valid. A calendar
lookup Grain cannot enter `scope.by`; obtain `calendar.grain(level)` with a
captured certificate. Equality and hashing retain that snapshot identity.

## Attach the window to the Metric

{/* example: metric-window-query */}

```python
from datetime import timedelta
rolling = session.observe({'revenue': revenue.window(mv.trailing_duration(duration=timedelta(days=7)))}, by=(days,)).compute()
month_to_date = session.observe({'revenue': revenue.window(mv.to_date(grain=mv.grain('month')))}, by=(days,)).compute()
rolling.show(n=5)
month_to_date.show(n=5)
```

Each endpoint evaluates the complete child Metric over W(t), including lookback
before the display start. trailing_duration is elapsed time; trailing_periods
uses complete civil/certified periods. since freezes a start; all_history has no
lower bound; to_date selects the reset period ending at the evaluation boundary.
A named-calendar rule is a checked semantic dependency; a snapshot-bound Grain
must match the Session's frozen certified scope. New windows/calendars require
explicit observe; certification does not prove source completeness. The endpoint
is each bucket's actual clipped right boundary. `trailing_periods` rejects
partial edge buckets and follows full-calendar predecessors for sparse axes.

## Pair completed endpoints

{/* example: period-comparison-query */}

```python
current_days = session.time_scope(start="2026-08-01", end="2026-08-04").by(mv.grain("day"))
prior_days = session.time_scope(start="2026-07-01", end="2026-07-04").by(mv.grain("day"))
current_daily = session.observe({'revenue': revenue}, by=(current_days,)).compute()
prior_daily = session.observe({'revenue': revenue}, by=(prior_days,)).compute()
comparison = current_daily.compare(
    {"reference": prior_daily}, match={"reference": mv.ordinal()},
).compute()
comparison.show()
```

Both inputs have one sole calendar axis, so on is inferred; the explicit
alias-keyed ordinal rule pairs complete original positions. Filtering never
renumbers them. Compare retains the current calendar and named baseline facts;
align owns paired output and a general two-ended time union.

## Observe exact shifted periods

{/* example: shifted-period-comparison-query */}

```python
months = session.time_scope(start="2026-08-01", end="2026-08-20").by(mv.grain("month"))
current_progress = session.observe({"revenue": revenue}, by=(months,))
previous_progress = session.observe(
    {"revenue": revenue}, by=(months.shift(mv.offset(periods=-1)),),
)
progress = current_progress.compare({"mom": previous_progress}).compute()
progress.show()
```

Each endpoint evaluates the original Metric over its own exact domain, including
nonadditive formulas. `offset(years=-1)` uses civil years and ISO week-year for
weeks; `offset(periods=-1)` uses nominal grain distance, never sparse row position.
Supply exactly one non-boolean integer keyword. Unit-step builtin week/month/year
shift supports full buckets or prefixes from their bucket starts. The example
pairs August 1–20 midnight with July 1–20 midnight; no current range is shortened.
Missing ISO W53 or civil cutoff dates have no target; selected targets may be
sparse or empty. No envelope filling, date clamping or ancestor recovery occurs.
Nonzero target DST gaps/folds reject; zero offsets retain exact captured instants.

A compatible immediate frozen shift relation supplies compare's match; wrong
anchors or conflicting explicit match reject. Otherwise omitted match is equality.
Fixed-data complete day/quarter offset matching remains supported; their partial
buckets reject, while week/month/year prefixes require exact saved progress.
Ordinal requires complete compatible nominal/actual partitions. Named calendars
support ordinal only; named/subday offsets and arbitrary maps remain outside the
scope. Exact checks actual joint keys; outer keeps mapped missing sides with
independent presence and rejects actual baseline time rows outside the current
declared domain. Saved endpoint/map facts do not reconstruct Metric, source or
current timezone rules. A Population contribution selection is unchanged by
shift; by=P is each endpoint's own complete domain and must be constructed
explicitly for both periods.

Only exact Session TimeScope boundaries are InstantAnchor values; Catalog periods
may have civil date bounds. Use `session.instant(...)` for an exact anchor.
Literal coordinates describe keys without proving source existence;
`session.members(...)` selects a source identity domain.
