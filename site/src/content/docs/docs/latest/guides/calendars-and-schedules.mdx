---
title: Calendars and temporal occurrences
description: Certify period boundaries and named temporal occurrences.
---

These declarations consume governed time/dimension fields from calendar,
and campaign Entities. They require their dedicated certified artifacts;
ordinary preview history does not establish those artifacts.

Import `date` from `datetime`, `marivo.datasource as md`, `marivo.semantic as ms`
and `marivo.analysis as mv`. Each declaration belongs to an existing sales domain;
`catalog = ms.load()` loads its models. Analysis examples additionally require
an existing Session and the admitted Metric/relationship named below.

## Certify a period calendar

The sales.calendar Entity declares calendar_date and all named period fields in the example. `catalog` loads that project.

{/* example: period-calendar */}

```python
calendar_ref = ms.period_calendar(
    name="fiscal",
    date=ms.ref.time_dimension("sales.calendar.calendar_date"),
    boundary_timezone="UTC",
    coverage=(date(2026, 1, 1), date(2027, 1, 1)),
    levels={"week": ms.ref.dimension("sales.calendar.fiscal_week")},
)
calendar = catalog.period_calendars.get(calendar_ref.path)
catalog.preview(
    calendar_ref,
    scope=md.unpruned(max_rows=400, timeout_seconds=30),
)

calendar = catalog.period_calendars.get("sales.fiscal")
grain = calendar.grain("week")
week_scope = calendar.period("week", "FY2026-W01")
assert week_scope.kind == "calendar_period"
week_scope.show()  # exact bounds and certified snapshot identity
```

Calendar identity governs boundaries and membership. Analysis alignment uses
those certified facts, not equal-looking period labels. A failed or truncated
certification does not publish a replacement artifact.

## Name temporal occurrences

The sales.campaigns Entity declares campaign identity and start/end boundaries with their exact time meaning. The observation also requires `sales.customer`, the `sales.order_buyer` relationship and a resolved `sales.revenue` Metric.

{/* example: temporal-set */}

```python
campaigns_ref = ms.temporal_set(
    name="campaigns",
    occurrence_id=ms.ref.dimension("sales.campaigns.campaign_id"),
    start=ms.ref.time_dimension("sales.campaigns.starts_at"),
    end=ms.ref.time_dimension("sales.campaigns.ends_at"),
    boundary_timezone="Asia/Shanghai",
    coverage=(date(2026, 1, 1), date(2027, 1, 1)),
    category=ms.ref.dimension("sales.campaigns.category"),
)
catalog.preview(
    campaigns_ref,
    scope=md.unpruned(max_rows=400, timeout_seconds=30),
)

campaigns = catalog.temporal_sets.get("sales.campaigns")
launch = campaigns.occurrence("spring-2026")
Customer = session.catalog.entities.get("sales.customer")
members = session.members(Customer)
revenue = session.catalog.metrics.get("sales.revenue")
query = session.observe({'revenue': revenue}, by=mv.product(launch, members))
```

Keep occurrence identity and interval semantics explicit; a selected occurrence is not a global time filter for every unrelated quantity.

`mv.grain` describes builtin units; `ms.calendar_grain` captures a source-free
lookup, while `calendar.grain(level)` retains the certified snapshot.
`scope.by(grain).scope` is the original scope. A shifted axis may have
`scope is None`; reading never fills it from the grid envelope. `axis.grid`
retains frozen buckets and calendar interpretation. A day bucket can span 23 or
25 hours across DST; nominal widths do not describe its elapsed duration.
