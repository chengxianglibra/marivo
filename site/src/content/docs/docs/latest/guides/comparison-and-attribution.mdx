This guide continues the [local tutorial](/docs/latest/guides/python-quick-start/). It compares the same named revenue quantity by region.

## Compare before executing

{/* example: compare-query */}

```python
change = current.compare(baseline, how="exact")
comparison = change.execute().to_pandas()
assert comparison[("value", "revenue.absolute")].tolist() == [-100, -100]
assert comparison[("value", "revenue.relative")].tolist() == [-1 / 3, -1 / 7]
outer = current.compare(baseline, how="outer")
```

Compare emits `<name>.current`, `.baseline`, `.absolute` and `.relative`. Relative is `(current-baseline)/abs(baseline)`. A common non-NA zero baseline defaults only the new relative to NA; `zero_denominator="error"` rejects that demanded division. Child policies remain in force. Business comparability still belongs to the caller.

Exact requires unique complete matching keys. Outer retains their union with independent current/baseline presence; an NA value does not mean its endpoint is absent. Missing sides are not zero. Only requesting the absolute difference can use align/select:

{/* example: aligned-absolute-only */}

```python
aligned = current.align(baseline)
difference = aligned.select({
    "difference": aligned["left.revenue"] - aligned["right.revenue"],
})
difference.execute().show()
```

## Follow up on endpoints

Query comparison has no direct drill or specialized attribution method. Select the relevant original endpoint coordinates, request a new admissible breakdown with `drill(add=(field,))` or a fresh observe, then compare those endpoints. Ordinary region selection in the tutorial is:

{/* example: comparison-endpoint-followup */}

```python
selected_current = current.where(current["revenue"] < 300)
selected_baseline = baseline.where(baseline["revenue"] < 400)
followup = selected_current.compare(selected_baseline)
followup.execute().show()
```

A declared additional field must be single-valued at an identity axis. A raw customer_id plus channel groups contribution images; it does not assert a customer identity domain. Saved comparison rows can be inspected or grouped in pandas; they cannot be passed back as a Query.

Source `rollup` and `drill` may read data that changed after the parent was evaluated.
For example, after `current.top(1, by=current["revenue"])` selects a region, a subsequent
drill keeps that selected region even if another region later becomes larger. New or
deleted contributions within the selected region can change the recomputed values.
No snapshot or cross-read consistency is promised. Source calculation and native
result conversion may also produce different rounding from local calculation.
Recomputation accepts this precision loss; subsequent filters and rankings use
the returned values, while completed parent selections stay fixed. Qualified
source-side Query filtering and Top also use native numeric values, with NaN
treated as missing and complete keys retained for ties.
Qualified formulas spanning multiple roots on one source session reduce each root
separately before aligning completed values. Row arithmetic retains its declared
NULL, overflow and division checks, including checks before an empty Top result.
For sampled metrics, a qualified rollup recomputes over the combined contributions
of the selected parents. It does not average their already completed means.
Windowed metrics retain each endpoint's lookback period; selecting parent rows
does not change the definition of that window.
Plain Calendar totals can regroup original contributions from day to month.
Qualified formulas across sources reduce each source separately, complete the
parent formula, then read target totals; they do not require a shared snapshot.

## Transport a complete reference

{/* example: broadcast-reference */}

```python
budget = session.values(
    by=(region,), columns={"budget": "CNY"},
    rows=((("east",), {"budget": 250}), (("west",), {"budget": 750})),
)
reference = mv.broadcast(budget["budget"], to=current)
vs_budget = current.select({
    "revenue": current["revenue"],
    "budget_variance": current["revenue"] - reference,
})
vs_budget.execute().show()
```

Reference keys must be unique and cover all target keys. Every reference axis needs an unambiguous complete target projection; matching names or row position are insufficient. A zero-axis reference must have exactly one row. Broadcast repeats value use, not facts or additivity authority.

For a genuine contribution share, use `current.share("revenue")`. Its denominator is computed from the same actual input. Filtering after share keeps that original denominator; filtering before share changes it. Ordinary reference division does not establish contribution inclusion.

## Choose correspondence explicitly

Different calendars require an axis-free rule such as `match=mv.ordinal()` or `mv.previous_year()`. Ordinal uses original complete bucket order; previous_year leaves daily leap days unmatched. `match=mv.corresponding(via=(relationship,))` uses a declared one-to-one identity path, not equal-looking fields. Nonidentity output saves both endpoint projections. See [time and identities](/docs/latest/guides/time-and-cohorts/).
