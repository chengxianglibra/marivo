---
title: Compare and investigate changes
description: Compare fixed data or request new source investigation and qualified contribution.
---

Read nested fact records from `frame.method_facts` and its fields.
`FrameMethodFacts` remains the root aggregate type; nested record classes are
not `mv.*` constructors. Use `marivo.help(type(value))` to discover their complete
fields. Inspect method variants through their `kind` values: `additive`,
`ratio_component` or `linear`. These records retain original explanations without
acquiring source authority or certifying a new decomposition.

This guide continues the [local tutorial](/docs/latest/guides/python-quick-start/).

## Compare fixed data

{/* example: compare-query */}

```python
on = tuple(zip(current.axes, baseline.axes))
change = current.compare({'reference': baseline}, on={'reference': on}, match={'reference': mv.ordinal()}, how="exact").compute()
comparison = change.to_pandas()
assert comparison[("value", "reference.absolute.revenue")].tolist() == [-100, -100]
assert comparison[("value", "reference.relative.revenue")].tolist() == [-1 / 3, -1 / 7]
outer = current.compare({'reference': baseline}, on={'reference': on}, match={'reference': mv.ordinal()}, how="outer")
```

Compare retains current `revenue`, then adds `reference.baseline.revenue`,
`reference.absolute.revenue` and `reference.relative.revenue`. Relative is
(current-baseline)/abs(baseline). A valid zero baseline defaults only the new
relative to NA; `zero_denominator="error"` fails that demanded division. Missing
rows or NA yield NA differences; strict child policies stay required.
`current.present` and `reference.present` are independent row flags; inherited
presence lives below `current.presence.*` and `reference.presence.*`.

Exact checks actual complete joint keys. Outer retains current order then
mapped baseline-only keys; actual baseline time rows outside the declared current
domain reject. Use align for a general two-ended time union. Each input here has
interval and region axes: the alias-keyed on entry covers both, and the
alias-keyed ordinal rule explicitly pairs periods. Display names do not bind
inputs. Single and multiple baselines use the same named mapping; a name such
as `yoy` never infers a rule or source computation.

Ordinary Frame axes retain complete key types, roles and time interpretation
without original Entity/Field nominal bindings. Explicit on declares your business
correspondence; validation does not check original Entity/Field equality. Even
compatible Customer/Product identity keys can be explicitly paired. Equal value
names select comparison pairs; names, types and units do not prove Metric identity
or business comparability. exact validates the declared key correspondence.

{/* example: aligned-absolute-only */}

```python
aligned = current.align(
    baseline, on=tuple(zip(current.axes, baseline.axes)), match=mv.ordinal(),
)
difference = aligned.select({
    "difference": aligned["left.revenue"] - aligned["right.revenue"],
}).compute()
difference.show()
```

## Ask for new source facts explicitly

`session.attribute` takes explicit current and baseline endpoints. Continuing the
tutorial's physical DuckDB table and resolved inputs, the default request needs
no contribution proof. Each `AttributeEndpoint` copies its named Metric mapping;
optional `where` is a native Deferred predicate and `memberships` supplies explicit
Grouping allocation rules. Endpoint `during` retains its independent time scope:

{/* example: attribute-default-investigation */}

```python
pending = session.attribute(
    mv.AttributeEndpoint({"revenue": revenue}, during=august),
    mv.AttributeEndpoint({"revenue": revenue}, during=july),
    by=(region,),
)
pending.show(n=0)
investigation = pending.compute()
assert investigation.to_pandas()[("value", "absolute.revenue")].tolist() == [-100, -100]
```

Left is current and right is baseline. Values are left/right/absolute groups,
with independent left/right presence. Unlike compare, Attribute adds no relative
column. Fine keys use the complete outer union and canonical order; missing or
NA values stay NA. Omitted parents mean one overall parent; an explicitly empty
parent selection stays empty. Ordinary parent axes need complete dual `parent_on`
bindings; `parent_how` exact/outer controls parents, not zero filling. Calendar and
paired-calendar parent axes retain their explicit binding rules. Interval and
paired-interval Frame parent axes refuse before reads; reduce the interval axis before
selecting parents, or use an explicit CalendarAxis parent and endpoint scopes. Endpoint `during=TimeScope` remains
supported.

## Request exact contribution explicitly

The tutorial uses the qualified physical DuckDB table route. The same endpoints
can explicitly request contribution; datasource access alone does not qualify
file or remote routes. Unsupported rules or missing component proof fail rather
than silently falling back. An explicit default investigation remains a separate
request when the original observation is valid.

{/* example: attribute-contribution-facts */}

```python
explained = session.attribute(
    mv.AttributeEndpoint({"revenue": revenue}, during=august),
    mv.AttributeEndpoint({"revenue": revenue}, during=july),
    by=(region,),
    contribution=True,
).compute()
assert explained.to_pandas()[("value", "contribution.revenue")].tolist() == [-100, -100]
facts = explained.method_facts
facts[0].show(n=0)
declines = explained.where(explained["contribution.revenue"] < 0).compute()
saved_declines = declines.persist()
reopened_declines = session.persisted_frame(saved_declines.artifact.id)
decline_rows = reopened_declines.to_pandas()
original_explanation = reopened_declines.method_facts
```

The overall change is -200, with contribution -100 and share 0.5 for each region.
Share uses the original parent change; selecting rows does not change that
denominator or certify a new decomposition. Zero parent change leaves contributions
defined and only share undefined. Direct ratio results also expose their numerator/
denominator endpoint groups. Actual completed numeric types, units and NA are
preserved; no universal Decimal precision or source-read count is promised.

`method_facts` explicitly reads complete original explanations. On stored Frames
it validates owned method files without primary rows, Catalog or source access;
the subsequent fact show is in-memory. Pending access requires compute/persist.
Frame cards show count, bounded origins and this read pointer. `to_pandas()` reads
current data only; stored compute and evaluated derivatives consume current data
and method facts. The saved derivative owns its payload even if the original
Artifact is removed. Facts never recover a Metric or source authority. Use
`marivo.help("analysis.analysis_frame.method_facts")` and
`marivo.help("analysis.frame_method_facts")` for exact fields and reading effects.

A nonlinear formula such as `revenue * revenue` rejects
`contribution=True` with `unsupported_expression`. This does not invalidate its
ordinary observation. Request default investigation explicitly instead of
changing the formula or relying on a fallback:

{/* example: attribute-explicit-default-after-refusal */}

```python
nonlinear = revenue * revenue
nonlinear_investigation = session.attribute(
    mv.AttributeEndpoint({"squared": nonlinear}, during=august),
    mv.AttributeEndpoint({"squared": nonlinear}, during=july),
    by=(region,),
    contribution=False,
).compute()
```

These are grouped nonlinear observations, not an assertion that summing them
reconstructs the original overall formula or provides exact contributions.

## Fix a parent selection before a new request

{/* example: comparison-endpoint-followup */}

```python
chosen = current.top(1, by=current["revenue"]).compute()
parents = session.population_from(chosen, on=((chosen.axes[1], region),))
prior_selected = session.observe({'revenue': revenue}, by=(july, region), where=mv.in_population(parents)).compute()
followup = chosen.compare(
    {"reference": prior_selected},
    on={"reference": tuple(zip(chosen.axes, prior_selected.axes))},
    match={"reference": mv.ordinal()},
).compute()
followup.show()
```

The fixed Top selects west; a new source observation investigates that selected
region in July. It does not rerank the parent or recover history from the result.
For a new breakdown, explicitly obtain its governed field and include it in a
new source request. New contributions may have changed since selection; no shared source
snapshot is promised. Frame current-row reduce never substitutes an original
Metric overall, and there is no Frame drill/rollup/share receiver.

## Align an explicit complete-domain reference

{/* example: broadcast-reference */}

```python
budget = session.values(
    by=(region,), columns={"budget": "CNY"},
    rows=((("east",), {"budget": 250}), (("west",), {"budget": 750})),
).compute()
regional = current.reduce({"revenue": current["revenue"].sum()},
                          by=(current.axes[1],)).compute()
aligned_budget = regional.align(budget, on=((regional.axes[0], budget.axes[0]),))
vs_budget = aligned_budget.select({
    "revenue": aligned_budget["left.revenue"],
    "budget_variance": aligned_budget["left.revenue"] - aligned_budget["right.budget"],
}).compute()
vs_budget.show()
```

The one-period revenue rows are explicitly summed by region to remove the interval axis before alignment. This current-row sum does not reconstruct arbitrary non-additive Metrics. The budget covers the same region domain. This is ordinary full-axis
alignment and arithmetic; it does not broadcast a scalar, infer a relationship,
or establish contribution inclusion. Automatic broadcast and a Frame share
receiver are outside this surface; optional source contribution share
belongs to the explicit Attribute request above.

## Choose calendar correspondence deliberately

Zero axes or a sole same-kind interval/calendar axis permit the specified on
inference; other axes require a complete explicit binding. Named compare accepts
per-alias match or a compatible immediate frozen shift relation. Align keeps an
explicit match and paired/general time-union behavior; compare keeps current axes
and inert named baseline facts. See [time and cohorts](/docs/latest/guides/time-and-cohorts/).
