Declare each connection in `models/datasources/`; loading a declaration does
not open a connection. For environment-based credentials, declare `*_env`
references. After a validated connection test, Marivo may cache
environment-sourced credentials as plaintext in the user-global
`~/.marivo/secrets.toml`. Set
`MARIVO_PERSIST_CREDENTIALS=0` to disable this cache.

`md.inspect` reads physical metadata. To collect a row sample, select columns
and pass an explicit scope with positive `max_rows` and `timeout_seconds`.
Backends may skip a timeout request they do not support; `max_rows` bounds
returned rows, not bytes scanned. Metadata and samples can guide modeling, but
do not establish business meaning. See [Datasource configuration](/docs/latest/modeling/datasources/).

## Collect a bounded row sample

Use `marivo.help("datasource.inspection")` to choose a scope and output column
names from `inspection.schema`; projected sources use their output aliases.
After `md.inspect(...)`, call `.sample(...)` on the returned `SourceInspection`.
By default, a fresh sample keeps profile values in the current process, but named
rows are not retained. `persist_values=True` makes bounded named rows and profile
values available and saves them as plaintext in project-local state. Matching
snapshots are reused even when marked stale; use `refresh=True` to read again.

## Choose physical sources

Choose a table or view with `md.table(...)`; Parquet, CSV, and JSON file sources
use DuckDB. See [physical sources](/docs/latest/modeling/datasources/#connections-and-physical-sources).

## Parameterized JSON

Put concrete GET query parameters or POST body values directly in the semantic
source definition. Use these descriptors as `source=` in `ms.entity(...)`, then
define fields and Metrics normally. Their Analysis Frames use ordinary
`compute()` or `persist()`:

```python
import marivo.datasource as md

alerts = md.json(
    "https://api.example/alerts",
    query_params={"page_number": 1, "page_size": 100},
    records_path="$.data.vcdn_list",
    columns={"id": "id", "severity": "severity"},
)
changes = md.json(
    "https://api.example/changes",
    method="POST",
    body={"filter": {"apps": ["app-a", "app-b"]}, "page_num": 1},
    records_path="$.data.change_infos",
    columns={"id": "change_id", "app_id": "specificsource[].appid"},
)
```

Loading, construction and metadata display send no request. During evaluation,
HTTP acquisition supplies both schema inference and subsequent computation;
identical requests share one response across consumers and projections. Each new
computation fetches again; completed/reopened Frames use fixed data. One page
never proves collection completeness, and Marivo does not traverse pages.

`md.source_param(...)` placeholders still support explicit datasource sampling
and Semantic preview. Complete them with concrete values in the source definition
before Analysis. Missing values in any pending dependency fail before any request.
See `marivo.help("datasource.json")` and `marivo.help("datasource.source_param")`.

## Default datasource and host credentials

The built-in `default` is a fresh, in-memory DuckDB with no credentials. For
durable data, declare a file-backed DuckDB or use a datasource backed by
persistent storage. For host-managed credentials, see
[runtime configuration](/docs/latest/reference/configuration/#integrate-host-credentials)
and `marivo.help("datasource.credential_scope")`.
