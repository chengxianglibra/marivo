---
title: Datasource configuration
description: Configure DuckDB, PostgreSQL, MySQL, ClickHouse, and Trino datasources.
---

Marivo provides five datasource constructors. Save each declaration under `models/datasources/`; the loader collects it without opening a connection. Choose the constructor for the backend, then reference its name from an Entity. Remote examples are templates: replace the host and database, then set the referenced environment variables before testing.

Each table lists constructor parameters and their Python defaults. An omitted optional value leaves backend, adapter, or driver behavior in effect. Set referenced environment variables before testing.

| Backend | Constructor | Typical use |
| --- | --- | --- |
| DuckDB | `md.duckdb` | Local database; file sources |
| PostgreSQL | `md.postgres` | PostgreSQL |
| MySQL | `md.mysql` | MySQL |
| ClickHouse | `md.clickhouse` | ClickHouse |
| Trino | `md.trino` | Distributed catalogs |

## DuckDB — `md.duckdb`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `name` | Yes | — | Project-wide lowercase snake_case datasource name; referenced by `ms.ref.datasource(name)`. |
| `path` | No | `':memory:'` | DuckDB file path, or `":memory:"` for a process-local database. Use a file for the tutorial. |
| `read_only` | No | `False` | Open the database in read-only mode when true. |
| `http_scope` | No | `None` | HTTP(S) URL prefix bounding remote JSON authentication; required when an HTTP auth mode is supplied. |
| `http_bearer_token_env` | No | `None` | Environment variable name for a bearer token; mutually exclusive with header authentication. |
| `http_headers_env` | No | `None` | Mapping from HTTP header names to environment variable names containing their secret values; mutually exclusive with bearer authentication. |
| `ai_context` | No | `None` | Optional business context via `ms.ai_context(...)`. |
| `extra` | No | `None` | Additional JSON-compatible Ibis connection arguments not modeled above. |


```python
# models/datasources/warehouse.py
import marivo.datasource as md

md.duckdb(name="warehouse", path="warehouse.duckdb", read_only=False)
```

Exact reference: `marivo.help("datasource.duckdb")`.

## PostgreSQL — `md.postgres`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `name` | Yes | — | Project-wide lowercase snake_case datasource name; referenced by `ms.ref.datasource(name)`. |
| `host` | Yes | — | Database server host name or IP address. |
| `database` | Yes | — | Database to connect to. |
| `port` | No | `None` | Connection port; set explicitly for a non-default endpoint. |
| `schema` | No | `None` | Default schema for table resolution. |
| `autocommit` | No | `None` | Driver autocommit override. |
| `user_env` | No | `None` | Environment variable name for the database user. |
| `password_env` | No | `None` | Environment variable name for the password. |
| `ai_context` | No | `None` | Optional business context via `ms.ai_context(...)`. |
| `extra` | No | `None` | Additional JSON-compatible Ibis connection arguments not modeled above. |


```python
# models/datasources/reporting.py
import marivo.datasource as md

md.postgres(
    name="reporting", host="postgres.example.internal", database="sales",
    port=5432, schema="public",
    user_env="PG_USER", password_env="PG_PASSWORD",
)
```

Exact reference: `marivo.help("datasource.postgres")`.

## Trino — `md.trino`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `name` | Yes | — | Project-wide lowercase snake_case datasource name; referenced by `ms.ref.datasource(name)`. |
| `host` | Yes | — | Database server host name or IP address. |
| `catalog` | Yes | — | Trino catalog, mapped to the Ibis database connection argument. |
| `user_env` | Yes | — | Required environment variable name for the Trino user; no implicit backend user fallback. |
| `port` | No | `None` | Connection port; set explicitly for a non-default endpoint. |
| `schema` | No | `None` | Default schema for table resolution. |
| `source` | No | `None` | Client application/source tag sent to Trino. |
| `timezone` | No | `None` | Trino engine session timezone; distinct from the Analysis Session report timezone. |
| `http_scheme` | No | `None` | HTTP transport scheme; use `"https"` for TLS. |
| `client_tags` | No | `None` | Tuple of client tags, passed to Trino as a list. |
| `session_properties` | No | `None` | Trino session property mapping. |
| `auth_env` | No | `None` | Environment variable name for authentication material, when the server requires it. |
| `ai_context` | No | `None` | Optional business context via `ms.ai_context(...)`. |
| `extra` | No | `None` | Additional JSON-compatible Ibis connection arguments not modeled above. |


```python
# models/datasources/lake.py
import marivo.datasource as md

md.trino(
    name="lake", host="trino.example.internal", catalog="hive", schema="sales",
    user_env="TRINO_USER", auth_env="TRINO_AUTH", http_scheme="https",
    client_tags=("marivo", "reporting"),
)
```

Exact reference: `marivo.help("datasource.trino")`.

## Credentials and connection checks

Reference credentials by environment variable name with `*_env`; Marivo does not infer variable names. After a successful `md.load().test(...)` round-trip, Marivo may cache environment-resolved values as plaintext in the user-global `~/.marivo/secrets.toml`. Caching is disabled when `MARIVO_PERSIST_CREDENTIALS=0` or `CI` is non-empty. The cache file is restricted to owner access (`0600`), its parent directory to `0700`, and Marivo refuses to write it inside a Git repository. Keep secret values out of model files and `extra`.

After creating the [tutorial database](/docs/latest/start/python/), run this from its project root:

```python
import marivo.datasource as md
import marivo.semantic as ms

warehouse = ms.ref.datasource("warehouse")
md.load().test(warehouse).show()
md.inspect(warehouse, md.table("orders"), workspace_dir=".").show()
```

## Connections and physical sources

`md.table(...)` selects a table or view in any supported backend. `md.parquet(...)` and `md.csv(...)` describe DuckDB file sources; `md.json(...)` describes a file or HTTP source. These are source descriptors, not additional datasource types. `md.inspect(...)` reads physical metadata. For a row sample, call `inspection.sample(...)` with an explicit scope, selected columns, and positive `max_rows` and `timeout_seconds`. Unsupported native timeout requests may be skipped; `max_rows` limits returned rows, not bytes scanned. Sample values stay in memory unless `persist_values=True` stores the bounded values as plaintext in project-local state. For JSON, Analysis Sessions currently admit only local files using GET with no declared query parameters. See [bounded datasource inspection](/docs/latest/guides/datasources/#bound-row-evidence), [backend and method limits](/docs/latest/reference/backends-and-limits/), then [define Entities](/docs/latest/modeling/semantic-layer/).
