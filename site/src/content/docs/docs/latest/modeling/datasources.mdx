---
title: Datasource configuration
description: Configure DuckDB, PostgreSQL, MySQL, ClickHouse, and Trino datasources.
---

Marivo provides five datasource constructors. Save each declaration under `models/datasources/`; the loader collects it without opening a connection. Choose the constructor for the backend, then reference its name from an Entity. Remote examples are templates: replace the host and database, then set the referenced environment variables before testing.

`wall_clock_timezone` is a source declaration, stored separately from connection options. Field parser timezones override it; `hour_prefix` inherits its prefix field’s effective timezone. It does not affect physical instants, including MySQL TIMESTAMP and ClickHouse DateTime. When a naive time or business date has no source declaration, declare it before analysis; connection, host and report timezones do not fill it. Trino uses a private UTC transport setting and has no public `timezone` parameter.

Each table lists constructor parameters and their Python defaults. An omitted optional value leaves backend, adapter, or driver behavior in effect. Set referenced environment variables before testing.

| Backend | Constructor | Typical use |
| --- | --- | --- |
| DuckDB | `md.duckdb` | Local database; file sources |
| PostgreSQL | `md.postgres` | PostgreSQL |
| MySQL | `md.mysql` | MySQL |
| ClickHouse | `md.clickhouse` | ClickHouse |
| Trino | `md.trino` | Distributed catalogs |

## Relative declaration imports

Share configuration with relative imports inside `models/datasources/`:

```python
# models/datasources/settings.py
WAREHOUSE_PATH = "warehouse.duckdb"
```

```python
# models/datasources/warehouse.py
import marivo.datasource as md
from .settings import WAREHOUSE_PATH

md.duckdb(name="warehouse", path=WAREHOUSE_PATH, wall_clock_timezone="UTC")
```

Each declaration read uses a fresh namespace and executes an imported file once.
Loading does not modify `sys.path`; model absolute imports are unsupported.
Standard-library and installed dependencies use ordinary imports and retain
Python's module cache. Restart Python after changing those dependencies or
upgrading packages. Modules from declaration loads remain until process exit.

`md.load()` retains the selected workspace; its catalog methods read current
declarations on each operation. A SemanticCatalog instead retains its captured
snapshot, independently from later loads.

## DuckDB — `md.duckdb`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `name` | Yes | — | Project-wide lowercase snake_case datasource name; referenced by `ms.ref.datasource(name)`. |
| `path` | No | `':memory:'` | DuckDB database file path, or a connection-local database with `:memory:`. |
| `read_only` | No | `False` | Open a DuckDB database file in native read-only mode when true. |
| `secrets` | No | `()` | List of `md.s3_secret`, `md.http_bearer_secret` or `md.http_headers_secret` values. |
| `wall_clock_timezone` | No | `None` | Source timezone for undeclared naive timestamps, encoded clocks and business dates; IANA name or fixed offset. |
| `ai_context` | No | `None` | Optional business context via `ms.ai_context(...)`. |
| `extra` | No | `None` | Additional JSON-compatible Ibis connection arguments not modeled above. |


```python
# models/datasources/warehouse.py
import marivo.datasource as md

md.duckdb(name="warehouse", path="warehouse.duckdb", read_only=False, wall_clock_timezone="UTC")
```

Exact reference: `marivo.help("datasource.duckdb")`.

## Credentials and connection checks

Reference credentials by environment variable name with `md.env("NAME")`; Marivo does not infer variable names. After a successful `md.load().test(...)` round-trip, Marivo may cache environment-resolved values as plaintext in the user-global `~/.marivo/secrets.toml`. Caching is disabled when `MARIVO_PERSIST_CREDENTIALS=0` or `CI` is non-empty. The cache file is restricted to owner access (`0600`), its parent directory to `0700`, and Marivo refuses to write it inside a Git repository. Keep secret values out of model files and `extra`.

After creating the [tutorial database](/docs/latest/start/python/), run this from its project root:

```python
import marivo.datasource as md
import marivo.semantic as ms

warehouse = ms.ref.datasource("warehouse")
md.load().test(warehouse).show()
md.inspect(warehouse, md.table("orders"), workspace_dir=".").show()
```

## Connections and physical sources

`md.table(...)` selects a table or view in any supported backend. `md.parquet(...)` and `md.csv(...)` describe DuckDB file sources; `md.json(...)` describes a file or HTTP source. These are source descriptors, not additional datasource types. `md.inspect(...)` reads physical metadata. For a row sample, call `inspection.sample(...)` with an explicit scope, output columns from `inspection.schema`, and positive `max_rows` and `timeout_seconds`. Unsupported native timeout requests may be skipped; `max_rows` limits returned rows, not bytes scanned. By default, a fresh sample keeps profile values in the current process, but named rows are not retained. `persist_values=True` makes bounded named rows and profile values available and saves them as plaintext in project-local state. Matching snapshots are reused even when stale; `refresh=True` reads again. Analysis admits local GET JSON and HTTP(S) GET/POST JSON on DuckDB with concrete request values in the source definition. Each evaluation reuses a response without automatic pagination; unresolved source parameters fail before acquisition. See [backend and method limits](/docs/latest/reference/backends-and-limits/), then [define Entities](/docs/latest/modeling/semantic-layer/).

HTTP JSON columns that are missing or null in every returned record retain the `null` type. Unused columns do not block Analysis, field preview, or selected-column sampling. Used inputs must satisfy the consuming operation’s type requirements; explicit casts and null predicates follow normal expression rules. Local JSON keeps DuckDB’s native inference. An empty records array may fail because declared column types cannot be inferred.

PostgreSQL, MySQL/MariaDB and Trino CHAR/CHARACTER columns retain their physical type and width. Entity/Dimension validation maps them to logical strings, including expression Entity inputs and declared keys. This mapping adds no SQL cast, trimming, padding or collation emulation; reads, comparisons and grouping follow the native backend. CHAR cannot supply a numeric Measure.

For `md.time_range(...)`, match endpoints to the inspected physical type: aware datetimes for aware timestamps, naive datetimes or dates for naive timestamps, and dates for DATE. Both endpoints must have the same kind and awareness. Mismatches fail before acquisition with `query_executed=False`; `wall_clock_timezone` does not fill boundary awareness.

## Scoped DuckDB credentials

All credential fields accept only `md.env("NAME")`; literal strings are rejected. S3 requires a region and static access key references. Optional `session_token` also takes `md.env`; `endpoint`, `url_style` (`vhost` or `path`) and `use_ssl` are non-secret options. Defaults are `s3.amazonaws.com`, `vhost`, and `True`. Declare multiple scopes in one list; bearer and headers cannot share a scope.

```python
import marivo.datasource as md

md.duckdb(name="lake", secrets=[
    md.s3_secret(scope="s3://analytics-lake/warehouse/", region="us-west-2",
                 key_id=md.env("LAKE_KEY_ID"), secret=md.env("LAKE_SECRET")),
    md.http_bearer_secret(scope="https://api.example/v1/", token=md.env("API_TOKEN")),
    md.http_headers_secret(scope="https://change-focus.example/api/",
                           headers={"x-api-key": md.env("API_KEY")}),
])
```

Without a host resolver, lookup uses the environment and then `~/.marivo/secrets.toml`. `md.credential_scope` routes the same references to a host resolver without persistence. Each operation resolves again, so rotated credentials apply on the next operation. `md.load().test` checks a literal round-trip, not access to S3 or HTTP; cached keys have not necessarily been validated at those endpoints.

Scopes accept host and path prefixes without user info, queries or fragments. DuckDB shares its secret catalog across connections to the same database instance. A file or named in-memory database with scoped secrets requires exclusive managed access until the Marivo connection closes. Use separate databases for concurrent access with different credentials.

DuckDB persistent secrets remain enabled. Its longest matching scope wins, including a persistent secret more specific than the declaration. JSON requests choose the longest matching declared HTTP scope; authenticated GET and all POST requests reject redirects.
