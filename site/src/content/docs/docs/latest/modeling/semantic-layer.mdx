The semantic layer defines reusable business meaning in Python. This page introduces Entity, Dimension, Time dimension, Measure, Metric, and Relationship: what each object represents, which properties it owns, and how to define it. Datasource owns physical access; semantic objects add identity, fields, aggregation rules, and mappings.

For focused discovery, start at `marivo.help("authoring")`. Use `semantic.model` for identity, fields, relationships and Metric definitions; `semantic.time` for time parsing and certified calendars; `semantic.catalog` for existing definitions; and `semantic.validation` to choose what load, readiness, preview or source health must prove. Supporting constructor values follow their definition. Question-scoped composition of established closed inputs uses `semantic.expressions` without requiring a published Metric.

The short declarations are model-file fragments, not commands to paste into an analysis script. Use the [complete model](#complete-model) below with the [local tutorial](/docs/latest/start/python/) to run them. A domain is declared in `models/semantic/sales/_domain.py` with `ms.domain(name="sales", owner="Mina Zhang")`; its default domain lets sibling definitions omit `domain=`. `ai_context=ms.ai_context(business_definition=..., guardrails=[...])` records meaning and usage limits, not executable logic.

Configure physical access on the [Datasource configuration](/docs/latest/modeling/datasources/) page. [Date and time definitions](/docs/latest/modeling/dates/) owns temporal parsing and calendars. Parameter defaults below are Python API defaults; `None` does not imply a guessed business rule.

## Domain — owning business scope

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `name` | Yes | — | Domain directory name, for example `sales`; participates in downstream identities. |
| `owner` | Yes | — | Person accountable for semantic correctness. |
| `default` | No | `True` | Allows definitions in the domain scope to omit `domain=` when true. |
| `ai_context` | No | `None` | Optional `ms.ai_context(...)` with business meaning and guardrails; no context is attached when omitted. |

## Entity — identity and source grain

An Entity gives a physical source a business identity and row grain. For orders, one instance is one order; its stable identity is `order_id`.

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `name` | Direct form | `None` | Direct construction name; omit it to use the table decorator, whose function name supplies the name. |
| `datasource` | Yes | — | Datasource symbol from `ms.ref.datasource(...)`. |
| `source` | Yes | — | Physical descriptor such as `md.table(...)`; selected columns become the Entity source schema. |
| `primary_key` | No | `None` | Ordered complete stable identity columns. `None` declares no Entity identity; it does not mean one singleton member. |
| `versioning` | No | `None` | `ms.snapshot(...)` or `ms.validity(...)`; `None` declares no historical version model. |
| `domain` | No | `None` | Explicit domain; `None` uses the applicable declared default domain. |
| `ai_context` | No | `None` | Optional `ms.ai_context(...)` with business meaning and guardrails; no context is attached when omitted. |

```python
orders = ms.entity(
    name="orders",
    datasource=ms.ref.datasource("warehouse"),
    source=md.table("orders"),
    primary_key=["order_id"],
)
```

A composite identity must include every component, such as tenant and order. Physical types come from source metadata when execution needs them; `ms.load()` does not read source rows. Declared identity is a business contract, not proof that current data obeys it. Snapshot/validity selection needs an exact temporal boundary; it never means “use the latest available row.” Help: `semantic.entity.define`.

## Dimension — categorical attributes

A Dimension is an attribute of one resolved Entity representation. Use it to group, filter, classify, or declare relationship keys. Its type and nullability follow its source binding or expression.

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `name` | Yes | — | Semantic name, unique in its owning scope. |
| `entity` | Yes | — | Owning Entity, binding the field to one source row grain. |
| `column` | Yes | — | Physical column name exposed by the Entity source; may differ from the semantic name. |
| `domain` | No | `None` | Explicit domain; `None` uses the applicable declared default domain. |
| `ai_context` | No | `None` | Optional `ms.ai_context(...)` with business meaning and guardrails; no context is attached when omitted. |

```python
region = ms.dimension_column(name="region", entity=orders, column="region")


@ms.dimension(entity=orders)
def normalized_region(rows):
    return ms.bind(region, rows).upper()
```

Prefer the column constructor for direct fields. The decorator takes an Entity table and captures a restricted Ibis expression for derived attributes. Null can be a valid grouping category. A current attribute does not automatically describe historical state. Help: `semantic.dimension.from_column` and `semantic.dimension.define`.

### Derived Dimension: `ms.dimension`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `name` | No | `None` | Override the function name; `None` uses the decorated function name. |
| `entity` | Yes | — | Owning Entity, binding the field to one source row grain. |
| `domain` | No | `None` | Explicit domain; `None` uses the applicable declared default domain. |
| `ai_context` | No | `None` | Optional `ms.ai_context(...)` with business meaning and guardrails; no context is attached when omitted. |

## Time dimension — business time

A Time dimension establishes an explicit business time role. Native dates, timestamps and encoded dates have different parsing and timezone requirements. See [Date and time definitions](/docs/latest/modeling/dates/) for the complete parameter table, parsers, ranges and business calendars. The complete model below keeps its `order_date` declaration.

## Measure — row quantities

A Measure describes a numeric quantity per source row, such as order amount or cost. It owns units and permission to aggregate; it is not yet the completed Metric consumed by `observe`.

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `name` | Yes | — | Semantic name, unique in its owning scope. |
| `entity` | Yes | — | Owning Entity, binding the field to one source row grain. |
| `column` | Yes | — | Physical column name exposed by the Entity source; may differ from the semantic name. |
| `additivity` | Yes | — | Summation permission: `ms.additive_all(except_=...)`, `ms.additive(over=...)`, or `ms.non_additive()`. |
| `status_time_dimension` | No | `None` | Optional status-time field; exclude the same field using `ms.additive_all(except_=(...))`. `None` declares no status-time role. |
| `unit` | No | `None` | Unit such as `"CNY"`; `None` means unspecified, while `"1"` explicitly means dimensionless. |
| `domain` | No | `None` | Explicit domain; `None` uses the applicable declared default domain. |
| `ai_context` | No | `None` | Optional `ms.ai_context(...)` with business meaning and guardrails; no context is attached when omitted. |

```python
amount = ms.measure_column(
    name="amount", entity=orders, column="amount",
    additivity=ms.additive_all(), unit="CNY",
)
cost = ms.measure_column(
    name="cost", entity=orders, column="cost",
    additivity=ms.additive_all(), unit="CNY",
)


@ms.measure()
def margin():
    return amount - cost
```

This cost example uses the extra column created in the complete model below. Derived Measure bodies take zero arguments and compose typed row quantities. Units describe dimension; additivity says where summing is meaningful. A product is not automatically summable, and inventory is not automatically additive over time. Help: `semantic.measure.from_column` and `semantic.measure.define`.

### Derived Measure: `ms.measure`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `unit` | No | `None` | Compatible assertion for a known inferred unit, or declaration of a previously unspecified unit; `None` inherits the expression unit. |
| `additivity` | No | `None` | Explicit compatible summation permission; `None` inherits expression facts. |
| `ai_context` | No | `None` | Optional `ms.ai_context(...)` with business meaning and guardrails; no context is attached when omitted. |

## Metric — completed business calculations

A Metric is a completed source reduction or a composition of Metrics. Revenue sums order amounts; average order value divides that revenue by the count of the same orders.

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `domain` | No | `None` | Explicit domain; `None` uses the applicable declared default domain. |
| `ai_context` | No | `None` | Optional `ms.ai_context(...)` with business meaning and guardrails; no context is attached when omitted. |

The function name supplies the published name. Its zero-argument body composes closed Metrics or source reductions; time/null/sample policies belong on those operators.

```python
@ms.metric()
def revenue():
    return amount.sum(time=order_date)


@ms.metric()
def average_order_value():
    return revenue / orders.count(time=order_date)
```

Bodies may contain fresh local expression bindings and a final return, but no table parameters, `ms.bind`, queries or arbitrary Python calls. Empty sum is zero; a nonempty all-null sum is unknown. Division by zero yields NA. Use `revenue.where(region == "east")` for a contribution condition, or `revenue.per(region).mean()` for the mean of regional revenues. These are different from filtering or averaging a completed Frame. Existing closed Metrics can be composed for one question without publishing a new definition. Help: `semantic.metric.define` and `semantic.expressions`.

### Exact and approximate quantiles

Use the same expression names across backends and choose accuracy explicitly:

```python
@ms.metric()
def exact_p95():
    return amount.quantile(0.95, time=order_date)


@ms.metric()
def approximate_p95():
    return amount.approx_quantile(0.95, time=order_date)
```

`median()` and `approx_median()` are the corresponding q=0.5 operations. Exact
quantiles use linear interpolation: `[0, 10]` at q=0.95 gives 9.5. DuckDB,
PostgreSQL, MySQL, Trino and ClickHouse support exact numeric quantiles. Explicit
approximation uses DuckDB `approx_quantile`, Trino `approx_percentile`, or
ClickHouse TDigest; PostgreSQL and MySQL reject approximate source methods.
Approximate values can differ across backends and from older ClickHouse reservoir
results. No algorithm is silently substituted. Empty/all-null inputs return NA;
`nulls="error"` rejects null contributions. `metric.per(time).mean()` still means
an equal-weight mean of time-key results, not a quantile over the whole window.

### Explicit scaling: `ms.rescale`

Use `ms.rescale` to divide a numeric Row or completed Metric by a constant and explicitly declare the target unit. It preserves stage, source roots, time restrictions and sum permissions. The source unit must be known after binding.

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `expr` | Yes | — | Numeric Row or completed Metric Deferred expression with a known source unit. |
| `divisor` | Yes | — | Keyword-only finite positive `int`, `float` or `Decimal` constant; booleans and dynamic expressions are rejected. |
| `unit` | Yes | — | Keyword-only target unit string; existing factorable units are canonicalized and opaque units are retained. |

Given an established byte-valued `total_bytes` Metric for a complete 86400-second interval and `hourly_p95_bytes`, the P95 of complete hourly byte totals:

{/* example: semantic-rescale */}
```python
daily_bandwidth = ms.rescale(
    total_bytes, divisor=86400 * 1024**3, unit="GiB/s",
)
p95_bandwidth = ms.rescale(
    hourly_p95_bytes, divisor=3600 * 1024**3, unit="GiB/s",
)
```

The author owns the scale factor and physical/business meaning, including cross-dimension assertions and `divisor=1`. Fixed duration factors do not change with the analysis window, and Marivo does not infer conversions. Ordinary scalar division retains the source unit; a Measure unit assertion remains compatible with a known inferred unit. Help: `semantic.rescale`.

## Relationship — directed entity mappings

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `name` | Yes | — | Semantic name, unique in its owning scope. |
| `from_entity` | Yes | — | Source Entity of the directed relationship. |
| `to_entity` | Yes | — | Target Entity of the directed relationship. |
| `keys` | Yes | — | List of `ms.join_on(from_field, to_field)` pairs covering the intended mapping; fields must be direct Dimensions/TimeDimensions on the exact endpoints. |
| `domain` | No | `None` | Explicit domain; `None` uses the applicable declared default domain. |
| `ai_context` | No | `None` | Optional `ms.ai_context(...)` with business meaning and guardrails; no context is attached when omitted. |

Cardinality is derived from whether join keys cover each endpoint’s complete primary key; it is not an extra declaration argument. Keys express mapping, not global completeness or allocation. Versioned endpoints also need the consumer’s exact version selection.

A relationship explains how business entities correspond. Declare it from known identity and grain rules, not from similar column names.

### Establish the grain before joining

Consider this complete worked example (illustrative input tables):

| Order | Customer | Amount |
| --- | --- | ---: |
| o1 | c1 | 100 |
| o2 | c1 | 200 |
| o3 | c2 | 500 |

Customers c1 and c2 belong to east and west respectively; c3 has no orders. The overall revenue is 800, and customer revenue is 300, 500, and no observed contribution for c3. A selected customer population can still include c3.

### Make the declaration match the rule

Declare orders and customers as Entities with complete primary keys, then a directed relationship using `ms.relationship` and `ms.join_on`. Obtain the exact constructor with `marivo.help("semantic.relationship.define")`. If identity is (tenant, customer), include both parts; a customer number alone can match another tenant.

Use relationship match/cardinality checks in [model validation](/docs/latest/modeling/semantic-layer/#load-and-validate). A declared relationship does not prove current source completeness.

### Decide how multiple memberships contribute

If c1 has labels A and B, joining orders to both labels repeats its 300. Counting that as 600 would be wrong for total revenue. Decide whether you want an existence filter, overlapping group totals, or a justified allocation. `mv.membership(...)` describes explicit grouping/allocation rules; it does not make an arbitrary join additive.

Keep identity when counting customers by a new attribute. Projecting only the attribute first counts categories instead. Continue with [population selection](/docs/latest/analysis/dsl/#select-and-filter).
Declaration fragment for this relationship, in the same model load scope:

```python
# Declaration fragment: orders, customers, order_customer_id, and customer_id
# are captured Entity and Dimension refs in the same model.
orders_to_customers = ms.relationship(
    name="orders_to_customers",
    from_entity=orders,
    to_entity=customers,
    keys=[ms.join_on(order_customer_id, customer_id)],
)
```

## Complete model

Agree on meaning before writing an equation. In the demo, revenue is the sum of six completed orders in CNY, without refunds. Average order value divides that revenue by the count of the same orders.

### Build one complete definition

Run [quick start](/docs/latest/start/python/), then add a cost column to the demo database. Each cost is set to 60% of its amount solely for this margin example. Save as `add_cost.py` and run it.

{/* example: semantic-cost-data */}

```python
import duckdb

with duckdb.connect("warehouse.duckdb") as connection:
    connection.execute("ALTER TABLE orders ADD COLUMN IF NOT EXISTS cost BIGINT")
    connection.execute("UPDATE orders SET cost = amount * 0.6")
```

Replace `models/semantic/sales/_domain.py` with the model below; do not keep another copy of these declarations. Compose native typed field symbols directly. The loader binds the complete dependency scope before returning the Catalog.

{/* example: semantic-model */}

```python
import marivo.datasource as md
import marivo.semantic as ms

sales = ms.domain(name="sales", owner="Mina Zhang")
orders = ms.entity(
    name="orders",
    datasource=ms.ref.datasource("warehouse"),
    source=md.table("orders"),
    primary_key=["order_id"],
)
region = ms.dimension_column(name="region", entity=orders, column="region")
order_date = ms.time_dimension_column(
    name="order_date", entity=orders, column="order_date", is_default=True
)
amount = ms.measure_column(
    name="amount",
    entity=orders,
    column="amount",
    additivity=ms.additive_all(),
    unit="CNY",
)
cost = ms.measure_column(
    name="cost", entity=orders, column="cost", additivity=ms.additive_all(), unit="CNY"
)


@ms.dimension(entity=orders)
def normalized_region(rows):
    return ms.bind(region, rows).upper()


@ms.measure()
def margin():
    return amount - cost


@ms.metric()
def revenue():
    return amount.sum(time=order_date)


@ms.metric()
def average_order_value():
    return revenue / orders.count(time=order_date)
```

### Preserve the business rule

Units describe quantities; additivity states where summing is permitted. A row product does not automatically become summable. An alias does not rename a published definition. Unknown units are not automatically dimensionless.

Measure and Metric declaration bodies take no table arguments and build closed expressions. Entity and field bodies use their restricted Ibis contract. Do not execute queries or arbitrary Python inside metric declarations.

An empty sum is zero; a nonempty all-null sum is unknown. Specify how cancellations and refunds enter the source/model rather than filling unknown results with zero.

After editing, [validate the model](/docs/latest/modeling/semantic-layer/#load-and-validate). Use [relationships](/docs/latest/modeling/semantic-layer/#relationships-and-membership) when a metric needs attributes from another entity.

## Load and validate

Start with the [local tutorial's model](/docs/latest/start/python/). Run these blocks in a new script from its project root. Choose the check that answers your current uncertainty.

### Check definitions, then inspect data

{/* example: readiness-3 */}

```python
import marivo.semantic as ms

catalog = ms.load()
amount = catalog.fields.get("sales.orders.amount")
catalog.readiness(refs=[amount]).show()
```

{/* example: readiness-1 */}

```python
import marivo.datasource as md

preview = catalog.preview(
    catalog.metrics.get("sales.revenue"),
    scope=md.unpruned(max_rows=1000, timeout_seconds=30),
    limit=20,
)
```

{/* example: readiness-2 */}

```python
amount = catalog.fields.get("sales.orders.amount")
health = catalog.source_health(
    [amount],
    checks=[ms.source_check.not_null(ms.ref.measure("sales.orders.amount"))],
    scope=md.unpruned(max_rows=1000, timeout_seconds=30),
)
health.show()
```

Loading checks project coherence. Readiness checks requested physical dependencies and required temporal artifacts without reading business data. Preview reads a bounded scope; ordinary preview does not change readiness. Source health checks connectivity/schema by default and only tests data expectations when explicitly requested.

For `preview` and `preview_many`, `limit` must be an integer from 1 to 100 inclusive and bounds retained preview rows per result. `scope.max_rows` independently guards acquisition; invalid limits raise a structured semantic error before a connection opens. `preview.is_truncated` reports omitted preview rows, while `preview.coverage` reports acquisition completeness. `preview.show(n=...)` only changes how many retained rows are displayed.

If connection testing fails, check the datasource path and credentials before retrying.

A missing or truncated [calendar certificate](/docs/latest/modeling/semantic-layer/#business-calendars) needs a complete bounded temporal preview. None of these checks confirms the business owner intended this revenue policy. Finish by executing the actual observation you need.

## Compose metric expressions

After defining fields and metrics, compose filters, per-group calculations, and derived metrics. Append this to the extended model above.

{/* example: semantic-composition */}

```python
# Expressions in the model above: amount, cost, order_date, region, and orders
# have been resolved; revenue is the published metric expression.
east_revenue = revenue.where(region == "east")
mean_regional_revenue = revenue.per(region).mean()


@ms.metric()
def gross_margin_rate():
    return (revenue - cost.sum(time=order_date)) / revenue
```

`east_revenue` selects east contributions; `mean_regional_revenue` averages regional revenues; gross margin rate uses revenue and cost with the same time role.
