## Check definitions, then inspect data

After editing a model, start from its project root. This example uses the
`sales.orders.amount` measure from the [local Python tutorial](/docs/latest/start/python/):

```python
import marivo.semantic as ms

catalog = ms.load()
amount_entry = catalog.get("measure:sales.orders.amount")
assert amount_entry.kind == "measure"
amount = amount_entry.value
catalog.readiness(refs=[amount]).show()
catalog.validate([amount_entry]).show()
```

`ms.load()` checks model declarations, references, dependency cycles, and
expression contracts. `catalog.readiness(...)` accepts definitions, including
declared Measures and Metrics, and checks their physical dependencies and
certified temporal artifacts. Neither step opens a datasource
connection.

`catalog.validate(...)` opens the datasource connections for the selected
dependency closure and checks actual Entity output schemas, field bindings,
numeric types and temporal parser/timezone contracts. Its report includes
physical types, affected fields, declaration locations and repairs. Preview and
analysis reuse the same field checks before executing their queries. HTTP JSON
acquires response rows during source preparation to infer physical types. A successful
validation does not certify every analysis method, and later source changes are
checked again at use.

For example, a native aware timestamp, including ClickHouse `DateTime` and
`DateTime64`, rejects `ms.timestamp(timezone="UTC")` even if its own zone is UTC.
Use `ms.timestamp()` for that source. A string parsed with
`ms.strptime(..., timezone="UTC")` may still need its declared source timezone.

To inspect current source data, use `catalog.preview(...)` with an explicit
bounded scope. Ordinary Metric previews support all five SQL backends and reuse
datasource partition preflight before business reads. Each Entity contributes at
most `min(scope.max_rows, 10_000)` output rows. These unordered subsets are not
full-source estimates. Read `preview.coverage.entity_rows`, `entity_row_limits`
and `execution_limits` for actual inputs and native timeout support. Output caps
do not bound physical scanning; no scan row/byte cap is requested and scan
statistics remain unknown.
`catalog.validate(...)` checks physical contracts by default;
it reads business rows only when you provide explicit checks
and their bounded scope. Omit `scope` when `checks` is empty. Build checks with
native lookup symbols from `ms.ref` or an entry's `.ref`; closed `.value`
expressions are not accepted by these builders. The [load and validate section](/docs/latest/modeling/semantic-layer/#load-and-validate)
has the complete preview and online validation examples.

## Unavailable physical types and string counts

An unavailable physical type such as `char(1)` keeps the schema check failed.
Read the schema check's `observed["unavailable_columns"]` for column names and raw
types, and `observed["unavailable_field_refs"]` for skipped fields. Direct Entities
still check other fields; expression Entities need the complete input schema.
Expose supported types or explicitly select supported columns with
`md.table(columns=...)`, then validate again.

For a string identifier, declare a Dimension with `ms.dimension_column(...)` and
use the closed field's `dimension.count_distinct()` to count different values.
A string column cannot be bound as a numeric/duration Measure.
