title: Installation and projects
description: Install Marivo and choose the Python environment and project directory.

Use one project environment for installation, Help, and analysis. Python 3.10 or newer is required. On Windows use `.venv/Scripts/python.exe` wherever these instructions use `.venv/bin/python`.

## Install the source used by these guides

The latest guides describe the development API. Obtain a checkout, record its revision, and install it into a separate demo directory. You need Git and uv available.

```bash
git clone https://github.com/chengxianglibra/marivo.git marivo-source
git -C marivo-source rev-parse HEAD
mkdir marivo-demo
cd marivo-demo
uv venv --python 3.10 --seed
uv pip install --python .venv/bin/python -e "../marivo-source[duckdb]"
.venv/bin/python -m marivo --version
.venv/bin/python -m marivo doctor --project-root .
```

Keep that revision when sharing a reproduction. Check Doctor's Python executable, package path, and project root before continuing.

For MySQL or MariaDB, select `../marivo-source[mysql]`. This uses PyMySQL,
including RSA authentication support, and requires no local MySQL client C
library or compiler. `all` includes the same driver. Existing mysqlclient
options such as `ssl_mode`, `auth_plugin` or protocol compression must be
replaced with supported PyMySQL settings; unsupported options fail explicitly.

## Use a released package

For a release, install `marivo[duckdb]` instead of the editable source and use its versioned documentation. Other extras include `postgres`, `mysql`, `trino`, and `clickhouse`; consult [backend prerequisites](/docs/latest/reference/backends-and-limits/).

The optional `curl -fsSL https://marivo.io/install.sh | bash` installer installs a released package and initializes a project. Read its reported interpreter and extras; it does not install the development checkout.

## Initialize when useful

```bash
.venv/bin/python -m marivo init
```

Initialization creates optional configuration and directories. An empty directory also works without a manifest. Avoid `--force` for an existing investigation: it recreates generated artifacts, including local state.

## Select a project

For an existing project, open the directory containing `models/`, install its dependencies, and set the environment variables referenced by its datasource declarations. For a new project, run the quick start in a separate directory before replacing its data and definitions.

Check the interpreter, package path, and project root, then continue to [quick start](/docs/latest/start/python/).
