Marivo 0.5.3 improves runtime observability, empty-project onboarding, and
calendar-window comparisons.

## Highlights

- Terminal `Run` records now persist ordered backend query executions.
  `run.queries` exposes the exact executed SQL together with its datasource,
  dialect, digest, row count, duration, timestamps, and success or failure
  status; failed executions are captured as well.
- Marivo can run from an empty current directory without `marivo.toml`,
  `models/`, or pre-created `.marivo/` state. Authored and runtime directories
  are created lazily when first needed; `marivo init` remains optional.
- `session.compare(...)` keeps calendar buckets that intersect a partial window
  in the frame's report timezone, including time-series, panel, and driver-axis
  replay comparisons.

## Changed

- Run cards show bounded query summaries, while exact SQL remains available
  through explicit `run.queries` reads.
- Project discovery and Doctor now report effective defaults for
  zero-initialization projects while rejecting invalid explicit configuration
  with typed repair guidance.
- Empty calendar alignments continue to fail with a typed alignment error
  instead of becoming an uninformative empty result.

## Fixed

- Window-bucket comparison no longer drops a same-day or partial tail bucket
  when the exclusive window end falls inside a calendar bucket.
- The corrected bucket spine is used consistently by time-series, panel, and
  driver-axis replay paths.

## Documentation

- Updated the analysis and evidence guidance for persisted query reads.
- Updated installation, quick-start, deployment, and project-configuration
  guidance for projects that begin from an empty directory.

## Installation

~~~bash
curl -fsSL https://marivo.io/install.sh | bash
~~~

In mainland China, use:

~~~bash
curl -fsSL https://marivo.io/install-marivo-cn.sh | bash
~~~

For manual installation:

~~~bash
pip install marivo
~~~

Marivo 0.5.3 requires Python 3.10 or newer.
