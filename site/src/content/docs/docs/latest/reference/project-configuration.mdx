## Keep the project contract in version control

`marivo.toml` is optional. Without it, the project name is the project-root directory
name, `semantic.layer_paths` is empty, local telemetry is enabled, and
`execute()` results use project-local Parquet. Missing tables or
fields use those defaults; an existing invalid TOML document or explicitly invalid field
fails closed. There is no project `version` setting.

Use `marivo.toml` to load semantic-layer packages that are maintained in other
repositories. Add each authored `models/` directory to `[semantic].layer_paths`:

```toml
[semantic]
layer_paths = [
  "../sales-domain/models",
  "/opt/company/finance-domain/models",
]
```

Marivo always loads the current project's `models/` directory first. It then
loads `layer_paths` in the listed order. Relative paths are resolved from the
directory containing `marivo.toml`; absolute paths are used as-is. Every external
semantic-layer root must contain both `datasources/` and `semantic/`.

Names must stay unique across every configured root: datasource names, domain
names, and semantic IDs cannot be duplicated. A duplicate stops the semantic
layer from loading. `marivo doctor`, semantic previews, verification, and
analysis sessions all resolve semantic objects and layer datasources through
these configured roots.

When configuration or declarations must travel with the project, commit `marivo.toml`
and `models/`. Add `.marivo/` to `.gitignore`; it contains local sessions, evidence,
telemetry, and cached metadata rather than shared declarations.

## Choose a result location only when needed

No analysis storage configuration is required for local Parquet. To write new
Artifacts to an explicitly selected object store, add:

```toml
[analysis]
storage = "object:archive"

[analysis.object_stores.archive]
endpoint_url = "https://objects.example.test"
bucket = "analysis"
access_key_id_env = "MARIVO_ARCHIVE_ACCESS_ID"
secret_access_key_env = "MARIVO_ARCHIVE_SECRET"
```

Credentials remain environment references. The selected target is fixed for an
execution; invalid configuration or a failed write raises a structured error.
Marivo does not switch targets or retry through another executor. Named bindings
can remain configured to read existing Artifacts after the write target changes;
changing a setting does not relocate those Artifacts.

See [Analysis Workflow](/docs/latest/concepts/analysis-workflow/) for the
construction, explicit execution and recovery boundaries.
