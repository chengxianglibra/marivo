| Backend | Extra | Important conditions |
| --- | --- | --- |
| DuckDB | `duckdb` | Local tutorial needs no server; contribution requires qualified physical tables |
| PostgreSQL | `postgres` | Requires libpq and access; exact median/quantile depend on supported physical types |
| MySQL | `mysql` | Native client/build prerequisites; exact ranked quantiles; no approximate source quantiles |
| Trino | `trino` | Catalog/schema and access; exact ranked quantiles or explicit approximate quantiles |
| ClickHouse | `clickhouse` | Ordinary qualified grouped aggregation; Distributed keyed join routes have restrictions; exact ranked quantiles or explicit TDigest approximation |

## Check source form and method

Table, file and HTTP discovery have different execution conditions. Parameterized HTTP JSON can be declared and previewed but is not an admitted numerical Frame source. Exact numeric source median/quantile supports all five backends. MySQL, Trino and ClickHouse extract ranked bounds on the source and interpolate locally; DuckDB and PostgreSQL retain their qualified exact paths. Approximate quantiles are explicitly authored and supported on DuckDB, Trino and ClickHouse, with backend-specific algorithms. PostgreSQL and MySQL reject approximate source methods. Ordinary count, distinct count, sum, min, max, mean and weighted mean still depend on actual types and expressions.

Contribution requires qualified physical tables and retained source declarations. DuckDB, PostgreSQL, MySQL, Trino and ClickHouse use their native execution paths, subject to actual method, type, key and source restrictions. Parent and fine reads are independent and have no shared-snapshot guarantee. Original formula, identity and classification checks remain required; only requested final targets must close within their numeric precision policy. Use explicit observe and compare to investigate unsupported contribution targets without claiming a decomposition.

Remote contribution retains direct physically nonnull integer or string identities and qualified string collations. Incompatible non-temporal scopes on one root are rejected. A successful ordinary observation alone does not qualify these contribution inputs.

## Account for resource and numeric limits

Local data operations can retain full required vectors in memory. A display limit is not a computation or scan limit. Timeouts retain the driver's native meaning and may be unsupported; there is no whole-graph deadline or silent switch to another executor.

`md.raw_sql()` requests a 600-second native query timeout by default. Override it with
`timeout_seconds`; Trino receives it as `query_max_run_time`. Connection acquisition
uses separate native 30-second settings. The query timeout is not a complete-call
or fetching deadline.

```python
import marivo.datasource as md
import marivo.semantic as ms

md.raw_sql(
    ms.ref.datasource("default"), "SELECT 1 AS ok",
    reason="check query path", timeout_seconds=600,
)
```

Source precision and overflow follow the qualified backend. Conversion cannot repair precision already lost or a value already wrapped by the source. Local arithmetic has its own checked rules. No universal Decimal precision guarantee applies across all sources.
