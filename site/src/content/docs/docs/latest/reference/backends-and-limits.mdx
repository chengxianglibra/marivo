| Backend | Extra | Important conditions |
| --- | --- | --- |

| MySQL / MariaDB | `mysql` | PyMySQL with RSA authentication support; no local MySQL client C library; exact ranked quantiles; no approximate source quantiles |

## Check source form and method

Table, file and HTTP discovery have different execution conditions. Parameterized HTTP JSON can be declared and previewed but is not an admitted numerical Frame source. Exact numeric source median/quantile supports all five backends. MySQL, Trino and ClickHouse extract ranked bounds on the source and interpolate locally; DuckDB and PostgreSQL retain their qualified exact paths. Approximate quantiles are explicitly authored and supported on DuckDB, Trino and ClickHouse, with backend-specific algorithms. PostgreSQL and MySQL reject approximate source methods. Ordinary count, distinct count, sum, min, max, mean and weighted mean still depend on actual types and expressions.

Contribution requires qualified physical tables and retained source declarations. DuckDB, PostgreSQL, MySQL, Trino and ClickHouse use their native execution paths, subject to actual method, type, key and source restrictions. Parent and fine reads are independent and have no shared-snapshot guarantee. Attribute trusts semantic identity, relationship cardinality and version-grain declarations. Operation-specific membership/Population coverage, overlap, distinct-value partitions and numeric checks remain required; only requested final targets must close within their closure tolerance. Float64 allows the greater of 1% of the absolute final target and its numeric rounding budget; other numeric types retain their existing rules. Use explicit observe and compare to investigate unsupported contribution targets without claiming a decomposition.

Remote contribution retains direct physically nonnull integer or string identities and qualified string collations. Incompatible non-temporal scopes on one root are rejected. A successful ordinary observation alone does not qualify these contribution inputs.

## Account for resource and numeric limits

Local data operations can retain full required vectors in memory. A display limit is not a computation or scan limit. Timeouts retain the driver's native meaning and may be unsupported; there is no whole-graph deadline or silent switch to another executor.

`md.raw_sql()` requests a 600-second native query timeout by default. Override it with
`timeout_seconds`; Trino receives it as `query_max_run_time`. Connection acquisition
uses separate native 30-second settings. The query timeout is not a complete-call
or fetching deadline.

```python
import marivo.datasource as md
import marivo.semantic as ms

md.raw_sql(
    ms.ref.datasource("default"), "SELECT 1 AS ok",
    reason="check query path", timeout_seconds=600,
)
```

Source precision and overflow follow the qualified backend. Marivo does not precheck native overflow or retry it locally: the backend may raise an error, wrap a value, or return Infinity or NaN. Completed and saved Frames retain native floating values through export. Conversion cannot repair precision already lost or a value already wrapped by the source. Local arithmetic, comparison deltas and paired statistics also follow their actual pandas/Arrow or Decimal scalar kernel, including native rounding, errors and nonfinite results. There is no extra overflow/finite scan, protective widening, precision emulation or fallback. Local int64 SUM stays int64 and can wrap; integer source SUM uses native Ibis accumulation, whose transport may reject a wider backend result. Direct projection, `is_null()` and persistence preserve validity. No universal Decimal precision guarantee applies across all sources.

MySQL SUM retains the server's widened Decimal result until safe conversion to
the declared Decimal carrier. A sum outside that carrier's range fails before
publication, rather than being clipped by an extra result CAST. Arithmetic within
a fused source expression still uses native precision and overflow behavior.

Mean skips NULL inputs and returns NULL when none are valid. The default `nulls="ignore"` uses this fixed computation; `nulls="error"` additionally asserts that its demanded input contains no NULLs, including native AVG. Empty input passes this assertion. Native AVG algorithms and overflow remain backend-owned. Business filling belongs in an explicit supported input expression or preprocessing step. A qualified `amount.mean(time=point).per(point).mean()` first completes each represented timestamp mean, then averages those means with equal weight in the source. It does not require scheduled time coverage, synthesize missing timestamps, or fall back to a local mean. For timestamp values `[0, 0, 0]` and `[100]`, the result is `50`, not the raw-row mean `25`. Time-sample `mean` and `weighted_mean` use represented samples on every admitted route, including local formulas, Duration and windows; they do not synthesize scheduled samples. Explicit Population domains and existing NULL/weight policies remain unchanged. Other reducers retain their own NULL and coverage contracts.
