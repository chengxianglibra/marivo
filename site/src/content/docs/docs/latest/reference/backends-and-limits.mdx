## Check source form and method

Database tables use their selected SQL backend; CSV, Parquet and file JSON use DuckDB.
Analysis Session supports local JSON files through the unparameterized GET route. Other
HTTP JSON forms can be declared and previewed through datasource APIs but are not Analysis
Session inputs.

Exact source `median` and `quantile` are available for numeric inputs on all five backends.
DuckDB and PostgreSQL use native exact algorithms; MySQL, Trino and ClickHouse select exact
rank bounds in source queries and interpolate from them. Linear interpolation uses
`h=(n-1)q`; for `[0, 10]` at `q=0.95`, the result is `9.5`. Integer and floating results
use `float64`; Decimal follows its declared precision and scale. Under the default NULL
policy, empty or all-NULL input returns NA; strict NULL checks still apply to the demanded
input.

Approximate numeric methods must be explicit. DuckDB uses `approx_quantile`, Trino uses
`approx_percentile`, and ClickHouse uses `quantileTDigest`; PostgreSQL and MySQL have no
approximate source route. Algorithms can differ, with no universal error bound. Other
common reductions—count, distinct count, sum, min, max, mean and weighted mean—remain
subject to type and expression qualification.

Contribution analysis uses qualified source routes on all five backends, subject to method,
type, key and source restrictions. Parent totals and fine contributions are read
independently and may come from different source snapshots. `Attribute` trusts declared
Entity identity, relationship cardinality and version grain; qualification also checks
membership/Population coverage and overlap, distinct-value partitions, time correspondence
and numeric closure. Only requested final targets are checked against fresh parent totals.
Float64 closure allows a residual up to the greater of 1% of the target's absolute value
and its numeric rounding budget; other types use their own rules. If a target is not
admitted, use explicit observations and comparison to investigate it without treating the
result as a contribution decomposition.

Remote `Attribute` routes require direct physical signed-integer or string identities and
qualified string collations. The Entity `primary_key` declares complete, non-null identity;
the route trusts that declaration even if physical metadata marks an identity column
nullable. It does not run a full-source NULL or uniqueness precheck; operation-specific
identity checks still apply. For scoped data validation, use `ms.source_check` with a bounded
`catalog.source_health(..., checks=..., scope=...)` call.
Incompatible non-time scopes within one source root cannot be combined.

## Account for resource and numeric limits

Local operations may keep all required vectors in memory. A display limit changes rendering;
it does not cap computation or source scan work. Query timeouts use native driver settings,
may be unsupported, and do not bound the full client call and result fetch.

`md.raw_sql()` requests a 600-second native query timeout by default. Override it with
`timeout_seconds`; Trino receives it as `query_max_run_time`. Connection acquisition
uses separate native 30-second settings. The query timeout is not a complete-call
or fetching deadline.

```python
import marivo.datasource as md
import marivo.semantic as ms

md.raw_sql(
    ms.ref.datasource("default"), "SELECT 1 AS ok",
    reason="check query path", timeout_seconds=600,
)
```

`md.raw_sql()` expects read-only SQL; Trino relies on database permissions to deny writes.
It loads all returned rows into memory. Use filters, aggregation or SQL `LIMIT` to control
result size; `LIMIT` does not bound source scan cost.

Numeric precision and overflow follow the backend and type. Integer SUM uses an `int64`
result: local sums can wrap, while a wider source accumulator may fail when the result
crosses the Ibis transport boundary. ClickHouse can return wrapped values. Conversion after
a source read cannot recover lost precision. MySQL SUM keeps its widened Decimal until it
can be safely converted to the declared Decimal result; an out-of-range value fails instead
of being clipped. Arithmetic inside a fused source expression still follows MySQL's native
rules. Saved Frames export committed values as stored; export does not recompute or repair
source precision or overflow.

`mean()` skips NULLs by default and returns NULL when no values are valid. `nulls="error"`
requires its demanded input to contain no NULLs; empty input passes. For
`amount.mean(time=point).per(point).mean()`, Marivo averages each represented timestamp's
mean with equal weight. With timestamp values `[0, 0, 0]` and `[100]`, the result is `50`,
not the row-weighted mean `25`. Missing scheduled timestamps are not synthesized;
time-sample `mean` and `weighted_mean` use represented samples.
