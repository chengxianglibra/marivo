## Repair predicates and correspondence

This independent commerce model declares order amount, customer region and the order_customer relationship. `current` and `reference` are compatible quantities.

{/* example: verification-premises */}

```python
orders = session.members(ms.ref.entity("commerce.order"))
amounts = orders.read(ms.ref.measure("commerce.order.amount"))
regions = orders.read(
    ms.ref.dimension("commerce.customer.region"),
    via=ms.ref.relationship("commerce.order_customer"),
)
quotient = current.ratio(reference, pairing=mv.ExactKeys(verification="assume"))
change = current.compare(
    reference, design=mv.TimeChange(pairing=mv.ExactKeys(verification="check"))
)
quotient.contract().show()
```

Select Defined values before numeric predicates. Complete typed key tuples,
Session ownership and units must match. Relationship matching trusts the consuming
contract and retains unverified assumptions; it has no automatic verification query.
A present owner's Null field remains `Null(source_null)`; an absent owner operand
fails when the field is consumed. Downstream filtering or reduction cannot hide
that failure: the lookup is consumed once and its result is reused. This creates
no matching proof or missing-value policy. Pairing `verification="assume"` remains an explicit caller
premise, not a successful check. Repair failed pairing inputs or alignment.
