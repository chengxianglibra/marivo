Use the symptom to choose a repair. Keep the original error and the interpreter, package version and project root from Doctor. For historical execution, inspect the event's runtime identity in [execution logs](/docs/latest/reference/telemetry/); Doctor only identifies the current environment.

| Symptom | Confirm | Repair |
| --- | --- | --- |
| A documented API is missing | Package version and loaded path | Use the matching development source or versioned guide |
| Connection fails | Named environment references, driver and network access | Correct the configuration and rerun the datasource test |
| Model fails to load | Duplicate names, missing refs, declaration syntax | Repair the named model file; restart after edits to imported dependencies |
| Readiness is blocked | Requested physical dependencies and temporal artifacts | Repair the reported dependency or certify the complete calendar range |
| A method is unsupported | Backend, source form, expression and types | Use a supported method or an explicit new observation; do not silently change the metric |
| Column/axis belongs to another input | Which exact Frame produced the handle | Obtain handles from the receiver or explicitly align inputs |
| Unexpected unknown difference | Presence, null values and zero baseline | Explain the missing value instead of filling every case with zero |
| Period comparison rejects | Complete boundaries, timezone and matching rule | Choose valid complete periods or a supported explicit correspondence |
| Contribution is unavailable after reopen | Saved data has no source declaration | Rebuild explicit source inputs for a new question |
| Saved result cannot be read | Exact Session/result ID, missing files and Marivo version | Preserve state; use the compatible original version for old data |

## Handle an uncertain save

Resume the owning Session to reconcile its original transaction before submitting again. Explicit resubmission can produce another saved result and may read changed sources. Keep returned IDs while they are available; there is no implicit latest result lookup.

Do not delete `.marivo/` or force initialization as a general repair. Older Store generations remain unchanged, and `mv.session.get_or_create(name)` can create the current generation in the same project. Each version writes independent Sessions and Artifacts; names and IDs are not merged or resolved across generations. An invalid current Store still requires repair.

`get_or_create()` and `recent()` warn once per project and observed older Store path set in each process. `recent()` returns only current-generation history; an empty page does not mean older history was deleted. `resume()` and `inspect()` report missing current-generation IDs with guidance about retained older Stores, without asserting ID ownership. `marivo doctor` reports older paths and file modification times on every run; those times are not the last business write times. These diagnostics do not read older databases or count their Sessions.

Use a compatible Marivo environment to read/export older data. Old generations are retained without automatic cleanup. Archive or delete one yourself only after verifying the export and confirming that its original history is no longer needed.

[Find Help](#query-the-installed-version) for the error's exact repair target. Frame/Column validation points to the public operation that rejected the input. For example, an old statistic passed to `over` links to `analysis.analysis_frame.over`; reconstruct it from the receiving Frame. Pending export links to `analysis.analysis_frame.to_pandas`; compute first and export the returned Frame. Internal errors without a unique public owner can still point to broader Help. Include a minimal reproduction with credentials and private data removed when asking for assistance.

## Find APIs

Use task guides to learn a workflow, Live Help for exact calls and constraints, and the [Python API reference](/api/) for the generated English reference.

### Query the installed version

```python
import marivo

marivo.help()
marivo.help("authoring")
marivo.help("analysis")
marivo.help("analysis.analysis_frame")
```

CLI uses the same targets: `.venv/bin/python -m marivo help analysis`. With a known returned object, `marivo.help(type(result))` discovers its type; query attributes by their string Help target.

Choose the information missing now; the topics are independent entry points.

| Need | Help target |
| --- | --- |
| Governed inputs, member domain or time | `analysis.inputs` |
| Choose observation, Frame construction, calculations or statistics | `analysis.operators` |
| Acquire Columns, complete axes or statistics | `analysis.inputs.frame` |
| Prepare a baseline or endpoint correspondence | `analysis.inputs.comparison` |
| Complete memory values or a saved result | `analysis.execution` |
| Data inspection, export or saved audit | `analysis.results` |
| Create or recover exact Session and saved Frame identities | `analysis.sessions` |

Known targets can be queried directly. Source construction captures explicit questions without business reads; evaluating a pending Frame can still execute its captured source dependencies. Complete or reopened Frame data supports calculations without recovering its original source declaration.

For authoring, start at `authoring`, then choose datasource, semantic or ontology. Datasource topics separate connections, sources, inspection and the semantic handoff. Semantic topics separate model definitions, expression roles, time, catalog lookup and validation. Exact APIs keep their own targets even when a shared prefix is not a topic.

Execution imports are `marivo.datasource as md`, `marivo.semantic as ms`, and `marivo.analysis as mv`. Create sessions through `mv.session.get_or_create`; there is no top-level `marivo.session` alias.

### Ask for help effectively

Record the version, exact interpreter and package path from Doctor, project selection, the smallest relevant declaration and code, the full structured error, expected result and actual result. Remove secrets and private rows. Use the repository's existing issue tracker or contribution links; do not post credentials in an example.
