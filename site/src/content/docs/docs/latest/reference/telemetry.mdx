Execution logs record queries and their outcomes; usage telemetry records operations and durations. Both stay local. Use saved Frames to read analytical values.

## Find the right records

| Record | Location | Use |
| --- | --- | --- |
| Execution logs | `.marivo/logs/execution-YYYY-MM-DD.NNN.jsonl` | Submitted SQL, outcomes, and durations |
| Usage telemetry | `.marivo/telemetry/events-YYYY-MM-DD.NNN.jsonl` | Operation, outcome, and duration summaries |

Use the query ID to match a SQL submission with its completion.

New execution records use `schema_version: 2`. Each event carries a `runtime` object with `marivo_version`, `python_version`, `python_executable`, `package_path` and `process_id`, including records read from a rotated file or a log tail. These fields belong to the logger and cannot be replaced by caller context.

This identity describes the environment that emitted the event. It does not prove package contents or a data snapshot; equal development versions and paths can contain different code. Doctor reports the current environment. Older records are unchanged, and missing runtime means the historical identity is unknown. One file can contain multiple schema versions; interpret each line separately. Usage telemetry has its own schema and is unchanged.


## Enable or disable telemetry

| Mode | Behavior |
| --- | --- |
| `on` | Default; records execution, session creation and reuse, datasource changes, and failures |
| `off` | Disables usage telemetry; execution logs remain enabled |

Set the project default in `marivo.toml`:

```toml
[telemetry]
enabled = "off"
```

The `MARIVO_TELEMETRY` environment variable accepts `on` or `off` and overrides project configuration. Invalid environment values are ignored; invalid project values raise a configuration error.

With telemetry enabled, explicit long operations such as analysis execution, semantic loading, and datasource queries record start and completion events. Short operations such as session creation or reuse record completion only. Lightweight reads record failures only; analysis constructors and semantic references do not record events. Nested calls omit successful events while retaining eligible failures and their parent operation identity.

## Understand retention and sharing

Files roll by UTC day and approximately 128 MiB segments. Historical records are normally kept for 14 days and pruned to a 1 GiB historical budget. Current-day files are not pruned, so the whole directory may exceed that size.

Execution logs contain SQL, which can include business conditions and literals. Usage telemetry can retain session questions and SQL reasons. Check records for sensitive content before sharing them.
