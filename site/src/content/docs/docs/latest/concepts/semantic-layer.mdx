The semantic layer gives stable names to business objects. Datasource metadata explains physical data; approved definitions establish business meaning.

## Choose the owner of each fact

| Object | Owns |
| --- | --- |
| Datasource | Connection, physical source, schema and bounded inspection |
| Domain / Entity | Business ownership, instance identity and historical versioning |
| Dimension / TimeDimension / Measure | Classification, source-time meaning, value, unit and additivity |
| Metric / Relationship | Governed equation, aggregation state and declared mapping |
| Event / StateModel | Occurrence meaning, participants, business order and normative transitions |
| Analysis | Question-specific membership, window, coordinates and computation |

## Reuse before authoring

Clone an existing project when its definitions fit the question. Read catalog
entries and their details before changing meaning. For new objects, write one
coherent dependency slice under `models/`, load it, repair structural errors and
certify only the roots needed for analysis.

Follow [semantic modeling](/docs/latest/guides/semantic-modeling/) and [Readiness](/docs/latest/concepts/readiness/). Python declarations are the shared authority; project-local `.marivo/` state is not a replacement for them.

## Establish business authority

Settle inclusions, exclusions, time axis, units, weighting and meaningful
breakdowns through the current request or an approved non-conflicting project
definition. Names and sample rows cannot settle those choices. `ai_context`
records business definitions and guardrails; richness is advisory and does not
turn them into a technical Readiness blocker.

Use [datasources](/docs/latest/guides/datasources/) for physical access, and [the Agent question guide](/docs/latest/guides/business-question/) for unresolved business choices.
