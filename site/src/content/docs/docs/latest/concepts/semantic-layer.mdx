The semantic layer gives stable names to business objects. Datasource metadata explains physical data; approved definitions establish business meaning.

## Choose the owner of each fact

| Object | Owns |
| --- | --- |
| Datasource | Connection, physical source, schema and bounded inspection |
| Domain / Entity | Business ownership, instance identity and historical versioning |
| Dimension / TimeDimension / Measure | Classification, source-time meaning, value, unit and additivity |
| Metric / Relationship | Governed equation, aggregation state and declared mapping |
| Analysis | Question-specific membership, window, coordinates and computation |

## Reuse before authoring

Clone an existing project when its definitions fit the question. Read catalog
entries and their details before changing meaning. For new objects, write one
coherent dependency slice under `models/`, load it, repair structural errors and
certify only the roots needed for analysis.

Follow [semantic modeling](/docs/latest/guides/semantic-modeling/) and [Readiness](/docs/latest/concepts/readiness/). Python declarations are the shared authority; project-local `.marivo/` state is not a replacement for them.

## Establish business authority

Settle inclusions, exclusions, time axis, units, weighting and meaningful
breakdowns through the current request or an approved non-conflicting project
definition. Names and sample rows cannot settle those choices. `ai_context`
records business definitions and guardrails for agent context; it does not
decide business meaning or certify execution.

Use [datasources](/docs/latest/guides/datasources/) for physical access, and [the Agent question guide](/docs/latest/guides/business-question/) for unresolved business choices.

## Expression Entity output grain

A direct Entity exposes its Source unchanged. A decorator Entity returns one
Ibis Table derived from its one injected Source. Its output owns keys, version
columns and downstream fields. Define reusable business grain here; calculate
question-specific Metrics through Analysis.

{/* example: semantic-entity-expression */}
```python
@ms.entity(datasource=warehouse, source=md.table("orders"), primary_key=["region"])
def regional_orders(raw):
    return raw.filter(raw.amount > 0).group_by("region").aggregate(total=raw.amount.sum())
```

Source capabilities still apply. Use `session.members(entity)` for Analysis;
Entity expressions cannot submit SQL or open another source. Read their bounded
normalized expression through Entity Details. Other computation Details expose
`details.definition`, whose `show()` and `to_dict()` describe the loaded snapshot
without execution.

Preview and certification request native query timeouts and continue when they
are unsupported. Read or cleanup failures do not publish a new certified snapshot.
Certification still requires complete scoped input and all validation; closing a
connection does not prove remote query termination.

## Local expressions and publication

Physical constructors return typed capture Refs. After the complete scope is finalized, resolving those lookup keys produces immutable expression values with complete dependency facts. Measure/Metric are pure zero-argument declarations over constructed objects, separating names from computation. They need no active loader/Session and do not publish Catalog objects. Model loading collects named Metrics for current Catalog discovery. Execution automatically prepares real physical types; native Deferred arithmetic and explicit per/window policies follow the owning semantic contract. Entity/Source and categorical/time fields retain restricted Ibis authoring.

Physical authoring captures typed Refs. Capture every dependency, then use `ms.finalize()` and `finalized.resolve(ref)` before composing row/Metric expressions. Finalization closes capture and does not publish Catalog Metrics or enable new execution.

Semantic objects need not remain bound to their original definition versions. A same-path definition change alone does not reject an input; the agent/user accepts the consequences of semantic changes during analysis. Resolving consumers use their completed scope. Immutable expressions keep their stored definitions and facts without live refresh. Kind, root, grain, unit, time-role, null and permission checks still apply. Fingerprints and cache keys describe actual consumed definitions; persisted provenance and records retain their own contracts.

Ordinary published Metrics on DuckDB support bounded preview through the shared nullable
Row/Metric kernel. Population/sample and path/attribute-anchor preview preparation is unavailable;
these inputs fail before opening a source.

```python
import marivo.datasource as md

revenue = catalog.metrics.get("sales.revenue")
preview = catalog.preview(
    revenue, scope=md.unpruned(max_rows=1000, timeout_seconds=30)
)
preview.show()
```

The preview aggregates at most 10,000 scoped Entity output rows and is approximate.
It does not publish an analysis Artifact or qualify analysis execution.
