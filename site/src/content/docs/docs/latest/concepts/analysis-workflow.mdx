Marivo analysis moves from a business question to a result you can inspect and
reuse. Choose the business definition, population and time scope, and how long
to retain the result based on the work that follows.

## Start with the question

Look up an existing `Metric` in the project Catalog and reuse it when its meaning
and aggregation answer the question. If no existing Metric fits, define the
needed business meaning in the [semantic layer](/docs/latest/modeling/semantic-layer/).
Use a stable project-local name with `mv.session.get_or_create(...)` when repeated
runs should recover the same Session.

See [Session acquisition](/docs/latest/analysis/dsl/#repeatable-session-acquisition)
and the [shared input example](/docs/latest/analysis/dsl/#complete-example-and-shared-inputs).

## Choose members, contributions, and time

Use a Population to select complete members. `session.observe(...)` captures a
Metric calculation; `by` selects output coordinates, while `where` filters
source contributions. When the Metric's time-sample reduction requires a finite
period, include a `TimeScope` or `CalendarAxis` in `by`. Use `session.read(...)`
to retrieve named attributes for selected Entity identities.

Continue with [population selection](/docs/latest/analysis/dsl/#select-and-filter),
[scope and grain](/docs/latest/analysis/dsl/#scope-and-grain), and
[observing Metrics](/docs/latest/analysis/dsl/#observe-metrics).

## Evaluate and retain the result

`session.observe(...)` returns a pending `AnalysisFrame`. `compute()` evaluates
it and returns a Frame whose values live in the current Python process.
`persist()` completes and publishes the result. If another process needs the
same values, save the returned Session and Artifact IDs before the producing
process exits. For current source values in a later analysis, capture a new
observation.

The DSL guide explains [when to compute or persist](/docs/latest/analysis/dsl/#choose-retention-before-execution);
the [results guide](/docs/latest/analysis/results/) shows how to reopen a saved
result.

## Continue with selected data

Use the returned Frame for follow-up work that should use the same computed
values. To carry a selected field or identity into a new source question, map
the axis from the completed Frame with `session.population_from(...)`, then pass
that Population to the new observation with `where=mv.in_population(...)`. The
selected keys stay fixed, while the new observation reads its source values
again. Build the bridge and observation in the owning Session. See
[select and filter](/docs/latest/analysis/dsl/#select-and-filter) for an example.
