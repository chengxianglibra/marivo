title: Analysis Workflow
description: Governed Dataset construction, explicit execution, retained evidence and recovery.
---

Give the agent the business question, confirmed Metric, Population and comparison
scope. The agent chooses the methods and checkpoints that answer that question.
You do not need to prescribe operator calls or result-display mechanics.

Datasource connectivity and semantic readiness do not prove that an analysis method
can execute on that source. Read `marivo.help("analysis.actions.execute")` for
execution boundaries, inspect the Dataset contract, and follow the concrete
structured repair for unsupported shapes. Remote sources require read-only
accounts; uploading retained results to bypass admission is unsupported.


Source execution checks only the columns required by the complete computation,
including hidden Metrics, identities, joins and version assertions. An unused
complex column does not block a supported scalar calculation. For example, the
existing revenue example still works when its table also declares an unused JSON
payload; referencing that payload does not gain a new supported method or type.
Column comments remain available through datasource inspection, including for
columns unused by the current Dataset.

## Construct and execute

Analysis uses a question-scoped Session. Source constructors and Dataset methods
describe work without querying sources. Explicit execution returns a retained,
immutable result for inspection and later continuation.

```python
import marivo
import marivo.analysis as mv
import marivo.semantic as ms

session = mv.session.get_or_create("revenue-review", report_timezone="UTC")
revenue = ms.ref.metric("sales.revenue")
current = session.observe(
    revenue, time_scope=mv.time_scope(start="2026-07-01", end="2026-08-01")
).aggregate()
baseline = session.observe(
    revenue, time_scope=mv.time_scope(start="2026-06-01", end="2026-07-01")
).aggregate()
change = current.compare(baseline).execute()
change.show()
```

The example requires an authored, typed `sales.revenue` Metric and an admitted
reference time axis. Windows are half-open: the end is excluded. `aggregate()`
explicitly removes Entity identity; a time series also declares a time axis and
grain. Population membership and observation windows are independent.

## Continue from exact meaning

Dataset fields belong to their exact Dataset. Use typed predicates, projection,
ranking and explicit coordinate reduction. Methods applied to retained results
start from those rows and their required private contribution state, preserving
identity and valid fold meaning. A mean is not summed as if it were additive;
selected ratios and distinct sets retain their actual components.

Comparison, attribution, correlation, forecast and discovery are Dataset methods.
Event matching starts at `session.events.match(...)`; Lifecycle replay starts at
`session.lifecycle.replay(...)`. Their reducers belong to the returned Datasets
and consume retained assignment/history. Cross-Session operands are rejected.
Event funnel comparisons require equal cohort duration, temporal domain and
follow-up offset. For funnel attribution, build both funnels logically from
complete journeys or journey checkpoints opened with `session.artifact(ref)`;
materialized funnel summaries or a materialized funnel Delta cannot replace
those journey inputs.

Source execution supports DuckDB and the PostgreSQL, MySQL, SQLite, Trino and ClickHouse scalar subsets below;
datasource authoring alone does not enable Dataset execution on another backend. Unsupported methods report
the backend and input shape. Retained results are never implicitly uploaded to
another source, and a same-Session execution-key hit needs no source connection.

## Inspect evidence and recover

`contract()` describes mechanical continuations; a Materialized Dataset's `show()`
provides bounded retained inspection. Read exact Findings or recover an Artifact
through its owning Session. A small preview is not permission to omit rows from
computation. See [Evidence](/docs/latest/concepts/evidence/) for the read contract.
Duration columns in the preview are explicitly labeled in microseconds;
`to_pandas()` returns those columns as timedeltas.

No configuration is needed for local Parquet result storage. Configure an object
store in `marivo.toml` only when a different location is explicitly required.
Execution never chooses database result storage or changes target/executor after
failure. Retained results preserve exact storage and temporal authority across
cold recovery. Older Store generations are rejected without rewriting files.

## Keep decisions explicit

Confirm changed business meaning when the Metric, membership, comparison or a
material assumption needs to change. Reusable semantic gaps belong to semantic
authoring. Exact quantiles use linear interpolation by default; choose
`ms.quantile_metric(..., method="duckdb_tdigest@v1")` only when approximation is
part of the intended meaning. Projection and recovery preserve that choice.

Attribution is algebraic, association is descriptive, Candidate scores are leads,
and forecasts retain model assumptions. The agent owns synthesis and conclusions.
Terminal custom analysis through `to_pandas()` or `md.raw_sql(...)` cannot be fed
back into governed Dataset composition.

Start discovery with `marivo.help("analysis")`. Follow its native entry, methods,
inputs, artifacts, evidence and runtime hubs for exact signatures and examples.
Structured errors provide concrete repair; packaged skills own workflow judgment.

Focused navigation: `analysis.entry`, `analysis.methods`, `analysis.inputs`,
`analysis.artifacts`, `marivo.help("analysis.evidence")`, and
`marivo.help("analysis.runtime")`. The terminal boundary is
`marivo.help("analysis.actions.to_pandas")`.


## Follow the current task

`analysis.entry` links Session creation/recovery and the Metric, Event and
Lifecycle starting points. `analysis.inputs` supplies missing inputs: resolve
confirmed semantic identities through the catalog and check readiness only for
the required closure. Membership, time, completeness and model assumptions have
named groups. `analysis.methods` groups summarization, comparison/attribution,
association, forecasting, screening, Event and Lifecycle work; no full-page sweep
is required.

With a Dataset in hand, read `dataset.contract().show()` and follow the exact Help
target attached to the chosen admitted action. Types and members remain focused
queries; an acquired public method can also be passed directly to
`marivo.help(...)`. Each focused callable supplies its required inputs and return
routes. Once those facts support the next step, save and run the minimum analysis.

Source checks, primary rows and required parts may observe different source states within one execution. Successful checks do not certify later reads. Marivo preserves required checks, single evaluation and atomic publication, but does not reject or retry solely because source data changed between queries.

The same execution definition in one Session recovers its committed snapshot.
For current source rows, use a new named Session or change an explicit
row-affecting definition input; repeated execution is not refresh evidence.
Recovery integrity checks cover Artifact, storage authority and Evidence, not
current semantic authority or datasource freshness.

## Local execution and resource responsibility

Local methods and `to_pandas()` run synchronously in the calling Python process,
returning complete results or preserving the original exception cause and
traceback. Marivo creates no execution/read workers and imposes no execution
row, byte, memory, spill, method complexity, storage or deadline budgets. Database,
driver, OS and external runner limits still apply.

`show()` keeps its display bounds. Complete-input validation, ownership and atomic
publication remain mandatory. Store generation 5 leaves older files untouched;
old Sessions are not migrated or resumed.

Supported execution does not require engine, driver or Ibis version certification.
Normal expression compilation preserves parameters, complete results and required
validation order. Recompilation alone does not submit another query.

Cancellation or close can leave a remote read's status unknown. Marivo reports
that uncertainty and permits later Session work once local publication is safe.
Unresolved commit state, conflicting writers and unsafe object writes still block
recovery. A failed Run has no successful local output; it does not prove a remote
server query stopped. Never automatically resubmit an ambiguously submitted action.

## Backend implementation boundaries

Operators share one semantic contract and backend registration mechanism. DuckDB
retains its existing sampling, Event/Lifecycle and Candidate implementations; its
adapter owns temporary resources, macros and registration. Remote implementations
must support read-only accounts and meet the same semantic requirements before
activation. An unavailable implementation fails explicitly; it does not silently
move source data to another engine. PostgreSQL, MySQL, SQLite, Trino and ClickHouse support the subsets below.


### Relational methods and native-date analysis

Within each backend's table and physical type scope, you can also use direct-column
mean, weighted mean and ratio, same-source relationships, native-date buckets
(day/week/month/quarter/year, one unit), and snapshot/validity membership.
PostgreSQL supports both validity interval closures and configured open-end sentinels;
MySQL, SQLite, Trino and ClickHouse admit closed-open intervals with NULL open ends.
All joins and version selections retain their required identity and fanout checks.

For an authored mean Metric, retain its sufficient components before rolling up:

```python
mean_amount = ms.ref.metric("sales.mean_amount")
channel = ms.ref.dimension("sales.orders.channel")
means = session.observe(mean_amount).with_dimensions(channel).aggregate().execute()
overall = means.rollup(drop_dimensions=(channel,)).execute()
overall.show()
```

The rollup recomputes the mean from retained sum/count state, rather than averaging
group means. Comparison and attribution use complete non-Entity retained axes.
Forecast, Kendall and time discovery run locally on complete source-aggregated
inputs. Cold retained reads and folds do not need the original source.

String-parser time axes, multi-unit or semantic-calendar
buckets, cumulative/status-time folds, linear Metric graphs and unresolved Decimal
result precision remain unsupported. Sampling, hidden-axis expanded attribution,
Entity correlation, exact distinct/quantile private state, Entity candidates,
source driver screening and Event/Lifecycle are not enabled by this extension.
Unsupported shapes report a concrete reason; they do not trigger raw source
collection or remote retained uploads.

### Native timestamp analysis

Qualified native timestamps support typed predicates and `hour`/`day` buckets
with `count=1`, through microsecond precision. PostgreSQL also admits timestamptz;
MySQL TIMESTAMP and ClickHouse DateTime/DateTime64 retain physical instant
semantics when bound with an aware timestamp type. ClickHouse timestamp execution
requires a verified UTC reader timezone; non-UTC column and report timezones remain
supported. Existing explicitly asserted
UTC-labelled civil bindings remain validated as civil values. A physical timezone
must match an aware declaration; a plain declaration cannot relabel a non-UTC
ClickHouse instant. Trino uses the actual Iceberg timestamp(6) type. SQLite keeps
its validated civil-text representation and uses connection-local deterministic
time functions without transferring source rows to another executor.

An authored native parser timezone takes precedence over the reader timezone.
Only engines without a timezone probe use recorded system fallback; failed probes
and invalid names fail when reader authority is needed. Physical instants and
explicit parser authority do not require a reader probe. IANA and explicit fixed
offsets are supported for reader/report authority; native parser declarations
retain their existing IANA validation. Report authority is persisted once.

Scopes compare exact instants before producing report-local civil coordinates.
Naive timestamps in DST gaps or folds fail rather than selecting an implicit
interpretation. Two known instants in a repeated report hour share its civil bucket.
Naive predicate literals compare civil fields; aware literals compare instant
fields. Mixing these kinds fails. Milliseconds/microseconds remain exact through
SQL literals, Arrow, Parquet and source-offline cold recovery. Hour-to-day retained
folds reuse the persisted temporal facts. String/epoch parsing, multi-unit buckets,
new timestamp version selection and semantic calendar/cumulative extensions are
not enabled on remote backends.

```python
import marivo.analysis as mv
import marivo.semantic as ms

orders_by_hour = (
    session.observe(
        ms.ref.metric("sales.revenue"),
        time_scope=mv.time_scope(start="2026-07-01", end="2026-07-03"),
    )
    .with_time_axis(ms.ref.time_dimension("sales.orders.order_time"), grain=mv.grain("hour"))
    .aggregate()
    .execute()
)
orders_by_hour.rollup(grain=mv.grain("day")).execute().show()
```

Actual adapter submissions own SQL diagnostics, with source/local domain, role
and submitted/succeeded/failed status. Compilation alone records no submitted SQL.
Driver-internal connection setup and transaction protocol traffic outside the
observed submission boundary are not claimed as captured queries.

### PostgreSQL scalar Metrics

PostgreSQL Group A accepts a single datasource and a single unversioned table,
with direct-column `sum`, `count`, `min` or `max` Metrics. You can select Population
membership, scope observations by native dates, add dimensions, aggregate Entity
rows, filter, project Metrics, rank deterministically and select Top-N. The entire
dependency graph must be supported, including Metrics removed by projection.

For example, with a sum Metric `sales.revenue` and a direct dimension
`sales.orders.channel` authored on the same PostgreSQL table:

```python
revenue = ms.ref.metric("sales.revenue")
by_channel = session.observe(
    revenue,
    time_scope=mv.time_scope(start="2026-07-01", end="2026-08-01"),
).with_dimensions(ms.ref.dimension("sales.orders.channel")).aggregate()
top_channels = by_channel.rank(by_channel.fields.metric(revenue)).limit(5).execute()
top_channels.show()
```

All required source columns must use Boolean, string, signed integers, float32,
float64, date, timestamp/timestamptz (precision 0–6) or Decimal types. PostgreSQL CHAR is rejected
because its trailing-space semantics differ from string; text/varchar remain supported. Decimal precision is at most 38,
with scale from zero to precision; generic Decimal declarations also undergo
physical metadata validation. String time parsing, sampling,
composed Metrics and private-state methods are outside this subset.

Use a read-only PostgreSQL account without write, CREATE or TEMP privileges.
Queries stream through an owned server-side cursor; no temporary tables, uploads
or UDFs are created. Validation and result queries may observe different source
states. Failures preserve their original error and never publish partial output.
Retained results use the existing reader and are not imported into PostgreSQL.


### MySQL and SQLite scalar Metrics

The Group A workflow above also applies to a single unversioned MySQL or SQLite
table: direct-column `sum/count/min/max`, Population, date-scoped observation,
dimensions, aggregation, filters, projection, deterministic rank and Top-N.
For example, the same authored `sales.revenue` and channel dimension use:

```python
revenue = ms.ref.metric("sales.revenue")
by_channel = session.observe(revenue).with_dimensions(
    ms.ref.dimension("sales.orders.channel")
).aggregate()
by_channel.rank(by_channel.fields.metric(revenue)).limit(5).execute().show()
```

MySQL requires InnoDB and a SELECT-only account. Inputs include signed and unsigned
integers, float32/64, native DATE, `utf8mb4_0900_bin` VARCHAR/TEXT and explicit
Decimal precision up to 38. Explicit Boolean bindings accept TINYINT(1) only after
necessary-column 0/1/NULL checks; integer bindings remain integers. DATETIME(0–6)
and TIMESTAMP(0–6) preserve microseconds; TIMESTAMP requires an observed session time_zone of UTC or +00:00; other aliases remain unqualified.
CHAR, BIT, ENUM/SET, nested values and generic Decimal sources are not admitted.
Zero/invalid dates and timestamps fail before publication. Integer SUM is decoded
exactly from Decimal; the current result is int64, so values beyond its range fail.
Floating SUM overflow raises the original database exception.

SQLite accepts persistent ordinary main-database tables. INTEGER/INT/BIGINT,
TINYINT/SMALLINT/MEDIUMINT/INT2/INT8 map to int64; REAL/DOUBLE/DOUBLE PRECISION/FLOAT
to float64; TEXT/CLOB/CHAR/VARCHAR (including declared lengths) to string with
BINARY collation and actual text storage. DATE requires valid canonical YYYY-MM-DD
text. BOOL/BOOLEAN requires integer 0/1/NULL. DATETIME/TIMESTAMP requires fixed
`YYYY-MM-DD HH:MM:SS.ffffff` civil text, valid Gregorian years 0001–9999, without
an offset. Necessary-column storage checks run even when output is empty.
Unsigned, Decimal, native aware SQLite storage, virtual and attached tables remain excluded.
SQLite stores inserted NaN as NULL; that distinction cannot be recovered.
Native integer SUM overflow remains an error.

Ordinary timestamps support exact transport, grouping, sorting and typed predicates.
The native timestamp extension above owns temporal method admission; a declaration
alone does not establish a naive timestamp's read-timezone authority.
UInt64 identities, min/max and transport preserve the full unsigned range through
Arrow, Parquet and cold reads without floating or signed conversion.

Both adapters preserve typed composite identities and read driver batches without
an intermediate pandas collection. MySQL unbuffered cursor close may drain
unread responses; no hard cancellation deadline or memory bound is promised.
SQLite steps its native cursor incrementally; sorting and aggregation may still
materialize inside the engine. Batches limit rows, not bytes, and each cell is
decoded in full. SQLite execution is query-only. Source assertions and output reads may see
different states; publication remains atomic. Retained results stay in Parquet
and use the existing native reader, without upload to either source. The relational/native-date extension above adds individually qualified methods.
Sampling and source-private advanced methods remain outside this subset.

### Trino Iceberg scalar Metrics

Trino Group A supports one datasource and one unversioned ordinary Iceberg base
table, with direct-column `sum`, `count`, `min` and `max`, Population filtering,
native-date scopes, same-Entity dimensions, aggregation, projection, rank and limit.
Use the existing catalog/schema/table declaration; both tuple and dotted
catalog/schema overrides are resolved consistently for metadata and executed SQL.
The adapter verifies connector identity and base-table metadata at execution;
a catalog merely named `iceberg` is not sufficient.

Declared physical inputs are signed integers supported by Iceberg, float32/64,
VARCHAR, BOOLEAN, timestamp(0–6) without time zone, DATE and explicit Decimal
precision/scale up to 38. The qualified Iceberg connector exposes timestamp DDL
with precision 0 or 3 as timestamp(6); bindings must match this observed precision. CHAR, generic Decimal source declarations, timezone-bearing
timestamps, precision above microseconds, nested values and other
connectors are excluded. Declared floating columns must contain finite values or
NULL; source checks reject NaN/infinity even for empty output, and non-finite
aggregate results fail before publication. Decimal and integer identities retain
exact values. Ranking preserves explicit NULL order and deterministic ties.

Use a read-only identity with access to connector and table metadata. Ordinary
Ibis compilation feeds incremental driver page reads; internal identity structs
are reconstructed from typed scalar columns. Batches are not byte or memory
limits. Driver/server limits remain external. Active cursors are owned before
submission; cancellation and close failures report unknown remote status without
blocking safe local recovery. Validation and output can observe different source
states. Sampling, retained imports and source-private advanced methods remain unavailable;
the relational/native-date extension above adds individually qualified methods.

The scalar workflow example above also applies to an authored Trino Iceberg Metric.

### ClickHouse MergeTree scalar Metrics

ClickHouse Group A admits one datasource and one unversioned ordinary local
MergeTree table: direct-column sum/count/min/max, Population filters, native-date
scopes, same-Entity dimensions, aggregation, projection, deterministic rank and
limit. Sampling, retained import and source-private advanced methods remain unavailable.
The relational/native-date extension owns additional method admission.

Physical inputs include Int8/16/32/64, UInt8/16/32/64, Bool, Float32/64, String,
Date and explicit Decimal precision up to 38, with legal Nullable wrappers.
LowCardinality(String) and LowCardinality(Nullable(String)) retain string semantics.
DateTime('UTC') and DateTime with verified UTC engine timezone preserve seconds.
DateTime64 through microseconds and aware non-UTC bindings are admitted by the
native timestamp extension. FixedString, Date32, Int128/256, UInt128/256, Enum
and nested values remain excluded. Distributed, Replicated, specialized engines
and views are not enabled by this scalar-type extension.

Use a SELECT-only account configured with effective `join_use_nulls=1`.
Metadata, required assertions and output run separately; empty output never
bypasses validation. Declared floating values must be finite or NULL. Exact
integer/Decimal sums widen internally to Decimal256 before checked output
conversion; overflow and non-finite output fail without publication.

Native row streams preserve Decimal and typed Entity identities without pandas
or raw source transfer to another engine. Each response is owned and closed;
driver close can drain unread data, so cancellation has no hard latency promise.
Connection close does not prove remote termination. Unknown remote status does
not prevent safe local recovery; partial output is never published. No shared
snapshot, execution budget, upload, temporary object or implicit retry is added.
Batch size is transport configuration, not a result cap.

MySQL/SQLite preview and sample preserve large nullable integers without an
intermediate float64 conversion.


Native timestamp timezone rules follow runtime ZoneInfo. Source-side validation
rejects ambiguous wall times or engine/runtime rule disagreements before publishing
results. Align the source engine and runtime timezone data before retrying a rule
mismatch; only aggregate bounds and validation counts cross the source boundary.
