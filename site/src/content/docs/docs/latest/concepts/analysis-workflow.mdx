Give the agent the business question, confirmed Metric, Population and comparison
scope. The agent chooses the methods and checkpoints that answer that question.
You do not need to prescribe operator calls or result-display mechanics.

## Construct and execute

Analysis uses a question-scoped Session. Source constructors and Dataset methods
describe work without querying sources. Explicit execution returns a retained,
immutable result for inspection and later continuation.

```python
import marivo
import marivo.analysis as mv
import marivo.semantic as ms

session = mv.session.get_or_create("revenue-review", report_timezone="UTC")
revenue = ms.ref.metric("sales.revenue")
current = session.observe(
    revenue, time_scope=mv.time_scope(start="2026-07-01", end="2026-08-01")
).aggregate()
baseline = session.observe(
    revenue, time_scope=mv.time_scope(start="2026-06-01", end="2026-07-01")
).aggregate()
change = current.compare(baseline).execute()
change.show()
```

The example requires an authored, typed `sales.revenue` Metric and an admitted
reference time axis. Windows are half-open: the end is excluded. `aggregate()`
explicitly removes Entity identity; a time series also declares a time axis and
grain. Population membership and observation windows are independent.

## Continue from exact meaning

Dataset fields belong to their exact Dataset. Use typed predicates, projection,
ranking and explicit coordinate reduction. Methods applied to retained results
start from those rows and their required private contribution state, preserving
identity and valid fold meaning. A mean is not summed as if it were additive;
selected ratios and distinct sets retain their actual components.

Comparison, attribution, correlation, forecast and discovery are Dataset methods.
Event matching starts at `session.events.match(...)`; Lifecycle replay starts at
`session.lifecycle.replay(...)`. Their reducers belong to the returned Datasets
and consume retained assignment/history. Cross-Session operands are rejected.
Event funnel comparisons require equal cohort duration, temporal domain and
follow-up offset. For funnel attribution, build both funnels logically from
complete journeys or journey checkpoints opened with `session.artifact(ref)`;
materialized funnel summaries or a materialized funnel Delta cannot replace
those journey inputs.

## Inspect evidence and recover

`contract()` describes mechanical continuations; a Materialized Dataset's `show()`
provides bounded retained inspection. Read exact Findings or recover an Artifact
through its owning Session. A small preview is not permission to omit rows from
computation. See [Evidence](/docs/latest/concepts/evidence/) for the read contract.
Duration columns in the preview are explicitly labeled in microseconds;
`to_pandas()` returns those columns as timedeltas.

No configuration is needed for local Parquet result storage. Configure an object
store in `marivo.toml` only when a different location is explicitly required.
Execution never chooses database result storage or changes target/executor after
failure. Retained results preserve exact storage and temporal authority across
cold recovery. Older Store generations are rejected without rewriting files.

## Keep decisions explicit

Confirm changed business meaning when the Metric, membership, comparison or a
material assumption needs to change. Reusable semantic gaps belong to semantic
authoring. Exact quantiles use linear interpolation by default; choose
`ms.quantile_metric(..., method="duckdb_tdigest@v1")` only when approximation is
part of the intended meaning. Projection and recovery preserve that choice.

Attribution is algebraic, association is descriptive, Candidate scores are leads,
and forecasts retain model assumptions. The agent owns synthesis and conclusions.
Terminal custom analysis through `to_pandas()` or `md.raw_sql(...)` cannot be fed
back into governed Dataset composition.

Start discovery with `marivo.help("analysis")`. Follow its native entry, methods,
inputs, artifacts, evidence and runtime hubs for exact signatures and examples.
Structured errors provide concrete repair; packaged skills own workflow judgment.

Focused navigation: `analysis.entry`, `analysis.methods`, `analysis.inputs`,
`analysis.artifacts`, `marivo.help("analysis.evidence")`, and
`marivo.help("analysis.runtime")`. The terminal boundary is
`marivo.help("analysis.actions.to_pandas")`.


## Follow the current task

`analysis.entry` links Session creation/recovery and the Metric, Event and
Lifecycle starting points. `analysis.inputs` supplies missing inputs: resolve
confirmed semantic identities through the catalog and check readiness only for
the required closure. Membership, time, completeness and model assumptions have
named groups. `analysis.methods` groups summarization, comparison/attribution,
association, forecasting, screening, Event and Lifecycle work; no full-page sweep
is required.

With a Dataset in hand, read `dataset.contract().show()` and follow the exact Help
target attached to the chosen admitted action. Types and members remain focused
queries; an acquired public method can also be passed directly to
`marivo.help(...)`. Each focused callable supplies its required inputs and return
routes. Once those facts support the next step, save and run the minimum analysis.

Source checks, primary rows and required parts may observe different source states within one execution. Successful checks do not certify later reads. Marivo preserves required checks, single evaluation and atomic publication, but does not reject or retry solely because source data changed between queries.

The same execution definition in one Session recovers its committed snapshot.
For current source rows, use a new named Session or change an explicit
row-affecting definition input; repeated execution is not refresh evidence.
Recovery integrity checks cover Artifact, storage authority and Evidence, not
current semantic authority or datasource freshness.

## Local execution and resource responsibility

Local methods and `to_pandas()` run synchronously in the calling Python process,
returning complete results or preserving the original exception cause and
traceback. Marivo creates no execution/read workers and imposes no execution
row, byte, memory, spill, method complexity, storage or deadline budgets. Database,
driver, OS and external runner limits still apply.

`show()` keeps its display bounds. Complete-input validation, ownership and atomic
publication remain mandatory. Store generation 4 leaves older files untouched;
old Sessions are not migrated or resumed.
