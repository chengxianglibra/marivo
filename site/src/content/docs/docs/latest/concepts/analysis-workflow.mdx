Give the agent the business question, confirmed Metric, Population and comparison
scope. The agent chooses the methods and checkpoints that answer that question.
You do not need to prescribe operator calls or result-display mechanics.

Datasource connectivity and semantic readiness do not prove that an analysis method
can execute on that source. Read `marivo.help("analysis.actions.execute")` for
execution boundaries, inspect the Dataset contract, and follow the concrete
structured repair for unsupported shapes. Remote sources require read-only
accounts; uploading retained results to bypass admission is unsupported.

Public Sessions now use Store 7. J1–J4 member reads, selection, grouping, windowed
observation, comparison, original-component ratio/rollup, row statistics and
Spearman use one graph Runtime. Qualified routes cover DuckDB tables, local
Parquet sources and verified fixed Arrow/Parquet-to-pandas continuations.
R6–R9 Dataset methods retain their signatures but reject before business reads
or Run allocation until they gain Store 7 qualification. Old-generation projects
remain unchanged; create a Session in a fresh project.

Construction may use R1 schema-only preflight to determine exact identity and
value types, without reading business rows. Member identity is one string/int64
column and the event axis is a UTC microsecond timestamp; each method still
requires its exact physical qualification.

## Construct and execute

Analysis uses a question-scoped Session. Source constructors and Dataset methods
describe work without business-row reads; schema-only preflight is allowed. Explicit execution returns a retained,
immutable result for inspection and later continuation.

The example below uses the qualified Entity member route.

```python
import marivo
import marivo.analysis as mv
import marivo.semantic as ms

session = mv.session.get_or_create("revenue-review", report_timezone="UTC")
customers = session.members(ms.ref.entity("sales.customer"))
revenue = ms.ref.metric("sales.revenue")
buyer = ms.ref.relationship("sales.order_buyer")
current = customers.observe(
    revenue, during=mv.time_scope(start="2026-08-01", end="2026-09-01"), via=buyer
)
baseline = customers.observe(
    revenue, during=mv.time_scope(start="2026-07-01", end="2026-08-01"), via=buyer
)
change = current.compare(baseline).execute()
change.show()
```

The example requires an authored, typed `sales.revenue` Metric and an admitted
reference time axis. Windows are half-open: the end is excluded.
Date-only bounds use the Session's persisted report timezone, so set
`report_timezone` explicitly for the intended calendar. Member selection and observation windows are independent. Read a member Dimension and select its values before calling `.members().observe(...)`.

For the admitted J1–J4 Entity domain on a configured DuckDB source, start with
`session.members(Entity Ref)`. The member domain owns `read`, `group_by`, and
`observe`; its returned relations own selection, comparison, rollup, row
statistics, and association. `marivo.help("analysis.entry")` directs
Entity-member questions here. The currently qualified Metric observation route requires a UTC
event Time Dimension; a different or unresolved axis timezone is rejected.
For example:

```python
customers = session.members(ms.ref.entity("sales.customer"))
revenue = ms.ref.metric("sales.revenue")
buyer = ms.ref.relationship("sales.order_buyer")
august = mv.time_scope(start="2026-08-01", end="2026-09-01")
august_revenue = customers.observe(revenue, during=august, via=buyer)
total = august_revenue.rollup().execute()
total.show()
restored = session.artifact(total.state.artifact_ref)
restored.contract().show()
for action in restored.contract().actions:
    print(action.call, action.help_target)
```

This shape requires the named Entity, Metric, and Relationship to be authored
and admitted in the project. Logical source execution evaluates the source on
each call. Exact fixed continuations can reuse a committed execution key;
`session.artifact(ref)` restores a public J1–J4 result from its validated
snapshot and retained parts without reading the current source or Semantic
catalog. Other Dataset execution remains unavailable until qualified for Store 7.
The bounded result card includes the available unit, method, Cell fields and
current-row weighting, and masks Entity member values. Each `AnalysisAction`
contains one mechanically admitted receiver call and its exact
`marivo.help("analysis.<target>")` route. A materialized contract verifies the exact retained parts before disclosing continuations.

The same configured project can continue through the other admitted J1–J4
shapes when it also declares `sales.order_count`, `sales.aov_from_lines`,
`sales.order`, `sales.order_line`, and `sales.line_order`:

```python
july = mv.time_scope(start="2026-07-01", end="2026-08-01")
september = mv.time_scope(start="2026-09-01", end="2026-10-01")
baseline = customers.observe(revenue, during=july, via=buyer)
change = august_revenue.compare(baseline)
falling = change.where(change.value.lt(0)).members()
next_month_mean = falling.observe(
    revenue, during=september, via=buyer
).summarize(mv.mean()).execute()

ratio_routes = mv.routes(
    mv.route(
        ms.ref.entity("sales.order_line"),
        through=(ms.ref.relationship("sales.line_order"), buyer),
    ),
    mv.route(ms.ref.entity("sales.order"), through=(buyer,)),
)
channel = ms.ref.dimension("sales.order.channel")
aov = customers.observe(
    ms.ref.metric("sales.aov_from_lines"), during=august, via=ratio_routes,
    coordinates=(channel,),
)
overall_aov = aov.rollup().execute()
channel_aov = aov.group_by(channel).rollup().execute()
current_row_mean = aov.summarize(mv.mean()).execute()

order_count = customers.observe(
    ms.ref.metric("sales.order_count"), during=august, via=buyer
)
association = august_revenue.correlate(order_count, method="spearman").execute()
coefficient = association.coefficient
negative = coefficient.where(coefficient.value.lt(0)).execute()
```

`rollup()` recombines retained original components; `summarize(mv.mean())`
calculates an equal-current-row mean. Spearman is descriptive and uses complete
member pairs from the same observation scope.

## Continue from exact meaning

Dataset fields belong to their exact Dataset. Use typed predicates, projection,
ranking and explicit coordinate reduction. Methods applied to retained results
start from those rows and their required private contribution state, preserving
identity and valid fold meaning. A mean is not summed as if it were additive;
selected ratios and distinct sets retain their actual components.

Comparison, attribution, correlation, forecast and discovery are Dataset methods.
Event matching starts at `session.events.match(...)`; Lifecycle replay starts at
`session.lifecycle.replay(...)`. Their reducers belong to the returned Datasets
and consume retained assignment/history. Cross-Session operands are rejected.
Event funnel comparisons require equal cohort duration, temporal domain and
follow-up offset. For funnel attribution, build both funnels logically from
complete journeys or journey checkpoints opened with `session.artifact(ref)`;
materialized funnel summaries or a materialized funnel Delta cannot replace
those journey inputs.

Source execution supports DuckDB and the PostgreSQL, MySQL, SQLite, Trino and ClickHouse scalar subsets below;
datasource authoring alone does not enable Dataset execution on another backend. Unsupported methods report
the backend and input shape. Retained results are never implicitly uploaded to
another source, and a same-Session execution-key hit needs no source connection.
`md.register()` saves a declaration without loading analysis execution code.
Execution loads only the selected backend implementation; a missing selected
dependency fails with a structured repair before a source connection opens.

## Inspect evidence and recover

For source-bound Metric and Population graphs, `contract()` reports the selected
backend's static source admission. `rejected` includes its reason; `static_pass`
only means the pure check passed, while graphs with retained Artifact inputs show
`not_checked`. `execute()` still decides final placement. The contract also
describes mechanical continuations; a Materialized Dataset's `show()` provides
bounded retained inspection. Read exact Findings or recover an Artifact
through its owning Session. A small preview is not permission to omit rows from
computation. See [Evidence](/docs/latest/concepts/evidence/) for the read contract.
Duration columns in the preview are explicitly labeled in microseconds;
`to_pandas()` returns those columns as timedeltas.

Results always use project-local Parquet; no result storage setting exists.
Execution never chooses database result storage or changes target/executor after
failure. Retained results preserve exact storage and temporal authority across
cold recovery. Store generation 7 does not migrate or rewrite older files.

## Keep decisions explicit

Confirm changed business meaning when the Metric, membership, comparison or a
material assumption needs to change. Reusable semantic gaps belong to semantic
authoring. Define approximation explicitly in the Metric with
`agg=("approx_percentile", q)`; observation and recovery preserve that definition.
Result contracts disclose source-native SQL precision limitations.

Attribution is algebraic, association is descriptive, Candidate scores are leads,
and forecasts retain model assumptions. The agent owns synthesis and conclusions.
Terminal custom analysis through `to_pandas()` or `md.raw_sql(...)` cannot be fed
back into governed Dataset composition.

Start discovery with `marivo.help("analysis")`. Follow its native entry, methods,
inputs, artifacts, evidence and runtime hubs for exact signatures and examples.
Structured errors provide concrete repair; packaged skills own workflow judgment.

Focused navigation: `analysis.entry`, `analysis.methods`, `analysis.inputs`,
`analysis.artifacts`, `marivo.help("analysis.evidence")`, and
`marivo.help("analysis.runtime")`. The terminal boundary is
`marivo.help("analysis.actions.to_pandas")`.


## Follow the current task

`analysis.entry` links Session creation/recovery and the Metric, Event and
Lifecycle starting points. `analysis.inputs` supplies missing inputs: resolve
confirmed semantic identities through the catalog and check readiness only for
the required closure. Membership, time, completeness and model assumptions have
named groups. `analysis.methods` groups summarization, comparison/attribution,
association, forecasting, screening, Event and Lifecycle work; no full-page sweep
is required.

With a Dataset in hand, read `dataset.contract().show()` and follow the exact Help
target attached to the chosen admitted action. Types and members remain focused
queries; an acquired public method can also be passed directly to
`marivo.help(...)`. Each focused callable supplies its required inputs and return
routes. Once those facts support the next step, save and run the minimum analysis.

Primary rows and required parts may observe different source states within one execution. Marivo preserves required Artifact checks, single evaluation and atomic publication, but does not reject or retry solely because source data changed between queries.

For the Entity-domain J1–J4 slice, repeated logical source execution reads the
source again. Fixed continuations can hit the same exact committed Artifact;
recover it explicitly with `session.artifact(ref)`. Other Dataset paths reject before execution until their R6–R9 migration.
Recovery integrity checks cover Artifact, storage authority and Evidence, not
current semantic authority or datasource freshness.

## Local execution and resource responsibility

Local methods and `to_pandas()` run synchronously in the calling Python process,
returning complete results or preserving the original exception cause and
traceback. Marivo creates no execution/read workers and imposes no execution
row, byte, memory, spill, method complexity, storage or deadline budgets. Database,
driver, OS and external runner limits still apply.

`show()` keeps its display bounds. Complete-input validation, ownership and atomic
publication remain mandatory. Store generation 7 leaves older files untouched;
old Sessions are not migrated or resumed.

Supported execution does not require engine, driver or Ibis version certification.
Normal expression compilation preserves parameters, complete results and required
validation order. Recompilation alone does not submit another query.

Cancellation or close can leave a remote read's status unknown. Marivo reports
that uncertainty and permits later Session work once local publication is safe.
Unresolved commit state and conflicting writers still block recovery. A failed
Run has no successful local output; it does not prove a remote
server query stopped. Never automatically resubmit an ambiguously submitted action.

## Backend implementation boundaries

The backend and method descriptions below preserve pre-refactor qualification
history. At the current R1 checkout, they do not grant execution to the older
source routes: Event, Lifecycle, Attribution, mean, time-scoped observation,
ranking and other non-basic methods reject at `source_admission` until their
R6–R9 migration and fresh backend qualification. Check the Dataset contract
and the repository's R1 acceptance record for current evidence.

Operators share one semantic contract and backend registration mechanism. DuckDB
retains its existing Event/Lifecycle and Candidate implementations; its
ordinary result batches use Ibis with an owned Arrow reader, while temporary
resources, macros and registration remain action-local. Remote implementations
must support accounts without write or object-creation privileges and meet the
same semantic requirements before activation. Their specialized transports remain
where exact types, incremental reads or shared snapshots require them. An
unavailable implementation fails explicitly; it does not silently
move source data to another engine. PostgreSQL, MySQL, SQLite, Trino and ClickHouse support the subsets below.


### Relational methods and native-date analysis

Within each backend's table and physical type scope, you can also use direct-column
mean, weighted mean and ratio, same-source relationships, native-date buckets
(day/week/month/quarter/year, one unit), and snapshot/validity membership.
All five remote backends admit both validity interval closures and configured
open-end sentinels. All joins and version selections retain their required
identity and fanout checks.

For an authored mean Metric, retain its sufficient components before rolling up:

```python
mean_amount = ms.ref.metric("sales.mean_amount")
channel = ms.ref.dimension("sales.orders.channel")
means = session.members(ms.ref.entity("sales.customer")).observe(
    mean_amount,
    during=mv.time_scope(start="2026-08-01", end="2026-09-01"),
    via=ms.ref.relationship("sales.order_buyer"),
    coordinates=(channel,),
).group_by(channel).rollup().execute()
overall = means.rollup().execute()
overall.show()
```

The rollup recomputes the mean from retained sum/count state, rather than averaging
group means. Comparison and attribution use complete non-Entity retained axes.
Forecast, Kendall and time discovery run locally on complete source-aggregated
inputs. Cold retained reads and folds do not need the original source.

The unified graph's DuckDB table and local-Parquet numeric methods support int64,
finite float64, Decimal and fixed Duration. Decimal sums retain input scale; mean,
Metric weighted mean and ratio finish once with HALF_EVEN at the declared scale.
Duration keeps its s/ms/us/ns unit and uses nearest-even ticks for means. Native
DuckDB INTERVAL contributes microseconds only after calendar components are rejected;
Parquet preserves all four Arrow Duration units. Original-state rollup and typed
time folds retain these types through cold recovery. Source computations run as
Ibis-compiled SQL; fixed continuations use verified retained state.

Exact and approximate distinct/quantile operations are chosen in the Metric
definition. Native quantile rounding is disclosed. A datasource that cannot execute
an exact definition reports its corresponding approximate declaration, including q,
and whether it is supported; it never changes the operation automatically. These
R5 qualifications do not grant remote-backend execution; that matrix belongs to R9.
Percentile status-time folds remain unqualified.

Existing correlation consumers retain their separate backend qualifications; Kendall uses its existing complete-input local
continuation. Hidden-axis expanded additive and component attribution over
complete non-Entity state is available on PostgreSQL, SQLite, Trino and
ClickHouse. MySQL remains unqualified after its live composed query exceeded
the qualification server's memory limit; expanded Top-K on Trino is also
unqualified because its query exceeded the server stage limit. Sampling,
Entity candidates and source driver screening remain unsupported. PostgreSQL
admits exact two- or three-step `session.events.match(...)` journeys and
`session.lifecycle.replay(...)` histories with two trigger Events. These shapes
require unversioned table sources and `int64` subject and occurrence identities.
Direct Event funnel, time-to-event and subject selection, and Lifecycle
distribution, transitions, dwell, violations and subject selection are qualified.
Complete PostgreSQL funnels support retained comparison and attribution.
ClickHouse and Trino admit two-step journeys with `first_per_subject()` or
`every_start()` (shared/exclusive), with the same table and identity requirements.
Trino was tested on Iceberg. ClickHouse requires a read-only reader permitted to
set `enable_materialized_cte=1`. Source-side assertions run even for empty output;
only complete admitted results can enter the existing local continuations.
Trino also supports direct ungrouped funnels, first-per-subject time-to-event,
subject selection and complete ungrouped funnel comparison. Grouped Trino funnels
and dependent attribution remain unsupported because reconciliation exceeds the
qualification server's stage limit. ClickHouse direct Event reducers and selection remain unsupported after
planner/memory qualification failures.
Trino (Iceberg) and ClickHouse (MergeTree) also support two-trigger Lifecycle
history with these table requirements and one `int64` component per subject
and occurrence identity. They replay complete sequences
with native array folds and verify same-time order ambiguity in the source.
Execute history first to use its complete retained distribution, transition,
dwell, violation and subject-selection continuations. Direct source Lifecycle
reducers on these two backends remain unsupported. SQLite and MySQL
Event/Lifecycle remain unsupported.

For a qualified PostgreSQL, Trino or ClickHouse model, materialize history before
continuing:

```python
history = session.lifecycle.replay(
    model,
    window=window,
    seed=mv.from_inception(),
    completeness=lifecycle_completeness,
)
retained_history = history.execute()
transitions = retained_history.transitions().execute()
transitions.show()
```

Here `model` is a governed two-trigger StateModel, `window` is an aware time scope,
and `lifecycle_completeness` contains source-origin coverage declarations. The
source replays the complete history; the published result retains the parts needed
for cold-process continuation.

String-parser time axes and multi-unit buckets are enabled per
backend, with the limits below. Unsupported shapes report a concrete reason; they
do not trigger raw source collection or remote retained uploads.

### Native timestamp analysis

Qualified native timestamps support typed predicates and `hour`/`day` buckets
with `count=1`, through microsecond precision. PostgreSQL also admits timestamptz;
MySQL TIMESTAMP and ClickHouse DateTime/DateTime64 retain physical instant
semantics when bound with an aware timestamp type. ClickHouse timestamp execution
requires a verified UTC reader timezone; non-UTC column and report timezones remain
supported. Existing explicitly asserted
UTC-labelled civil bindings remain validated as civil values. A physical timezone
must match an aware declaration; a plain declaration cannot relabel a non-UTC
ClickHouse instant. Trino uses the actual Iceberg timestamp(6) type. SQLite keeps
its validated civil-text representation and uses connection-local deterministic
time functions without transferring source rows to another executor.

An authored native parser timezone takes precedence over the reader timezone.
Only engines without a timezone probe use recorded system fallback; failed probes
and invalid names fail when reader authority is needed. Physical instants and
explicit parser authority do not require a reader probe. IANA and explicit fixed
offsets are supported for reader/report authority; native parser declarations
retain their existing IANA validation. Report authority is persisted once.

Scopes compare exact instants before producing report-local civil coordinates.
Naive source timestamps in DST gaps or folds are not preflighted; conversion follows
the declared authority and backend behavior. Two known instants in a repeated report hour share its civil bucket.
Naive predicate literals compare civil fields; aware literals compare instant
fields. Mixing these kinds fails. Milliseconds/microseconds remain exact through
SQL literals, Arrow, Parquet and source-offline cold recovery. Hour-to-day retained
folds reuse the persisted temporal facts. Epoch parsing and new timestamp version
selection remain unsupported on remote backends.

### String time parsing and multi-unit buckets

A time dimension authored with an explicit parser (`ms.strptime(...)`) executes on
the source for DuckDB, SQLite, MySQL, PostgreSQL, ClickHouse and Trino, including
composite hour-prefix axes. Source cells are not scanned for format validity before
the requested query; backend parsing may produce NULL or raise an error.
PostgreSQL's `TO_TIMESTAMP`
is lenient toward format-mismatched text. A well-formed cell that its format
misreads can produce a wrong instant there. Trino accepts `%f` with `date_parse`'s native
millisecond result precision; a six-digit fraction can lose its final three digits.

A multi-unit bucket (`mv.grain(unit, count=...)` with `count > 1`) is anchored on
the civil midnight of its own day, and only counts whose width divides one civil
day are admitted; `mv.grain("hour", count=7)` therefore fails rather than picking
an arbitrary origin. Because the anchor is a civil boundary, a six-hour bucket
spanning a spring-forward gap is five hours and one spanning a fall-back gap is
seven, while the DST day itself still starts at local midnight.

```python
import marivo.analysis as mv
import marivo.semantic as ms

orders_by_hour = (
    session.observe(
        ms.ref.metric("sales.revenue"),
        time_scope=mv.time_scope(start="2026-07-01", end="2026-07-03"),
    )
    .with_time_axis(ms.ref.time_dimension("sales.orders.order_time"), grain=mv.grain("hour"))
    .aggregate()
    .execute()
)
orders_by_hour.rollup(grain=mv.grain("day")).execute().show()
```

Actual adapter submissions own SQL diagnostics, with source/local domain, role
and submitted/succeeded/failed status. Compilation alone records no submitted SQL.
Driver-internal connection setup and transaction protocol traffic outside the
observed submission boundary are not claimed as captured queries.

### PostgreSQL scalar Metrics

PostgreSQL Group A accepts a single datasource and a single unversioned table,
with direct-column `sum`, `count`, `min` or `max` Metrics. You can select Population
membership, scope observations by native dates, add dimensions, aggregate Entity
rows, filter, project Metrics, rank deterministically and select Top-N. The entire
dependency graph must be supported, including Metrics removed by projection.

For example, with a sum Metric `sales.revenue` and a direct dimension
`sales.orders.channel` authored on the same PostgreSQL table:

```python
revenue = ms.ref.metric("sales.revenue")
by_channel = session.observe(
    revenue,
    time_scope=mv.time_scope(start="2026-07-01", end="2026-08-01"),
).with_dimensions(ms.ref.dimension("sales.orders.channel")).aggregate()
top_channels = by_channel.rank(by_channel.fields.metric(revenue)).limit(5).execute()
top_channels.show()
```

All required source columns must use Boolean, string, signed integers, float32,
float64, date, timestamp/timestamptz (precision 0–6) or Decimal types. PostgreSQL CHAR is rejected
because its trailing-space semantics differ from string; text/varchar remain supported. Decimal precision is at most 38,
with scale from zero to precision; generic Decimal declarations also undergo
physical metadata validation. String time parsing,
composed Metrics and private-state methods are outside this subset.

Use a read-only PostgreSQL account without write, CREATE or TEMP privileges.
Queries stream through an owned server-side cursor; no temporary tables, uploads
or UDFs are created. Validation and result queries may observe different source
states. Failures preserve their original error and never publish partial output.
Retained results use the existing reader and are not imported into PostgreSQL.


### MySQL and SQLite scalar Metrics

The Group A workflow above also applies to a single unversioned MySQL or SQLite
table: direct-column `sum/count/min/max`, Population, date-scoped observation,
dimensions, aggregation, filters, projection, deterministic rank and Top-N.
For example, the same authored `sales.revenue` and channel dimension use:

```python
revenue = ms.ref.metric("sales.revenue")
by_channel = session.observe(revenue).with_dimensions(
    ms.ref.dimension("sales.orders.channel")
).aggregate()
by_channel.rank(by_channel.fields.metric(revenue)).limit(5).execute().show()
```

MySQL admits tables and views with a SELECT-only account. Inputs include signed and unsigned
integers, float32/64, native DATE, `utf8mb4_0900_bin` VARCHAR/TEXT and explicit
Decimal precision up to 38. Explicit Boolean bindings accept TINYINT(1) only after
necessary-column 0/1/NULL checks; integer bindings remain integers. DATETIME(0–6)
and TIMESTAMP(0–6) preserve microseconds; TIMESTAMP requires an observed session time_zone of UTC or +00:00; other aliases remain unqualified.
CHAR, BIT, ENUM/SET, nested values and generic Decimal sources are not admitted.
Zero/invalid dates and timestamps fail before publication. Integer SUM is decoded
exactly from Decimal; the current result is int64, so values beyond its range fail.
Floating SUM overflow raises the original database exception.

SQLite accepts persistent ordinary main-database tables and views. INTEGER/INT/BIGINT,
TINYINT/SMALLINT/MEDIUMINT/INT2/INT8 map to int64; REAL/DOUBLE/DOUBLE PRECISION/FLOAT
to float64; TEXT/CLOB/CHAR/VARCHAR (including declared lengths) to string with
BINARY collation and actual text storage. DATE requires valid canonical YYYY-MM-DD
text. BOOL/BOOLEAN requires integer 0/1/NULL. DATETIME/TIMESTAMP requires fixed
`YYYY-MM-DD HH:MM:SS.ffffff` civil text, valid Gregorian years 0001–9999, without
an offset. Necessary-column storage checks run even when output is empty.
Unsigned, Decimal, native aware SQLite storage, virtual and attached tables remain excluded.
SQLite stores inserted NaN as NULL; that distinction cannot be recovered.
Native integer SUM overflow remains an error.

Ordinary timestamps support exact transport, grouping, sorting and typed predicates.
The native timestamp extension above owns temporal method admission; a declaration
alone does not establish a naive timestamp's read-timezone authority.
UInt64 identities, min/max and transport preserve the full unsigned range through
Arrow, Parquet and cold reads without floating or signed conversion.

Both adapters preserve typed composite identities and read driver batches without
an intermediate pandas collection. MySQL unbuffered cursor close may drain
unread responses; no hard cancellation deadline or memory bound is promised.
SQLite steps its native cursor incrementally; sorting and aggregation may still
materialize inside the engine. Batches limit rows, not bytes, and each cell is
decoded in full. SQLite execution is query-only. Output reads may see
different states; publication remains atomic. Retained results stay in Parquet
and use the existing native reader, without upload to either source. The relational/native-date extension above adds individually qualified methods.
Sampling and source-private advanced methods remain outside this subset.

### Trino scalar Metrics

Trino Group A supports one datasource and one unversioned ordinary relation —
table or view — with direct-column `sum`, `count`, `min` and `max`, Population
filtering, native-date scopes, same-Entity dimensions, aggregation, projection,
rank and limit. Use the existing catalog/schema/table declaration; both tuple and
dotted catalog/schema overrides are resolved consistently for metadata and
executed SQL. The connector name and relation form are observation receipts, not
gates: any connector's ordinary relations enter, and only `$`-suffixed internal
tables are rejected.

Declared physical inputs are signed integers, float32/64,
VARCHAR, BOOLEAN, timestamp(0–6) without time zone, DATE and explicit Decimal
precision/scale up to 38. The observed Iceberg connector exposes timestamp DDL
with precision 0 or 3 as timestamp(6); bindings must match this observed precision. CHAR, generic Decimal source declarations, timezone-bearing
timestamps, precision above microseconds and nested values
are excluded. Declared floating columns must contain finite values or
NULL; source checks reject NaN/infinity even for empty output, and non-finite
aggregate results fail before publication. Decimal and integer identities retain
exact values. Ranking preserves explicit NULL order and deterministic ties.

Use a read-only identity with access to connector and table metadata. Ordinary
Ibis compilation feeds incremental driver page reads; internal identity structs
are reconstructed from typed scalar columns. Batches are not byte or memory
limits. Driver/server limits remain external. Active cursors are owned before
submission; cancellation and close failures report unknown remote status without
blocking safe local recovery. Validation and output can observe different source
states. Sampling, retained imports and source-private advanced methods remain unavailable;
the relational/native-date extension above adds individually qualified methods.

The scalar workflow example above also applies to an authored Trino Metric.

### ClickHouse scalar Metrics

ClickHouse Group A admits one datasource and one unversioned ordinary relation —
table or view — under any engine: direct-column sum/count/min/max, Population
filters, native-date scopes, same-Entity dimensions, aggregation, projection,
deterministic rank and limit. Distributed and multi-shard relations are accepted,
as are unstable reads: engines whose reads depend on background merge state (for
example ReplacingMergeTree) can return different rows between runs as merges
progress; replay of a committed snapshot is unaffected. Sampling, retained import
and source-private advanced methods remain unavailable. The relational/native-date
extension owns additional method admission.

Physical inputs include Int8/16/32/64, UInt8/16/32/64, Bool, Float32/64, String,
Date and explicit Decimal precision up to 38, with legal Nullable wrappers.
LowCardinality(String) and LowCardinality(Nullable(String)) retain string semantics.
DateTime('UTC') and DateTime with verified UTC engine timezone preserve seconds.
DateTime64 through microseconds and aware non-UTC bindings are admitted by the
native timestamp extension. FixedString, Date32, Int128/256, UInt128/256, Enum
and nested values remain excluded. Engine form is not restricted by this
scalar-type extension.

Use a SELECT-only account configured with effective `join_use_nulls=1`.
Metadata, required assertions and output run separately; empty output never
bypasses validation. Declared floating values must be finite or NULL. Exact
integer/Decimal sums widen internally to Decimal256 before checked output
conversion; overflow and non-finite output fail without publication.

Native row streams preserve Decimal and typed Entity identities without pandas
or raw source transfer to another engine. Each response is owned and closed;
driver close can drain unread data, so cancellation has no hard latency promise.
Connection close does not prove remote termination. Unknown remote status does
not prevent safe local recovery; partial output is never published. No shared
snapshot, execution budget, upload, temporary object or implicit retry is added.
Batch size is transport configuration, not a result cap.

MySQL/SQLite preview and sample preserve large nullable integers without an
intermediate float64 conversion.


Native timestamp conversion uses the declared authority and runtime ZoneInfo.
Analysis does not scan source rows for ambiguous wall times, malformed parsed
cells, or engine/runtime timezone-rule disagreements. Backend conversion errors
still surface during the requested query; temporal provenance remains in the Artifact.


### Complete members and typed attributes

Member identity includes the complete declared key, including composite keys.
Root membership does not deduplicate rows or choose a latest available version.
For a versioned customer Entity, select membership and attribute versions
independently:

```python
from datetime import datetime, timezone

anchor = datetime(2026, 8, 1, tzinfo=timezone.utc)
customers = session.members(ms.ref.entity("sales.customer"), at=anchor)
region = customers.read(ms.ref.dimension("sales.customer.region"), at=anchor)
# A declared @ms.measure row expression uses the same read entry point:
score = customers.read(ms.ref.measure("sales.customer.score"), at=anchor)
assert isinstance(region, mv.LogicalCategoryRelation)
selected = region.where(region.value.eq("west")).members()
selected.execute().show()
```

`at=scope.before_end` means immediately before the exact end, without subtracting
a timestamp tick. An absent exact snapshot yields no represented members; it
never carries an older row forward. Unversioned Entities omit `at`.

`read` returns a Numeric relation for a Measure, a Category or Boolean relation
for a Dimension, and a Temporal relation for a TimeDimension. Integer indicators
remain categorical. Native dates stay dates; aware timestamps retain their
physical precision and timezone. This slice supports direct columns and bound
row-expression Measures on
DuckDB tables/Parquet; unsupported parsing and naive timestamp conversion reject.
Use an explicit `via=relationship` for another owner's single-valued attribute.
Missing coverage and multiple matching rows reject; a represented null remains
Null. Inspect the structured repair instead of taking the first row or filling zero.

After execution, `.where(...).members()` uses retained values and complete
Subject keys. It supports fixed continuation after the source is offline, but
cannot introduce a new attribute read. Recover with `session.artifact(ref)` and
inspect `.contract()` for the actual result's available operations. Artifacts
from an earlier frozen-definition contract are rejected rather than migrated.

## Group coordinates and current rows

Use complete retained axes or an explicitly corresponding category relation.
The original Metric merges its components, while `summarize` creates a new
statistic over the current finished values:

```python
all_members = session.members(ms.ref.entity("sales.customer"))
all_regions = all_members.read(ms.ref.dimension("sales.customer.region"))
members = all_regions.where(all_regions.value.eq("east")).members()
region = members.read(ms.ref.dimension("sales.customer.region"))
values = members.observe(
    ms.ref.metric("sales.revenue"),
    during=mv.time_scope(start="2026-08-01", end="2026-09-01"),
    via=ms.ref.relationship("sales.order_buyer"),
)
targets = all_regions.group_by()
original = values.group_by(region, groups=targets).rollup().execute()
row_mean = values.group_by(region, groups=targets).summarize(mv.mean()).execute()
total_row_mean = row_mean.rollup().execute()
selected_regions = all_regions.where(all_regions.value.eq("east"))
category_counts = selected_regions.group_by(groups=targets).summarize(mv.count()).execute()
fixed_targets = selected_regions.group_by(groups=targets).execute()
```

Pass `groups=all_regions.group_by()` to preserve explicit empty target groups. Fixed
continuations need fixed classifications and targets too. Use
`mv.count_defined()` to count only Defined Cells; `count()` includes all Cells.
Empty mean/min/max return Undefined but retain valid merge state. A mean over
finished AOV rows can be `50.5` while the original component rollup is `200/101`.
`group_by(*keys).rollup()` keeps the named axes; `rollup()` removes all axes.
Time-grid coarsening is not part of this qualification.

A selected category keeps its classification axis when grouped without keys.
Materializing `fixed_targets` above retains east, south and west, including empty
groups, for later fixed continuations. An exactly corresponding numeric predicate
may use another fact source; both source bindings are retained by the graph.

On a materialized grouped numeric result, `summarize` preserves the group axes
and uses the materialized group rows: count is one per existing group. It does
not restore pre-group members. Use original `rollup()` to merge Metric components.
