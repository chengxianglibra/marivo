title: Evidence and recovery
description: Store 10 terminal publication and the R2.6 reading boundary.

Store 10 saves final output under `.marivo/analysis/generations/v10/`.
A single SQLite transaction publishes the output manifest, receipts, Findings,
Evidence and Run success after the Parquet files are durable. Failed invocations
publish no partial Artifact. Recovery reconciles the original Run and its exact
resource journal without replaying computation.

## Execute and inspect the Run

Given a resolved `revenue` Metric and a Session:

```python
query = session.observe({"revenue": revenue})
artifact = query.execute()
print(artifact.id)
print(artifact)
for run in session.runs(limit=5).items:
    run.show()
```

Each execute reevaluates the Query and creates a new Run and Artifact. The
Artifact contains only committed identity and metadata; it has no `contract()`
or DSL continuation. Source-independent constants also use this publication path.

## Saved facts and reading boundary

Ordinary observations produce no Findings. Evidence records only actual source
reads and checks, including the read scope; an omitted period explicitly means
no additional time constraint. These records do not certify source completeness,
cross-source snapshots, freshness or causal conclusions.

The saved schema describes complete keys, named nullable values, explicit presence,
types and units. Necessary output attachments retain calendar bounds in UTC, with
the selected calendar timezone saved in both schemas. Read-scope summaries retain
nested Boolean grouping. The Store
saves no semantic definitions, graph, formulas, hidden aggregation components,
calculation fingerprints or continuation.

R2.5 returns a committed Artifact identity. `session.artifact(id)`, `show()`,
`to_pandas()`, `findings()` and `evidence_digest()` report the R2.6 reading gap.
Public cold opening and bounded reading are not yet delivered. Retain the exact ID.

Earlier Stores and graph/continuation formats are rejected without rewriting or
migration. Changing a Session name cannot bypass the generation restriction;
create a new-format Store in a fresh project and rerun the analysis script.
Same-generation Session resume preserves identity and Run history.

Start discovery with `marivo.help("analysis")`.
