分别建模来源编码、业务时间角色和观察范围与粒度。民用 `DATE` 表示一个日历日；带时区的时间戳标识一个时刻；`TimeScope` 捕获有限的左闭右开区间 `[start, end)`。解析器时区解释来源值，Session 时区确定报告边界。

声明片段假定语义模型已导入 `marivo.semantic as ms`，并已定义引用的 Entity 和字段。不同片段展示不同来源编码的用法。

## Time dimension：时间维度

Time dimension 声明观察、窗口和日历使用的时间角色。将普通 Dimension 命名为 `date` 不会使其成为时间维度。

| 参数 | 必填 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `name` | 是 | — | 语义名称，在所属范围内唯一。 |
| `entity` | 是 | — | 所属 Entity，确定字段对应的来源行粒度。 |
| `column` | 是 | — | Entity 来源暴露的物理列名，可以与语义名称不同。 |
| `sample_interval` | 否 | `None` | 规范的正数日内采样间隔 `(count, "minute" 或 "hour")`，时长小于一天且能整除一个标准日，并且来源编码可表达该间隔；DATE 字段不能提供日内样本。 |
| `parse` | 否 | `None` | 来源编码解析器；`None` 使用原生时间类型，编码字符串或整数须显式解析。 |



```python
order_date = ms.time_dimension_column(
    name="order_date", entity=orders, column="order_date", parse=ms.date(timezone="UTC")
)
```

物理列使用 `ms.time_dimension_column`，派生字段使用 `@ms.time_dimension`。原生日期和带时区时间戳无需解析器；编码字符串或整数使用 `ms.strptime(...)`，只有小时的字段使用 `ms.hour_prefix(...)`。DATE、无时区时间戳和编码时间必须在解析器或 Datasource `wall_clock_timezone` 上声明源时区；两者都缺失时在读取业务数据前拒绝。原生带时区时间戳忽略 Datasource 默认值。源规约通过 `time=field` 或继承 Entity 的可选 `default_time` 固定贡献时间。范围合计使用 `where=scope`，时间分组使用 `by=(scope.by(grain),)`。财务期间参见[业务日历](#业务日历与节假日)。

`sample_interval` 描述来源采样节拍，不会将时间戳截断或分桶。所有 TimeField 样本规约均允许缺点；已表示样本上的 NULL 遵循规约自身策略，声明节拍不代表来源完整。

### 原生日期：`ms.date`

`ms.date(timezone="UTC")` 声明原生 DATE 的业务日时区。省略时使用 Datasource
`wall_clock_timezone`，省略 `parse` 时也一样。时区统一接受 IANA 名和固定偏移量。
投影保持 DATE 标签。时间成员判定和报告分桶按源业务日的午夜起点归属整行，因此支持源时区与
报告时区不同，但不能据此重建另一时区自然日内的事件明细汇总。

## 派生时间字段：`ms.time_dimension`

当时间字段是 Entity 表达式时，使用 `@ms.time_dimension`。它接受上文介绍的 `entity`、`parse` 和 `sample_interval` 参数。默认使用函数名，也可通过 `name=` 指定名称。

## 原生时间戳：`ms.timestamp`

| 参数 | 必填 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `timezone` | 否 | `None` | 无时区时间戳的来源时区；`None` 使用 Datasource `wall_clock_timezone`，已有时区的时间戳拒绝任何解析器时区。 |


```python
created_at = ms.time_dimension_column(
    name="created_at", entity=orders, column="created_at",
    parse=ms.timestamp(timezone="Asia/Shanghai"),
)
```

此示例假定来源是上海本地的无时区时间戳。已有时区的来源值已标识一个时刻，因此省略解析器时区。解析只作用于 TimeDimension 投影，不会改写 Entity 主键。单独的无时区本地时钟无法区分回拨时重复时刻对应的两个瞬间；若这一区分重要，应保留带偏移量或 UTC 的来源值，或使用其他身份字段。

## 日期与时间编码：`ms.strptime`

| 参数 | 必填 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `format` | 是 | — | Python `strptime` 来源编码。有序格式声明规范的合法值；其他格式保留原生解析。 |
| `timezone` | 否 | `None` | 纯日期业务日和带时间值的来源时区；省略时使用 Datasource `wall_clock_timezone`。 |


```python
business_date = ms.time_dimension_column(
    name="business_date", entity=orders, column="date_key",
    parse=ms.strptime("%Y%m%d"),
)
```

`%Y%m%d` 声明 `20260801` 这样的八位编码，Python `%M` 表示分钟。有序格式 `%Y%m%d`、`%Y-%m-%d`、`%Y%m%d%H`、`%Y-%m-%d %H`、`%Y%m%d%H%M`、`%Y-%m-%d %H:%M`、`%Y%m%d%H%M%S` 和 `%Y-%m-%d %H:%M:%S` 要求合法、固定宽度、补零且分隔符完全一致的日期或时间。整数支持无分隔符格式；物理字符串比较顺序必须与时间顺序一致。`2026081` 这类缩短编码和不存在的日期违反声明，即使原生解析器能接受。无需 `canonical` 开关，也不自动扫描数据。

符合条件的物理列范围直接比较原始字段和源时区下的同类型常量。上海业务日范围 `[2026-10-28,2026-10-29)` 在 `%Y%m%d` 字段上编译为 `log_date >= '20261028' AND log_date < '20261029'`。边界向上对齐到首个可表示刻度：小时编码筛选 `[10:30,12:30)` 时使用 `[11:00,13:00)`。原生 DATE 和时间戳使用相同的范围规则，保留实际类型和精度。UTC、固定偏移量可以直接换算；具名时区要求端点通过资格检查，避开 gap/fold 切换。MySQL/MariaDB 具名时区改写使用共同验证范围 1971–2037。派生表达式与其他格式保留原生解析。

命名时区的原始范围优化使用宿主时区数据库。所选日期的规则必须与源后端的时区数据库保持一致；Marivo 不会在应用优化前探测两者的规则差异。

SQL NULL 保持 NULL，不归属任何期间。输出投影、日历分桶和未通过资格检查的端点保留原生解析及 gap/fold 解释。DuckDB、Trino、ClickHouse 和 MySQL/MariaDB 将解析器拒绝的数据变为 NULL；PostgreSQL 原生 `to_timestamp` 可能使查询报错。有序格式契约以外的原生接受规则可能因后端而异。没有 `on_error`、trim、格式猜测、重试、分区枚举或验证查询。格式、时区、类型与能力错误仍报错。Trino TRY 可捕获部分输入表达式错误，其他后端可能传播错误。NULL 仅用于属性控制时间时保留事实及 NULL 标签。直接谓词为下推提供条件；实际索引使用和分区裁剪取决于后端与表布局。

ClickHouse 22.3 支持上述有序格式的投影和日历分桶：日期保留 `Date32`，时间保留 `DateTime64`。其他格式要求 ClickHouse 23.3 或更新版本。需要不可用解析器的查询会在业务查询提交前报错；可改用有序编码、通过数据源提供原生 `Date32`/`DateTime64` 列，或升级服务端。源时区声明及原生 gap/fold 行为仍然适用。

## 独立小时列：`ms.hour_prefix`

| 参数 | 必填 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `prefix` | 是 | — | 提供民用日期前缀的 TimeDimension 表达式。小时字段递归继承前缀字段的有效解析器或 Datasource 时区。 |

小时来源值使用 0 到 23 的整数或 `'00'` 到 `'23'` 的规范字符串。
小时 `24` 及其他不规范的非 NULL 值违反该声明；午夜应使用下一日期和小时 `0`。
SQL NULL 保留原生语义。Marivo 不为非法编码值增加源数据扫描或统一的解析报错策略。

```python
event_hour = ms.time_dimension_column(
    name="event_hour", entity=orders, column="hour",
    parse=ms.hour_prefix(business_date),
)
```

组合字段可以作为源归约的贡献时钟。**报表粒度不会替换指标时钟**：绑定 DATE 前缀的
指标仍然拒绝小时桶，TimeDimension 本身也不能直接作为普通分类传入 `by`。

已有 Session、完整日范围 `scope`、从 Catalog 取得的所属 Entity `entity`，以及
已声明 `hour_prefix` 的 TimeDimension `partition_hour` 时，可以显式按分区小时计数：

{/* example: partition-hour-observation */}

```python
import marivo.analysis as mv

partition_counts = session.observe(
    {"count": entity.count(time=partition_hour)},
    by=(scope.by(mv.grain("hour")),),
).compute()
```

其他指标显式改绑时钟时，应保留原归约、过滤条件与公式分支。NULL 小时不归属任何
时间范围；改用提交或事件时间可能选中不同记录。日总量与小时合计对账要求小时合法且
非空、过滤条件相同、输入数据稳定，并使用源与报告业务时区一致的完整日范围。
替换已发布指标前先对账。若要保留原 DATE 时钟及全部选中记录，应另声明普通小时标签
Dimension，按日加标签分组，并保留 NULL 组。这是普通分类标签，不是小时 CalendarAxis。

同一源日期内的正向范围（如 `[03:00,04:00)`）在时区转换通过等价性检查时，
可以直接比较原始日期列和小时列。该优化适用于观察范围，以及直接使用或位于顶层
AND 中的必需 `event_hour` 显式边界比较，包括午夜起点。整日、跨日及单边范围可为
每个通过检查的端点增加原始日期列范围条件，同时保留精确的时间谓词；未通过检查的
端点保留通用路径。NULL 值及取反、组合后的布尔表达式保留原生语义。
是否发生分区裁剪需要检查后端物理计划，不能只根据 SQL 形态判断。

## 观察范围：`session.time_scope`

| 参数 | 必填 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `start` | 是 | — | 包含的起点，可用 ISO 日期/时间字符串、`date` 或带时区的 `datetime`。 |
| `end` | 是 | — | 不包含的终点，必须晚于 `start`；同样支持上述输入类型。 |


```python
# Continue in the quick-start analysis Session.
august = session.time_scope(start="2026-08-01", end="2026-09-01")
day = mv.grain("day")
```

Python 无时区 `datetime` 对象以及含糊或不存在的本地边界时间会被拒绝。民用边界使用 `date`，精确的日内时刻使用带明确偏移量的 ISO 时间戳。

范围始终使用 Session 已保存的报告时区解释民用时间边界并进行日历分桶；带时区输入保留原有瞬间。需要其他普通报告时区时，创建对应时区的 Session；`time_scope` 不再接受时区覆盖参数。

## 日历粒度：`mv.grain`

| 参数 | 必填 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `unit` | 是 | — | 日历单位：second、minute、hour、day、week、month、quarter、year。 |
| `count` | 否 | `1` | 日内单位的规范正数宽度，时长小于一天且能整除一个标准日；日及更粗单位使用 `count=1`。 |

用 `by=(august.by(day),)` 观察按日分桶的结果。`scope.by(grain)` 返回 `CalendarAxis`，也可用于显式 Population 或偏移域。在日内粒度下，日历网格会跳过不存在的本地时间，并为重复的本地时间保留两个时刻。自然日和自然月是日历期间，因此夏令时切换前后的经过时长可能不同。DATE 时间角色要求贡献使用日或更粗粒度，并以业务午夜为起止边界。观察和比较示例见[时间序列与窗口](/zh-cn/docs/v0.6/analysis/time-series/)。

## 业务日历与节假日

节假日、调休、财务周期的权威来源和版本由 harness 或外部业务服务管理。日期、工作日状态和财务月 key 可以建模为普通 Entity、TimeDimension 和 Dimension；声明所需关系后，直接按业务维度汇总原始 Metric。

harness 负责选择准确范围和比较配对，通过 `session.time_scope(...)`、普通字段或成员筛选交给 Marivo。自然日历使用 `mv.grain(...)`。不连续工作日不能替换成一个包围区间；缺失状态不代表休息日。财务累计和节假日跨年对齐需要外部提供明确范围或映射。
