发布于 2026 年 11 月 3 日。Marivo 0.6.0 统一类型化语义输入、显式分析与不可变结果。
相对 0.5.x，本版本包含破坏性变更；请依据当前指南与原生 Help 更新集成。

## 重点功能

- 统一使用 `AnalysisFrame` 表示待执行表达式、完整内存数据与持久化结果。
  `compute()` 在内存中完成数据；`persist()` 提交该结果，供其他进程复用。
- 直接组合已解析的 Catalog 对象与类型化 Deferred 符号。加载器绑定完整依赖作用域；
  针对当前问题的 Metric 表达式可复用既有业务含义，无须另行发布定义。
- 原生日历轴、按日历粒度折叠的 Metric 和逐行 as-of 输入支持显式报表时间与版本匹配。
  数据源时区声明决定民用日期和时钟解释，涵盖夏令时边界。
- Frame 保留语义列血缘、数值解释、比较与对齐元数据。持久化的 `source_reads` 记录
  实际消费的数据源读取；`method_facts` 保留受支持的贡献分解说明。

## 行为变更

- Frame 方法统一负责固定数据组合、比较、当前行统计与贡献分析，包括满足条件路径上的
  固定状态和源数据 Shapley、精确的比率与结构效应分解。固定数据操作与重新打开结果
  不会隐式重读数据源或重跑生产过程。
- 同时保存 `session_id` 和 `artifact_id`，通过 `mv.session.resume()` 与
  `session.persisted_frame()` 精确重开数据。`session.persisted_frames()` 提供有界发现，
  `persist(description=...)` 可记录用途。命名 Session 可通过 `get_or_create()` 重复获取。
- `schema`、`read_page()` 和 `read_periods()` 提供有界、类型化读取。
  `to_pandas()` 返回隔离的扁平表，包含可读列名和显式存在性列，`attrs` 为空。
  单位、血缘与冻结时间解释应从 Frame 获取。
- 数据源声明与发现使用唯一的规范入口，并支持 HTTP JSON 数据源。在线语义校验检查
  物理合约；限定范围的数据源检查仍需显式执行。常规分析信任声明的身份与关系基数。
- 算术、精度与溢出遵循实际后端或本地计算内核。DuckDB 固定为 1.5.3，MySQL 读取改用
  PyMySQL。遥测仅接受 `on` 与 `off`，移除原有 `full` 模式。
- 移除旧分析、Artifact 和 Run API 及兼容别名。当前 Store 代际为 28，Frame 输出格式为 17。
  旧代际单独保留，不自动迁移；请使用兼容环境重开，或通过原版本导出数据。

## 修复

- 修正受支持后端的日历分桶、民用 DATE 键、原始时间范围裁剪与夏令时跳过或重复小时处理。
- ClickHouse 22.3 支持有序规范格式的时间解析，保留 Date32 与 DateTime64 的宽范围载体；
  不支持的显式解析格式在提交查询前失败。同时修复常量外连接与旧版本日期边界兼容性。
- DuckDB、Trino、ClickHouse 和 MySQL/MariaDB 对解析失败的数据返回 NULL。
  PostgreSQL 保留原生 `to_timestamp` 行为，可能使查询失败；原生格式、时区与精度限制仍适用。
- 修正固定轴类型解析、稀疏时间样本覆盖、可空身份、全 NULL JSON 列，以及数值除法和分位数行为。
- 稳定跨 Python 版本的语义表达式身份哈希，并在计算、持久化与恢复过程中保留冻结元数据。

## 文档

- 按安装、建模、分析和结果复用重组中英文指南，保持可执行示例一致。
- 统一 Python 与 CLI Help 导航、结果事实和结构化修复指引。静态 API 发现从 `marivo.help()` 开始。
- 新增 v0.6 文档快照，保留 v0.5 文档供仍使用旧合约的集成查阅。

## 内部改进

- 减少重复编译与求值，合并兼容的数据源观察，并将满足条件的聚合和日历计算下推到原生查询。
- 统一 lint、类型检查、本地测试、Runtime、包内容、安装后场景与 API 文档发布门禁。
  PyPI 通过 GitHub Actions Trusted Publishing 从发布标签对应的提交构建并发布。
