使用相关语义定义已确认且可加载的项目，不需要指定 Python 算子或固定检查顺序。

## 向 Agent 提供明确范围的问题

> 使用 `marivo-analysis`解释已确认 `sales.revenue`在 2026 年 7 月与 8 月间的变化。
> 比较同一已完成订单范围，先看地区，最后报告结论、关键证据与限制。

说明决策、有意义的基准、纳入和排除群体及初始重点。定义缺失时，先解决最小语义缺口，
不要静默替换 Metric。

## 理解 Agent 的工作

Agent 验证所选环境、读取已有 catalog 对象，在一个 Session 中构造明确分析，
并在下一决策需要结果时执行。通过 `.show()`读取已提交行，通过 `.contract()`跟随合法
后续操作，对不熟悉的调用使用 focused Help。

可复用定义缺失时交给 `marivo-semantic`，认证修改的根，再回到原问题。
终端 raw SQL 可回答已披露临时口径的问题，但其行不能进入 typed analysis。
Readiness、连接和执行成功证明不同事实。

## 审阅回答

确认 Metric 含义、群体、时期、比较方向与拆分。检查重要主张具有结果或 Evidence 支持，
并明确覆盖、缺失、删失和方法限制。代数分配与关联本身不证明原因。

仅为仍有意义的问题继续。历史问题复用确切保存结果，新鲜度重要时执行当前来源。
