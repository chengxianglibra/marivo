## 开始分析

使用项目中已经确认业务含义、并且当前目录可以加载的指标。如果指标缺失或口径仍有
疑问，类型化分析会停止；智能体可以使用有界、只读的 `md.raw_sql(...)` 和明确披露的
临时口径继续分析，但必须在收尾保留该缺口并提交审批。

你不需要编写 Python、选择算子或安排检查步骤。只要说明问题、指标、比较范围，以及希望
优先检查的因素：

> 使用 `marivo-analysis`，分析 2026 年第四季度收入相比 2025 年同期下降的原因。
> 使用已经确认的 `sales.revenue` 指标，按月比较，并优先检查地区差异。
> 最后给出结论、关键证据和限制。

## Marivo 会处理什么

智能体会读取相关语义定义，解析并验证实时语义输入，在同一个分析会话中
执行合适的类型化分析，并保留支持结论的结果和证据。语义缺口不允许智能体在分析过程中
修改口径。终端原始 SQL 可以提供临时答案，但必须和规范 Marivo 证据分开；智能体
在收尾提出最小语义修订，并且只在用户批准后进入 `marivo-semantic`。

目录导航返回当前类型化条目；符合条件的语义和分析运行时调用
可以直接接收它，配置与 recovery 仍可使用精确引用。Marivo 会在规划、证据、
持久化或重放之前把两种输入都归一化为引用。

智能体先使用宿主提供的项目解释器运行一次 `marivo doctor`，验证实时环境。
进入分析后，智能体优先使用手中已有的公开对象：用 `.show()` 读取当前状态，在不熟悉的组合
操作前读取 `.contract()`；只有当对象契约不足，或第一次使用不熟悉的能力时，才查询专项
`marivo.help(...)`（先 `import marivo`）。发生失败后，智能体按照结构化修复指引继续。
专项帮助并不是每次 API 调用的前置步骤。

类型化边界（`session.observe` 入、`frame.to_pandas()` / `md.raw_sql` 出）确保自定义分析
不会断开证据链。
`RawSqlResult.shape` 和 `.row_count` 只表示有界返回行；该结果没有 `.contract()`，也不能
回到类型化分析。Marivo 目前不提供类型化 regression；需要回归时仍使用显式的终端
custom 分析。

这些执行细节由实时帮助、frames 和结构化错误负责，不需要写进你的提示词。

## 继续之前需要检查什么

接受结论或要求进一步调查前，请确认：

- 指标含义与你关心的业务结果一致；
- 时间范围和分析群体（包括排除范围）正确；
- 比较方式和优先检查的因素具有业务意义；
- 每项重要判断都有 Marivo 结果或证据支持；
- 限制、质量问题和未解决的问题都已明确说明；
- 智能体没有悄悄修改语义层。
