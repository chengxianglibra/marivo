## 先检查定义，再检查数据

编辑模型后，请在项目根目录运行检查。以下示例使用[本地 Python 教程](/zh-cn/docs/latest/start/python/)
中的 `sales.orders.amount` measure：

```python
import marivo.semantic as ms

catalog = ms.load()
amount_entry = catalog.get("measure:sales.orders.amount")
assert amount_entry.kind == "measure"
amount = amount_entry.value
catalog.readiness(refs=[amount]).show()
catalog.validate([amount_entry]).show()
```

`ms.load()` 检查模型声明、引用、依赖循环和表达式契约。`catalog.readiness(...)`
接受所选定义（包括声明式 Measure 和 Metric），检查其物理依赖和已认证的时间产物。这两步都不会打开数据源连接。

`catalog.validate(...)` 会连接所选对象的完整物理依赖，使用实际 Entity 输出
结构检查字段绑定、数值类型、时间解析器和时区契约。报告包含物理类型、受影响字段、
声明位置与修复方法。Preview 和 analysis 在执行查询前复用相同字段校验。
HTTP JSON 在源准备阶段获取响应行，用于推断物理类型。
校验通过不代表所有分析方法都可执行；使用时仍会重新检查后续来源变化。

例如，原生带时区时间戳（包括 ClickHouse `DateTime` 和 `DateTime64`）会拒绝
`ms.timestamp(timezone="UTC")`，即使来源本身就是 UTC；应改用 `ms.timestamp()`。
字符串使用 `ms.strptime(..., timezone="UTC")` 解析时，仍可声明来源时区。

若要查看当前来源数据，请用显式有界范围调用 `catalog.preview(...)`。
普通 Metric 预览支持五类 SQL 后端，在读取业务数据前复用 datasource 分区预检。
每个 Entity 最多贡献 `min(scope.max_rows, 10_000)` 行输出，这些无序子集不能
用于估计全量指标。通过 `preview.coverage.entity_rows`、`entity_row_limits`
和 `execution_limits` 查看实际输入及原生超时支持。输出上限不限制物理扫描；
预览没有请求扫描行数或字节数上限，扫描统计保持 unknown。
`catalog.validate(...)` 默认检查物理契约；只有显式传入检查规则及其有界范围时，才会读取业务数据。`checks` 为空时必须省略 `scope`。检查规则使用 `ms.ref` 或条目的 `.ref` 原生查找符号构造，不接受闭合的 `.value` 表达式。
[加载与检查](/zh-cn/docs/latest/modeling/semantic-layer/#加载与检查)一节提供完整的预览和在线校验示例。

## 不可用的物理类型与字符串计数

`char(1)` 等不可用的物理类型会使 schema 检查保持失败。通过 schema 检查的
`observed["unavailable_columns"]` 查看列名与原始类型，通过
`observed["unavailable_field_refs"]` 查看跳过类型检查的字段。直接映射的 Entity
仍会检查其他字段；表达式 Entity 需要完整的输入 schema。
请提供受支持的物理类型，或用 `md.table(columns=...)` 显式选择受支持的列，再次校验。

字符串标识应使用 `ms.dimension_column(...)` 声明为 Dimension；通过闭合字段的
`dimension.count_distinct()` 统计不同值的数量。字符串列不能绑定为要求
numeric/duration 类型的 Measure。
