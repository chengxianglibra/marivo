语义层用 Python 声明数据源、实体、字段、关系和指标。下面的示例按文件和操作组织；快速开始中的六笔订单可作为本地数据。

## 连接与检查

先通过[本地教程](/zh-cn/docs/latest/start/python/)创建 `warehouse.duckdb` 与数据源声明。将下面保存为 `inspect_data.py`，从项目根运行。

### 确认访问与结构

```python
import marivo.datasource as md
import marivo.semantic as ms

warehouse = ms.ref.datasource("warehouse")
md.test(warehouse).show()
md.inspect(warehouse, md.table("orders"), workspace_dir=".").show()
```

表中包含 order_id、order_date、region、amount。接入自己的数据时，应向数据负责人确认主键与指标定义，不能仅凭样本值推断。

### 连接远程数据库

下面的声明配方需要真实服务和凭据。替换示例主机并设置命名环境变量，保存为 `models/datasources/lake.py`。

{/* example: trino-declaration */}

```python
# models/datasources/lake.py
import marivo.datasource as md

md.trino(
    name="lake",
    host="trino.example.internal",
    catalog="hive",
    user_env="TRINO_USER",
    auth_env="TRINO_AUTH",
)
```

凭据通过 `*_env` 引用环境变量，不写进模型文件。默认解析在通过连接验证后，可能将秘密明文缓存到 `~/.marivo/secrets.toml`。设置 `MARIVO_PERSIST_CREDENTIALS=0` 可关闭。

### 选择物理来源

实体可以引用受支持的表、Parquet、CSV 或 JSON。文件与 HTTP 的检查能力和数值分析有不同支持条件。参数化 JSON 用于声明与预览，不是已准入的数值 Session 来源路线。

只为未解决的编码问题读取有界样本。返回行数限制不等于扫描预算。原始 SQL 可以回答物理问题，但其结果是终端数据，不能进入类型化 Frame 分析。查询超时使用后端原生语义，不是整个调用的期限。

接下来[定义指标](/zh-cn/docs/latest/modeling/semantic-layer/#定义字段与指标)，并查询[来源限制](/zh-cn/docs/latest/reference/backends-and-limits/)。

## 定义字段与指标

先确认含义，再写公式。演示收入是六笔完成订单金额之和，单位 CNY，无退款。客单价应使用相同订单范围的收入和计数。

### 编写完整定义

先运行[快速开始](/zh-cn/docs/latest/start/python/)。下面在演示库中添加成本列，每笔成本设为金额的 60%，仅用于演示毛利计算。将代码保存为 `add_cost.py` 并运行。

{/* example: semantic-cost-data */}

```python
import duckdb

with duckdb.connect("warehouse.duckdb") as connection:
    connection.execute("ALTER TABLE orders ADD COLUMN IF NOT EXISTS cost BIGINT")
    connection.execute("UPDATE orders SET cost = amount * 0.6")
```

然后用下面的模型替换 `models/semantic/sales/_domain.py`，不要另加一份同名定义。直接组合原生 typed field 符号；loader 在返回 Catalog 前绑定完整依赖范围。

{/* example: semantic-model */}

```python
import marivo.datasource as md
import marivo.semantic as ms

sales = ms.domain(name="sales", owner="Mina Zhang")
orders = ms.entity(
    name="orders",
    datasource=ms.ref.datasource("warehouse"),
    source=md.table("orders"),
    primary_key=["order_id"],
)
region = ms.dimension_column(name="region", entity=orders, column="region")
order_date = ms.time_dimension_column(
    name="order_date", entity=orders, column="order_date", is_default=True
)
amount = ms.measure_column(
    name="amount",
    entity=orders,
    column="amount",
    additivity=ms.additive_all(),
    unit="CNY",
)
cost = ms.measure_column(
    name="cost", entity=orders, column="cost", additivity=ms.additive_all(), unit="CNY"
)


@ms.dimension(entity=orders)
def normalized_region(rows):
    return ms.bind(region, rows).upper()




@ms.measure()
def margin():
    return amount - cost


@ms.metric()
def revenue():
    return amount.sum(time=order_date)


@ms.metric()
def average_order_value():
    return revenue / orders.count(time=order_date)
```

### 保持业务规则

单位描述数量，可加性说明允许沿哪些范围求和。逐行乘积不会自动获得求和许可；别名不会改名已发布定义；未知单位也不自动等同无量纲。

Measure 和 Metric 声明体不接收表参数，而是构造闭合表达式。实体与字段体保留受约束的 Ibis 写法。不要在指标声明中查询来源或执行任意 Python。

空输入求和为零，非空且全空值则未知。应在来源与模型中明确取消和退款规则，不能简单把未知值补零。

编辑后[检查模型](/zh-cn/docs/latest/modeling/semantic-layer/#加载与检查)。涉及其他实体属性时，阅读[关系与归属](/zh-cn/docs/latest/modeling/semantic-layer/#关系与归属)。

## 关系与归属

关系说明业务实体如何对应。应根据已知身份与粒度规则声明，不能仅因为列名相似就连接。

### 先明确连接粒度

考虑下面这组完整手算输入：

| 订单 | 客户 | 金额 |
| --- | --- | ---: |
| o1 | c1 | 100 |
| o2 | c1 | 200 |
| o3 | c2 | 500 |

c1、c2 分别属于 east、west，c3 没有订单。总收入 800，客户收入分别为 300、500，c3 没有观察贡献；但选定客户集合仍可以包含 c3。

### 让声明符合规则

先声明具有完整主键的订单和客户实体，再使用 `ms.relationship` 与 `ms.join_on` 声明有向关系。通过 `marivo.help("semantic.relationship.define")` 获取精确构造方式。身份是 (tenant, customer) 时必须包含两个部分，只用客户编号可能误连其他租户。

通过[模型检查](/zh-cn/docs/latest/modeling/semantic-layer/#加载与检查)中的关系匹配与基数检查核对来源。声明关系不证明当前来源完整。

### 决定多重归属如何贡献

若 c1 同时有 A、B 两个标签，将订单连接到两种标签会重复它的 300。把它计为总收入 600 就错了。先确定是存在性筛选、允许重叠的分组总额，还是有业务依据的分配。`mv.membership(...)` 描述明确的分组与分配规则，不能让任意连接自动可加。

按新属性统计客户时保留身份；先只投影属性再计数，得到的是分类数。接下来[选择分析对象](/zh-cn/docs/latest/analysis/dsl/#选择与筛选)。
以上关系的声明片段，放在同一模型加载范围内：

```python
# Declaration fragment: orders, customers, order_customer_id, and customer_id
# are captured Entity and Dimension refs in the same model.
orders_to_customers = ms.relationship(
    name="orders_to_customers",
    from_entity=orders,
    to_entity=customers,
    keys=[ms.join_on(order_customer_id, customer_id)],
)
```

## 加载与检查

使用[本地教程的模型](/zh-cn/docs/latest/start/python/)。在项目根的新脚本中运行下面代码，根据当前疑问选择检查。

### 先检查定义，再检查数据

{/* example: readiness-3 */}

```python
import marivo.semantic as ms

catalog = ms.load()
amount = catalog.fields.get("sales.orders.amount")
catalog.readiness(refs=[amount]).show()
```

{/* example: readiness-1 */}

```python
import marivo.datasource as md

preview = catalog.preview(
    catalog.metrics.get("sales.revenue"),
    scope=md.unpruned(max_rows=1000, timeout_seconds=30),
)
```

{/* example: readiness-2 */}

```python
amount = catalog.fields.get("sales.orders.amount")
health = catalog.source_health(
    [amount],
    checks=[ms.source_check.not_null(ms.ref.measure("sales.orders.amount"))],
    scope=md.unpruned(max_rows=1000, timeout_seconds=30),
)
health.show()
```

加载检查项目是否自洽。readiness 在不读业务数据的前提下检查所选物理依赖与必要时间产物。preview 读取有界范围，普通预览不改变 readiness。source health 默认检查连接与结构，只有显式要求时才检查数据预期。

连接检查失败时，先检查数据源路径与凭据，再重试。

[日历证书](/zh-cn/docs/latest/modeling/semantic-layer/#业务日历)缺失或截断，需要覆盖完整有限范围的时间预览。这些检查均不代表业务负责人认可收入口径，最后仍应运行实际观察。

## 业务日历

自然日与月符合业务时，直接使用[时间分析](/zh-cn/docs/latest/analysis/time-series/)中的普通粒度。本页演示如何创建自己的有限业务日历。

### 准备七天日历

使用[安装](/zh-cn/docs/latest/start/installation/)的环境。在独立 `calendar-demo` 项目中创建 `models/datasources/warehouse.py`，使用教程的 DuckDB 声明与本地路径 `warehouse.duckdb`。从新项目执行命令，使用已安装解释器的绝对路径。将下面保存为 `seed_calendar.py` 并运行，它只替换此演示的 calendar 表。

{/* example: calendar-seed */}

```python
from datetime import date, timedelta
import duckdb

with duckdb.connect("warehouse.duckdb") as connection:
    connection.execute(
        "CREATE OR REPLACE TABLE calendar (day DATE PRIMARY KEY, fiscal_week VARCHAR)"
    )
    connection.executemany(
        "INSERT INTO calendar VALUES (?, ?)",
        [(date(2026, 1, 1) + timedelta(days=i), "FY2026-W01") for i in range(7)],
    )
```

### 声明日期与期间

保存为 `models/semantic/sales/_domain.py`。这是独立项目的完整日历模型，在此独立项目中使用时替换原教程声明。演示周为 1 月 1 日至 8 日，不是 ISO 周，含起点不含终点。

{/* example: calendar-model */}

```python
from datetime import date
import marivo.datasource as md
import marivo.semantic as ms

ms.domain(name="sales", owner="Mina Zhang", default=True)
calendar_days = ms.entity(
    name="calendar",
    datasource=ms.ref.datasource("warehouse"),
    source=md.table("calendar"),
    primary_key=["day"],
)
day = ms.time_dimension_column(name="calendar_date", entity=calendar_days, column="day")
week = ms.dimension_column(
    name="fiscal_week", entity=calendar_days, column="fiscal_week"
)
ms.period_calendar(
    name="fiscal",
    date=day,
    boundary_timezone="UTC",
    coverage=(date(2026, 1, 1), date(2026, 1, 8)),
    levels={"week": week},
)
```

### 认证并读取

保存为 `check_calendar.py` 并运行。完整范围有七行，行数上限设为八，以免截断。

{/* example: calendar-read */}

```python
import marivo.datasource as md
import marivo.semantic as ms

catalog = ms.load(workspace_dir=".")
ref = ms.ref.period_calendar("sales.fiscal")
catalog.preview(ref, scope=md.unpruned(max_rows=8, timeout_seconds=30))
calendar = catalog.period_calendars.get("sales.fiscal")
period = calendar.period("week", "FY2026-W01")
assert period.kind == "calendar_period"
period.show()
```

预期期间是 FY2026-W01，覆盖七个日期。把 max_rows 临时改成 1 会导致认证无法覆盖完整范围；恢复为 8 后重试。失败或截断不会发布替代证书。

实际模型应提供经确认的所有业务期间和完整日期，不能靠相同标签推断边界。分析时使用 `calendar.grain("week")` 取得已认证粒度，而不是向普通粒度构造器传入猜测名称。

### 活动与工作日

活动期间用 `ms.temporal_set` 声明唯一发生项 ID、开始、结束和可选分类，并通过完整有界预览认证。日期边界需明确业务时区。同名节日分类不自动配对不同年份；通过 `marivo.help("semantic.temporal_set")` 查询精确声明。

工作日字段必须覆盖所有日期并考虑调休。缺日期或未知状态不等于休息日。不同组织或地区的日程应分开定义。

## 组合指标表达式

在字段与指标定义完成后，可以组合筛选、逐组计算与派生指标。下面接在本页扩展模型的末尾。

{/* example: semantic-composition */}

```python
# Expressions in the model above: amount, cost, order_date, region, and orders
# have been resolved; revenue is the published metric expression.
east_revenue = revenue.where(region == "east")
mean_regional_revenue = revenue.per(region).mean()


@ms.metric()
def gross_margin_rate():
    return (revenue - cost.sum(time=order_date)) / revenue
```

`east_revenue` 只计算 east 的贡献；`mean_regional_revenue` 是地区收入的均值；毛利率在相同时间口径下计算收入与成本。
