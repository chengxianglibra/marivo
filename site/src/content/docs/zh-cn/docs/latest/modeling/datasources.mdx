---
title: 数据源配置
description: 配置 DuckDB、PostgreSQL、MySQL、ClickHouse 和 Trino 数据源。
---

Marivo 提供五种数据源构造函数。将声明保存在 `models/datasources/` 下；loader 收集配置时不会打开连接。按后端选择构造函数，再从 Entity 引用其名称。远程示例是配置模板：测试前请替换主机和数据库，并设置所引用的环境变量。

每张表列出构造参数及其 Python 默认值。省略可选值时，由后端、Marivo 适配器或驱动采用默认行为。测试连接前，请设置所引用的环境变量。

| 后端 | 构造函数 | 用途 |
| --- | --- | --- |
| DuckDB | `md.duckdb` | 本地数据库与文件来源 |
| PostgreSQL | `md.postgres` | PostgreSQL |
| MySQL | `md.mysql` | MySQL |
| ClickHouse | `md.clickhouse` | ClickHouse |
| Trino | `md.trino` | 分布式 catalog |

`wall_clock_timezone` 是独立于连接选项存储的源声明。字段 parser 时区优先，`hour_prefix` 继承前缀字段的有效时区。它不影响物理瞬间，包括 MySQL TIMESTAMP 和 ClickHouse DateTime。无时区时间或业务日缺少声明时，应先补齐声明；连接、宿主机和报告时区都不补全它。Trino 使用私有 UTC 传输设置，没有公开 `timezone` 参数。

## DuckDB — `md.duckdb`

| 参数 | 必填 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `name` | 是 | — | 项目内全局唯一的小写 snake_case 数据源名称，用 `ms.ref.datasource(name)` 引用。 |
| `path` | 否 | `':memory:'` | DuckDB 数据库文件的路径。使用 `:memory:` 时，数据库仅在本次连接内存在。 |
| `read_only` | 否 | `False` | 为 True 时以原生只读模式打开 DuckDB 文件库。 |
| `secrets` | 否 | `()` | `md.s3_secret`、`md.http_bearer_secret` 或 `md.http_headers_secret` 的列表。 |
| `wall_clock_timezone` | 否 | `None` | 未单独声明时区的 naive timestamp、编码时钟和业务日使用的源时区；接受 IANA 名或固定偏移。 |
| `ai_context` | 否 | `None` | 可选 `ms.ai_context(...)` 业务上下文与使用约束。 |
| `extra` | 否 | `None` | 未在此列出的其他 JSON 可序列化 Ibis 连接参数。 |


```python
# models/datasources/warehouse.py
import marivo.datasource as md

md.duckdb(name="warehouse", path="warehouse.duckdb", read_only=False, wall_clock_timezone="UTC")
```

精确参考：`marivo.help("datasource.duckdb")`.

## 凭据与连接检查

凭据通过 `md.env("NAME")` 引用环境变量名；Marivo 不会推断变量名。`md.load().test(...)` 成功完成连接往返后，Marivo 可能将从环境变量解析的值以明文缓存到用户级 `~/.marivo/secrets.toml`。设置 `MARIVO_PERSIST_CREDENTIALS=0` 或 `CI` 环境变量非空时会关闭缓存。缓存文件权限限制为仅所有者可读写（`0600`），父目录权限为 `0700`，且 Marivo 不会将其写入 Git 仓库内。请勿将秘密值写入模型文件或 `extra`。

创建[教程数据库](/zh-cn/docs/latest/start/python/)后，从项目根运行：

```python
import marivo.datasource as md
import marivo.semantic as ms

warehouse = ms.ref.datasource("warehouse")
md.load().test(warehouse).show()
md.inspect(warehouse, md.table("orders"), workspace_dir=".").show()
```

## 连接与物理来源

`md.table(...)` 可在受支持的后端中选择表或视图。`md.parquet(...)` 和 `md.csv(...)` 描述由 DuckDB 读取的文件来源；`md.json(...)` 可描述文件或 HTTP 来源。这些都是来源描述符，不是新增的数据源类型。`md.inspect(...)` 读取物理元数据。若要采集行样本，请在 inspection 上调用 `inspection.sample(...)`，显式指定范围、`inspection.schema` 中的输出列以及正数 `max_rows` 和 `timeout_seconds`。后端不支持的原生超时请求可能会跳过；`max_rows` 限制返回行数，不限制扫描字节数。默认情况下，新采样的 profile 摘要值保留在当前进程中，但不会保留具名行。设置 `persist_values=True` 会提供有界具名行和 profile 值，并将它们以明文保存在项目状态中。即使匹配的快照已过期，默认仍会复用；使用 `refresh=True` 可重新读取。Analysis 支持 DuckDB 本地 GET JSON，以及在源定义中写入具体请求值的 HTTP(S) GET/POST JSON。每次计算复用一份响应，不自动翻页；未填入的来源参数会在获取数据前报错。参见[后端与方法限制](/zh-cn/docs/latest/reference/backends-and-limits/)，然后[定义 Entity](/zh-cn/docs/latest/modeling/semantic-layer/)。

HTTP JSON 中全部缺失或全为 null 的列保留 `null` 类型。未使用的列不会阻塞 Analysis、字段预览或按列采样；实际使用的输入仍须满足消费操作的类型要求，显式类型转换和空值判断遵循正常表达式规则。本地 JSON 保持 DuckDB 的原生类型推断。空记录数组可能因无法推断声明列类型而失败。

PostgreSQL、MySQL/MariaDB 和 Trino 的 CHAR/CHARACTER 列保留物理类型与长度，Entity/Dimension 验证将其映射为逻辑字符串；也支持表达式 Entity 输入与声明主键。该映射不增加 SQL cast、trim、补空格或排序规则模拟，读取、比较与分组遵循原生后端。CHAR 不能作为数值 Measure。

`md.time_range(...)` 的边界必须匹配检查得到的物理类型：aware timestamp 使用 aware datetime，naive timestamp 使用 naive datetime 或 date，DATE 只接受 date。两端必须保持相同类别和 awareness。不匹配会在取数前失败并报告 `query_executed=False`；`wall_clock_timezone` 不补全边界时区。

## DuckDB 凭据作用域

所有凭据字段只接受 `md.env("NAME")`，不接受字面字符串。S3 必须提供 region 和静态 key 引用；可选的 `session_token` 也使用 `md.env`。`endpoint`、`url_style`（`vhost` 或 `path`）和 `use_ssl` 是非机密选项，默认分别为 `s3.amazonaws.com`、`vhost`、`True`。列表支持多个作用域；bearer 与 headers 不能使用同一个 scope。

```python
import marivo.datasource as md

md.duckdb(name="lake", secrets=[
    md.s3_secret(scope="s3://analytics-lake/warehouse/", region="us-west-2",
                 key_id=md.env("LAKE_KEY_ID"), secret=md.env("LAKE_SECRET")),
    md.http_bearer_secret(scope="https://api.example/v1/", token=md.env("API_TOKEN")),
    md.http_headers_secret(scope="https://change-focus.example/api/",
                           headers={"x-api-key": md.env("API_KEY")}),
])
```

没有宿主 resolver 时，依次从环境变量和 `~/.marivo/secrets.toml` 查找；`md.credential_scope` 将相同引用交给宿主，返回值不落盘。每次操作重新解析，轮换的凭据在下一次操作生效。`md.load().test` 只验证字面量往返，不验证 S3 或 HTTP 访问，因此缓存的 key 未必经过对应端点验证。

作用域使用主机和路径前缀，不能包含 URL 用户信息、查询字符串或片段。DuckDB 中，同一个数据库实例的连接共享 secret 目录。文件数据库或命名的内存数据库使用作用域凭据时，Marivo 要求独占其托管连接，直到连接关闭。需要使用不同凭据并发访问时，请使用不同的数据库。

DuckDB 持久 secret 保持启用，按最长 scope 匹配；比声明更具体的持久 secret 会被选中。JSON 请求使用最长匹配的已声明 HTTP scope；带认证的 GET 和所有 POST 拒绝自动重定向。
