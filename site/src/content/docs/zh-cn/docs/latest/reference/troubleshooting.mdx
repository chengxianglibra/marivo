## 环境与语义范围

在选定环境运行 `marivo doctor --project-root <project>` 并安装所需 datasource extra。
未知身份按需发现 Catalog，凭据使用环境引用。readiness、preview、source health 与实际方法
求值是不同证据。同路径定义变化本身不拒绝旧输入，仍保留 kind/root/grain/unit/time/null 检查；
业务版本身份锚点是独立合同。

## 完整键与精确 Frame 句柄

Column/FrameAxis 属于精确输入；从接收者重新取得，或显式对齐完整轴。
同名、指纹或导出 attrs 不能重新绑定。继续[教程](/zh-cn/docs/latest/guides/python-quick-start/)：

{/* example: repair-query-domain */}

```python
aligned = current.align(
    baseline, on=((current.axes[0], baseline.axes[0]),), how="outer",
)
difference = aligned.select({"difference": aligned["left.revenue"] - aligned["right.revenue"]})
difference.show()
```

exact 要求唯一完整联合键对应；outer 保留缺侧与独立 presence，不自动补零。
Field Null 是合法类别。read 要求完整 Entity 身份域、非空字段、合法单值路径与版本锚点，
后置过滤不能隐藏必要错误。新来源事实要显式提供受治理输入与普通轴 population_from 映射；
on 必填，零轴允许 on=()。

## 时间与数值政策

使用 Session instant/time_scope，并向 `mv.offset(years=...)` 或
`mv.offset(periods=...)` 指定唯一整数关键字。CalendarAxis.shift 支持单位步长内建
week/month/year 完整桶或桶首前缀；部分 day/quarter、中段截取和有歧义的非零目标时刻
需要显式支持的时间域。缺目标 ISO 周/民用截止日期是合法无对应，不夹日期。
ordinal 仍要求完整桶，过滤不压缩原始序号。

命名 compare 需要非空别名到 Frame 的映射，有普通轴时按别名完整提供 on。
冻结直接关系必须与完整本期域相符；使用原始相容端点或显式一致规则，不能通过改 how
修复错误锚点或冲突规则。实际基期时间行超出本期声明域时，显式过滤基期或使用 align 的
一般双端时间并集。outer 不修复缺失/损坏附件或把 NA 当零。分别检查
`current.present` / `<alias>.present`、值 NA 与继承的 `<alias>.presence.*`。
参见 `marivo.help("analysis.calendar_axis.shift")` 和
`marivo.help("analysis.analysis_frame.compare")`。



除零政策只作用新算子，不覆盖严格子式。非有限值、溢出与必要覆盖失败阻止完成。
缺少执行路线不授权改算法、来源或精度。

## 显式 Attribute 与完整解释读取

AttributeEndpoint 要求已解析来源 Metric 和显式范围；Frame/Column/Artifact 不能恢复来源
权限。普通父轴必须从精确接收者完整双向 `parent_on` 绑定；`by` 必须增加业务分类。
`contribution` 严格要求 boolean，不接受仅具有真值的标记。

`unsupported_expression` 表示所需精确分解没有准入规则，`missing_component_proof` 表示
所需样本/分区/组件未被证明；`unqualified_contribution_route` 表示来源超出合格物理 DuckDB
表路线。原来源与数值失败仍按其自身错误修复。不改精度、不虚构证明、不静默降级；原观察
合法时，显式请求 `contribution=False` 做调查。精确调用见
`marivo.help("analysis.session.attribute")`。

pending `method_facts` 访问需先 compute/persist。存储 getter 校验完整 owned 方法文件，
不读主表或来源。卡片、打开、预览和 `to_pandas()` 不验证方法载荷，stored compute 与
派生求值会消费它；坏方法文件可使当前行仍可导出而完整消费失败。保留原文件，按错误修复
报告的 owned 载荷，不用当前来源重建。见 `marivo.help("analysis.analysis_frame.method_facts")`。

## 精确数据恢复与重新提交

保留 Session ID 与 frame.artifact.id，恢复该 Session 后用字符串调用
`session.persisted_frame(id)`。Frame 拥有数据操作，`.artifact` 拥有审计；
Artifact/ID 对象及 RawSqlResult 不是计算操作数。保存错误直接给出失败阶段与具体修复。
提交结果未知时，先恢复所属 Session，再显式重新提交；原提交可能已成功，因此可能重复保存。
返回的 Artifact ID 丢失时也采用显式重新提交。完整内存数据可再次保存而不求值；
重新构建来源输入可能读取变化的数据。
缺失或损坏的消费数据不是 cache miss，不能回放来源修复。

Store 15 拒绝所有旧 generation 数据且保持字节不变，不迁移或双读。缺少当前 generation 的
发现可返回 None/空而不暴露旧状态；create 不能绕过仅有旧 Store 的项目。
切换前用原版本导出必要结果，或保留兼容读取环境。预览限制只影响显示，不截断完整执行。
保留旧 Store，当前工作在新项目创建新的命名 Session。Store15 的 generation15/output-v4
适用于所有 Frame，不提供自动导出/导入迁移或同项目旁路。
[Store 代际兼容合同](https://github.com/chengxianglibra/marivo/blob/main/docs/architecture/analysis/session-state-and-runtime.md#store-generation-and-data-layout)
说明当前格式、旧代际拒读边界与兼容恢复选择。
