执行日志记录提交的 SQL 和结果；使用遥测记录选定操作的事件与耗时。两者都保存在项目本地文件中。分析数值请从 Frame 读取。

## 找到正确记录

| 记录 | 位置 | 用途 |
| --- | --- | --- |
| 执行日志 | `.marivo/logs/execution-YYYY-MM-DD.NNN.jsonl` | 查看提交的 SQL、结果与耗时 |
| 使用遥测 | `.marivo/telemetry/events-YYYY-MM-DD.NNN.jsonl` | 查看操作、结果与耗时摘要 |

通过 query ID 对应一次 SQL 的提交和完成。

新执行日志记录使用 `schema_version: 2`，并包含 `runtime` 对象，其中有 `marivo_version`、`python_version`、`python_executable`、`package_path` 和 `process_id`。这些字段由日志器写入，调用方上下文无法覆盖。它们能标识产生记录的进程环境，但不能证明包内容或数据快照。运行 `marivo doctor` 可查看当前环境，不能还原历史环境。旧记录保持原样；缺少 `runtime` 表示历史身份未知。同一文件可以包含多个 schema 版本，应逐行解释。

新使用遥测事件使用 schema v3，版本标记为 `marivo.event.schema_version`。旧事件不会迁移，应按各自的 schema 版本解释。

已发布的 `0.5.7` 至 `0.5.9` 版本支持 `full`；该模式的引入见 [Marivo 0.5.7 发布说明](/zh-cn/docs/latest/release-notes/0.5.7/)。当前源码版本 `0.6.0.dev0` 仅接受 `on` 和 `off`。


## 开启或关闭遥测

| 模式 | 行为 |
| --- | --- |
| `on` | 默认开启，记录选定操作和失败 |
| `off` | 关闭使用遥测，执行日志仍然保留 |

在 `marivo.toml` 中设置项目默认值：

```toml
[telemetry]
enabled = "off"
```

`MARIVO_TELEMETRY` 可设为 `on` 或 `off`，并覆盖项目设置。无效环境变量值会被忽略；`marivo.toml` 中无效的 `[telemetry].enabled` 值会导致配置校验失败。

开启遥测后，分析执行、语义加载和数据源查询等显式长操作会记录开始与完成事件。选定的短操作只记录完成事件；部分操作仅在失败时记录。嵌套调用的成功事件会省略；没有事件并不表示没有执行操作。SQL 活动请查阅执行日志。

## 理解保留与分享

文件按 UTC 日分段，每段约 128 MiB。每个日志目录中的历史记录最多保留 14 天，并控制在 1 GiB 历史额度内。当天文件不参与清理，因此目录可能超过该大小。

执行日志包含提交的 SQL，可能带有业务条件和字面值。使用遥测不含 SQL 文本或异常消息，但可能包含 Session 问题、分析用途，以及传给 `md.raw_sql` 的 `reason`。分享记录前请检查其中的敏感内容。
