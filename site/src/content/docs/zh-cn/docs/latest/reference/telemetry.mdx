执行日志记录查询与执行结果，使用遥测记录操作与耗时。它们都保存在本地；需要读取分析数值时，使用保存的 Frame。

## 找到正确记录

| 记录 | 位置 | 用途 |
| --- | --- | --- |
| 执行日志 | `.marivo/logs/execution-YYYY-MM-DD.NNN.jsonl` | 查看提交的 SQL、结果与耗时 |
| 使用遥测 | `.marivo/telemetry/events-YYYY-MM-DD.NNN.jsonl` | 查看操作、结果与耗时摘要 |

通过 query ID 对应一次 SQL 的提交和完成。

新执行记录使用 `schema_version: 2`。每条事件都带有 `runtime` 对象，包含 `marivo_version`、`python_version`、`python_executable`、`package_path` 和 `process_id`；从轮转文件或日志尾部截取记录也能读到身份。这些字段由日志器拥有，调用方上下文不能覆盖。

该身份描述产生事件时的运行环境，不证明包内容或数据快照；相同开发版本与路径可能包含不同代码。Doctor 报告当前环境。旧记录保持原样，缺少 runtime 表示历史身份未知。同一文件可以包含多个 schema 版本，应逐行解释。使用遥测保留自己的 schema，本次不变。


## 开启或关闭遥测

| 模式 | 行为 |
| --- | --- |
| `on` | 默认开启，记录执行、会话创建与复用、数据源变更及失败 |
| `off` | 关闭使用遥测，执行日志仍然保留 |

在 `marivo.toml` 中设置项目默认值：

```toml
[telemetry]
enabled = "off"
```

环境变量 `MARIVO_TELEMETRY` 可设为 `on` 或 `off`，优先于项目配置。无效环境变量值会被忽略；无效项目配置值会触发配置错误。

开启遥测后，显式调用的分析执行、语义加载和数据源查询等长操作记录开始与完成事件；会话创建或复用等短操作仅记录完成事件。轻量读取仅记录失败，分析构造器和语义引用不记录事件。嵌套调用省略成功事件，保留符合采集策略的失败事件及其父操作身份。

## 理解保留与分享

文件按 UTC 日和约 128 MiB 分段。历史记录通常保留 14 天，历史总量按 1 GiB 清理；当天文件不参与清理，因此整个目录可能超过该大小。

执行日志包含 SQL，可能带有业务条件和字面值。使用遥测可能保留会话问题和 SQL 的 reason。分享记录前检查其中是否有敏感内容。
