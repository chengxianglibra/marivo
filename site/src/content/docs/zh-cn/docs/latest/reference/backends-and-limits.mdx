分别选择连接与分析方法。驱动安装和连接成功，不代表所有方法都可执行。

| 后端 | 可选依赖 | 重要条件 |
| --- | --- | --- |
| DuckDB | `duckdb` | 本地教程无需服务；贡献要求合格物理表 |
| PostgreSQL | `postgres` | 需要 libpq 和权限；精确中位数/分位数受物理类型限制 |
| MySQL | `mysql` | 需要原生客户端/构建依赖；支持排序取界的精确分位，不支持近似源端分位 |
| Trino | `trino` | 需要 catalog/schema 与权限；支持排序取界的精确分位或显式近似分位 |
| ClickHouse | `clickhouse` | 支持合格普通分组聚合，Distributed 键连接有限制；支持排序取界的精确分位或显式 TDigest 近似分位 |

## 核对来源形式与方法

表、文件和 HTTP 的发现能力与执行条件不同。参数化 HTTP JSON 可以声明和预览，但不是数值 Frame 来源。五种 backend 均支持精确数值来源中位数/分位数。MySQL、Trino 和 ClickHouse 在源端排序取界后本地插值；DuckDB 和 PostgreSQL 保留已准入的精确路径。近似分位必须显式声明，支持 DuckDB、Trino 和 ClickHouse，各 backend 的算法可以不同；PostgreSQL 和 MySQL 拒绝近似源端方法。普通计数、去重数、求和、最值、均值与加权均值仍取决于实际类型与表达式。

贡献要求合格的物理表及保留的来源声明。DuckDB、PostgreSQL、MySQL、Trino 和 ClickHouse 使用各自的原生执行路径，仍受实际方法、类型、键和来源能力限制。父级与细分独立读取，不保证共享快照。Attribute 信任语义层的身份、关系基数和版本粒度声明，仍检查操作新增的 membership/Population 缺失与重叠、distinct 值跨组及数值有效性；只对请求的最终目标按其闭合容差验收。Float64 容差取最终目标绝对值的 1% 与数值舍入预算的较大值；其他数值类型保持原有规则。不支持贡献时，可显式观察和比较继续调查，但不宣称精确分解。

远端贡献仍要求直接映射到物理非空整数或字符串列的 identity，以及合格的字符串 collation。同一 root 内不兼容的非时间 scope 会被拒绝。普通观察成功本身不代表这些输入已满足贡献准入条件。

## 考虑资源与数值限制

本地操作可能在内存保留全部所需向量。展示行数限制不是计算或扫描限制。超时遵循驱动原生含义，部分设置可能不受支持；没有整个计算图的期限，也不会静默切换执行器。

`md.raw_sql()` 默认请求 600 秒的原生查询超时，可通过 `timeout_seconds` 覆盖；
Trino 将其用于 `query_max_run_time`。连接获取使用独立的原生 30 秒设置。
查询超时不代表整个调用或结果获取的总时限。

```python
import marivo.datasource as md
import marivo.semantic as ms

md.raw_sql(
    ms.ref.datasource("default"), "SELECT 1 AS ok",
    reason="check query path", timeout_seconds=600,
)
```

来源精度和溢出遵循合格后端。转换无法修复已丢失的精度或来源已经回绕的值；本地算术有自己的检查规则。不同来源之间没有统一 Decimal 精度保证。

本地教程只演示其 DuckDB 路线。配置见[接入数据](/zh-cn/docs/latest/modeling/semantic-layer/#连接与检查)，具体失败见[故障排查](/zh-cn/docs/latest/reference/troubleshooting/)。
