分别选择连接与分析方法。驱动安装或连接成功，不保证具体方法适用于当前来源的
数据类型和结构。

| 后端 | 可选依赖 | 重要条件 |
| --- | --- | --- |
| DuckDB | `duckdb` | 本地数据库与文件来源引擎；教程无需服务器 |
| PostgreSQL | `postgres` | 需要 libpq 和数据库访问权限 |
| MySQL / MariaDB | `mysql` | PyMySQL 包含 RSA 认证支持；无需本地 MySQL 客户端 C 库 |
| Trino | `trino` | 必须设置 `catalog` 和 `user_env`；`schema` 可选 |
| ClickHouse | `clickhouse` | JOIN 操作要求通过准入的 MergeTree 表；Distributed 表的 JOIN 路线受限 |

## 核对来源形式与方法

数据库表使用所选 SQL 后端；CSV、Parquet 和文件 JSON 由 DuckDB 读取。Analysis Session
只支持未参数化 GET 路线的本地 JSON 文件。其他 HTTP JSON 形式仍可通过数据源 API 声明
和预览，但不能作为 Analysis Session 输入。

源侧精确 `median()` 与 `quantile(q)` 使用 DuckDB `quantile_cont`、PostgreSQL
`percentile_cont` 或 ClickHouse `quantileExactInclusive` 原生函数。MySQL 和 Trino
在编译时拒绝精确源侧分位数。ClickHouse 接受整数与浮点输入；DuckDB/PostgreSQL
也支持 Decimal。源侧 Duration 分位数不可用，不通过排序模拟或本地插值补偿。
线性插值采用 `h=(n-1)q`，所以 `[0, 10]` 在 `q=0.95` 时得到 `9.5`。
整数和浮点结果使用 `float64`；获准的 Decimal 路线保留声明的载体。空输入或全 NULL
输入返回 NA；严格 NULL 检查仍作用于其输入。

近似方法必须显式声明。分位数使用 DuckDB `approx_quantile`、Trino `approx_percentile`
或 ClickHouse `quantileTDigest`；去重估算分别使用 `approx_count_distinct`、
`approx_distinct` 或 `uniqHLL12`。PostgreSQL 和 MySQL 在编译时拒绝这两类近似操作。
精确去重使用 `COUNT(DISTINCT ...)` 或 ClickHouse `uniqExact`。不支持的操作与类型
在聚合查询执行前报错；HTTP JSON 已在源准备阶段获取响应，用于推断类型。
精确与近似算法不会相互替换。近似结果可能因后端而异，没有
统一误差界限；其他规约仍须满足类型与表达式的准入条件。

贡献分析使用五类后端的合格来源路线，但仍受方法、类型、键和来源限制。父级总量与
细分贡献独立读取，可能来自不同来源快照。`Attribute` 信任实体身份、关系基数和版本
粒度声明；准入还会检查 membership/Population 覆盖与重叠、distinct 值的跨组分区、
时间对应和数值闭合。只核对请求的最终目标与新读取的父级总量。未改变的 additive/level Float64 闭合容差取
目标绝对值的 1% 与数值舍入预算的较大值；paired rate/mix 使用传播的舍入界，
没有该 1% 业务容差；其他类型使用各自规则。若目标不满足准入
条件，可通过显式观察和比较继续调查，但不能把结果当作贡献分解。

远端 `Attribute` 要求直接物理有符号整数字段或字符串身份字段，以及合格的字符串
collation。Entity 的 `primary_key` 声明完整且非空的身份；即使物理元数据将身份列标为可空，
该路线仍信任此声明，不会全量预检来源数据中的空值或唯一性；各操作的身份检查仍会执行。
需要按范围核验数据时，使用 `ms.source_check` 构造检查，并通过有界的
`catalog.validate(..., checks=..., scope=...)` 执行。同一来源 root 内不兼容的非时间
scope 不能合并。

## 考虑资源与数值限制

本地计算可能在内存保留全部所需向量。展示行数限制只影响输出，不限制计算量或来源扫描。
查询超时使用后端原生设置，可能不受支持，也不覆盖完整客户端调用和结果获取过程。

普通 Metric 预览支持五类 SQL 后端，读取显式范围内的无序 Entity 输入。
每个 Entity 最多贡献 `min(scope.max_rows, 10_000)` 行输出。已有分区值证据时，必须显式
指定分区值或支持的时间范围；无法取得分区值时仍允许显式选择广泛读取。不会自动选择最新分区。`coverage.entity_rows` 和
`entity_row_limits` 披露采样输入；`execution_limits` 报告请求的原生超时及实际
支持。预览没有请求扫描行数或字节数上限，扫描统计保持 unknown。单个分区仍可能
很大，Entity 内部聚合或去重发生在输出限制之前。

`md.raw_sql()` 默认请求 600 秒的原生查询超时，可通过 `timeout_seconds` 覆盖；
Trino 将其用于 `query_max_run_time`。连接获取使用独立的原生 30 秒设置。
查询超时不代表整个调用或结果获取的总时限。

```python
import marivo.datasource as md
import marivo.semantic as ms

md.raw_sql(
    ms.ref.datasource("default"), "SELECT 1 AS ok",
    reason="check query path", timeout_seconds=600,
)
```

`md.raw_sql()` 只应执行只读 SQL；Trino 依赖数据库权限禁止写入。它会把查询返回的全部
行加载到内存。可使用筛选、聚合或 SQL `LIMIT` 控制结果大小；`LIMIT` 不限制来源扫描成本。

数值精度和溢出遵循后端与数据类型。整数 SUM 使用 `int64` 结果：本地求和可能回绕，
较宽的来源端累计值也可能在通过 Ibis 传输时失败；ClickHouse 可能返回回绕值。来源读取
后再转换无法恢复已经丢失的精度。MySQL SUM 会先保留服务器返回的宽精度 Decimal，再安全
转换为声明的 Decimal 结果；超出范围时会报错，而不会截断。融合来源表达式内部的算术仍
遵循 MySQL 原生规则。已保存的 Frame 按已提交值导出；导出不会重算，也不能修复来源端已
发生的精度损失或溢出。

算术结果为 `float64` 时，本地执行会将数值操作数按普通舍入规则转换为浮点数，包括
整数与浮点混合运算、Metric 除法和 `ms.rescale`；超过 `2**53` 的整数可能丢失低位。
纯整数运算保留整数载体，身份键不经过浮点转换，最终存储转换仍保持安全检查。
应在符合业务含义的聚合层级换算：`sum(x) / divisor` 与 `sum(x / divisor)` 可能产生
不同的舍入结果。

`mean()` 默认跳过 NULL，没有有效值时返回 NULL。`nulls="error"` 要求本次需求输入不含
NULL；空输入通过此断言。对于 `amount.mean(time=point).per(point).mean()`，先求每个已出现
时间点的均值，再对这些均值等权平均。时间点数据为 `[0, 0, 0]` 和 `[100]` 时，结果是
`50`，而非按原始行加权的 `25`。不会合成没有数据的预期时间点；时间样本 `mean` 和
`weighted_mean` 使用实际出现的样本。

本地教程只演示其 DuckDB 路线。配置见[接入数据](/zh-cn/docs/latest/modeling/semantic-layer/#连接与检查)，具体失败见[故障排查](/zh-cn/docs/latest/reference/troubleshooting/)。


## 逐行属性时间与容错解析

逐行 as-of 的首轮范围为 DuckDB/Trino 同源、单事实根 observe 分类；版本连接保留 left join。同一目标、完整路径和控制时间共享连接，不同字段、固定锚点或路径角色保持独立。安全事实时间范围、独立物理条件与可证明的事实侧 AND 条件在连接前过滤；目标标签 OR 不拆分。目标分区包络裁剪尚未提供。

`strptime` 在 DuckDB、Trino、ClickHouse 和 MySQL/MariaDB 上将拒绝的数据变为 NULL；PostgreSQL 使用原生 `to_timestamp`，被拒绝的数据可能使查询报错。DuckDB 用 try_strptime，Trino 用 TRY，ClickHouse 用 OrNull，MySQL/MariaDB 在 SELECT parser 后用零日算术排除无效日历载体。原生格式及精度限制继续生效。解析后的 membership 保持 wall-order，原始编码范围不能绕过解析，因此扫描成本可能上升；独立物理过滤仍可下推。Trino TRY 可捕获输入表达式内的部分错误，其他后端可能传播参数错误，不保证统一的上游错误隔离。

Trino 不支持 `%U` 和 `%w` 的 strptime 格式；这类配置在 TRY 之前给出类型化错误，不会静默返回全列 NULL。
