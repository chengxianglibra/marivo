---
title: 项目读取服务
description: 读取已保存报告，并显式刷新返回 AnalysisFrame 或 DataFrame 的脚本端点。
---

在项目所用的 Marivo Runtime 中安装可选 API 依赖。用
`secrets.token_urlsafe(32)` 一次性生成令牌，将它保存到部署凭据配置，并在
服务环境中设置 `MARIVO_API_TOKEN`。普通重启沿用该值。需要轮换时更新
配置并重启服务。

通过 Agent 管理服务时，可使用内置的 `marivo-service` 工作流。
`marivo help analysis.results.service` 可导航到当前 Runtime 的脚本和 HTTP 契约。
Host 负责选择项目并管理连接、凭据和用户权限。

```bash
pip install 'marivo[api]'
marivo serve --project-root /path/to/project --port 0
```

默认监听 `127.0.0.1:8765`。端口 `0` 由操作系统分配可用端口。
从 stdout 的单行 JSON 回执读取 `host`、`port`、`protocol`、`pid`、
`marivo_version` 和 `api_version`。服务日志写入 stderr。

## 读取报告

保留 `persist()` 返回的已提交 Frame 的两个身份字段。

```python
saved = frame.persist(description="Recorded revenue")
ref = {
    "schema": "marivo.frame_ref/v1",
    "session_id": saved.session_id,
    "artifact_id": saved.artifact_id,
}
```

向服务地址发送准确的引用。下面使用默认端口，由客户端环境提供管理员配置的令牌。

```bash
curl --fail-with-body -H "Authorization: Bearer ${MARIVO_API_TOKEN}" \
  "http://127.0.0.1:8765/v1/sessions/${session_id}/frames/${artifact_id}"
```

一次成功请求返回 `kind: "analysis_frame"`、`ref`、`description`、`committed_at`、`schema`、
`lineage`、`source_reads`、`data` 和 `periods`。每行的单元格顺序由
`data.layout` 决定。通过字段 slot 或坐标身份在 `schema` 中取得原始显示名和
类型。坐标默认名称冲突时，导出名会加上确定的后缀。`data.coordinates` 按 key slot
提供与结果行一一对应的原始坐标值。

按 schema 类型解码业务值。整数和 Decimal 使用精确字符串，日期和时间戳使用 ISO
字符串，duration 使用声明单位的整数 tick。有限浮点数用 JSON number，非有限浮点数
使用 `{"float":"nan"}` 等标签值。NULL 与布尔 presence 独立。期间键和标签均带
`dtype` 和 `value`。保存的期间可以没有对应结果行，比较期间保留已保存的端点
或缺失原因。

## 刷新脚本端点

在项目中创建 `endpoints/sales/revenue.py`：

```python
import marivo.analysis as mv


def main(session: mv.Session) -> mv.AnalysisFrame:
    revenue = session.catalog.get("metric:sales.revenue")
    assert revenue.kind == "metric"
    return session.observe({"revenue": revenue})
```

服务启动时发现小写 snake_case 路径，不导入脚本。以 `_` 开头的文件和目录为私有代码。
新增路径后重启服务；已有端点每次刷新加载最新源代码。声明一个同步 `main(session)`，
参数使用示例中的 Session 注解，返回值声明一种具体类型。服务提供新的项目 Session 并
保存输出；即使导入代码配置了其他项目环境，该 Session 仍属于服务启动时绑定的项目。
AnalysisFrame 必须属于该 Session 且尚未持久化。脚本负责时间范围和业务逻辑，
导入代码按受信任的项目代码执行。

```bash
curl --fail-with-body -X POST -H "Authorization: Bearer ${MARIVO_API_TOKEN}" \
  'http://127.0.0.1:8765/v1/data/sales/revenue/refresh'
curl --fail-with-body -H "Authorization: Bearer ${MARIVO_API_TOKEN}" \
  'http://127.0.0.1:8765/v1/data/sales/revenue'
```

只有空请求体的 `POST /v1/data/{endpoint}/refresh` 执行脚本、发布新结果并原子切换
当前引用。`GET /v1/data/{endpoint}` 只读已保存数据，即使脚本或模型已经删除也可读取。
首次发布前返回 `result_not_found`，不会隐式执行。两个路由都拒绝所有查询参数，
包括 `refresh`。刷新同步返回完整报告及固定引用。不要自动重试 POST 刷新：超时或响应
丢失不代表发布失败，应先读取当前状态，再决定是否需要再次刷新。

## DataFrame 结果与报告固定版本

DataFrame 端点同样接收 Session，可以继续进行 Marivo 分析：

```python
# endpoints/sales/revenue_table.py
import pandas as pd
import marivo.analysis as mv


def main(session: mv.Session) -> pd.DataFrame:
    revenue = session.catalog.get("metric:sales.revenue")
    assert revenue.kind == "metric"
    table = session.observe({"revenue": revenue}).compute().to_pandas()
    return table.assign(double_revenue=table["revenue"] * 2)
```

列名必须是唯一的非空字符串，索引必须是默认无名 RangeIndex；业务索引先转为列。
支持 null、布尔、字符串、整数、float32/64、Decimal、日期、时间戳和 duration 标量列。
无法表示的对象和嵌套值明确报错，`attrs` 不作为语义元数据。保留行列顺序、空表列类型
和零列表格的逻辑行数。

```json
{
  "kind": "dataframe",
  "ref": {"schema":"marivo.dataframe_ref/v1","result_id":"df_0123456789abcdef0123456789abcdef"},
  "session_id": "session_example",
  "committed_at": "2026-11-07T00:00:00+00:00",
  "schema": {"columns":[{"name":"count","dtype":{"kind":"int64"}}]},
  "data": {"layout":["count"],"rows":[["9007199254740993"]],"row_count":1}
}
```

DataFrame 独立保存在 `.marivo/server/dataframes/{result_id}.parquet`。
`GET /v1/dataframes/{result_id}` 读取固定版本，不加载 Session、Analysis Store、模型或脚本。
`session_id` 记录生产上下文，`schema.columns` 声明物理类型，`data.layout` 给出列顺序。
标量编码沿用上面的 Frame 规则，不从 pandas 数据推断语义轴、血缘、单位或期间。

UI 报告保存服务身份、`kind` 和 `ref`；AnalysisFrame 还应保留连接的 `/v1/info`
所返回的 `store_id`。重开报告使用精确 Frame 或 DataFrame 路由，这些路由不接受
`refresh`。刷新命名端点不会改变报告保存的版本；只有显式更新报告时才替换其 ref。
当前指针位于 `.marivo/server/endpoints/`。`committed_at` 是保存时间，不代表源数据新鲜度。

## 浏览当前定义

所有 API 请求使用相同的 Bearer 请求头。通过 `GET /v1/openapi.json` 获取类型化
的路由和载荷合同。OpenAPI 描述通用命名端点路由；具体端点名称由项目或 Host 提供。
`GET /v1/info` 返回版本、Store 和当前 Catalog 加载状态。
语义对象使用规范 `kind:path` 身份，作为路径参数时使用 URL 编码。

| 操作 | 路由 |
| --- | --- |
| 列出语义对象 | `GET /v1/semantic/objects`，可选 `kind` 和 `domain` |
| 读取定义 | `GET /v1/semantic/objects/{id}` |
| 浏览依赖或被依赖对象 | `GET /v1/semantic/objects/{id}/related?relation=dependencies` |
| 刷新当前定义 | `POST /v1/semantic/reload`，请求体为空 |
| 发现 Session 和 Frame | `GET /v1/sessions` 和 `GET /v1/sessions/{session_id}/frames` |

目录默认每页 20 条，允许 1 到 100 条。使用 `next_cursor` 续读并保留相同过滤条件
和页大小。Catalog 刷新成功后旧语义游标失效，失败时保留上次成功加载的目录。
已保存报告独立于当前模型加载。
reload 会启动新加载；如果已有加载正在进行，则返回 `409 catalog_load_in_progress`，
应等该加载结束后再请求 reload。普通读取共享首次加载，或在 reload 期间读取上次成功
加载的快照。Catalog 加载由服务管理，客户端断线或请求超时不会取消它；加载自身的读取
期限和服务关闭仍会停止它。未预期的请求异常及 Catalog 工作进程 traceback 写入服务
stderr，不放入 HTTP 响应。遇到 `catalog_load_failed`，应查看日志并在绑定项目中运行
`marivo doctor --semantic`。

## 部署和处理错误

原生 TLS 需要成对提供 PEM 文件。也可通过现有 HTTPS 入口终止 TLS，再转发给受
保护的 HTTP 监听地址。

```bash
marivo serve --project-root /path/to/project --host 0.0.0.0 --port 8765 \
  --ssl-certfile /etc/tls/fullchain.pem --ssl-keyfile /etc/tls/privkey.pem \
  --allow-origin https://analysis.example.com
```

对每个允许的浏览器 Origin 分别指定 `--allow-origin`，按完整 Origin 匹配。
默认配置允许携带 Bearer、无 Origin 的服务端请求。合法预检无需令牌，实际业务请求
始终要求 Bearer。允许的 Origin 可读取成功和错误响应。公开 API 主机名应使用浏览器
信任的证书。宿主负责用户授权与项目绑定。

`--max-response-mib` 默认 128，`--read-timeout-seconds` 默认 300。两者都接受
正整数，覆盖整份报告，Catalog 加载使用同样的限制。遇到 `response_too_large`
或 `read_timeout` 时，可由管理员调高对应设置并重启，再重试同一引用，也可显式
保存较小的结果。成功响应包含完整报告，表格分页在客户端进行。

失败时查看 `error.code`、`location`、`repair` 和可空的 Help `target`。
`invalid_cursor` 应从目录首屏重新读取，`not_found` 应核对项目和身份，
`corrupt_artifact` 应恢复已提交文件。

`--refresh-timeout-seconds` 默认 300，`--max-refreshes` 默认每个服务进程 1 个。
两者都接受正整数。刷新使用独立期限和相同的响应大小预算。同端点刷新跨服务进程互斥，
冲突返回 `refresh_in_progress`；刷新容量已满返回 `service_unavailable`，不排队。
普通已保存读取继续可用。

超时或断线会先停止工作进程，再释放槽位和锁。继承刷新进程组的子进程与本次刷新共享
生命周期，在完成、取消或父进程退出时一同停止。指针切换前的脚本、持久化或编码失败保留
旧结果；已保存但未发布的快照可能留存，已有固定版本不会被删除。如果发布后响应丢失，
重试前先读取当前端点确认状态。`refresh_timeout`、`script_contract_error`、
`refresh_failed`、`result_publication_failed`、`invalid_result_reference` 和
`corrupt_dataframe` 区分失败环节，按其 repair 字段处理。管理员配置的令牌可触发已安装
脚本的刷新；宿主负责报告保存和用户授权。
