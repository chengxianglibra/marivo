调用 `session.observe(...)`，即可按所选输出域构造 Metric 计算，并返回待执行的
`AnalysisFrame`。调用 `compute()` 执行计算；调用 `persist()` 则完成计算并发布结果。

完整的最小示例可直接查看 `marivo.help("analysis")`。在已有指标定义的项目中，
先按业务含义搜索：

```python
import marivo.analysis as mv

session = mv.session.get_or_create("revenue-trend", timezone="UTC")
catalog = session.catalog
catalog.search("revenue", kind="metric", limit=5).show()
```

查看候选，选择符合问题口径的指标，而非自动使用第一条结果。
以下假设确认的 ID 是 `metric:sales.revenue`；实际应使用搜索返回的真实 ID。
已知确切身份时可跳过搜索。日期和时区应按问题调整；继续同一分析时复用已有 Session。

```python
revenue = catalog.get("metric:sales.revenue")
assert revenue.kind == "metric"
period = session.time_scope(start="2026-08-01", end="2026-09-01")
result = session.observe(
    revenue,
    by=(period.by(mv.grain("day")),),
).compute()
result.show(n=31)
```

时间范围按 Session 时区包含 8 月 1 日、不包含 9 月 1 日。
指标的每个分支都需要贡献时间。该示例直接计算并展示每日数值，无需持久化；
指定时间范围不代表已确认来源数据完整。

范围合计使用 `where=scope`；时间分组使用 `by=(scope.by(grain),)`。
CalendarAxis 可与普通 Dimension、非时间 Grouping 放在同一元组中，裸 Grain 输入会被拒绝。
若 by 已携带时间，where 中不能再传报告 TimeScope，即使两者选择相同。
自定义日历轴要求一个完整认证期间和已捕获快照的 Grain。

`by=P` 保留 P 的完整输出键，包括没有事实的键，但不会自动筛选贡献。
P 必须覆盖所有必要输出键；如需限制贡献，显式使用 `where=mv.in_population(P)`。
若 P 已含报告时间坐标，则不能在 `where` 中另传 TimeScope。

每个源规约在定义时固定贡献时间，可显式传入 `time=field`，或继承所属 Entity 的
`default_time`。使用报告范围或 CalendarAxis 时，每个 Metric 的每个分支都须具备贡献时间。
组合 Metric 可以保留各分支不同的时间字段。

例如，`amount` 是已加载的 Measure，`booked_at` 和 `paid_at` 是已加载的 TimeDimension：

```python
import marivo.analysis as mv

scope = session.time_scope(start="2026-11-01", end="2026-12-01")
booked = amount.sum(time=booked_at)
paid = amount.sum(time=paid_at)
difference = booked - paid
difference.show()
total = session.observe({"difference": difference}, where=scope).compute()
frame = session.observe(
    {"booked": booked, "paid": paid, "difference": difference},
    by=(scope.by(mv.grain("day")),),
).compute()
```

`difference.show()` 在无需接收作用域即可确定时展示捕获的各分支归期。对于已发布的
Catalog Metric，可查看 `metric.definition.time_bindings`，或调用
`metric.show(section="definition", max_output_bytes=None)` 读取全部绑定。归期可用不代表
特定粒度或来源物理类型已经通过验证。

用 `where=(scope, status == "paid")` 将一个报告范围与行谓词取交集。
`where=paid_at >= start` 这样的显式字段比较是固定来源字段谓词，可筛选没有贡献时间的
Metric；它在窗口求值期间持续生效，包括报告范围之前的历史。窗口端点由报告时间上下文提供。若某个分支缺少贡献时间，请修订该分支的定义，
或在此次观察中省略报告时间。

对于时间能力尚不确定的现有 `metric`，可先读取观察错误的完整结构化详情，再决定如何修复：

```python
try:
    pending = session.observe({"value": metric}, where=scope)
except mv.MetricContributionTimeError as error:
    print(error.output)
    for missing in error.missing:
        print(missing.path, missing.metric, missing.root, missing.reason)
```

`reason` 区分缺少 Entity 默认时间的源规约与固定 Population 计数。不要给固定
Population 计数指定归期；应将它放在报告时间运算之外。

精确契约见 `marivo.help("semantic.metric.define")` 和
`marivo.help("analysis.session.observe")`。

完整说明和示例见[分析 DSL 的 observe 部分](/zh-cn/docs/latest/analysis/dsl/#观察指标)。
