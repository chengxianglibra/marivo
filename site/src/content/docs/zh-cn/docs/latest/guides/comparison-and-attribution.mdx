使用已有 Session 和约定导入。多数示例使用[分析流程](/zh-cn/docs/latest/concepts/analysis-workflow/)
中的 customer/order 模型。差值是代数结果；在所选 axes 下的分配解释方程，
不等于解释业务结果的原因。

## 选择比较设计

`current`与 `baseline`是同一 Session 中兼容的观察；已导入 `marivo`用于 focused Help。

{/* example: comparison-designs */}

```python
comparison = current.compare(baseline)
absolute = comparison.absolute
relative = comparison.relative
union = current.compare(baseline, align=mv.outer())
quotient = current.ratio(current, align=mv.exact())
result = comparison.execute()
result.show()
marivo.help("analysis.dsl.NumericComparison.compare")
marivo.help("analysis.dsl.one_to_one")
```

compare 从冻结的目标与观察时间推导唯一设计：只变时间时比较时期，只变目标时在共同
Group/Singleton 坐标上比较群体；两者同时变化或均不变会拒绝。网格比较显式使用
`align=mv.exact(time=mv.ordinal())` 或带同一时间键的 outer。输出时间位置是
带时间键种类前缀的 string 对齐键，不挂载 time_grid；两侧原时间坐标保留为对应投影。exact
要求对齐键集合相等，outer keep 允许任一侧网格更长。
`mv.exact()` 固定 checked；`mv.outer()` 默认保留缺侧，`missing="empty_value"`
显式使用准入 Metric 的空集 finish，但构造时拒绝时间键缺侧：窗口外未观察
不同于窗口内无数据，应改用 keep 或调整窗口。结果固定包含 absolute/relative 两个视图，
通过同一 Artifact 读取，不分配新的 Run。根没有数值续接，先选择视图。
absolute = current-baseline；relative = (current-baseline)/abs(baseline)，
无量纲，因此 -100 到 -50 的 relative 为 +0.5。零基线只使 relative 为
Undefined(zero_baseline)；溢出或非有限数值使整个 Run 失败。

## 比较不等长时期

沿用流程页的 `customers` 和 `buyer`。两侧每个分组都必须保留完整原网格；筛选
不能重新编号桶。下面输出 `ordinal:1`、`ordinal:2`、`ordinal:3`，第三个对齐键的两视图均为
Undefined(missing_side)，`.show()` 同时展示两侧原时间坐标。

{/* example: period-coverage */}

```python
current_grid = mv.time_grid(
    during=mv.time_scope(start="2026-08-01", end="2026-08-04"),
    grain=mv.grain("day"), timezone="UTC",
)
baseline_grid = mv.time_grid(
    during=mv.time_scope(start="2026-07-01", end="2026-07-03"),
    grain=mv.grain("day"), timezone="UTC",
)
metric = ms.ref.metric("sales.order_count")
current = customers.observe(metric, during=current_grid, via=buyer, by=(mv.member(),))
baseline = customers.observe(metric, during=baseline_grid, via=buyer, by=(mv.member(),))
periods = current.compare(baseline, align=mv.outer(time=mv.ordinal())).execute()
periods.show()
weekdays = current.compare(baseline, align=mv.outer(time=mv.weekday())).execute()
selected = periods.absolute.where(periods.absolute.value.is_defined()).execute()
```

对齐结果及仍保留 aligned 坐标的后续筛选或行统计拒绝时间网格/粒度分组、
时间上卷、runs、forecast 和显式 lag correlate。先在原端点完成这些操作再比较。
普通筛选、行统计、有效成员续接和准入的 exact absolute 归因仍按各自契约工作。
带 `time=mv.ordinal()` 的 one_to_one ratio 使用同一输出形态，要求精确覆盖。

闭合时间键族还包括 `mv.weekday()`、`mv.holiday(current=..., baseline=...)` 和
`mv.holiday_then_weekday(current=..., baseline=...)`。weekday 按 ISO 星期几及其在原网格中的序次配对；
holiday 按相对 occurrence 首日的有符号民用日偏移配对；hybrid 在 occurrence 内按偏移，
在前后按从边界向外计数的同星期序次配对。这三种映射要求单日日粒度网格。
节假日输入来自 `session.catalog.temporal_sets.get(...).occurrence(key)`，必须具有整日边界，
且边界时区与对应网格一致。四种映射均输出规范字符串，例如 `ordinal:1`、`weekday:1:1`、
`holiday:0` 和 `holiday_then_weekday:holiday:0`。键像不等时仍按 exact/outer 覆盖政策处理，
映射及 occurrence 快照身份在 fixed 与 cold 续接中保持冻结。

若模型已认证 UTC 中的 `sales.holidays` 及其 `august`、`july` occurrence，
可用它们构造上述日粒度端点的节假日描述符。

{/* example: holiday-period-correspondence */}

```python
holidays = session.catalog.temporal_sets.get("sales.holidays")
current_holiday = holidays.occurrence("august")
baseline_holiday = holidays.occurrence("july")
holiday_key = mv.holiday(current=current_holiday, baseline=baseline_holiday)
hybrid_key = mv.holiday_then_weekday(current=current_holiday, baseline=baseline_holiday)
holiday_result = current.compare(baseline, align=mv.outer(time=holiday_key)).execute()
hybrid_result = current.compare(baseline, align=mv.outer(time=hybrid_key)).execute()
```

## 继续逻辑选择

`customers`、`revenue`、`buyer`、`august_revenue`由流程页的原始 rollup 示例定义。在物化选择之前构造下游 live 依赖。

{/* example: selected-next-month */}

```python
july = mv.time_scope(start="2026-07-01", end="2026-08-01")
september = mv.time_scope(start="2026-09-01", end="2026-10-01")
baseline = customers.observe(revenue, during=july, via=buyer, by=(mv.member(),))
change = august_revenue.compare(baseline).absolute
falling = change.where(change.value.lt(0)).members()
next_month_mean = (
    falling.observe(revenue, during=september, via=buyer, by=(mv.member(),))
    .aggregate(mv.mean())
    .execute()
)
```

只有 Defined、有限且兼容的值可进入数值谓词。如果中间本地算法要求执行后再继续，跟随接收者 contract。

## 保留比率组成状态

line/order 模型还声明了 `sales.aov_from_lines`及两条关系路径。前述流程已绑定 `customers`、`buyer`、`august`。

{/* example: multi-root-ratio */}

```python
ratio_routes = (mv.path(ms.ref.relationship("sales.line_order"), buyer),mv.path(buyer),)
channel = ms.ref.dimension("sales.order.channel")
aov = customers.observe(
    ms.ref.metric("sales.aov_from_lines"),
    during=august,
    via=ratio_routes,
    by=(mv.member(), channel),
)
overall_aov = aov.rollup().execute()
channel_aov = aov.group_by(channel).rollup().execute()
current_row_mean = aov.aggregate(mv.mean()).execute()
current_row_mean.show()
```

每个不同根需要自身准入映射。原始 ratio rollup 和对显示行比率取均值回答不同问题。

## 构造固定参照

customer 模型有类别 region 和针对订单贡献的 Count Metric。明确参照 strata 与观察单位。

{/* example: reference-standardization */}

```python
members = session.members(ms.ref.entity("sales.customer"))
region = members.read(ms.ref.dimension("sales.customer.region"))
counts = members.observe(
    ms.ref.metric("sales.order_count"),
    during=mv.time_scope(start="2026-08-01", end="2026-09-01"),
    via=ms.ref.relationship("sales.order_buyer"),
    by=(mv.member(),),
)
shares = counts.share_of(counts.rollup())
selected_shares = shares.where(shares.value.gt(0)).execute()
penetration = counts.where(counts.value.gt(0)).members().penetration_in(members).execute()
stratum_counts = counts.group_by(region).rollup()
composition = stratum_counts.share_of(stratum_counts.rollup())
weights = mv.reference_weights(composition, strata=(region,), unit=ms.ref.entity("sales.order"))
standardized = stratum_counts.standardize(reference=weights).execute()
standardized.contract().show()
```

share_of、penetration_in、standardize 使用不同分母。保留的 reference weights 绑定
确切 strata、unit 和 owner，标签不建立兼容性。标准化回答固定组成下的问题。

## 分配绝对变化

customer/order 模型声明了 order count、buyer、channel、region。两个时期使用相同的准入数量含义。

{/* example: absolute-attribution */}

```python
attribution_members = session.members(ms.ref.entity("sales.customer"))
channel = ms.ref.dimension("sales.order.channel")
current_counts = attribution_members.observe(
    ms.ref.metric("sales.order_count"),
    during=mv.time_scope(start="2026-08-01", end="2026-09-01"),
    via=ms.ref.relationship("sales.order_buyer"),
    by=(channel,),
).rollup()
baseline_counts = attribution_members.observe(
    ms.ref.metric("sales.order_count"),
    during=mv.time_scope(start="2026-07-01", end="2026-08-01"),
    via=ms.ref.relationship("sales.order_buyer"),
    by=(channel,),
).rollup()
change = current_counts.compare(baseline_counts).absolute
allocation = change.attribute(axes=(channel,), top_k=3).execute()
selected_allocation = allocation.where(allocation.contribution.value.is_defined()).execute()
allocated_table = mv.table(
    contribution=selected_allocation.contribution,
    current=selected_allocation.current,
    baseline=selected_allocation.baseline,
).execute()
allocation.contract().show()
restored_allocation = session.artifact(allocation.state.artifact_ref)
```

读取贡献、对应 current/baseline 端点、残差与对账。Joint axes 标识组合；
分开的 axes 是各自分解，不能相加。组成方程与保留状态决定可执行的分配。
归因不是因果估计。

## 排名与展示

`counts`、`region`是参照示例中的兼容 relation。并列与分区策略明确。

{/* example: ranking-table */}

```python
ranking = counts.rank(order="descending", ties="min", partition_by=(region,))
defined = ranking.where(ranking.ranks.value.is_defined())
top = defined.where(defined.ranks.value.lte(3))
prefix = ranking.limit(3)
result = mv.table(amount=top.values, rank=top.ranks).execute()
result.show()
frame = result.to_pandas()
restored = session.artifact(result.artifact_ref)
```
{/* example: scoped-channel-observation */}

```python
revenue = ms.ref.metric("sales.revenue")
by_channel = (
    session.members(ms.ref.entity("sales.orders"))
    .observe(
        revenue,
        during=mv.time_scope(start="2026-07-01", end="2026-08-01"),
        by=(ms.ref.dimension("sales.orders.channel"),),
    )
)
top_channels = by_channel.rank(order="descending", ties="ordinal").limit(5).execute()
top_channels.show()
```
{/* example: unscoped-channel-observation */}

```python
revenue = ms.ref.metric("sales.revenue")
by_channel = (
    session.members(ms.ref.entity("sales.orders"))
    .observe(
        revenue,
        by=(ms.ref.dimension("sales.orders.channel"),),
    )
)
by_channel.rank(order="descending", ties="ordinal").limit(5).execute().show()
```

最后两种备选使用 `sales.orders`和 channel 贡献坐标，分别带窗口与不带窗口。
Table 与 `to_pandas()`是终端展示。通过确切 artifact ref 恢复保存的表，
不要将自定义 DataFrame 重新输入已治理组合。
