## 显式选择完整身份

{/* example: explicit-identity-read */}

```python
Orders = session.catalog.entities.get("sales.orders")
fixed_orders = mv.identities(Orders, keys=((4,), (5,), (6,)))
attributes = session.read(fixed_orders, {"region": region}).compute()
chosen_orders = attributes.where(attributes["region"] == "east").compute()
east = session.population_from(chosen_orders, on=((chosen_orders.axes[0], Orders),))
selected = session.observe(
    {"revenue": revenue}, during=august,
    members=east, by=(mv.member(),),
).compute()
selected.show()
session.frame(east).compute().show()
```

identities 捕获完整显式引用，不证明来源存在。复合键保留全部主键分量。
read 要求一个 Entity 身份域与非空命名字段；桥接把精确结果的完整身份轴绑定到显式已解析
Entity，不能把 Field 升级为身份。on 必填，零轴可用 on=()；空投影域仍是空约束。
Population 保持惰性，frame 绑定一般键域。属性 `.at(anchor)` 独立于观察期间。
coord 只接受单物理分量 FrameAxis，复合身份仍保持完整键。

## 保留精确日历边界

{/* example: calendar-query */}

```python
days = august.by(mv.grain("day"))
daily = session.observe({"revenue": revenue}, during=days).compute()
sum_of_days = daily.reduce({"sum_of_days": daily["revenue"].sum()}).compute()
sum_of_days.show()
monthly_source = session.observe(
    {"revenue": revenue}, during=august.by(mv.grain("month")),
).compute()
monthly_source.show()
```

sum_of_days 是当前行标量统计，monthly_source 请求新的来源计算。
即使可加 demo 的总数相同，两者仍是不同问题；没有 Frame 日历粗化或 CalendarAxis.coarsen。
Session instant/time_scope 冻结精确边界；日期与无偏移字符串使用指定时区，aware 输入保持其瞬时。
naive Python datetime、歧义或不存在的民用时刻拒绝。CalendarAxis 保留原名义桶与截断实际桶，
民用日可能有 23 或 25 小时。

## 将窗口附着到 Metric

{/* example: metric-window-query */}

```python
from datetime import timedelta
rolling = session.observe(
    {"revenue": revenue.window(mv.trailing_duration(duration=timedelta(days=7)))},
    during=days,
).compute()
month_to_date = session.observe(
    {"revenue": revenue.window(mv.to_date(grain=mv.grain("month")))},
    during=days,
).compute()
rolling.show(n=5)
month_to_date.show(n=5)
```

每个端点都在自己的 W(t) 上完成完整子 Metric，显示起点不截断回看输入。
trailing_duration 使用经过时间，trailing_periods 使用完整民用或认证期间；since 固定起点，
all_history 无下界，to_date 选择在评估边界结束的重置期间。
命名日历规则是受检查的语义依赖；已绑定快照的 Grain 必须匹配 Session 冻结的认证作用域。
更换窗口或日历需要显式 observe，日历认证不证明来源完备。

## 配对已经完成的端点

{/* example: period-comparison-query */}

```python
current_days = session.time_scope(start="2026-08-01", end="2026-08-04").by(mv.grain("day"))
prior_days = session.time_scope(start="2026-07-01", end="2026-07-04").by(mv.grain("day"))
current_daily = session.observe({"revenue": revenue}, during=current_days).compute()
prior_daily = session.observe({"revenue": revenue}, during=prior_days).compute()
paired = current_daily.compare(prior_daily, match=mv.ordinal()).compute()
paired.show()
```

双方各自仅有一个日历轴，因此 on 可推导，match 仍显式选择。
对应需要相容完整名义分区且实际边界等于名义边界。过滤不重排原 ordinal。
目录中未使用的桶不产生行；exact 检查实际联合行完整配对，outer 保留缺侧及独立 presence。
两种政策均拒绝部分桶。

builtin period_offset 支持 day/week/month/quarter/year；previous_year 支持
 day/month/quarter/year，闰日没有对应。命名日历只支持 ordinal，命名 offset、子日/DST offset
与任意映射延期。规则只消费保存的标签与目录，不重建模型或时区规则。
配对输出保留原始键、两端冻结描述和映射；show 解析标签与边界，不新增 endpoint 方法或 current-only 投影。
