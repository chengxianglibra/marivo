readiness 只检查选定语义闭包和物理声明，不打开数据源。普通 preview 提供有界来源证据。

结合 `status`、`blockers` 和 `warnings` 阅读报告。`blocked` 表示发现至少一个阻塞项；
`ready_with_warnings` 表示没有阻塞项，但仍有警告需要检查。按报告修复阻塞项后重新运行；
状态只描述本次请求的范围。

`analysis_ready_inputs` 列出直接请求且依赖闭包没有阻塞项的物理引用。若要将就绪输入交给后续分析，
应直接请求所需的物理字段或 `Entity` 引用。选择声明式 `Measure` 或 `Metric` 时，会检查其物理依赖，
但派生表达式本身不会作为物理交接输入返回。

通过就绪检查仅表示静态检查范围内没有阻塞项，不代表物理类型兼容、当前来源数据符合预期或业务口径正确，
也不保证后续分析一定能执行。检查物理契约时使用 `catalog.validate(refs)`；检查当前数据预期时，再指定明确的
`ms.source_check` 规则和有界的 `scope`，然后运行实际观察。示例及各检查的区别见[“加载与检查”](/zh-cn/docs/latest/modeling/semantic-layer/#加载与检查)。
