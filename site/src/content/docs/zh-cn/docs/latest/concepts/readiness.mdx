示例需要约定的 `md`/`ms` 导入、已加载 `catalog`及下面所列确切 sales 字段。`amount` 是物理目录字段。

## 就绪检查判断什么

`catalog.readiness(refs=[...])` 对当前物理目录对象、精确引用、编译依赖闭包和
专用时间认证产物做显式零查询检查。它不连接数据源、不读取 schema 或普通 preview
历史，也不导入可选后端客户端。限定范围内保留依赖 warning，排除无关 warning。

已发布的 Measure/Metric 表达式通过 `catalog.describe()` 查看定义；readiness
检查它们消费的物理字段与 Entity。Query 准备与执行负责物理类型、聚合/后端支持和
操作专属资格。分析 API 不会自动调用 readiness。业务描述与 guardrail 缺失不会阻塞它。

## Preview 与 readiness 相互独立

Preview 通过显式有界 scope 直接读取当前数据源：

{/* example: readiness-1 */}

```python
import marivo.datasource as md

preview = catalog.preview(
    catalog.metrics.get("sales.revenue"),
    scope=md.unpruned(max_rows=1000, timeout_seconds=30),
)
```

多实体引用必须传入由精确 `Ref[entity]` 键控的完整 mapping。参数化 JSON source
通过 `source_bindings=` 使用同样的精确实体引用 mapping 形状。Marivo 会在打开连接
之前验证 scope 键、数据源兼容性、正数行数与超时 guard，以及完整 batch。

普通 preview 只返回本次执行结果，不创建 authoring checkpoint，也不会改变
readiness。原生 naive timestamp 如果没有显式 parse 契约，会由当前 preview 直接
报告 `time_parse_risk` warning。

Period calendar、temporal set 与 work schedule 的 preview 同时也是认证路径。
Marivo 会在 scope 的 `max_rows + 1` 边界内读取全部必需列；只有 scope 完整且行值
符合声明时才发布 immutable artifact。`limit` 只限制展示行，不限制认证读取。

## Source health 独立于 readiness

当问题是当前 source 或已声明的数据期望是否发生漂移时，使用
`catalog.source_health(...)`。它不会在 load、preview、readiness 或分析中被隐式
调用，也不保存 checkpoint 或历史。

{/* example: readiness-2 */}

```python
from datetime import timedelta

amount = catalog.fields.get("sales.orders.amount")
health = catalog.source_health([amount])  # connectivity and metadata only

health = catalog.source_health(
    [amount],
    checks=[
        ms.source_check.not_null(ms.ref.measure("sales.orders.amount")),
        ms.source_check.freshness(
            ms.ref.time_dimension("sales.orders.created_at"),
            max_age=timedelta(hours=24),
        ),
    ],
    scope=md.unpruned(max_rows=1000, timeout_seconds=30),
)
```

没有声明 check 时，source health 只执行连接 roundtrip 与权威 schema/capability
inspection；此时省略 `scope`，且不会查询用户数据。Null、enum、uniqueness、
freshness、relationship match 与 cardinality 期望只有通过 `ms.source_check`
显式构造后才存在，并且必须提供正数行数与超时边界。每条结果都会报告
`current`、`failed`、`unavailable` 或 `unknown`、受影响的当前语义引用、类型化
repair，以及是否在什么精确 scope 下查询了用户数据。

运行 source health 不会改变 `ReadinessReport.status`、issues 或
`analysis_ready_inputs`。

## 报告字段

`catalog.readiness(refs=[...])` 返回冻结的 `ReadinessReport`：

| 字段 | 含义 |
| --- | --- |
| `scope` | 固定为 `"semantic_static"`；操作专属执行检查仍由消费 API 负责。 |
| `status` | `"ready"`、`"ready_with_warnings"` 或 `"blocked"`。 |
| `analysis_ready_inputs` | 按请求顺序仅保留完整依赖闭包中没有 blocker 的直接请求物理引用；依赖只进入 `input_summary`。 |
| `blockers` | 阻止受影响请求根进入分析的问题。 |
| `warnings` | 不阻塞的 warning 与 advisory。 |
| `input_summary` | 本次检查涉及的数据源、引用和表。 |
| `checked_at` | ISO-8601 检查时间。 |
| `catalog_definition_fingerprint` | 精确的当前编译语义项目身份。 |

`analysis_ready_inputs` 保留直接选中的物理输入。不再有仅引用投影、
preview-required 列表、认证令牌或隐藏传递对象。

每条 issue 都携带类型化 `repair`，其中包含具体动作和所属 live-help 目标。按 repair
处理后重新运行 readiness，再使用对应的当前 Catalog 值构造分析；报告不授予表达式执行资格。

## 重要 blocker

未知引用、物理声明或依赖问题，以及缺失、过期或无效的时间认证产物会阻塞受影响输入。
聚合与后端不兼容由 Query 准备与执行报告；不会自动替换原定义。

专用时间 artifact blocker 使用 artifact 术语：

- `period_calendar_artifact_missing`、`_stale` 或 `_invalid`
- `temporal_set_artifact_missing`、`_stale` 或 `_invalid`
- `work_schedule_artifact_missing`、`_stale` 或 `_invalid`

其 repair 会指向带完整显式 scope 的 `catalog.preview(..., scope=...)`。认证失败或
scope 被截断时不会发布替代 artifact。

## 继续进入分析

{/* example: readiness-3 */}

```python
import marivo.semantic as ms

catalog = ms.load()
amount = catalog.fields.get("sales.orders.amount")
report = catalog.readiness(refs=[amount])

if report.status == "blocked":
    report.show()
    raise SystemExit

ready_inputs = report.analysis_ready_inputs
```

非阻塞报告只认证所选语义闭包，不保证所有未来查询或操作专属 artifact 形状都能
成功。运行时执行、数据质量和分析专属契约仍由实际消费操作负责。
