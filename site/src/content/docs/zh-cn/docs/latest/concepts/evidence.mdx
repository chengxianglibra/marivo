Store 10 将最终输出保存在 `.marivo/analysis/generations/v10/`。
Parquet 文件持久化后，通过一个 SQLite 事务共同发布 manifest、receipt、Finding、
Evidence 和 Run 成功状态。失败调用不会发布部分 Artifact；恢复只协调原 Run 及其确切
资源 journal，不重放计算。

## 执行并检查 Run

已有解析完成的 `revenue` Metric 和 Session：

```python
query = session.observe({"revenue": revenue})
artifact = query.execute()
print(artifact.id)
print(artifact)
for run in session.runs(limit=5).items:
    run.show()
```

每次 execute 重新求值，创建新的 Run 和 Artifact。Artifact 只持已提交身份与元数据，
没有 `contract()` 或 DSL 续算能力。无来源常量也使用同一发布路径。

## 保存事实与阅读边界

普通观察不产生 Finding。Evidence 只记录实际来源读取与实际检查，包括读取范围；
省略期间明确表示未追加时间约束。这些记录不认证来源完整性、跨来源快照、新鲜度或因果结论。

保存的 schema 描述完整键、命名 nullable 值、独立 presence、类型和单位；
必要输出附件保存 UTC 日历边界，主表及附件的 schema 同时保留所选日历时区；读取范围摘要保留布尔条件的嵌套分组。不保存语义定义、图、公式、隐藏规约组件、计算指纹或 continuation。

R2.5 返回已提交 Artifact 身份。`session.artifact(id)`、`show()`、`to_pandas()`、
`findings()` 和 `evidence_digest()` 仍报告 R2.6 阅读缺口。
公开跨进程打开与有界阅读尚未交付；请保留确切 ID。

旧 Store 及图/continuation 格式明确拒绝，不改写或迁移。更换 Session 名称不能绕过代际限制；
请在新项目创建新格式 Store 并重新运行分析脚本。同代际 Session resume 保留身份和 Run 历史。

从 `marivo.help("analysis")` 开始发现。
