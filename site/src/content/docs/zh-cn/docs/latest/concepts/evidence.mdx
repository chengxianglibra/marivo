Artifact 管理保存的行、保留状态与执行证据；Run 记录执行身份及成功或失败。
跨结果综合、业务判断与因果解释由 Agent 负责。

## 读取产生结果的 Run

`current`与 `baseline`是同一 Session 中兼容的 Logical 数值观察。

{/* example: evidence-producing-run */}

```python
artifact = current.compare(baseline).execute()
artifact.show()
artifact.contract().show()
run = session.get_run(artifact.state.producing_run_ref)
run.show()
```

`contract()`描述保留状态与准入后续操作，不认证文件字节未改变。Logical 值在执行之前没有已提交 Evidence。

## 读取有界 Findings

`artifact`是前述示例的已提交结果。

{/* example: evidence-findings */}

```python
digest = artifact.evidence_digest()
print(digest.finding_count)
findings = artifact.findings(limit=20)
for finding in findings.items:
    finding.show()
run = session.get_run(artifact.state.producing_run_ref)
run.show()
```

Evidence/Findings 与结果共同发布。Finding cursor 属于确切 owning Artifact，
通过 `has_more`、`next_cursor`分页。空 Findings 表示空的已提交集合。
Findings 报告确定性计算事实，不是生成叙事或因果解释。

## 恢复确切成功结果

已有 `session`、`mv`与记录的 `run_id`。读取成功专属字段前先检查 Run variant。

{/* example: evidence-recovery */}

```python
run = session.get_run(run_id)
if isinstance(run, mv.SucceededRun):
    artifact = session.artifact(run.output_artifact_ref)
    artifact.show()
```

Store 9 将项目本地 Parquet 和 SQLite 元数据保存在
`.marivo/analysis/generations/v9/`。信任本地已提交结果、Evidence 和 Findings；
读取解码所需 typed data，不比较内容哈希、不重放 producer、不重新提取 Findings。
缺失或不可读 part、格式不兼容和跨 Session/cursor ownership 仍明确失败。

Store 8 及更早代不能恢复或迁移。在同一项目创建新的 Session 时，Store 9 使用独立目录，旧目录保持不变。
没有 revalidation 或自动重建入口。新的 live 执行创建新结果；恢复保留原结果的确切范围与时间依据。

## 在证据范围内解释

观察描述保留范围。比较与归因是代数的，关联是描述性的，预测是模型输出。
筛选与 Journey/History 汇总保留拟合、assignment、覆盖和删失限制。
它们本身都不建立业务依据、新鲜度或因果结论。

跟随 `marivo.help("analysis.evidence")`，或运行[本地恢复教程](/zh-cn/docs/latest/guides/python-quick-start/)。

已保存的 Artifact 内部使用紧凑 Cell 绑定；`show()` 与 `to_pandas()` 仍保留原有的值、标签和原因字段。旧格式 Artifact 不能恢复或继续执行。请保留历史记录与文件，重新执行来源分析，保存当前格式的 Artifact。旧 Store 代际保留原文件，不执行迁移。
