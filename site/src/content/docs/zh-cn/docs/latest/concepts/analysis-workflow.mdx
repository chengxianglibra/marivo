## 从 Metric 构造 Query

从已声明的模型解析业务表达式。构造 Query 不读取 schema 或业务行，也不创建 Run。

```python
import marivo
import marivo.analysis as mv
import marivo.semantic as ms

session = mv.session.get_or_create("metric-review", report_timezone="UTC")
revenue = session.catalog.metrics.get("sales.revenue")
aov = session.catalog.metrics.get("sales.aov")
region = session.catalog.fields.get("sales.customers.region")
scope = session.time_scope(start="2026-01-01", end="2026-02-01")
query = session.observe(
    {"revenue": revenue, "aov": aov},
    during=scope.by(mv.grain("day")),
    by=(region,),
    where=region == "APAC",
)
query.contract().show()
result = query.execute()
result.show(n=20)
```

每个贡献根到普通分组字段都需要合法的标量路径。用
`field.via((relationship,))` 捕获显式标量角色；版本属性通过
`field.at(session.instant(...))` 绑定精确时刻。绑定保持不可变。
共同条件分别绑定到每个贡献使用位置。普通规约省略 `during` 不追加时间过滤；
时间采样和窗口依赖仍要求显式期间或端点。

## 选择实际坐标或完整坐标域

普通 `by=(region,)` 按实际出现的坐标分组。Population 指定完整有限输出域，
包含明确要求保留的空坐标：

```python
regions = mv.coordinates(by=(region,), keys=(("APAC",), ("EMEA",)))
query = session.observe({"revenue": revenue}, during=scope, by=regions)
keys_only = session.query(regions)
keys_only.execute().show()
```

完整输出域必须覆盖所有实际贡献坐标。空总量按规约的声明策略解释，例如默认 sum 为零。
来源 Null 类别与缺少坐标保持区别。

`session.members(ms.ref.entity("sales.customers"))` 从来源选择实际存在的完整 Entity 身份。
`mv.identities(session.catalog.entities.get("sales.customers"), keys=(("C1",),))` 则捕获明确的身份引用，不证明来源档案存在。
复合主键仍是一个身份轴，包含按声明顺序排列的全部分量。identities 只接已解析 Entity，
裸 Ref 须先通过 catalog 解析。

`query.coord(axis)` 定位标量坐标 Column；构造不读取来源，准备期在 Run 准入和业务编译/读取前
拒绝把复合身份作为单量。完整身份仍保留为输出键，元组筛选用
`query.population()` 与 `mv.in_population(...)`；需要单量坐标值时使用已有单字段轴。

Population 支持 `project(by=...)`、`union`、`intersection`、`difference`，以及
`where(mv.in_population(other))`；谓词使用 `&`、`|`、`~` 组合。
`classify(by=(field,))` 明确读取身份 Entity 的属性。
`image(via=(relationship,))` 沿声明方向取得目标身份；
`preimage(targets, via=(relationship,))` 仅保留接收者中匹配的身份。
缺少必需属性或关系映射会失败；能由完整外键确定的目标引用不会因目标档案缺失而被删除。

`mv.product(regions, calendar)` 按因子顺序形成完整笛卡尔坐标域。
日历坐标绑定与观察期间必须相容，窗口端点仍需显式观察时间绑定。

`query.population()` 捕获该 Query 自己的坐标选择、期间、条件、声明闭包和 Session。
它仍保持惰性，另一次观察不会覆盖已捕获的选择上下文。
通过 `session.query(population)` 发布完整键；Population 没有 `execute()` 方法。

## 通过 Session 读取属性

`session.read(population, {"region": region})` 返回保留完整输入身份键及命名属性量的 lazy Query。读取由显式 Session 拥有，没有 Population.read 别名或 ambient Session 查找。版本字段用 field.at(anchor)，标量路径用 field.via((relationship,))。缺少或重复必需映射在消费时失败，计算 Measure 应交 observe。

## 显式分配重叠成员桶

membership 描述绑定成员分桶字段与贡献分配路径。同一个描述内的多个字段保持相关：

```python
tag = session.catalog.fields.get("sales.tags.label")
order_links = session.catalog.relationships.get("sales.order_links")
link_tags = session.catalog.relationships.get("sales.link_tags")
tags = mv.membership(
    tag, via=((order_links, link_tags),), unmatched="exclude"
)
query = session.observe({"revenue": revenue}, during=scope, by=(tags,))
```

同一完整贡献身份到同一桶的重复映射只计一次；值相同的不同贡献仍分别保留。
多个独立 membership 描述形成独立分配因子。
选择 `unmatched="null"` 可将未分配贡献保留在 Null 桶中。
成员身份域使用相同描述进行 classify 时，直接读取成员字段，
并为后续观察保留分配定义，不在分类时执行分配路径。

## 规约完整的内部 Metric 样本

`per` 先在每个样本坐标求完整 Metric 公式，再规约这些值。
因此每客户比率的均值与总体比率保持不同含义：

```python
customer = session.catalog.fields.get("sales.orders.customer")
customers = mv.coordinates(by=(customer,), keys=((1,), (2,), (3,)))
query = session.observe({"mean_customer_revenue": revenue.per(customers).mean()})
```

字段或 membership 描述使用实际样本。显式 Population 选择完整内部样本，
空样本按各自规约策略处理。内部样本可以选择子域；外部输出域必须覆盖实际输出坐标。
整个组合过程保留精确坐标类型与 Session 归属。

## 在 Metric 上声明端点窗口

窗口规则属于 Metric；观察提供评价端点：

```python
from datetime import timedelta

rolling = revenue.window(mv.trailing_duration(duration=timedelta(days=7)))
query = session.observe(
    {"rolling_revenue": rolling},
    during=scope.by(mv.grain("day")),
    by=(region,),
)
```

`all_history()` 没有下界，`trailing_duration` 使用实际经过时长，
`trailing_periods(count=...)` 要求日历期间，`since(start=...)` 保留精确固定起点，
`to_date(grain=...)` 在民用或语义期间边界重置。
所有窗口都在端点之前按左闭右开范围取贡献；实际裁剪后的输出端点与名义日历边界保持区别。

## 执行并读取已提交输出

执行先准备真实来源 schema 并固定计划，再准入 Run。每次调用重新求值输入，
原子发布 Artifact。纯有限键程序在完成必需的类型准备后本地执行；
来源驱动的域和 Metric 使用已获准的 datasource 读取。

Artifact 是终端结果，可调用 `show(n=20)`、`to_pandas()`、`findings()` 和
`evidence_digest()`。完整 pandas 导出是独立副本。
用 `session.artifact(result.id)` 打开精确保存的 ID，不恢复计算也不读取当前来源。
Artifact 不能成为语义表达式输入。

准备失败不创建 Run。准入之后的失败可通过错误中的 `run_ref` 调用
`session.get_run(run_ref).show()` 检查；重试是新的执行调用。
预览上限不截断执行或完整导出。

使用 `marivo.help("analysis.Population")`、`marivo.help("analysis.membership")`、
`marivo.help("analysis.Query.population")` 和 `marivo.help("analysis.windows")`
查看聚焦的当前合同。
