告诉 Agent 业务问题、已确认的指标、人群和比较范围。Agent 选择能够回答问题的方法和结果检查点；你无需指定算子调用或展示步骤。

## 构造与执行

一次调查使用一个 Session。源构造器和 Dataset 方法只描述工作，不查询数据源；显式执行后返回可检查、可继续使用的不可变结果。

```python
import marivo
import marivo.analysis as mv
import marivo.semantic as ms

session = mv.session.get_or_create("revenue-review", report_timezone="UTC")
revenue = ms.ref.metric("sales.revenue")
current = session.observe(
    revenue, time_scope=mv.time_scope(start="2026-07-01", end="2026-08-01")
).aggregate()
baseline = session.observe(
    revenue, time_scope=mv.time_scope(start="2026-06-01", end="2026-07-01")
).aggregate()
change = current.compare(baseline).execute()
change.show()
```

示例要求项目已定义具有明确源类型和参考时间轴的 `sales.revenue` 指标。窗口为左闭右开，结束边界不包含在内。`aggregate()` 显式移除 Entity 身份轴；时间序列还需声明时间轴和粒度。Population 成员选择与指标观测窗口相互独立。

## 按确切语义继续分析

字段选择器属于取得它的那个 Dataset。使用类型化谓词、投影、排序和显式坐标聚合。对持久化结果调用方法时，计算从其保留行及必要的私有贡献状态开始，保持身份和合法聚合语义。均值不能作为可加值直接求和；筛选后的比率和 distinct 集合保留真实组成状态。

比较、归因、相关性、预测和发现属于 Dataset 方法。Event 匹配从 `session.events.match(...)` 开始，Lifecycle 回放从 `session.lifecycle.replay(...)` 开始。它们的下游方法属于返回的 Dataset，并消费已保留的匹配或历史。不同 Session 的输入不能混用。

## 检查证据与恢复

`contract()` 描述机械上合法的继续操作；Materialized Dataset 的 `show()` 提供有界结果检查。通过所属 Session 读取确切 Finding 或恢复 Artifact。展示少量行不代表计算可以省略其他输入。参见[证据](/zh-cn/docs/latest/concepts/evidence/)。

本地 Parquet 结果存储不需要配置。只有明确需要其他位置时，才在 `marivo.toml` 配置对象存储。执行不使用数据库结果存储，也不在失败后切换目标或执行器。冷恢复保留确切存储和时间语义；旧 Store 代际被拒绝，原文件不会被改写。

## 保持判断明确

当指标、人群、比较方式或重要假设需要改变时，确认新的业务含义。可复用的语义缺口归属语义建模。分位数默认使用精确线性插值；只有明确接受近似语义时，才选择 `ms.quantile_metric(..., method="duckdb_tdigest@v1")`。投影与恢复保持这一选择。

归因是代数分解，相关性是描述性结果，Candidate 分数是调查线索，预测带有模型假设。Agent 负责综合判断与结论。`to_pandas()` 或 `md.raw_sql(...)` 的自定义分析是终端出口，结果不能重新注入受治理的 Dataset 组合。

从 `marivo.help("analysis")` 开始发现能力，沿原生入口、方法、输入、Artifact、证据和 Runtime 导航读取准确签名和示例。结构化错误提供具体修复；打包技能负责工作流判断。

准确导航入口为 `analysis.entry`、`analysis.methods`、`analysis.inputs`、
`analysis.artifacts`、`marivo.help("analysis.evidence")` 和
`marivo.help("analysis.runtime")`；终端出口由
`marivo.help("analysis.actions.to_pandas")` 说明。


## 按当前任务逐步发现能力

`analysis.entry` 连接 Session 创建或恢复，以及 Metric、Event、Lifecycle 的分析起点。
`analysis.inputs` 负责缺失输入：沿 catalog 精确取得已确认的语义对象，只检查所需闭包的 readiness；人群、时间、完整性声明和模型假设各有具名分组。
`analysis.methods` 按汇总、比较归因、关联、预测、筛查及事件和生命周期等任务分组，不需要遍历全部页面。

已有 Dataset 时，读取 `dataset.contract().show()`，沿当前允许动作提供的准确 Help target 继续。类型与成员仍可按需精确查询；也可以把已取得的公共方法传给 `marivo.help(...)`。
聚焦叶子列出这次调用所需的前提和返回值路径。读取这些信息足以执行下一步时，就保存并运行最小分析脚本。

同一 Session 中相同执行定义命中的是已提交快照。若问题要求当前源数据，应使用新的命名 Session，或改变明确影响行的定义输入；重复执行不能证明数据已刷新。
恢复后的完整性检查分别检查 Artifact、存储权限和 Evidence，不证明当前语义有效或源数据新鲜。
