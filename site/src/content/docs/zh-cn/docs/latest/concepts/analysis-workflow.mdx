告诉 Agent 业务问题、已确认的指标、人群和比较范围。Agent 选择能够回答问题的方法和结果检查点；你无需指定算子调用或展示步骤。

数据源连接成功和语义就绪不代表该分析方法能在此源执行。通过
`marivo.help("analysis.actions.execute")` 查看执行边界，结合 Dataset contract
和不支持形状的结构化修复建议继续。远程源需要只读账号；不支持通过上传
retained 结果绕过准入限制。
`md.register()` 只保存数据源声明，不加载分析执行代码。执行准入只加载所选后端；若该后端依赖缺失，
会在连接数据源前给出结构化修复建议。

当前 R1 过渡期，合格的单表、无时间范围 Population 扫描/过滤及 sum/count Metric
聚合通过内部 `SourceSession` 执行。DuckDB 和 SQLite 有本地基础读取证据；MySQL
有单列身份的 Population 表/视图及 sum/count 表格证据。PostgreSQL、Trino 和
ClickHouse 的 adapter 基础读取证据不转授所有 Dataset 方法或物理形态。基础 Metric
路线还支持按直接维度分组。
其他旧来源型 `Dataset.execute()` 路线会在创建 Run、读取来源之前以
结构化 `source_admission` 错误拒绝；错误指出需要完成的 R5–R8 方法迁移阶段。

目标源执行只检查完整计算所需的列，包括隐藏 Metric、身份字段、关系键和版本坐标。
Analysis 信任 Entity 的身份和时间声明，不对源数据进行自动预检。
未使用的复杂列不会阻止已支持的标量计算。例如，下文收入计算的表即使还声明了
未使用的 JSON payload，也可以执行；这不代表引用 payload 获得了新的类型或方法支持。
可选列注释在数据源检视中可能标为 unavailable，包括当前 Dataset 未使用的列。
准入必需的物理事实缺失时，对应来源形态保持阻断。

## 构造与执行

一次调查使用一个 Session。源构造器和 Dataset 方法只描述工作，不查询数据源；显式执行后返回可检查、可继续使用的不可变结果。

下例展示目标来源工作流；其中的 `execute()` 在 R1.1 期间会被阻断，须等方法迁移并取得资格。

```python
import marivo
import marivo.analysis as mv
import marivo.semantic as ms

session = mv.session.get_or_create("revenue-review", report_timezone="UTC")
revenue = ms.ref.metric("sales.revenue")
current = session.observe(
    revenue, time_scope=mv.time_scope(start="2026-07-01", end="2026-08-01")
).aggregate()
baseline = session.observe(
    revenue, time_scope=mv.time_scope(start="2026-06-01", end="2026-07-01")
).aggregate()
change = current.compare(baseline).execute()
change.show()
```

示例要求项目已定义具有明确源类型和参考时间轴的 `sales.revenue` 指标。窗口为左闭右开，结束边界不包含在内。仅含日期的边界按 Session 持久化的报告时区解释；应为所需日历显式设置 `report_timezone`。`aggregate()` 显式移除 Entity 身份轴；时间序列还需声明时间轴和粒度。Population 成员选择与指标观测窗口相互独立。
可用 `population.where(...)` 缩小 Entity 成员范围；Analysis 不提供 Entity 抽样。

对于已配置 DuckDB 来源且通过准入的 J1–J4 Entity 域，从
`session.members(Entity Ref)` 开始。成员域提供 `read`、`group_by` 和
`observe`；返回的关系提供筛选、比较、rollup、行统计与关联。
`marivo.help("analysis.entry")` 会将 Entity 成员问题指向此入口；
上面的 `session.observe` 示例仍用于既有 Dataset 形状。当前成员来源路径要求事件时间维度的时区为 UTC；其他时区或无法确定时区的时间轴会被拒绝。例如：

```python
customers = session.members(ms.ref.entity("sales.customer"))
revenue = ms.ref.metric("sales.revenue")
buyer = ms.ref.relationship("sales.order_buyer")
august = mv.time_scope(start="2026-08-01", end="2026-09-01")
august_revenue = customers.observe(revenue, during=august, via=buyer)
total = august_revenue.rollup().execute()
total.show()
restored = session.artifact(total.state.artifact_ref)
restored.contract().show()
for action in restored.contract().actions:
    print(action.call, action.help_target)
```

此形状要求项目已经编写并准入相应 Entity、Metric 与 Relationship。
每次执行逻辑来源分支都会重新读取来源；固定续算可命中已提交的精确执行键。
`session.artifact(ref)` 依据校验过的快照与保留部件恢复公开 J1–J4 结果，
不读取当前来源或 Semantic 目录。其他 Analysis 能力继续使用原有入口。
有界结果卡会展示已有的单位、方法、Cell 字段和当前行权重，并遮蔽 Entity 成员键。
每个 `AnalysisAction` 给出当前结果可执行的调用形式和对应的精确
`marivo.help("analysis.<target>")` 路由。contract 反映声明的保留部件；
如需验证底层文件完整性，应显式执行 Artifact revalidation。

同一项目若还声明 `sales.order_count`、`sales.aov_from_lines`、
`sales.order`、`sales.order_line` 和 `sales.line_order`，可继续运行其余
已准入的 J1–J4 形状：

```python
july = mv.time_scope(start="2026-07-01", end="2026-08-01")
september = mv.time_scope(start="2026-09-01", end="2026-10-01")
baseline = customers.observe(revenue, during=july, via=buyer)
change = august_revenue.compare(baseline)
falling = change.where(change.value.lt(0)).members()
next_month_mean = falling.observe(
    revenue, during=september, via=buyer
).summarize(mv.mean()).execute()

ratio_routes = mv.routes(
    mv.route(
        ms.ref.entity("sales.order_line"),
        through=(ms.ref.relationship("sales.line_order"), buyer),
    ),
    mv.route(ms.ref.entity("sales.order"), through=(buyer,)),
)
aov = customers.observe(
    ms.ref.metric("sales.aov_from_lines"), during=august, via=ratio_routes
)
overall_aov = aov.rollup().execute()
current_row_mean = aov.summarize(mv.mean()).execute()

order_count = customers.observe(
    ms.ref.metric("sales.order_count"), during=august, via=buyer
)
association = august_revenue.correlate(order_count, method="spearman").execute()
coefficient = association.coefficient
negative = coefficient.where(coefficient.value.lt(0)).execute()
```

`rollup()` 依据保留的原始组件重新计算；`summarize(mv.mean())` 对当前行
等权求均值。Spearman 只描述同一观测范围内完整成员配对的关联，不构成因果判断。

## 按确切语义继续分析

字段选择器属于取得它的那个 Dataset。使用类型化谓词、投影、排序和显式坐标聚合。对持久化结果调用方法时，计算从其保留行及必要的私有贡献状态开始，保持身份和合法聚合语义。均值不能作为可加值直接求和；筛选后的比率和 distinct 集合保留真实组成状态。

比较、归因、相关性、预测和发现属于 Dataset 方法。Event 匹配从 `session.events.match(...)` 开始，Lifecycle 回放从 `session.lifecycle.replay(...)` 开始。它们的下游方法属于返回的 Dataset，并消费已保留的匹配或历史。不同 Session 的输入不能混用。
Event 漏斗比较要求队列窗口时长、时间域和后续跟踪偏移一致。漏斗归因需要从完整旅程或通过 `session.artifact(ref)` 打开的旅程检查点逻辑构建两侧漏斗；已物化的漏斗汇总或漏斗 Delta 不能替代这些旅程输入。

当前源端执行支持 DuckDB 和下述 PostgreSQL 标量子集；数据源建模支持某个后端，不代表 Dataset 已能在该后端执行。不支持的方法会报告后端与输入形状。保留结果不会被隐式上传到其他来源，同一 Session 的执行键命中不需要连接来源。

## 检查证据与恢复

对于源端 Metric 和 Population 图，`contract()` 会展示所选后端的静态源准入结果：`rejected` 包含拒绝原因，`static_pass` 只表示纯静态检查通过；含 retained Artifact 输入的图显示 `not_checked`。最终 placement 仍由 `execute()` 决定。contract 也描述机械上合法的继续操作；Materialized Dataset 的 `show()` 提供有界结果检查。通过所属 Session 读取确切 Finding 或恢复 Artifact。展示少量行不代表计算可以省略其他输入。参见[证据](/zh-cn/docs/latest/concepts/evidence/)。
预览中的时长列会明确标注微秒单位；`to_pandas()` 会将这些列转换为 timedelta。

分析结果始终使用项目本地 Parquet，没有结果存储配置。执行不使用数据库结果存储，也不在失败后切换执行器。冷恢复保留确切存储和时间语义；Store 使用 generation 6，旧文件不会被迁移或改写。

## 保持判断明确

当指标、人群、比较方式或重要假设需要改变时，确认新的业务含义。可复用的语义缺口归属语义建模。分位数默认使用精确线性插值；只有明确接受近似语义时，才选择 `ms.quantile_metric(..., method="duckdb_tdigest@v1")`。投影与恢复保持这一选择。

归因是代数分解，相关性是描述性结果，Candidate 分数是调查线索，预测带有模型假设。Agent 负责综合判断与结论。`to_pandas()` 或 `md.raw_sql(...)` 的自定义分析是终端出口，结果不能重新注入受治理的 Dataset 组合。

从 `marivo.help("analysis")` 开始发现能力，沿原生入口、方法、输入、Artifact、证据和 Runtime 导航读取准确签名和示例。结构化错误提供具体修复；打包技能负责工作流判断。

准确导航入口为 `analysis.entry`、`analysis.methods`、`analysis.inputs`、
`analysis.artifacts`、`marivo.help("analysis.evidence")` 和
`marivo.help("analysis.runtime")`；终端出口由
`marivo.help("analysis.actions.to_pandas")` 说明。


## 按当前任务逐步发现能力

`analysis.entry` 连接 Session 创建或恢复，以及 Metric、Event、Lifecycle 的分析起点。
`analysis.inputs` 负责缺失输入：沿 catalog 精确取得已确认的语义对象，只检查所需闭包的 readiness；人群、时间、完整性声明和模型假设各有具名分组。
`analysis.methods` 按汇总、比较归因、关联、预测、筛查及事件和生命周期等任务分组，不需要遍历全部页面。

已有 Dataset 时，读取 `dataset.contract().show()`，沿当前允许动作提供的准确 Help target 继续。类型与成员仍可按需精确查询；也可以把已取得的公共方法传给 `marivo.help(...)`。
聚焦叶子列出这次调用所需的前提和返回值路径。读取这些信息足以执行下一步时，就保存并运行最小分析脚本。

一次执行中的主结果和必要附属结果可能观察到不同的源数据状态。Marivo 保留必要的 Artifact 校验、单次求值和原子发布，但不会仅因查询之间源数据发生变化而拒绝或重试。

Entity 域 J1–J4 的逻辑来源执行每次都会重新读取来源；固定续算可命中同一个精确 Artifact，
并可通过 `session.artifact(ref)` 显式恢复。其他 Dataset 路径保留各自所属的执行键行为。
恢复后的完整性检查分别检查 Artifact、存储权限和 Evidence，不证明当前语义有效或源数据新鲜。

## 本地执行与资源责任

本地计算和 `to_pandas()` 在调用 Python 进程中同步执行，完整返回结果或抛出保留原始原因与调用栈的异常。Marivo 不启动执行或读取 worker，也不设置执行行数、字节、内存、spill、方法复杂度、存储或时限预算。数据库、驱动、操作系统与外部 runner 的限制仍然适用。

`show()` 保持展示长度限制；完整输入校验、所有权和原子发布保持不变。Store 使用 generation 6，旧代文件保持原样，旧 Session 不迁移或恢复。

已支持的执行不要求引擎、驱动或 Ibis 版本认证。正常表达式编译保留参数、完整结果与必要校验顺序；重复编译本身不会再次提交查询。

取消或关闭失败可能使远端只读查询状态未知。Marivo 如实记录这种不确定性；本地发布安全后，同一 Session 可继续工作。未确定的提交状态与冲突写入者仍会阻塞恢复。失败 Run 表示没有成功的本地输出，不证明服务端查询已停止。提交结果不明确时，不自动重新提交动作。

## 后端实现边界

下面的后端和方法描述保留重构前的资格历史，不为当前 R1 checkout 的旧来源
方法授予执行资格。Event、Lifecycle、Attribution、mean、带时间范围的观察、
排名及其他非基础方法在完成 R5–R9 迁移与后端重新验收前，会在
`source_admission` 拒绝。当前证据以 Dataset contract 和
仓库中的 R1 验收记录为准。

算子共享同一套语义契约和后端注册机制。DuckDB 保留已有采样、Event/Lifecycle 和
Candidate 实现；普通结果批次使用 Ibis 与受控 Arrow reader，临时资源、宏和注册仍属于单次动作。
远程实现必须兼容无写入、无创建表或视图权限的账号，并满足相同语义要求后才能启用。
精确类型、增量读取或共享快照确有需要时，保留专用传输。没有可用实现时明确拒绝，不会隐式把源数据搬到其他
引擎执行。PostgreSQL、MySQL、SQLite、Trino 与 ClickHouse 支持下述子集。


### 关系方法与原生日期分析

在各后端已支持的表和物理类型范围内，还可以使用直接列上的 mean、weighted mean、
ratio、同源关系、原生日期桶（单单位 day/week/month/quarter/year）以及 snapshot/validity
成员选择。五个远程后端都支持两种 validity 区间闭合方式及已配置的开放端哨兵。
版本选择使用声明的时间边界；不再自动扫描源数据核验身份与时间。

对于已声明的均值 Metric，先保留充分组成状态，再进行 rollup：

```python
mean_amount = ms.ref.metric("sales.mean_amount")
channel = ms.ref.dimension("sales.orders.channel")
means = session.observe(mean_amount).with_dimensions(channel).aggregate().execute()
overall = means.rollup(drop_dimensions=(channel,)).execute()
overall.show()
```

rollup 从保留的 sum/count 状态重新计算均值，不对分组均值直接平均。
比较与归因使用完整的非 Entity 保留轴；Forecast、Kendall 和时间发现方法在源端完整
聚合后于调用进程执行。冷读与保留结果折叠不需要原始数据源。

线性 Metric 图与计算型 Measure（对单一 Entity 已声明列的行级表达式）已在六个后端
启用；组合 Decimal 结果按发布单元逐个判定：Decimal 线性结果在后端 scale 契约公开时
逐值精确，Decimal 分量上的 mean/div 仍不支持并给出具体引擎原因（逐后端矩阵见所属
设计规范）。语义日历桶与累计 Metric 图已在五个远程后端启用，运行在原生 civil-date
轴且日历快照一致时；其余任何 source requirement 仍然拒绝。所有已准入的累计
anchor 形态都在每个后端准入，包括财政复合形
`ms.cumulative(anchor=ms.grain_to_date(grain=<认证日历粒度>))`；该复合形当前由
DuckDB oracle 旅程执行，五个远程后端的执行证据随 C7/C8 日历工作排期。status-time 折叠按后端
准入：PostgreSQL、SQLite、Trino 与 ClickHouse 支持 first/last/mean/min/max，MySQL
支持 mean/min/max，first/last 等待引擎 argmin/argmax 支持，percentile 折叠在所有
后端仍拒绝。未确定精度的 Decimal mean/div 结果仍不支持。直接 Measure 键及 Entity 身份键的精确去重已在
PostgreSQL、MySQL、SQLite、Trino 和 ClickHouse 启用；SQLite/MySQL 在 SQL 中逐列去重有类型的身份字段，
私有 part 保持原有 Arrow struct。精确线性插值 median/percentile 已在五个远程后端启用。远程
`duckdb_tdigest@v1` 以及 percentile status-time 折叠仍未准入。五个远程后端已支持在源端对完整私有配对做 Entity Pearson 和 Spearman 相关性归约；Kendall 继续使用完整输入的本地续算。
PostgreSQL、SQLite、Trino 与 ClickHouse 支持基于完整非 Entity 状态的隐藏轴展开加性与组件归因。MySQL 的组合查询在实测中超过验收服务的内存限制，因此仍拒绝；Trino 的展开 Top-K 查询超过服务的 stage 上限，也保持拒绝。PostgreSQL 支持精确的两步或三步 `session.events.match(...)` 旅程，以及包含两个触发 Event 的 `session.lifecycle.replay(...)` 历史；要求未版本化表源和 `int64` 主体、事件身份。直接 Event 漏斗、耗时和主体选择，以及 Lifecycle 状态分布、转移、停留、违规和主体选择均已验收。完整 PostgreSQL 漏斗可通过既有保留结果路径继续比较和归因。

ClickHouse 和 Trino 支持相同表源与身份条件下的两步旅程，匹配策略包括 `first_per_subject()` 和 `every_start()` 的共享／独占完成分配。Trino 的真实验收使用 Iceberg；ClickHouse 要求只读账户获准设置 `enable_materialized_cte=1`。空输出也执行源端断言，只有契约允许的完整结果进入既有本地续算。Trino 还支持直接无分组漏斗、first-per-subject 耗时、主体选择和完整无分组漏斗比较。Trino 分组漏斗的核对查询超过验收服务的 stage 上限，因此分组漏斗和依赖它的归因保持拒绝。ClickHouse 的直接 Event 派生方法与主体选择仍因计划或内存限制保持拒绝。Trino（Iceberg）和 ClickHouse（MergeTree）还支持相同表源条件下的双触发 Event Lifecycle history，主体与事件身份各限定为一个 `int64` 分量：使用源端数组折叠完成全量重放，并验证并列顺序是否有歧义。先执行 history，再从完整保留结果继续状态分布、转移、停留、违规和主体选择；这两个后端的直接源端 Lifecycle 派生方法仍未开放。SQLite、MySQL 的 Event/Lifecycle 仍未开放。

对于已验收的 PostgreSQL、Trino 或 ClickHouse 模型，先执行 history，再从保留结果继续：

```python
history = session.lifecycle.replay(
    model,
    window=window,
    seed=mv.from_inception(),
    completeness=lifecycle_completeness,
)
retained_history = history.execute()
transitions = retained_history.transitions().execute()
transitions.show()
```

其中 `model` 是包含两个触发 Event 的受治理 StateModel，`window` 是带时区的时间范围，`lifecycle_completeness` 提供从源头开始的覆盖声明。源端完成完整回放，发布结果保留冷进程续算需要的组成部分。

采样、Entity candidates 和源端 driver screening 仍不支持。
字符串时间解析与多单位桶按后端逐步启用，限制见下节。
不支持的形状会返回具体原因，不会隐式收集原始源数据或向远端上传保留结果。

### 原生 timestamp 时间分析

六后端已准入的原生 timestamp 支持微秒以内的类型匹配谓词，以及 count=1 的小时/日桶。
PostgreSQL 包含 timestamptz；MySQL TIMESTAMP 与 ClickHouse DateTime/DateTime64 的
aware 声明保留 instant。ClickHouse timestamp 执行要求已验证的 UTC reader 时区；
列时区和报告时区仍可为非 UTC。既有显式 UTC civil 绑定继续验证，不能把非 UTC 物理 instant
重新标成 civil。Trino 使用 Iceberg 实际暴露的 timestamp(6)。SQLite 保持规范 civil
文本，通过连接内确定性时间函数计算，不搬运完整源表。

显式原生 parser 时区优先于 reader 时区；仅引擎没有探测能力时允许有来源记录的
系统 fallback。需要 reader 权威而探测失败或名称非法时直接失败；已有物理 instant
或显式 parser 时不依赖额外探测。reader/report 支持 IANA 与固定偏移，parser 声明
保持既有 IANA 校验。Session 保存 report 权威，冷读不会随主机 TZ 改变。

范围先按 instant 做半开比较，再生成报告时区 civil 桶。源端 naive gap/fold 时间不做预检，转换遵循声明的时间权威及后端行为；
两个已知 instant 落在重复的报告小时内时归入同一 civil 桶。naive 谓词字面量比较
civil 字段，aware 字面量比较 instant，混用拒绝。微秒 SQL 边界、Arrow/Parquet 和
源离线冷读必须保真；小时到日续算复用保存的时间事实。远程 epoch 解析与
新 timestamp 版本选择仍不受支持。

### 字符串时间解析与多单位桶

用显式 parser 声明的时间维度（`ms.strptime(...)`）在 DuckDB、SQLite、MySQL、
PostgreSQL、ClickHouse 与 Trino 上于源端执行，包含复合小时前缀轴。执行请求查询前
不扫描源单元格的格式有效性；后端解析可能产生 NULL 或报错。PostgreSQL 的 `TO_TIMESTAMP` 对格式不匹配的文本较宽松，
格式看错但形状合法的单元格可能得到错误 instant。Trino 接受 `%f`，结果遵循 `date_parse`
原生的毫秒精度；六位小数秒的后三位可能丢失。

多单位桶（`mv.grain(unit, count=...)` 且 `count > 1`）以该 civil 日本地午夜为锚点，
且只准入宽整除以一个 civil 日的 count；`mv.grain("hour", count=7)` 直接失败而不是
任选一个起点。由于锚点是 civil 边界，跨春季 gap 的 6 小时桶实际为 5 小时、跨秋季
fold 的为 7 小时，而 DST 当天本身仍从本地午夜起算。

```python
import marivo.analysis as mv
import marivo.semantic as ms

orders_by_hour = (
    session.observe(
        ms.ref.metric("sales.revenue"),
        time_scope=mv.time_scope(start="2026-07-01", end="2026-07-03"),
    )
    .with_time_axis(ms.ref.time_dimension("sales.orders.order_time"), grain=mv.grain("hour"))
    .aggregate()
    .execute()
)
orders_by_hour.rollup(grain=mv.grain("day")).execute().show()
```

SQL 诊断来自 adapter 的实际提交，记录 source/local 执行域、角色和提交/成功/失败状态。
仅编译不算提交；未观测的 driver 连接初始化与事务协议流量不宣称已捕获。

### PostgreSQL 标量 Metric

PostgreSQL Group A 接受单个数据源、单张未版本化表，以及直接列上的 `sum`、`count`、
`min`、`max` Metric。可以选择 Population 成员、按原生日期限定观察范围、添加维度、
聚合 Entity 行、过滤、投影 Metric、确定性排名和选择 Top-N。整个依赖图都必须受支持，
包括被投影移除的 Metric。

例如，`sales.revenue` 是求和 Metric，`sales.orders.channel` 是同一 PostgreSQL
表上的直接列维度：

```python
revenue = ms.ref.metric("sales.revenue")
by_channel = session.observe(
    revenue,
    time_scope=mv.time_scope(start="2026-07-01", end="2026-08-01"),
).with_dimensions(ms.ref.dimension("sales.orders.channel")).aggregate()
top_channels = by_channel.rank(by_channel.fields.metric(revenue)).limit(5).execute()
top_channels.show()
```

所有必要源列必须使用 Boolean、string、有符号整数、float32、float64、date、
精度为 0–6 的 timestamp/timestamptz 或 Decimal。PostgreSQL CHAR 因尾空格语义不同而拒绝，text/varchar 保持支持。Decimal 精度最大为 38，scale 从零到精度；
未指定精度的 Decimal 声明仍需通过实际元数据校验。带时区的字符串解析、采样、
组合 Metric 和私有状态方法不在此子集内。

使用没有写入、CREATE、TEMP 权限的 PostgreSQL 只读账户。查询通过明确管理的
服务端游标分批传输，不创建临时表、不上传数据、不创建 UDF。验证与结果查询可能
观察到不同的来源状态。失败保留原始异常，且不会发布部分输出。保留结果继续使用
现有读取器，不会导入 PostgreSQL。


### MySQL 与 SQLite 标量 Metric

上面的 Group A 流程同样适用于单张未版本化的 MySQL 或 SQLite 表：直接列上的
`sum/count/min/max`、Population、日期限定观察、维度、聚合、过滤、投影、确定性排名与 Top-N。
例如，已声明的 `sales.revenue` 和渠道维度可以使用相同调用：

```python
revenue = ms.ref.metric("sales.revenue")
by_channel = session.observe(revenue).with_dimensions(
    ms.ref.dimension("sales.orders.channel")
).aggregate()
by_channel.rank(by_channel.fields.metric(revenue)).limit(5).execute().show()
```

MySQL 支持表和视图，要求只读账户，文本限定 utf8mb4_0900_bin，支持 signed/unsigned 整数、
浮点、DATE、明确精度不超过 38 的 Decimal，以及 DATETIME(0–6)。TIMESTAMP(0–6)
还需验证 UTC 会话。显式 Boolean 声明仅兼容 TINYINT(1)，必要列必须为 0/1/NULL；
普通整数声明仍保持整数。CHAR、BIT、ENUM/SET、嵌套类型及通用 Decimal 源声明不准入。
非法日期/时间在发布前失败；整数 SUM 精确解码为现有 int64 结果，越界失败。

SQLite 主库普通表和视图支持整数声明别名（统一 int64）、REAL/DOUBLE/FLOAT（float64）、
BINARY 排序的 TEXT/CLOB/CHAR/VARCHAR（string），以及规范 DATE。BOOL/BOOLEAN
必须实际存储整数 0/1/NULL；DATETIME/TIMESTAMP 必须为固定宽度、无偏移的
`YYYY-MM-DD HH:MM:SS.ffffff` 文本，年份 0001–9999 且日期时间合法。即使输出为空也检查
全部必要列。unsigned、Decimal、SQLite 原生 aware 时间存储、虚拟表及附加数据库仍不支持；NaN 写入后成为
NULL，无法恢复原区别。普通 timestamp 支持精确传输、分组、排序和类型匹配的时间谓词。
UInt64 身份及 min/max 通过 Arrow、Parquet 和冷读保留全值域，不经 float 或有损 int64。

两个适配器保留精确的复合身份，直接按驱动批次读取，不经 pandas 全量中转。
MySQL 非缓冲游标提前关闭时可能排空未读响应，不承诺硬取消时限或内存上限。
SQLite 原生游标逐步读取，但引擎内部仍可能物化排序或聚合。批次限制行数而非字节数，
单个值仍会完整解码。SQLite 执行启用 query-only。校验与输出查询可能观察到不同源状态，结果仍原子发布。
保留结果使用 Parquet 和现有读取器，不上传到来源。关系与组合指标的扩展见上文；采样和源端私有状态高级方法仍未启用。

### Trino 标量 Metric

Trino Group A 支持单个数据源、单个未版本化的普通关系——表或视图——以及直接列上的
`sum`、`count`、`min`、`max`、Population 过滤、原生日期范围、同 Entity 维度、聚合、
投影、排名与 limit。沿用现有 catalog/schema/table 声明；元数据和执行 SQL 都解析
元组及 `catalog.schema` 字符串覆盖。connector 身份和关系形式只是观测回执，不是门禁：
任何 connector 的普通关系都准入，仅 `$` 内部表被拒绝。

物理输入为有符号整数、float32/64、VARCHAR、DATE，以及明确
精度和小数位且精度不超过 38 的 Decimal，并支持 Boolean 和无时区 timestamp(0–6)。当前观测到的 Iceberg connector 将精度 0 或 3 的建表声明暴露为 timestamp(6)，绑定必须匹配实际元数据精度。
CHAR、通用 Decimal 源声明、带时区或超微秒时间戳、嵌套值均不支持。声明的浮点列只接受有限值或 NULL；
即使输出为空，源检查也拒绝 NaN/Infinity，非有限聚合结果不得发布。Decimal 与整数
身份保持精确值，排名保留明确的 NULL 顺序和确定性的并列处理。

使用有 connector 和表元数据读取权限的只读身份。正常 Ibis 编译配合驱动增量分页，
内部身份结构由类型化标量列重建；batch 不是字节或内存限制。驱动与服务端限制属于
外部限制。提交前登记活跃 cursor；取消或关闭失败如实报告远程状态未知，但不阻塞
安全的本地恢复。校验和输出可观察不同源状态。关系与组合 Metric 的扩展见上文；采样、retained 导入及源端私有状态高级方法仍未启用。

上述标量工作流示例也适用于已建模的 Trino Metric。

### ClickHouse 标量 Metric

ClickHouse Group A 支持单数据源、单个未版本化的普通关系——表或视图——且不限制引擎：
直接列 sum/count/min/max、Population 过滤、原生日期范围、同 Entity 维度、
聚合、投影、确定性排名与 limit。Distributed 与多分片关系均准入；不稳定读取属于已接受语义：
读取依赖后台 merge 进度的引擎（例如 ReplacingMergeTree）可能随 merge 推进而返回不同行，
但已提交快照的重放不受影响。关系与版本的扩展范围见上文；采样、retained import 和源端私有状态高级方法仍未启用。

物理类型包括 Int8/16/32/64、UInt8/16/32/64、Bool、Float32/64、String、Date、
精度不超过 38 的 Decimal 及合法 Nullable 包装。LowCardinality(String) 和
LowCardinality(Nullable(String)) 保留字符串语义。DateTime('UTC') 以及已验证引擎时区为
UTC 的 DateTime 保留秒精度。原生时间契约还支持微秒以内 DateTime64 和带实际时区的绑定。FixedString、Date32、
Int128/256、UInt128/256、Enum、嵌套类型仍不准入；本标量类型扩展不限制表引擎形式。

只读账户须配置有效的 `join_use_nulls=1`。元数据、必要断言与输出分别执行，
输出为空也必须完成校验。浮点输入必须为有限值或 NULL；整数与 Decimal SUM
在内部扩宽到 Decimal256 后检查输出转换，溢出或非有限结果不发布。

原生分块流精确保留 Decimal 和 Entity 身份，不经 pandas 或转移原始来源到其他引擎。
执行拥有并关闭每条响应；驱动 close 可能排空未读数据，因此不承诺固定取消时延，
也不把连接关闭当作远端终止证明。远端状态未知时仍允许安全的本地恢复。
不增加共享快照、执行预算、上传、临时对象或隐式重试；批大小只是传输配置。

MySQL TIMESTAMP 当前要求实际会话 `time_zone` 为 `UTC` 或 `+00:00`，其他时区别名尚未验收。
MySQL/SQLite 的 preview 和 sample 保留含 NULL 的大整数精度，不先转为 float64。


原生 timestamp 转换使用声明的权威时区与运行时 ZoneInfo。Analysis 不再扫描
源数据检查歧义本地时间、解析失败的单元格或引擎与运行时时区规则的差异。
查询时发生的后端转换错误仍会返回；Artifact 保留时间来源记录。
