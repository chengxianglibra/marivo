告诉 Agent 业务问题、已确认的指标、人群和比较范围。Agent 选择能够回答问题的方法和结果检查点；你无需指定算子调用或展示步骤。

数据源连接成功和语义就绪不代表该分析方法能在此源执行。通过
`marivo.help("analysis.actions.execute")` 查看执行边界，结合 Dataset contract
和不支持形状的结构化修复建议继续。远程源需要只读账号；不支持通过上传
retained 结果绕过准入限制。
`md.register()` 只保存数据源声明，不加载分析执行代码。执行准入只加载所选后端；若该后端依赖缺失，
会在连接数据源前给出结构化修复建议。

公共 Session 的成员读取、观察、比较、统计、Event 和 Lifecycle 使用类型化图、
方法 registry、Runtime 与 Store 8。每个来源与固定方法都需要精确物理资格；
下面的有界后端向量不授予其他组合资格。旧代际项目保持原样并明确拒绝，请在新项目中创建 Session。

构造可进行仅 schema 预检，确定精确身份和值类型，不读取业务行。成员身份保留完整的
string/int64 声明键元组，事件轴使用受治理的 DATE 或带时区时间戳解释。

## 构造与执行

一次调查使用一个 Session。构造器描述工作，可进行仅 schema 预检，不读取业务行；显式执行后返回可检查、可继续使用的不可变结果。

下例使用已取得资格的 Entity 成员路线。

```python
import marivo
import marivo.analysis as mv
import marivo.semantic as ms

session = mv.session.get_or_create("revenue-review", report_timezone="UTC")
customers = session.members(ms.ref.entity("sales.customer"))
revenue = ms.ref.metric("sales.revenue")
buyer = ms.ref.relationship("sales.order_buyer")
current = customers.observe(
    revenue, during=mv.time_scope(start="2026-08-01", end="2026-09-01"), via=buyer
)
baseline = customers.observe(
    revenue, during=mv.time_scope(start="2026-07-01", end="2026-08-01"), via=buyer
)
change = current.compare(baseline).execute()
change.show()
```

`show()` 默认没有行数上限，在 8 KiB 预算内展示完整数据行，并明确报告总行数、
已展示和遗漏行数，保留解释边界。需要完整操作目录时再读取 `contract()`。

```python
change.show(n=20)
change.show(n=0)
change.show(max_output_bytes=None)
```

`n=0` 只展示元数据与列信息。`max_output_bytes=None` 取消 UTF-8 字节预算
（包含打印末尾换行），仍遵守显式 `n`。这些调用只读取已保存结果，不重新查询业务源。
非 Defined Cell 保留状态与原因；Duration 展示精确 ticks 和单位。


`compare` 接受同类型 int64/float64、同标度 Decimal 绝对差和同单位 Duration。
默认 `TimeChange` 要求递归量定义一致，并共享同一次目标捕获；`CohortContrast`
在共同 Group 或 Singleton 坐标上比较同一观察时间的不同人群。
`PeriodChange(alignment=mv.window_bucket())` 消费完整等长的原始桶映射，筛选不能重新编号。

```python
relative = current.compare(baseline, value="relative_change")
union = current.compare(
    baseline, design=mv.TimeChange(pairing=mv.UnionKeys(missing="keep"))
)
quotient = current.ratio(current, pairing=mv.ExactKeys())
marivo.help("analysis.dsl.NumericComparison.compare")
marivo.help("analysis.dsl.one_to_one")
```

`ExactKeys` 要求完整有类型键唯一且键集相等，允许双空。`UnionKeys(missing="keep")`
独立保存缺失坐标和 Cell，缺侧结果为 `Undefined(missing_side)`。
`missing="metric_empty"` 只在完整原始观察和覆盖证明下调用具体 Metric 的空状态 finish，
不能填补筛选留下的缺行。已存在且参与配对的端点必须是有限 Defined 值。

相对变化以 `abs(baseline)` 为分母，零基线保留 `Undefined(zero_baseline)`。
普通 ratio 保留分母符号，零分母保留 `Undefined(zero_denominator)`；对应可使用完整精确键，
或以 `mv.one_to_one(left=..., right=..., via=...)` 绑定精确有序节点、已声明的一对一关系和保留键。
普通 ratio 和 Difference 不自动获得原 Metric 的 rollup、share 或 attribution。
非零浮点分母的保留误差区间跨零时拒绝执行。
浮点时间折叠和分位数尚无获资格的比较误差界部件，在构造时拒绝。

Logical 和 Materialized 接口均返回 Logical 结果。固定续算验证 receipt 和保留部件，
不会回源。Difference 使用 state/part v2，相对变化和普通 ratio 使用 v1；旧 Difference
必须从源定义重新执行后再续算。

### 有符号偏离评分

数值关系提供 `deviation(method="zscore")` 和 `deviation(method="mad")`。
两者均构造 `LogicalDeviationResult`；`execute()` 保存一次拟合及同一生产者的
`observed`、`reference`、`deviation`、`score` 四个字段。Zscore 使用总体标准差；
MAD 使用精确中位数和系数 7413/5000，原 MAD 为零时改用围绕同一中位数的平均绝对偏差。
分数保留正负号。非 Defined 输入保留原 tag/reason；单样本和常量拟合的分数为 Undefined。

```python
scored = current.compare(baseline).deviation(method="mad")
defined = scored.where(scored.score.value.is_defined())
positive = defined.where(defined.score.value.gt(0))
followup = positive.observed.members().observe(
    revenue, during=mv.time_scope(start="2026-08-01", end="2026-09-01"), via=buyer
)
followup.summarize(method=mv.count_defined()).execute().show()
fixed = scored.execute()
fixed.contract().show()
ranking = fixed.score.rank(order="descending", ties="dense").limit(10).execute()
ranking.ranks.contract().show()
mv.table(score=ranking.values, rank=ranking.ranks).execute().show()
marivo.help("analysis.dsl.NumericComparison.deviation")
```

结果筛选和字段排名保留原拟合域；先筛选数值输入再评分会建立新拟合域。
将分数与分类、原值、另一拟合或排名组成表时，也会保留拟合权威部件。
排名视图保留原拟合域，物化后通过 `contract()` 披露相同部件。
`partition_by` 接受精确对应的分类关系，Null 分类也是真实分区坐标。
三个派生字段不取得原 Metric 的 rollup 或 attribution 权限。
固定拟合仅消费捕获输入及 receipts；新来源观察须在来源图中先准备，再进行本地选人。
Decimal 输入保持精确，单位字段按 Decimal(38,max(s,6)) HALF_EVEN 一次完成，
score 最终完成为有限 float64。R8.2 evidence index 记录实际执行覆盖；远程后端、
安装 wheel 和真实 Agent 资格属于后续阶段。


示例要求项目已定义具有明确源类型和参考时间轴的 `sales.revenue` 指标。窗口为左闭右开，结束边界不包含在内。仅含日期的边界按 Session 持久化的报告时区解释；应为所需日历显式设置 `report_timezone`。成员筛选与观测窗口相互独立。先读取成员维度、按值筛选，再调用 `.members().observe(...)`。

对于已配置 DuckDB 来源且通过准入的 J1–J4 Entity 域，从
`session.members(Entity Ref)` 开始。成员域提供 `read`、`group_by` 和
`observe`；返回的关系提供筛选、比较、rollup、行统计与关联。
`marivo.help("analysis.entry")` 会将 Entity 成员问题指向此入口；
Metric 观察路径要求声明事件时间维度，并使用已获资格的原生 DATE 或带时区时间戳；冲突或无法确定的时区权威会被拒绝。例如：

```python
customers = session.members(ms.ref.entity("sales.customer"))
revenue = ms.ref.metric("sales.revenue")
buyer = ms.ref.relationship("sales.order_buyer")
august = mv.time_scope(start="2026-08-01", end="2026-09-01")
august_revenue = customers.observe(revenue, during=august, via=buyer)
total = august_revenue.rollup().execute()
total.show()
restored = session.artifact(total.state.artifact_ref)
restored.contract().show()
for action in restored.contract().actions:
    print(action.call, action.help_target)
saved_observation = august_revenue.execute()
recovered_observation = session.artifact(saved_observation.state.artifact_ref)
recovered_observation.summarize(method=mv.count()).execute().show()
```

此形状要求项目已经编写并准入相应 Entity、Metric 与 Relationship。
每次执行逻辑来源分支都会重新读取来源；固定续算可命中已提交的精确执行键。
`session.artifact(ref)` 依据校验过的快照与保留部件恢复公开 J1–J4 结果，
不读取当前来源或 Semantic 目录。其他能力遵循各自当前类型化入口与精确资格。

成员分组本身不要求额外的 relationship。当 Metric 的贡献根就是成员 Entity 时，
可以省略 `via` 或传入 `None`。例如，按订单自身的渠道观察订单收入：

```python
orders = session.members(ms.ref.entity("sales.order"))
channel = ms.ref.dimension("sales.order.channel")
channel_revenue = orders.group_by(channel).observe(
    ms.ref.metric("sales.revenue"),
    during=mv.time_scope(start="2026-08-01", end="2026-09-01"),
).rollup().execute()
channel_revenue.show()
```

在客户域上观察这个订单 Metric 时，仍需声明订单到客户的路由，
例如前一示例中的 `via=buyer`。

恢复后的观察保留完整当前行，包括已有的贡献坐标。`summarize` 消费当前行，
`rollup` 消费已存原量聚合状态。历史属性筛选后的新逻辑观察保留所选版本。
History 的状态、区间和违规选人先准备来源候选，再消费本地行；
已存 History 续算读取捕获状态，不重放事件。
有界结果卡会展示已有的单位、方法、Cell 字段和当前行权重，并遮蔽 Entity 成员键。
每个 `AnalysisAction` 给出当前结果可执行的调用形式和对应的精确
`marivo.help("analysis.<target>")` 路由。物化结果的 contract 会验证确切保留部件，再披露可续算动作。

同一项目若还声明 `sales.order_count`、`sales.aov_from_lines`、
`sales.order`、`sales.order_line` 和 `sales.line_order`，可继续运行其余
已准入的 J1–J4 形状：

```python
july = mv.time_scope(start="2026-07-01", end="2026-08-01")
september = mv.time_scope(start="2026-09-01", end="2026-10-01")
baseline = customers.observe(revenue, during=july, via=buyer)
change = august_revenue.compare(baseline)
falling = change.where(change.value.lt(0)).members()
next_month_mean = falling.observe(
    revenue, during=september, via=buyer
).summarize(mv.mean()).execute()

ratio_routes = mv.routes(
    mv.route(
        ms.ref.entity("sales.order_line"),
        through=(ms.ref.relationship("sales.line_order"), buyer),
    ),
    mv.route(ms.ref.entity("sales.order"), through=(buyer,)),
)
channel = ms.ref.dimension("sales.order.channel")
aov = customers.observe(
    ms.ref.metric("sales.aov_from_lines"), during=august, via=ratio_routes,
    coordinates=(channel,),
)
overall_aov = aov.rollup().execute()
channel_aov = aov.group_by(channel).rollup().execute()
current_row_mean = aov.summarize(mv.mean()).execute()
current_row_mean.show()

order_count = customers.observe(
    ms.ref.metric("sales.order_count"), during=august, via=buyer
)
association = august_revenue.correlate(order_count, method="spearman").execute()
coefficient = association.coefficient
negative = coefficient.where(coefficient.value.lt(0)).execute()
```

`rollup()` 依据保留的原始组件重新计算；`summarize(mv.mean())` 对当前行
等权求均值。Spearman 只描述同一观测范围内完整成员配对的关联，不构成因果判断。

对于保留的 `NoTime` Entity 分位数量，若值类型是 `Decimal(18,2)`，当前行 sum
返回 `Decimal(38,2)`，mean 通过一次 HALF_EVEN 舍入返回 `Decimal(38,6)`。
新 RowStatistic 的 `rollup()` 合并已捕获的精确 sum/count 状态；mean 保留 sum
原有的小数位。空集 sum 为零，mean 为 `Undefined(empty_mean)`。原分位数量仍不能
rollup。其他 Decimal group/time/source 当前行归约键需要各自的资格。

## 按确切语义继续分析

字段选择器属于取得它的那个 Dataset。使用类型化谓词、投影、排序和显式坐标聚合。对持久化结果调用方法时，计算从其保留行及必要的私有贡献状态开始，保持身份和合法聚合语义。均值不能作为可加值直接求和；筛选后的比率和 distinct 集合保留真实组成状态。

比较、归因、相关性、预测和发现属于 Dataset 方法。Event 匹配从
`session.events.match(..., population=members)` 开始，返回类型化 JourneyResult；
耗时与选人消费保留的 assignment。R7.5 Lifecycle replay 通过 typed graph 返回 canonical HistoryResult。
不同 Session 的输入不能混用。first-per-subject Journey 提供 `funnel(axes=())`。
漏斗比较要求完全一致的 pattern、population、时间依据、队列窗口时长、随访偏移
和完整覆盖。Logical 归因可以按同一 assignment 准备入口轴；fixed 归因要求
已经保留这些轴及原组件。下方可执行示例展示 owned read、比较和 Findings。

当前源端执行支持 DuckDB 和下述 PostgreSQL 标量子集；数据源建模支持某个后端，不代表 Dataset 已能在该后端执行。不支持的方法会报告后端与输入形状。保留结果不会被隐式上传到其他来源，同一 Session 的执行键命中不需要连接来源。

## 检查证据与恢复

对于源端类型化图，`contract()` 会展示所选后端的静态源准入结果：`rejected` 包含拒绝原因，`static_pass` 只表示纯静态检查通过；含 retained Artifact 输入的图显示 `not_checked`。最终 placement 仍由 `execute()` 决定。contract 也描述机械上合法的继续操作；物化关系的 `show()` 提供有界结果检查。通过物化结果读取确切 Finding，通过所属 Session 恢复 Artifact。展示少量行不代表计算可以省略其他输入。参见[证据](/zh-cn/docs/latest/concepts/evidence/)。
预览中的时长列会明确标注微秒单位；`to_pandas()` 会将这些列转换为 timedelta。

分析结果始终使用项目本地 Parquet，没有结果存储配置。执行不使用数据库结果存储，也不在失败后切换执行器。冷恢复保留确切存储和时间语义；Store 使用 generation 7，旧文件不会被迁移或改写。

## 保持判断明确

普通表的受限 UTC 微秒、int64 子集支持 DuckDB、SQLite、PostgreSQL、MySQL 和 Trino
的原生精确 distinct，以及 ClickHouse 上显式许可的近似 distinct。精确分位数适用于
DuckDB/PostgreSQL；显式近似分位数也适用于 Trino/ClickHouse。不支持的定义在读取前
拒绝，不自动替换。原分布量不能归约或用于变化归因，固定恢复不读取来源。distinct 另接受
float64、string、boolean、date 与 timestamp。PostgreSQL/MySQL/Trino 的精确 Decimal distinct
保留原系数；显式近似 Decimal distinct 也使用这些后端的原生操作及 ClickHouse 既有的近似操作。
DuckDB 保留其原生 Decimal carrier。quantile 另接受 float64。MySQL BOOLEAN 被读取为 int8，继续拒绝。
DuckDB 之外的 Decimal quantile 原生结果不能保留 Decimal carrier；原生 Duration lowering 需要 DuckDB epoch_us。
这些输入、无界窗口及完整 C10 仍须独立验收。

当指标、人群、比较方式或重要假设需要改变时，确认新的业务含义。可复用的语义缺口归属语义建模。在 Metric 定义中通过 `agg=("approx_percentile", q)` 明确允许近似；观察与恢复保持该定义。原生 SQL 的数值精度限制由结果契约披露。

归因是代数分解，相关性是描述性结果，deviation 分数是调查线索，预测带有模型假设。Agent 负责综合判断与结论。`to_pandas()` 或 `md.raw_sql(...)` 的自定义分析是终端出口，结果不能重新注入受治理的 Dataset 组合。

从 `marivo.help("analysis")` 开始发现能力，沿原生入口、方法、输入、Artifact、证据和 Runtime 导航读取准确签名和示例。结构化错误提供具体修复；打包技能负责工作流判断。

准确导航入口为 `analysis.entry`、`analysis.methods`、`analysis.inputs`、
`analysis.artifacts`、`marivo.help("analysis.evidence")` 和
`marivo.help("analysis.runtime")`；终端出口由
`marivo.help("analysis.actions.to_pandas")` 说明。


## 按当前任务逐步发现能力

`analysis.entry` 连接 Session 创建或恢复，以及 Metric、Event、Lifecycle 的分析起点。
`analysis.inputs` 负责缺失输入：沿 catalog 精确取得已确认的语义对象，只检查所需闭包的 readiness；人群、时间、完整性声明和模型假设各有具名分组。
`analysis.methods` 按汇总、比较归因、关联、预测、筛查及事件和生命周期等任务分组，不需要遍历全部页面。

已有 Dataset 时，读取 `dataset.contract().show()`，沿当前允许动作提供的准确 Help target 继续。类型与成员仍可按需精确查询；也可以把已取得的公共方法传给 `marivo.help(...)`。
聚焦叶子列出这次调用所需的前提和返回值路径。读取这些信息足以执行下一步时，就保存并运行最小分析脚本。

当前行统计可从 `analysis.methods` 直接到达
`analysis.methods.metric.summary`。这类统计创建新 quantity；原始 Metric rollup
合并保留状态。同义 receiver 变体共享导航摘要，并保留各自准确的 Help target。
已有对象时，从 contract 直接查询所选绑定方法，例如
`marivo.help(dataset.summarize)`，无需重新阅读方法目录。
聚焦示例直接构造受支持的策略与谓词；仅在需要时将 receiver、治理 Ref
和比较端点保留为外部输入。

披露回归在八个固定公共场景上累计字符数和阅读页数，包括重复 Help、contract、
预览与修复阅读。这些是上下文代理指标，不是模型 token 数。压缩输出时仍须保留
约束、完整续接与结构化修复。

一次执行中的来源检查与计算可以观察到不同的源数据状态。检查成功只证明自身那次查询，
不证明后来读取的事实。一个逻辑 Run/result 身份不承诺一次物理扫描或共享快照。
已获资格的纯原生图直接查询 Ibis 表达式，不把 Arrow 中间捕获重新暂存回源。
最终主表和必要部件仍须具有合法的完整键绑定、Cell 和一致的内部算术，再原子发布；
源数据变化不能为内部不一致的 Artifact 开脱，也不会触发失败后换路线。

Entity 域 J1–J4 的逻辑来源执行每次都会重新读取来源；固定续算可命中同一个精确 Artifact，
并可通过 `session.artifact(ref)` 显式恢复。其他路径遵循各自当前方法与物理输入的精确资格。
本地恢复信任已提交的 Artifact 和 Evidence，不重复进行防篡改验证，也不证明当前语义有效或源数据新鲜。Store 8 不兼容旧 Store；旧数据保持不变，需要使用新的项目根目录。

## 本地执行与资源责任

本地计算和 `to_pandas()` 在调用 Python 进程中同步执行，完整返回结果或抛出保留原始原因与调用栈的异常。Marivo 不启动执行或读取 worker，不增加输入行数、字节或内存容量准入限制。typed graph 执行沿用 600 秒单调 execute deadline、资源释放和原子失败规则。数据库、驱动、操作系统与外部 runner 的限制仍然适用。

`show()` 保持展示长度限制；完整输入校验、所有权和原子发布保持不变。Store 使用 generation 7，旧代文件保持原样，旧 Session 不迁移或恢复。

已支持的执行不要求引擎、驱动或 Ibis 版本认证。正常表达式编译保留参数、完整结果与必要校验顺序；重复编译本身不会再次提交查询。

取消或关闭失败可能使远端只读查询状态未知。Marivo 如实记录这种不确定性；本地发布安全后，同一 Session 可继续工作。未确定的提交状态与冲突写入者仍会阻塞恢复。失败 Run 表示没有成功的本地输出，不证明服务端查询已停止。提交结果不明确时，不自动重新提交动作。

## 后端实现边界

受限 R9.3 原生表、UTC 微秒路线支持 SQLite、PostgreSQL、MySQL、Trino Iceberg、ClickHouse 的两个
来源根 float64 运行时线性观察。各根独立归约，再按完整目标键组合。PostgreSQL、MySQL、
Trino Iceberg、ClickHouse 也保持从 Decimal(18,6) 原始事实归约出的 Decimal(38,6) 组件，与 DuckDB 的精确
Decimal 值一致。SQLite 非有限输入拒绝且不发布结果，其 Decimal 线性组合仍未取得资格。
其他 Decimal 形状及完整 C04 资格仍未验证。

受限 R9.3 原生 UTC 微秒路线也支持 SQLite、PostgreSQL、MySQL、Trino Iceberg、ClickHouse
的 int64 组件运行时比值，以及基于 int64 事实、string 键 Entity 目标的加权平均。比值保留
完整目标、Defined 的零分子和 Undefined 的零分母；加权平均保留 Null 空贡献。其他比值
数值形状及完整 C04 资格仍未验证。

两个来源根的 float64 比值精确键也具有六后端原生 UTC 微秒受限向量，并为固定汇总
保留原始组件。DuckDB、PostgreSQL、MySQL 与 ClickHouse 的 Decimal 比值保留精确组件，按 HALF_EVEN 一次舍入至
Decimal(38,6)。MySQL 与 ClickHouse 的原组件与最终比值溢出均在发布前拒绝。
ClickHouse 使用 Decimal256 求和，并检查声明精度边界。
SQLite、Trino 的 Decimal 比值键仍未取得资格；准入拒绝不能证明要求的
Decimal 执行成功。

该受限 int64 比值的固定汇总合并原始组件：30/9 得到 10/3，而平均目标比值 6 和 0
会错误地得到 3。六后端来源生产者保留这些组件，续算不重新读取来源。

受限原生 UTC 微秒、int64 运行时聚合与维度切片观察也具有六后端来源向量。运行时
sum 保留 Null 空贡献；对显式 zero 策略的静态 sum 切片时，被排除的目标保留为
Defined zero。其他聚合函数、切片组合及完整 C04 资格仍未验证。

下面的后端和方法描述记录有界的资格范围。当前执行遵循类型化图、方法 registry、
Runtime 和 Store 7。检查返回关系的 contract 及当前 owning qualification 记录；
历史通过不授予另一种物理输入或方法组合的资格。

算子共享语义契约和后端注册机制。DuckDB 的 typed graph 使用 Ibis 来源准备和统一本地方法；
普通结果批次使用受控 Arrow reader，资源与注册属于单次动作。专属 Candidate/Driver 数值宏安装通道已退役。
远程实现必须兼容无写入、无创建表或视图权限的账号，并满足相同语义要求后才能启用。
精确类型、增量读取或共享快照确有需要时，保留专用传输。没有可用实现时明确拒绝，不会隐式把源数据搬到其他
引擎执行。PostgreSQL、MySQL、SQLite、Trino 与 ClickHouse 支持下述子集。


### 关系方法与原生日期分析

在各后端已支持的表和物理类型范围内，还可以使用直接列上的 mean、weighted mean、
ratio、同源关系、原生日期桶（单单位 day/week/month/quarter/year）以及 snapshot/validity
成员选择。五个远程后端都支持两种 validity 区间闭合方式及已配置的开放端哨兵。
版本选择使用声明的时间边界；不再自动扫描源数据核验身份与时间。

对于已声明的均值 Metric，先保留充分组成状态，再进行 rollup：

```python
mean_amount = ms.ref.metric("sales.mean_amount")
channel = ms.ref.dimension("sales.orders.channel")
means = session.members(ms.ref.entity("sales.customer")).observe(
    mean_amount,
    during=mv.time_scope(start="2026-08-01", end="2026-09-01"),
    via=ms.ref.relationship("sales.order_buyer"),
    coordinates=(channel,),
).group_by(channel).rollup().execute()
overall = means.rollup().execute()
overall.show()
```

rollup 从保留的 sum/count 状态重新计算均值，不对分组均值直接平均。
比较与归因使用完整的非 Entity 保留轴；Forecast、Kendall 和时间发现方法在源端完整
聚合后于调用进程执行。冷读与保留结果折叠不需要原始数据源。

统一图的 DuckDB table 与本地 Parquet 数值方法支持 int64、有限 float64、Decimal
和固定 Duration。Decimal 求和保留输入 scale，mean、Metric weighted mean 和 ratio
按声明 scale 仅做一次 HALF_EVEN 舍入。Duration 保留 s/ms/us/ns 单位，均值只做一次
nearest-even tick 舍入。原生 DuckDB INTERVAL 必须先拒绝日历成分，按微秒处理；
Parquet 保留四种 Arrow Duration 单位。原状态上卷和时间 fold 在冷恢复后仍保留这些
类型。源端计算由 Ibis 编译为 SQL，断源续算只消费已校验的保留状态。

普通原生表的时间均值保留 string 与 int64 Subject 身份，包括大于 `2**53` 的相邻
int64 键。计算先归约空间贡献，再折叠时间样本。原始上卷消费保留样本和支持量，
而不是对显示的 Subject 值取均值。其他源形状与时间戳单位需要独立取得资格。
DuckDB 原生表的微秒时间、string Subject 观察及 int64 原量归约还支持 Asia/Tokyo
报告时区。原生 DATE 和显式解析的原生 timestamp 输入在固定归约中保留原网格与窗口事实。
比较报告时区下的同一瞬时时间范围时，应使用带时区的 scope 端点；civil 字面量按选定的报告时区解释。

精确与近似 distinct/quantile 由 Metric 定义选择，原生分位数的舍入限制会明确披露。
数据源不支持精确定义时，错误会提示对应的近似定义、保留 q，并说明是否支持；不会
自动替换。这些 R5 资格不扩展远程后端执行范围，完整矩阵由 R9 验证。percentile
status-time fold 仍未准入。相关性消费者保留其独立资格边界。

PostgreSQL、SQLite、Trino 与 ClickHouse 支持基于完整非 Entity 状态的隐藏轴展开加性与组件归因。MySQL 的组合查询在实测中超过验收服务的内存限制，因此仍拒绝；Trino 的展开 Top-K 查询超过服务的 stage 上限，也保持拒绝。以下 Event 后端记录属于保留的旧实现，不构成 R7.3 新公共入口资格。PostgreSQL 支持精确的两步或三步旧旅程；要求未版本化表源和 `int64` 主体、事件身份。直接 Event 漏斗、耗时和主体选择，已验收；旧 Lifecycle Dataset 后端记录不授予 R7.5 资格。旧 PostgreSQL 私有漏斗比较和归因消费者已退出；历史后端证据不授予新 R7.4 路线资格。

ClickHouse 和 Trino 支持相同表源与身份条件下的两步旅程，匹配策略包括 `first_per_subject()` 和 `every_start()` 的共享／独占完成分配。Trino 的真实验收使用 Iceberg；ClickHouse 要求只读账户获准设置 `enable_materialized_cte=1`。空输出也执行源端断言，只有契约允许的完整结果进入既有本地续算。Trino 还支持直接无分组漏斗、first-per-subject 耗时、主体选择。其旧私有无分组漏斗比较消费者已退出，不授予新 R7.4 路线资格。Trino 分组漏斗的核对查询超过验收服务的 stage 上限，因此分组漏斗和依赖它的归因保持拒绝。ClickHouse 的直接 Event 派生方法与主体选择仍因计划或内存限制保持拒绝。R7.5 canonical Lifecycle History 接通受治理的 DuckDB 表和本地 Parquet。入口要求精确 StateModel Ref、显式逻辑 Subject 域、带时区的报告窗口和 `from_inception()`；业务顺序由模型拥有。Ibis 先准备全部源输入，本地扫描再消费同一捕获。History 保留每个主体、全部迁移与违规轨迹，已发布结果可独立断源读取。六类 History 视图、精确 Duration 统计和选人后同 Run 的 count/sum 观察已在 R7.6 本地验收；远端 Lifecycle replay 尚未验收。

受限 R9.3 SQLite 路线也支持 main 数据库原生表、int64 身份与 UTC 微秒时间戳的 replay
和无分类轴 History 视图，使用已注册的原生备份准备。完整、前缀及未知覆盖保留各自轨迹；
fixed 视图与恢复消费保留部件。其他来源形状及分类 checkpoint 轴仍未取得资格。

```python
members = session.members(ms.ref.entity("commerce.subjects"))
history = session.lifecycle.replay(
    ms.ref.state_model("commerce.model"),
    population=members,
    window=window,
    seed=mv.from_inception(),
    completeness=lifecycle_completeness,
)
retained_history = history.execute()
retained_history.show()
retained_history.contract().show()
recovered = session.artifact(retained_history.state.artifact_ref)
recovered.show()
```

R7.6 已接通六个 History 视图及具体字段关系。检查点可取窗口 end 的左极限。
区间和违规筛选通过保留的 Subject 绑定选人；状态读取已经具有完整主体键。
新 Metric 观察应从执行前的逻辑 History 构造。固定续算仅消费保留部件。
Duration 均值从 completed 区间的精确 ticks 计算；Dwell 的均值、中位数及 p90 摘要不能平均或合并。

```python
checkpoint = window.end
done = ms.model_state(model=ms.ref.state_model("commerce.model"), name="done")
truth = history.read(mv.in_state(done, at=checkpoint))
distribution = history.distribution(at=(window.start, checkpoint))
transitions = history.transitions()
violations = history.violations()
intervals = history.intervals()
dwell = history.dwell()

truth.where(truth.value.eq(True)).members().observe(
    ms.ref.metric("commerce.revenue"),
    during=window,
    via=ms.ref.relationship("commerce.participant"),

retained_intervals = intervals.execute()
interval_ref = retained_intervals.evidence_digest().artifact_ref
session.artifact(interval_ref).state.execute().show()
completed = retained_intervals.where(retained_intervals.status.value.eq("completed"))
completed.members(through=retained_intervals.subjects()).execute().show()
completed.observed_duration.summarize(mv.mean()).execute().show()
distribution.execute().known_state_count.execute().show()
transitions.execute().count.execute().show()
violations.execute().kind.execute().show()
dwell.execute().p90_duration.execute().show()
```

其中 `window` 为带时区的半开范围，`lifecycle_completeness` 包含全部模型触发 Event 的 source-origin 声明。声明本身不能证明覆盖；依据不足时保留 Unknown 与已知前缀，完整起源的无事件主体为 NotStarted。精度遵循实际捕获转换及其损失披露。

旧 Entity Candidate 和 driver screening 链已退役；采样在这些后端仍不支持。
字符串时间解析与多单位桶按后端逐步启用，限制见下节。
不支持的形状会返回具体原因，不会隐式收集原始源数据或向远端上传保留结果。

### 原生 timestamp 时间分析

六后端已准入的原生 timestamp 支持微秒以内的类型匹配谓词，以及 count=1 的小时/日桶。
PostgreSQL 包含 timestamptz；MySQL TIMESTAMP 与 ClickHouse DateTime/DateTime64 的
aware 声明保留 instant。ClickHouse timestamp 执行要求已验证的 UTC reader 时区；
列时区和报告时区仍可为非 UTC。既有显式 UTC civil 绑定继续验证，不能把非 UTC 物理 instant
重新标成 civil。Trino 使用 Iceberg 实际暴露的 timestamp(6)。SQLite 保持规范 civil
文本，通过连接内确定性时间函数计算，不搬运完整源表。

显式原生 parser 时区优先于 reader 时区；仅引擎没有探测能力时允许有来源记录的
系统 fallback。需要 reader 权威而探测失败或名称非法时直接失败；已有物理 instant
或显式 parser 时不依赖额外探测。reader/report 支持 IANA 与固定偏移，parser 声明
保持既有 IANA 校验。Session 保存 report 权威，冷读不会随主机 TZ 改变。

范围先按 instant 做半开比较，再生成报告时区 civil 桶。Metric 观察的 naive 事件时间
必须有声明或驱动报告的时区；SQLite 需要显式 UTC parser，不会采用主机、报告或网格时区。
发布前验证源端原始/归一化时间对。原生 DST gap/fold 返回结构化 `MaterializationError`，
指出字段、时区、墙钟值和修复方式，不发布部分 artifact。
两个已知 instant 落在重复的报告小时内时归入同一 civil 桶。naive 谓词字面量比较
civil 字段，aware 字面量比较 instant，混用拒绝。微秒 SQL 边界、Arrow/Parquet 和
源离线冷读必须保真；小时到日续算复用保存的时间事实。远程 epoch 解析与
新 timestamp 版本选择仍不受支持。

### 字符串时间解析与多单位桶

用显式 parser 声明的时间维度（`ms.strptime(...)`）在 DuckDB、SQLite、MySQL、
PostgreSQL、ClickHouse 与 Trino 上于源端执行，包含复合小时前缀轴。执行请求查询前
不扫描源单元格的格式有效性；后端解析可能产生 NULL 或报错。PostgreSQL 的 `TO_TIMESTAMP` 对格式不匹配的文本较宽松，
格式看错但形状合法的单元格可能得到错误 instant。Trino 接受 `%f`，结果遵循 `date_parse`
原生的毫秒精度；六位小数秒的后三位可能丢失。

多单位桶（`mv.grain(unit, count=...)` 且 `count > 1`）以该 civil 日本地午夜为锚点，
且只准入宽整除以一个 civil 日的 count；`mv.grain("hour", count=7)` 直接失败而不是
任选一个起点。由于锚点是 civil 边界，跨春季 gap 的 6 小时桶实际为 5 小时、跨秋季
fold 的为 7 小时，而 DST 当天本身仍从本地午夜起算。

```python
import marivo.analysis as mv
import marivo.semantic as ms

window = mv.time_scope(start="2026-07-01", end="2026-07-03")
orders = session.members(ms.ref.entity("sales.orders"))
hours = mv.time_grid(during=window, grain=mv.grain("hour"))
orders_by_hour = (orders.each(hours)
    .observe(ms.ref.metric("sales.revenue"), during=hours.window)
    .group_by(hours).rollup().execute())
# A new daily observation uses the same business window.
days = mv.time_grid(during=window, grain=mv.grain("day"))
orders.each(days).observe(ms.ref.metric("sales.revenue"), during=days.window).group_by(days).rollup().execute().show()

```

SQL 诊断来自 adapter 的实际提交，记录 source/local 执行域、角色和提交/成功/失败状态。
仅编译不算提交；未观测的 driver 连接初始化与事务协议流量不宣称已捕获。

### PostgreSQL 标量 Metric

PostgreSQL Group A 接受单个数据源、单张未版本化表，以及直接列上的 `sum`、`count`、
`min`、`max` Metric。可以选择 Population 成员、按原生日期限定观察范围、添加维度、
聚合 Entity 行、过滤、投影 Metric、确定性排名和选择 Top-N。整个依赖图都必须受支持，
包括被投影移除的 Metric。

例如，`sales.revenue` 是求和 Metric，`sales.orders.channel` 是同一 PostgreSQL
表上的直接列维度：

```python
revenue = ms.ref.metric("sales.revenue")
by_channel = session.members(ms.ref.entity("sales.orders")).observe(
    revenue, during=mv.time_scope(start="2026-07-01", end="2026-08-01"),
    coordinates=(ms.ref.dimension("sales.orders.channel"),),
).group_by(ms.ref.dimension("sales.orders.channel")).rollup()
top_channels = by_channel.rank(order="descending", ties="ordinal").limit(5).execute()
top_channels.show()
```

所有必要源列必须使用 Boolean、string、有符号整数、float32、float64、date、
精度为 0–6 的 timestamp/timestamptz 或 Decimal。PostgreSQL CHAR 因尾空格语义不同而拒绝，text/varchar 保持支持。Decimal 精度最大为 38，scale 从零到精度；
未指定精度的 Decimal 声明仍需通过实际元数据校验。带时区的字符串解析、采样、
组合 Metric 和私有状态方法不在此子集内。

使用没有写入、CREATE、TEMP 权限的 PostgreSQL 只读账户。查询通过明确管理的
服务端游标分批传输，不创建临时表、不上传数据、不创建 UDF。验证与结果查询可能
观察到不同的来源状态。失败保留原始异常，且不会发布部分输出。保留结果继续使用
现有读取器，不会导入 PostgreSQL。


### MySQL 与 SQLite 标量 Metric

上面的 Group A 流程同样适用于单张未版本化的 MySQL 或 SQLite 表：直接列上的
`sum/count/min/max`、Population、日期限定观察、维度、聚合、过滤、投影、确定性排名与 Top-N。
例如，已声明的 `sales.revenue` 和渠道维度可以使用相同调用：

```python
revenue = ms.ref.metric("sales.revenue")
by_channel = session.members(ms.ref.entity("sales.orders")).observe(
    revenue, coordinates=(ms.ref.dimension("sales.orders.channel"),),
).group_by(
    ms.ref.dimension("sales.orders.channel")
).rollup()
by_channel.rank(order="descending", ties="ordinal").limit(5).execute().show()
```

MySQL 支持表和视图，要求只读账户，文本限定 utf8mb4_0900_bin，支持 signed/unsigned 整数、
浮点、DATE、明确精度不超过 38 的 Decimal，以及 DATETIME(0–6)。TIMESTAMP(0–6)
还需验证 UTC 会话。显式 Boolean 声明仅兼容 TINYINT(1)，必要列必须为 0/1/NULL；
普通整数声明仍保持整数。CHAR、BIT、ENUM/SET、嵌套类型及通用 Decimal 源声明不准入。
非法日期/时间在发布前失败；整数 SUM 精确解码为现有 int64 结果，越界失败。

SQLite 主库普通表和视图支持整数声明别名（统一 int64）、REAL/DOUBLE/FLOAT（float64）、
BINARY 排序的 TEXT/CLOB/CHAR/VARCHAR（string），以及规范 DATE。BOOL/BOOLEAN
必须实际存储整数 0/1/NULL；DATETIME/TIMESTAMP 必须为固定宽度、无偏移的
`YYYY-MM-DD HH:MM:SS.ffffff` 文本，年份 0001–9999 且日期时间合法。即使输出为空也检查
全部必要列。unsigned、Decimal、SQLite 原生 aware 时间存储、虚拟表及附加数据库仍不支持；NaN 写入后成为
NULL，无法恢复原区别。普通 timestamp 支持精确传输、分组、排序和类型匹配的时间谓词。
UInt64 身份及 min/max 通过 Arrow、Parquet 和冷读保留全值域，不经 float 或有损 int64。

两个适配器保留精确的复合身份，直接按驱动批次读取，不经 pandas 全量中转。
MySQL 非缓冲游标提前关闭时可能排空未读响应，不承诺硬取消时限或内存上限。
SQLite 原生游标逐步读取，但引擎内部仍可能物化排序或聚合。批次限制行数而非字节数，
单个值仍会完整解码。SQLite 执行启用 query-only。校验与输出查询可能观察到不同源状态，结果仍原子发布。
保留结果使用 Parquet 和现有读取器，不上传到来源。关系与组合指标的扩展见上文；采样和源端私有状态高级方法仍未启用。

### Trino 标量 Metric

Trino Group A 支持单个数据源、单个未版本化的普通关系——表或视图——以及直接列上的
`sum`、`count`、`min`、`max`、Population 过滤、原生日期范围、同 Entity 维度、聚合、
投影、排名与 limit。沿用现有 catalog/schema/table 声明；元数据和执行 SQL 都解析
元组及 `catalog.schema` 字符串覆盖。connector 身份和关系形式只是观测回执，不是门禁：
任何 connector 的普通关系都准入，仅 `$` 内部表被拒绝。

物理输入为有符号整数、float32/64、VARCHAR、DATE，以及明确
精度和小数位且精度不超过 38 的 Decimal，并支持 Boolean 和无时区 timestamp(0–6)。当前观测到的 Iceberg connector 将精度 0 或 3 的建表声明暴露为 timestamp(6)，绑定必须匹配实际元数据精度。
CHAR、通用 Decimal 源声明、带时区或超微秒时间戳、嵌套值均不支持。声明的浮点列只接受有限值或 NULL；
即使输出为空，源检查也拒绝 NaN/Infinity，非有限聚合结果不得发布。Decimal 与整数
身份保持精确值，排名保留明确的 NULL 顺序和确定性的并列处理。

使用有 connector 和表元数据读取权限的只读身份。正常 Ibis 编译配合驱动增量分页，
内部身份结构由类型化标量列重建；batch 不是字节或内存限制。驱动与服务端限制属于
外部限制。提交前登记活跃 cursor；取消或关闭失败如实报告远程状态未知，但不阻塞
安全的本地恢复。校验和输出可观察不同源状态。关系与组合 Metric 的扩展见上文；采样、retained 导入及源端私有状态高级方法仍未启用。

上述标量工作流示例也适用于已建模的 Trino Metric。

### ClickHouse 标量 Metric

ClickHouse Group A 支持单数据源、单个未版本化的普通关系——表或视图——且不限制引擎：
直接列 sum/count/min/max、Population 过滤、原生日期范围、同 Entity 维度、
聚合、投影、确定性排名与 limit。Distributed 与多分片关系均准入；不稳定读取属于已接受语义：
读取依赖后台 merge 进度的引擎（例如 ReplacingMergeTree）可能随 merge 推进而返回不同行，
但已提交快照的重放不受影响。关系与版本的扩展范围见上文；采样、retained import 和源端私有状态高级方法仍未启用。

物理类型包括 Int8/16/32/64、UInt8/16/32/64、Bool、Float32/64、String、Date、
精度不超过 38 的 Decimal 及合法 Nullable 包装。LowCardinality(String) 和
LowCardinality(Nullable(String)) 保留字符串语义。DateTime('UTC') 以及已验证引擎时区为
UTC 的 DateTime 保留秒精度。原生时间契约还支持微秒以内 DateTime64 和带实际时区的绑定。FixedString、Date32、
Int128/256、UInt128/256、Enum、嵌套类型仍不准入；本标量类型扩展不限制表引擎形式。

只读账户须配置有效的 `join_use_nulls=1`。元数据、必要断言与输出分别执行，
输出为空也必须完成校验。浮点输入必须为有限值或 NULL；整数与 Decimal SUM
在内部扩宽到 Decimal256 后检查输出转换，溢出或非有限结果不发布。

原生分块流精确保留 Decimal 和 Entity 身份，不经 pandas 或转移原始来源到其他引擎。
执行拥有并关闭每条响应；驱动 close 可能排空未读数据，因此不承诺固定取消时延，
也不把连接关闭当作远端终止证明。远端状态未知时仍允许安全的本地恢复。
不增加共享快照、执行预算、上传、临时对象或隐式重试；批大小只是传输配置。

MySQL TIMESTAMP 当前要求实际会话 `time_zone` 为 `UTC` 或 `+00:00`，其他时区别名尚未验收。
MySQL/SQLite 的 preview 和 sample 保留含 NULL 的大整数精度，不先转为 float64。


原生 timestamp 转换使用声明的权威时区与运行时 ZoneInfo。Analysis 不再扫描
源数据检查歧义本地时间、解析失败的单元格或引擎与运行时时区规则的差异。
查询时发生的后端转换错误仍会返回；Artifact 保留时间来源记录。


### 完整成员与有类型的属性

成员身份保留声明主键的全部列，包括复合主键。根成员不会默认去重，也不会寻找最近可用版本。
对于已声明版本的 customer Entity，分别指定成员版本和属性版本：

```python
from datetime import datetime, timezone

anchor = datetime(2026, 8, 1, tzinfo=timezone.utc)
customers = session.members(ms.ref.entity("sales.customer"), at=anchor)
region = customers.read(ms.ref.dimension("sales.customer.region"), at=anchor)
# A declared @ms.measure row expression uses the same read entry point:
score = customers.read(ms.ref.measure("sales.customer.score"), at=anchor)
assert isinstance(region, mv.LogicalCategoryRelation)
selected = region.where(region.value.eq("west")).members()
selected.execute().show()
```

`at=scope.before_end` 表示精确结束边界之前的左极限，不减去一个时间刻度。
指定快照缺失时没有该快照所表示的成员，不沿用旧行。无版本 Entity 不传 `at`。
PostgreSQL/MySQL/Trino/ClickHouse 原生表也支持 int64/entity/NoTime 的成员传输、int64 键时间乘积和直接 int64/date 读取键，
包括精确 UTC DATE 快照、NULL 开放结束的左闭右开 validity，以及完整 int64/string 身份。
PostgreSQL/Trino/ClickHouse 支持原生 Boolean 读取；MySQL BOOLEAN 实测为 int8，
在业务读取前拒绝，不进行整数到 Boolean 的转换。可以显式声明返回 `rows.enabled == 1` 的 Boolean Dimension，并通过其 Ref 读取；读取会绑定表达式及其依赖。Category/Boolean 筛选返回完整成员身份。
选定的重复身份在发布前拒绝。完整 int64/string 键的单条显式定向 to-one 原生表路径支持直接 int64 属性：
当前成员范围内缺失或多重匹配会拒绝；匹配到的 NULL 保持 Null Cell，范围外目标重复不使读取失效。
其他标量类型与更长路径仍需独立资格证据。

`read` 对 Measure 返回 Numeric，对 Dimension 返回 Category 或 Boolean，对
TimeDimension 返回 Temporal。整数指示列仍是分类；原生日期保持日期，带时区时间戳保留
物理精度和时区。本切片支持 DuckDB table/Parquet 的直接列和已绑定行表达式 Measure
读取；未取得资格的解析和
无时区时间戳转换会被拒绝。读取另一实体的单值属性时显式指定 `via=relationship`。
映射缺失或多行匹配会拒绝发布；已表示的空值仍是 Null。按照结构化错误修复，不取首行或补零。

执行后的 `.where(...).members()` 使用保留值与完整 Subject 键，来源离线后仍可固定续算，
但不能引入新的属性读取。通过 `session.artifact(ref)` 恢复后查看 `.contract()`，确认当前结果
实际可用的操作。旧冻结定义契约生成的 Artifact 会被拒绝，不自动迁移。

## 坐标分组与当前行统计

版本化属性读的汇总保留输入的精确版本选择，从 Artifact 恢复筛选结果后也遵循这一约束。

使用完整的已保留坐标，或按完整键对应的显式分类关系。原 Metric 合并原组件；
`summarize` 则对当前完成值建立独立统计量：

```python
all_members = session.members(ms.ref.entity("sales.customer"))
all_regions = all_members.read(ms.ref.dimension("sales.customer.region"))
members = all_regions.where(all_regions.value.eq("east")).members()
region = members.read(ms.ref.dimension("sales.customer.region"))
values = members.observe(
    ms.ref.metric("sales.revenue"),
    during=mv.time_scope(start="2026-08-01", end="2026-09-01"),
    via=ms.ref.relationship("sales.order_buyer"),
)
targets = all_regions.group_by()
original = values.group_by(region, groups=targets).rollup().execute()
row_mean = values.group_by(region, groups=targets).summarize(mv.mean()).execute()
total_row_mean = row_mean.rollup().execute()
selected_regions = all_regions.where(all_regions.value.eq("east"))
category_counts = selected_regions.group_by(groups=targets).summarize(mv.count()).execute()
fixed_targets = selected_regions.group_by(groups=targets).execute()
```

传入 `groups=all_regions.group_by()` 可保留显式目标域中的空组。固定结果续算也需要固定的分类与目标域。
`mv.count_defined()` 只统计 Defined Cell，`count()` 统计所有 Cell。
空 mean/min/max 返回 Undefined，但保留有效的合并状态。当前 AOV 行的 mean 可以是 `50.5`，
而原组件归约为 `200/101`。`group_by(*keys).rollup()` 保留指定轴，`rollup()` 消去全部轴。
本次资格不包含时间网格粗化。

六个后端的普通表均支持这条显式空目标组流程，范围为 int64/float64 观察、string 分类及 UTC 微秒来源时间，
包括 count/count_defined/sum/mean 当前行统计与原 sum/mean 状态上卷。新增精确键不扩展到 Decimal 输入。
远端图捕获完整中间交换表，通过 Ibis 编译的明确物理类型常量关系消费，不写入远端表。
完整捕获的行数保持不变，不构成输入容量配额；ClickHouse 通过带明确类型的结构数组展开消费交换表。
对已分组的原均值，`grouped.group_by().summarize(mv.mean())` 先移除分组轴，再归约当前值；
`grouped.rollup()` 合并保存的 sum/count 组件。来源与固定续算路径均区分 `50.5` 和 `200/101`。
Null 观察仍计入 count，count_defined 只计入 Defined Cell，sum/mean 拒绝非 Defined 当前 Cell。
这些限定证据不构成完整 C05 数值类型、域、数据检查和取消矩阵验收。

DuckDB table 的 UTC 微秒 int64 Entity/group 观察也可以在本地生产者之后归约原 sum 状态：

```python
local_total = values.deviation(method="zscore").observed.rollup().execute()
```

该调用先完成完整 deviation 拟合，再归约原状态。R9.6 也接通本地 CSV/JSON 的
这条 int64 Entity 路线，既有 Parquet 本地生产者可以归约同一原 sum 状态。
新增文件键不授予 group 域、MAD、其他标量类型或本地 difference/attribution 资格。

六种普通表后端的限定 UTC 微秒 int64 参照份额、排名与字符串身份 cohort 路径均保留完整复合成员键。
固定 cohort 可将静态目标与完整 Entity/time 机会 Artifact 组合，读取已保留的网格，
不重新读取来源，也不改变输入的时间元数据。这些路径不构成完整 C08 矩阵验收。

筛选后的分类在无键分组时仍保留分类轴。上面的 `fixed_targets` 物化后保留 east、south、west，
包括空组，可用于后续固定续算。按完整键精确对应的数值谓词可以来自另一事实来源；图会同时运输两侧来源绑定。

对已物化的数值分组结果调用 `summarize` 会保留分组轴，并统计当前已物化的分组行：
每个已存在的组计数为一，不恢复分组前的成员行。合并 Metric 原组件使用原指标的 `rollup()`。

## 固定参照与标准化值

先绑定完整参照。筛选保留原分母与支持证明，普通 `ratio` 不会获得份额语义：

```python
members = session.members(ms.ref.entity("sales.customer"))
region = members.read(ms.ref.dimension("sales.customer.region"))
counts = members.observe(
    ms.ref.metric("sales.order_count"),
    during=mv.time_scope(start="2026-08-01", end="2026-09-01"),
    via=ms.ref.relationship("sales.order_buyer"),
)
shares = counts.share_of(counts.rollup())
selected_shares = shares.where(shares.value.gt(0)).execute()
penetration = counts.where(counts.value.gt(0)).members().penetration_in(members).execute()
stratum_counts = counts.group_by(region).rollup()
composition = stratum_counts.share_of(stratum_counts.rollup())
weights = mv.reference_weights(
    composition, strata=(region,), unit=ms.ref.entity("sales.order")
)
standardized = stratum_counts.standardize(reference=weights).execute()
standardized.contract().show()
```

统计单位 Entity 与计量单位分开。原 Metric/runtime Metric 的 sum、count、linear、
mean、weighted_mean、ratio 在冻结组件能证明统计单位时准入。总量标准化输出加权
分层总量，不宣称实际总体值。缺层、重复层、负或非有限权重、错轴、错单位、时间
范围不一致或权重总和错误均拒绝；不归一化。零权重层仍须存在并保留非 Defined
标签，所有正权重层都严格消费有限 Defined 值。份额覆盖 int64、float64、Decimal
和 Duration；标准化覆盖 int64/float64 配整数或浮点权重，以及 Decimal 配 Decimal 权重。

六后端普通表的限定路径支持 UTC 微秒 int64 分层值与 float64 参照权重。
缺失 strata 和负权重均拒绝，fixed 续算也保留此约束。证明按完整分层键和值比较，
不依赖来源返回行顺序。同一六后端普通表限定路径也支持静态成员域的字符串复合身份
渗透率。来自独立 fixed producer 的成员映射保留原 Artifact 回执，交集证明按完整
类型化键比较。空键和重复身份行均拒绝，空参照仍返回 `Undefined/empty_reference`。
完整 C08 矩阵仍未收口。

fixed 续算须同时使用 fixed 值、分类与权重。恢复后，即使来源断开，`where` 也使用
原保留参照执行。数值筛选仅在保留完整 Subject 映射时，才在 contract 中披露
`members()`。数值坐标和参照 parts 本身不授予该映射；缺少映射时，投影在执行前拒绝。
通过 `marivo.help("analysis.methods.metric.reference")` 发现聚焦入口。
排名与 Top-K 参照不变验收见下节；安装 wheel 收口仍归 R6.7。

## 排名与终端表格

排名需要显式平局政策。两个视图始终同键，筛选保留原名次和参照。
`limit` 取全局前缀；每分区 Top-K 则对筛选后的 ranks 分两步操作：

```python
ranking = counts.rank(order="descending", ties="min", partition_by=(region,))
defined = ranking.where(ranking.ranks.value.is_defined())
top = defined.where(defined.ranks.value.lte(3))
prefix = ranking.limit(3)
result = mv.table(amount=top.values, rank=top.ranks).execute()
result.show()
frame = result.to_pandas()
restored = session.artifact(result.artifact_ref)
```

`ordinal` 用完整实例键打破平局；`dense`、`min`、`max` 各自保留对应名次规则，
因此 Top-K 可能超过 K 行。非 Defined Cell 保留标签和原因，在分区内排在 Defined
行之后。int64、有限 float64、Decimal、Duration 精确排序，float 不使用 epsilon
平局。固定续算可在断源后使用已保存部件执行。

表格要求完整同键、时间含义相容、同 Session 和同 source/fixed 模式。导出使用规范
键序，只输出一次键列，再按作者顺序输出值列，并保持大整数、Decimal、Duration
精度。非 Defined 值在 pandas 中变成缺失值，标签和原因信息随之丢失；Artifact 与
`show()` 保留这些信息。Table 没有 `contract`、动态列属性或分析续算入口。
使用 `marivo.help("analysis.dsl.NumericComparison.rank")` 或
`marivo.help("analysis.dsl.table")` 查看聚焦说明。资格覆盖 DuckDB table、local
Parquet 和固定 Artifact；安装 wheel 的收口归 R6.7。

## 分配绝对变化

在物化 Difference 前保留贡献轴。原始方法决定使用 sum/count/linear 的加法差分，
或 mean/weighted_mean/原始 ratio 的 component_mix。分量侧项使用该侧的整体分母，
因此表达分配后的贡献，而不是各组的比值。

```python
attribution_members = session.members(ms.ref.entity("sales.customer"))
channel = ms.ref.dimension("sales.order.channel")
current_counts = attribution_members.observe(
    ms.ref.metric("sales.order_count"),
    during=mv.time_scope(start="2026-08-01", end="2026-09-01"),
    via=ms.ref.relationship("sales.order_buyer"),
    coordinates=(channel,),
).rollup()
baseline_counts = attribution_members.observe(
    ms.ref.metric("sales.order_count"),
    during=mv.time_scope(start="2026-07-01", end="2026-08-01"),
    via=ms.ref.relationship("sales.order_buyer"),
    coordinates=(channel,),
).rollup()
change = current_counts.compare(baseline_counts)
allocation = change.attribute(axes=(channel,), top_k=3).execute()
selected_allocation = allocation.where(allocation.contribution.value.is_defined()).execute()
allocated_table = mv.table(
    contribution=selected_allocation.contribution,
    current=selected_allocation.current,
    baseline=selected_allocation.baseline,
).execute()
allocation.contract().show()
restored_allocation = session.artifact(allocation.state.artifact_ref)
```

Top-K 在两侧完整基底的并集上使用一个共同映射。余项掩码区分映射出的 Other 与真实
字符串 "Other"。两个或更多轴可以使用 `mode="hierarchy"`，按作者顺序输出每个前缀，
各层独立核对；`joint` 输出完整元组。筛选保留原始目标、完整基底、规则和核对范围，
并无条件撤销当前子域的完整性，不重新分配或平衡残差。

逻辑输入缺轴时，以显式图依赖展开冻结的观测定义；固定输入缺轴会在访问来源前拒绝。
完整固定状态支持断源归因、视图筛选与表格导出，包括新进程恢复。
原始 UTC 微秒周期桶和日→月归约分区保留此固定归因路线；其他时间精度与报告时区
仍需要各自资格。
加法 int64、Decimal 和 Duration 使用精确载体；component_mix 接受 int64/float64/Decimal 分量，拒绝 Duration。
整体分母为零或不稳定、非零分子与零基底矛盾、舍入残差超限都会拒绝。相对或嵌套变化、
distinct/distribution/extrema 与未经证明的重叠状态没有分配方法。通过
`marivo.help("analysis.dsl.LogicalDifferenceRelation.attribute")` 阅读聚焦契约。
此资格不授予安装 wheel 或远端验收。

六后端普通表的受限子集也支持 UTC 微秒时间轴、显式字符串贡献轴和有界窗口上的
int64 sum-zero 或原均值观测。远端输入先准备原生行，再由本地消费者执行原状态归约、绝对比较
与加法或分量分配。保留的 joint/hierarchy、共同 Top-K/Other 与筛选可断源执行。
缺失分类会拒绝且不发布产物。普通来源读取保留原有读取保证，不获得共享快照权威；
历史域准备仍要求原有快照捕获。其他原方法、来源数值类型及完整 C09 仍须独立验收。

## R6 恢复边界

比较、严格选择/cohort、固定参照、排名和归因沿用同一 typed graph 与 Store 7。
用 `session.artifact(ref)` 恢复，并读取结果的 `contract()`。fixed 命中或续算前
校验完整部件；恢复不会沿 lineage 重新读取来源。`mv.table(...)` 保持终端边界。
旧 Metric Dataset 比较、Delta/Attribution Dataset 公共导出及 Help target 已删除，
不提供重定向。R7.4 以公共 graph 结果替换私有 funnel Delta 和 Attribution
消费者；R7/R8 来源准入、R9 后端
资格及 R10 真实 Agent 验收各自交接。

保留组键的原状态归约返回 MaterializedGroupedNumericRelation；Singleton 返回
MaterializedRolledNumericRelation。冷恢复保留同一类型及后续操作契约。


## R7.3 Journey 匹配与耗时

本地 Subject 选人产生的 Metric 观察需要先 `execute()`，再进行 rollup 等后续操作。
Duration 当前行统计也需要先执行，再合并其状态。逻辑态 contract 仅推荐 `execute()`，
物化态 contract 再展示已获资格的 retained-state 后续操作。


`session.events.match` 现在要求显式逻辑 AnalysisDomain population，返回
LogicalJourneyResult。DuckDB 原生表与本地 Parquet 先经 Ibis 准备 occurrence，
再执行已注册的本地匹配。同 Run 的后续 Metric 贡献也在本地选人前准备完毕，
来源失败不会切换引擎。

受限 SQLite 路线支持 main 数据库原生表、int64 Event 与 Subject 身份及 UTC 微秒时间戳。
准备前通过原生备份接口将整个 main 数据库冻结到私有临时文件；复制和查询共享执行期限。
成功或失败均删除备份并恢复原连接。附加数据库及其他来源形状仍未取得资格。

```python
import marivo.analysis as mv
import marivo.semantic as ms
from marivo.refs import ref
from datetime import datetime, timezone

members = session.members(ref.entity("sales.customers"))
start = mv.step(participant=ms.participant_role(
    event=ref.event("sales.started"), name="buyer"), key="start")
finish = mv.step(participant=ms.participant_role(
    event=ref.event("sales.finished"), name="buyer"), key="finish")
window = mv.time_scope(start="2026-02-01T00:00:00Z", end="2026-02-02T00:00:00Z")
end = datetime(2026, 2, 3, tzinfo=timezone.utc)
journeys = session.events.match(
    mv.sequence(start, finish), population=members, cohort_window=window,
    completion_through=end, matching=mv.first_per_subject(),
    completeness=(mv.BoundedCompletenessDeclarationV1(
        inputs=(start.event, finish.event), complete_from=datetime(2026, 2, 1, tzinfo=timezone.utc),
        complete_through=end, rationale="Verified source coverage"),),
)
elapsed = journeys.time_to_event(from_step=start, to_step=finish)
mean = elapsed.completed().duration.summarize(mv.mean()).execute()
dropped = journeys.read(mv.dropped_before(step=finish))
selected = dropped.where(dropped.value.eq(True)).members(
    through=journeys.subjects(start.participant))
revenue = selected.observe(
    ref.metric("sales.revenue"), during=window,
    via=ref.relationship("sales.order_customer"),
).execute()
```

示例要求已声明对应语义对象，并已验证所声明的覆盖区间。first-per-subject、
every-start shared/exclusive 均保留 canonical assignment、完整 Journey 身份和
逐步 reach 真值。没有开始 occurrence 就没有 Journey。开始窗口左闭右开，随访上界
排他；同刻事件必须有已证明的业务顺序。只有 first-per-subject 开放 dropout。
覆盖 Unknown 不会变成 False，普通筛选遇到未决真值会拒绝；完整 Journey 机会域
可以交给既有的显式 Subject cohort 规则。

EventDurationResult 提供 `status`、`started_at`、`completed_at`、`duration`、
`observed_duration`、`followup_until` 六个关系。状态精确区分 complete、incomplete、
coverage_censored、not_entered、entry_unknown。只有已完成步骤对有 duration，
`completed()` 返回 CompletedJourneys。Duration 谓词使用 `datetime.timedelta`。
当前行 Duration `mean` 保留 Journey 分母：10、30、100 秒的均值为 140/3 秒，
仅在微秒输出时舍入一次到 46.666667 秒；先按主体得到 20、100 秒再平均则为
60 秒。选人不会替换原 Journey 分母。
状态和时间字段经过多次 `where` 与冷恢复后，仍保留值和 Cell 标签及原因。
保留的状态、时间戳和微秒 Duration 字段支持当前行 `count` 与 `count_defined`，
分组使用已保留的完整 Subject 坐标。

保留的微秒 Journey 耗时支持 `duration.ratio(duration)`，配对使用完整 Journey 键。
Defined 操作数正常相除；零分母产生 `Undefined(zero_denominator)`。
Unknown 观察耗时将 `coverage_censored` 或 `entry_unknown` 保留为标量 float64 Unknown，
自除也不消除未知状态。两个原始端点 Cell 均保留，其他非 Defined 操作数仍拒绝。
固定标量比值支持 zscore/MAD，并保留 Unknown Cell。
Pearson/Spearman/Kendall 拒绝 Unknown，不补值或删除配对。
该 Journey 域不提供 forecast/runs 所需的完整时间网格。
其他单位及来源 Journey ratio 输入仍未取得资格。

Store 7 保存 assignment、reach、覆盖、映射、精度和归约状态。fixed read、归约、
筛选和断源新进程恢复均消费保留部件，不重新匹配。显式 fixed population 不能与
新来源匹配或观察混合。结果卡披露原始及捕获单位与潜在精度损失（包括原生纳秒转
微秒）；边界与顺序使用捕获时间，精度下降造成的同刻仍需业务顺序。整个执行共享
600 秒期限。本阶段不授予 funnel、Lifecycle、Anchor、远端后端或同 wheel 完整 R7 资格。

## 固定 Anchor 总体上的留存

```python
import marivo.analysis as mv
import marivo.semantic as ms

session = mv.session.get_or_create("anchor-retention", report_timezone="UTC")
population = session.members(ms.ref.entity("commerce.subjects"))
starting = ms.participant_role(event=ms.ref.event("commerce.started"), name="subject")
returning = ms.participant_role(event=ms.ref.event("commerce.finished"), name="subject")
anchors = session.anchors(
    starting,
    population=population,
    during=mv.time_scope(start="2026-08-01", end="2026-09-01"),
    business_order=ms.ref.business_order("commerce.order"),
)
retention = anchors.retention(
    returning, within=mv.elapsed(mv.duration(hours=168))
).execute()
retention.show()
retention.contract().show()
selected = retention.known_true().execute()
selected.members(through=selected.subject_binding).execute().show()
subjects = retention.by_subject(rule=mv.any_anchor()).execute()
subjects.known_true().members().execute().show()
```

SQLite main 原生表的 int64 身份、UTC 微秒 Event 起点 retention 支持 elapsed 与 calendar
窗口，使用冻结来源准备及已注册的本地消费者。Unknown 保留在原机会域中；选择和独立进程
恢复保持其界与 any/every Subject 分组。该 Event 起点 retention 路线也接受 string Subject
键。int64 与 string occurrence 键在固定执行和冷恢复中保留完整的 Subject/Event/occurrence
身份；occurrence 键的类型不决定 Subject 键的类型。其他源形状仍需独立取得资格。
SQLite elapsed/calendar Anchor 观察支持 count、int64/float64 additive sum 的 zero/null
空策略、Metric 切片及 ratio/signed linear 组合。每个组件独立读取，再打包为 typed 列表后本地消费。
保留重叠窗口贡献重数、业务顺序与断源恢复。mean、fold、cumulative、distinct、贡献坐标及
其他数值 carrier 继续拒绝。
同一 SQLite 形状支持从 Journey 绑定 Anchor，保留原始分配与起点时间。
从恢复后的 fixed Journey 绑定时，不访问来源，也不重新执行匹配。
这些 Journey 起点支持同一直接 Metric 观察及 elapsed/calendar retention，保留原始分配
与机会域；候选输入先准备，再进入本地绑定。Calendar Metric 观察排除恰落在 DST 截止点
的返回；elapsed 24 小时与一个日历日的结果可能不同。

即使后续覆盖不完整，观察到合格返回也是真。只有精确绑定 returning Event、来源、
版本的完整性覆盖整个半开窗口，未观察到返回才是假；否则为 Unknown。
有完整性声明时通过 `completeness=` 传入。原实例 Ω 保留未知项：25 真、5 假、
70 未知的界为 `[0.25, 0.95]`；空 Ω 的界为 Undefined。状态视图保持原分母与界。

`any_anchor()` 和 `every_anchor()` 显式将 Subject 像固定为新 Ω。一真一未知在 any
下为真、every 下未知；一假一未知在 any 下未知、every 下为假。没有 Anchor 的
Subject 不进入该像。只有已选中的真状态能产生成员。实例状态需要精确 SubjectBinding；
Subject 状态无需 `through`。结果不提供界的算术或 rollup。

在 Anchor 仍为逻辑对象时构造留存。MaterializedAnchorDomain 仅保留 starts，
会在执行前拒绝新增 return 输入。已物化留存结果保留完整真值、覆盖与实例纤维，支持
断源状态选择和量化。R7.8 证据记录区分已验证的有界执行和原 fixed-retention 资格中
未完成的目标；同 wheel、远端与完整 R7 验收仍独立。
恢复状态或已选择状态的 Artifact 时，布尔字段协议保持不变，
`value.eq(True)` 在恢复后仍可使用。

## 精确漏斗比较与证据

两期使用同一显式总体上的 first-per-subject Journey。pattern、matching 和定义必须
一致，开始窗口及随访长度相同，并具有完整覆盖。下面继续已有的 `journeys`、
`baseline_journeys`，以及其 pattern 中精确的 `finish_step`。

```python

change = funnel.compare(baseline_journeys.funnel())
allocation = change.attribute(
    target=mv.funnel_loss_rate(step=finish_step),
    axes=(ms.ref.dimension("sales.customers.region"),),
    mode="joint",
    top_k=5,

allocation.contract().show()
page = allocation.findings(limit=20)
if page.items:
    finding = allocation.finding(page.items[0].finding_id)
```

漏斗轴在本地 matching 前，按全部合格开始 occurrence 的入口时点准备；计算消费同一
canonical assignment。snapshot/validity 版本和完整轴元组保留真实 Null 类别。
七项计数使用精确 int64；零分母和初始步骤流失率为 Undefined。字段 handle 绑定 receiver。

归因分别计算 loss 和 denominator mix，以两期 resolved-entry 合计建立统一 Top-K，
保留 typed Other 与 masks。joint/hierarchy 的每个 resolution 都核对两侧项和目标差值。
筛选保留原 reconciliation scope，并撤销完整分区承诺。fixed 必须具有 retained 轴及
组件，不读取当前 Semantic、不连接来源，也不重新 matching。

物化结果提供 Evidence、分页 Findings 和单条读取；每次读取都验证整个冻结集合。
compare/归因的发射上限为 1000，保留 eligible/emitted/truncated 权威。
SQLite main 原生表的 int64 身份与 UTC 微秒时间支持任意非空、去重、有序的直接
string/int64 Subject 轴组合；Subject 必须未版本化，除既有图与快照预算外不增加轴数或

或以 NULL 表示开放结束的 UTC DATE 左闭右开 validity 路径的 string/int64 轴。
nullable int64 坐标在 pandas 读取中保留精确 Arrow 类型，包含 hierarchy 非活动前缀；
超过 `2**53` 的值不会经过 float64 转换。
兼容的固定比较及 loss/denominator-mix 归因保留完整轴元组，可断源续算与冷恢复。
snapshot 轴要求精确入口期；缺失时拒绝，不选择最新或较早的行。validity 包含起点、排除终点；
缺失或重叠区间在发布前拒绝。此路线可组合直接与历史轴并保留同一 DATE profile；其他类型、路径/版本条件、
空轴来源归约及形状仍需独立取得资格。

## 相关与预测

SQLite 普通表支持两个 int64 实体观察量的 Pearson、Spearman 和 Kendall 相关，
要求微秒精度的 UTC 事件时间轴。coefficient 和 selected 视图沿同一准备图执行。
其他 SQLite 统计类型和形态仍需各自的物理资格验证。
PostgreSQL 和 MySQL 普通表也支持这一双 int64 实体配对路线；MySQL 要求
读取连接成功初始化为 UTC。
Trino Iceberg 和 ClickHouse 本地 MergeTree 表也支持这一配对路线。
ClickHouse 要求显式声明或物理列提供 UTC 时间轴；不可用的服务器时区事实不能
提供隐式读取时区。其他类型、分布式形态和完整取消验收仍需独立验证。
六个后端的普通表也支持对此准备路线的完整 int64 实体观察量执行 zscore 和 MAD，保留
完整整数原值和拟合状态。其他源端数值类型仍需独立验收。
每次图执行共享一个 600 单调秒预算，包括普通来源读取、当前行统计和固定输入续算。
外层预算保留原始起点。提交或发布前超时会拒绝结果，保留先前产物并释放所拥有的资源。

统计来源读取在原生提交和分批消费期间共享 execute deadline。DuckDB 和 SQLite 可以
在无需 domain preparation 时中断活动原生查询；执行线程清理游标和连接。
超时返回结构化错误，无法确认连接释放时阻止发布；远端服务器是否终止仍须独立证明。
MySQL 来源图先准备独立且有时间界限的控制连接，只取消所选连接的自有活动查询。
清理在执行线程进行。无法确认控制连接关闭时保留 Run 资源记录，阻止自动恢复；
控制提交成功本身不构成服务器终止证明。
PostgreSQL 在超时时发送驱动原生取消请求；独立验证之前，远端终止状态仍为 unknown。
Trino 在提交前登记游标，可在执行或分批读取期间取消查询；重试覆盖首次 HTTP 响应前
的竞态，执行线程负责关闭游标。服务器查询状态须独立验证，客户端关闭本身不能证明取消。
分批读取时，超时 checkpoint 可能先于定时器回调触发退出。游标清理会在执行线程调用
原生取消；证据明确记录 `owner_checkpoint`，须有实际取消调用和独立服务器确认，不能
声称发生了定时器中断。
ClickHouse 每次读取通过原生 HTTP 超时设置使用 execute 预算的剩余时间。只读账户须允许
修改 `max_execution_time` 和 `timeout_before_checking_execution_speed`，并保持超时抛错。
设置不可用时在业务读取前结构化拒绝；保留原始 deadline，不发布部分结果。
独立的有界控制连接使用同一 reader 认证，仅取消当前 Session 自有的 query ID 和 user。
账户需要由运维配置 `SELECT(query, query_id, user) ON system.processes`；这些列允许查看
一般查询元数据。权限缺失时提供结构化修复，不提升凭据权限。控制连接关闭未确认时保留
incomplete Run，并阻止自动恢复。服务端超时和查询终止须独立验证，本地 MergeTree
证明不授予 Distributed 分片资格。
服务器原生超时可能先于 Python 的期限触发；其证明依赖已配置的期限和独立服务器查询
状态，客户端与服务器时钟分别记录。

六个后端的普通表还支持微秒 UTC 时间格上的完整 int64 实体 runs 及 count
视图，以及完整 int64 时间分组历史的 naive/drift/seasonal-naive 预测及 prediction
视图。空贡献表示零时须显式声明零策略，不填补 null 或 unavailable 历史。
ClickHouse UTC 时间轴保留物理时区，因此非 UTC 会话设置下的窗口边界也保持 UTC。

Numeric 关系支持 2–16 个互异量的全部两两组合。默认方法为 Pearson；
Spearman 和 Kendall 需显式指定。正 lag 在原始完整格上配对左侧 t 与右侧 t+k。
coefficient 和 selected 视图可在执行前组合；相关结果只描述关联。

```python
import marivo.analysis as mv

association = revenue.correlate(order_count, method="spearman")
selected = association.where(association.selected.value.eq(True))
coefficients = selected.coefficient.execute()
coefficients.show()

future = daily.forecast(horizon=mv.periods(3), model=mv.drift())
report = mv.table(prediction=future.prediction, lower=future.lower, upper=future.upper)
report.execute().show()
```

这里 revenue 和 order_count 是共同完整观察域上的量；daily 是历史格完整、
每格 Defined 且有限、未来周期已获批准的时间观察。
模型工厂为 naive()、drift()、seasonal_naive(periods=s)，最短历史分别为 2、3、s+1。
上下界是未来观察值的名义预测区间。结果筛选保留原训练或搜索域及 Findings；
固定恢复只验证捕获事实，不读取来源或重新拟合。


## 扩展 observation 与入口路径

普通 Metric/Count 与 relative observation 不再限制固定跳数。路径仍须连续、明确 join keys、
有向 to-one；普通实体保持未版本化，relative 保留当前版本捕获规则。PostgreSQL、MySQL、
Trino、ClickHouse 支持原生普通 Count，保留完整身份检查、bounded 过滤及原 count 状态。
每条合法贡献计为一，空成员为零。

SQLite Funnel 支持未版本化 Subject 的直接/历史混合、多条历史路径与多跳 string/int64 轴。

## 九种统计方法及保留视图

以下假设 `revenue` 与 `order_count` 是同域数值观察，`daily` 是至少三期、
Defined 且有限的完整时间观察，时间网格已批准请求的未来周期。九种方法都通过 typed graph 执行。

```python
zscore = revenue.deviation(method="zscore")
mad = revenue.deviation(method="mad")
fixed = zscore.execute()
chosen = fixed.where(fixed.score.value.is_defined())
chosen = chosen.where(chosen.score.value.gt(0)).execute()
chosen.contract().show()
mv.table(observed=chosen.observed, reference=chosen.reference,
         deviation=chosen.deviation, score=chosen.score).execute().show()
chosen.score.rank(order="descending", ties="dense").limit(2).execute().show()
mad.execute().show()

segments = daily.runs(where=daily.value.gt(0)).execute()
segments.where(segments.count.value.gt(1)).execute().show()

pearson = revenue.correlate(order_count, method="pearson")
spearman = revenue.correlate(order_count, method="spearman")
kendall = revenue.correlate(order_count, method="kendall")
for associations in (pearson, spearman, kendall):
    fixed_associations = associations.execute()
    selected = fixed_associations.where(fixed_associations.selected.value.eq(True)).execute()
    mv.table(coefficient=selected.coefficient, selected=selected.selected).execute().show()
    selected.coefficient.rank(order="descending", ties="dense").limit(1).execute().show()

naive = daily.forecast(horizon=mv.periods(2), model=mv.naive())
drift = daily.forecast(horizon=mv.periods(2), model=mv.drift())
seasonal = daily.forecast(horizon=mv.periods(2), model=mv.seasonal_naive(periods=2))
for future in (naive, drift, seasonal):
    fixed_future = future.execute()
    selected = fixed_future.where(fixed_future.prediction.value.gt(0)).execute()
    mv.table(prediction=selected.prediction, lower=selected.lower,
             upper=selected.upper).execute().show()
    selected.contract().show()
```

结果筛选保留原拟合、分类、配对搜索或训练范围以及完整 Findings。所属字段共享计算。
系数和预测值可做当前行的描述统计，但不获得原 Metric 的 rollup 或 attribute 能力；
预测区间边界不可加总。固定续算与冷恢复使用已验证的捕获部件，缺失或损坏部件直接失败，
不重算或回源。旧统计 Artifact descriptor 明确拒绝，不迁移。R8.5 证据不补授前序 R8、
同 wheel、远程后端或真实 Agent 资格。旧 `.discover`、Candidate 和旧 Association/Forecast Dataset 链已退役。

PostgreSQL、MySQL、Trino 和 ClickHouse 的远端准备允许多次读取期间源数据变化。
保留输入记录实际读取的事实，不承诺来自同一个数据库快照，也不把先前查询的检查证明
扩展到后续读取。全部来源依赖仍须先于本地选人；固定结果的后续操作校验并使用这些
保留输入，不重新连接来源。

MySQL sample 和 raw_sql 的超时控制仅取消独立读取连接的当前自有查询，并关闭读取和控制连接；认证专用的 SET/读取语句仍保持独立用途。


## 声明完整网格上的业务完整性

读取成功并不能证明某个桶的业务数据已经全部到达。对于原始 sum 观测，使用
`observe(complete_during=(scope, ...))` 声明完整区间。区间必须使用带时区的 datetime
绝对边界，并配合 `during=grid.window` 和无 partial 桶的完整原始网格。
这次调用同时绑定接收域、Metric 和原始贡献来源。

```python
from datetime import datetime, timezone

complete = mv.time_scope(
    start=datetime(2026, 8, 1, tzinfo=timezone.utc),
    end=datetime(2026, 8, 3, tzinfo=timezone.utc),
)
daily = members.each(grid).observe(
    sum_metric, during=grid.window, complete_during=(complete,),
)
```

只有整个原始桶都落在声明的区间并集中，才保留原本的 Defined/Null。
其他桶返回 `Unknown(insufficient_business_coverage)`；实际读取覆盖、部分值和原始贡献
仍被保留。空元组表示没有完整桶；省略参数保留原有策略。最多接受 64 个区间，重叠和相邻
区间会合并。当前生产路径为 DuckDB table/Parquet 的 sum 观测，不能同时传端点或贡献坐标。

Forecast 拒绝 Unknown 训练输入；runs 将其视为 unavailable 并切断区间。
Duration 商会将该 Unknown 原因保留为 float64。此类观测不能通过 rollup 或合并时间桶把
部分业务数据变成完整值；固定和冷恢复消费会在不读取源的情况下核对同一声明。


### 本地 CSV 与 JSON 的 sum-zero 执行

现有本地 CSV 文件和不带请求参数的 GET JSON 文件可以进入 DuckDB 的 R1 schema

## 检查前提

```python
quotient = current.ratio(reference, pairing=mv.ExactKeys(verification="assume"))
```

`assume` 保留 ExactKeys 的语义，不选择交集，也不新增缺失或 Null 政策。必要索引插入
遇到冲突、必需取值遇到缺失仍失败；零分母、Null 和 Unknown 沿用方法政策。跨 Session
