Marivo 0.4.16 让 discovery 更容易配置和恢复，记录每个 objective 实际使用的规范值列，
并为 evidence 分页边界提供结构化、可复制的修复建议。同时，本版本记录了面向
agent workflow 的 progressive analysis help 拓扑。

## 重点

- 聚焦的 `marivo.help("analysis.<target>")` 现在会展示每个 `discover.*` objective 的策略
  契约：默认策略、合法备选、适用的 semantic kind、threshold 含义和使用时机。策略事实
  直接从运行时 registry 渲染。
- `discover` 现在会按 frame 解析省略的 `value`：`DeltaFrame` 使用规范的 `delta` 列，
  `MetricFrame` 使用声明的 measure/value 列。解析后的列名会记录在 params 和 evidence 中，
  因此省略值与显式传入等价。
- `session.evidence.findings()` 和 `.digests()` 现在明确支持 `[1, 100]` 的有界 `limit`
  （默认值分别为 `50` 和 `10`），并提供不可变的分页状态以及 `has_more`/`next_cursor`
  续读。无效的 limit 会抛出带可复制修复建议的 `EvidenceLimitError`。

## 变更

- `discover` 显式选择 `value` 时会校验列存在且为数值类型；失败时提供数值列候选和重试
  路径。多指标 frame 应先使用 `frame.metric(...)` 投影后再 discovery。
- Discovery 策略说明现在区分单点异常、局部 regime 变化、整窗行为，以及应交给
  `compare` 处理的持续性变化。

## 修复

- `observe` → `compare` → `discover` 链路在解析当前 frame 轴时，不再把配对的 baseline bucket
  当作维度。
- `DeltaFrame` 同时包含 current、baseline、delta 和 percent-change 等数值列时，省略 `value`
  不再因为数值列过多而失败；带有额外数值轴的 `MetricFrame` 也可以使用其声明的 measure。

## 文档

- 更新中英文 analysis workflow 和 evidence 文档，补充 discovery 策略、值列解析和有界分页。
- 在 analysis design specification 中记录 progressive analysis live-help 拓扑及其边界归属。

## 内部

- 增加真实 observe/compare/discover 链路、聚焦策略帮助、evidence 分页和结构化 limit 修复
  建议的回归覆盖。

## 安装

国内网络建议运行：

~~~bash
curl -fsSL https://marivo.io/install-marivo-cn.sh | bash
~~~

也可以使用标准安装器：

~~~bash
curl -fsSL https://marivo.io/install.sh | bash
~~~

手动安装：

~~~bash
pip install marivo
~~~

Marivo 0.4.16 要求 Python 3.10 或更高版本。
