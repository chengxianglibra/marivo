Marivo 0.4.2 统一了语义编写、分析选择、对齐、证据与
forecasting 中的时间语义，加入可认证的自定义周期、命名发生项、工作日
schedule，以及让这些能力可复现的类型化契约。

## 重点

- 时间语义现在由彼此独立、可复用的权威来源组成：`PeriodCalendar` 负责 fiscal
  与 retail 周期，`TemporalSet` 负责命名的区间或日期，`WorkSchedule` 负责经过认证的
  工作日状态。`Grain`、`TimeScope` 与 `AlignmentPolicy` 会携带精确的语义 variant 和
  来源信息。
- 语义编写与目录加载支持认证周期日历、calendar 层级、时间
  发生项和工作日安排。分析复用项目本地的精确快照与摘要，不再在
  不同路径中独立推导边界或 holiday。
- Certified 语义粒度支持观测、roll-up、比较和自定义周期预测；
  它们使用带精确键与 bound 的 ordinal 周期。快照不完整、过期或不匹配时，会在写入
  产物前失败即停止。
- 比较新增类型化的 `period_progress`、`period_correspondence`、`occurrence_progress`
  与 `working_day_progress` 策略，分别用于周期内等进度、命名周期映射、命名发生项
  和工作日 ordinal 对齐。

## 破坏性变更

- 时间权威来源必须使用精确的类型化语义引用或目录条目。分析不再
  从名称、locale 或分析-本地参数推断 fiscal 周期、holiday、发生项或工作日
  状态。
- 分析产物使用 `analysis-artifact/v8`。旧产物结构以及
  `component_graph_ref` 等已移除字段会失败即停止，不再迁移或 dual-read；升级后请重新创建
  分析会话。

## 变更

- 时间绑定、周期对应关系、发生项范围、工作日安排和对齐策略
  以类型化证据持久化，其中包括权威来源引用、快照摘要、边界时区与精确
  的半开区间边界。
- Frame 元数据现在保留覆盖率与质量计算所使用的报告时区；计算覆盖率比率
  前会先 canonicalize 混合时区。
- 公共错误与契约对缺失时间权威来源、无效覆盖率、保留列和不支持的指标
  arity 给出更精确的修复位置。实时帮助、公共导出与运行时接口保持确定性一致。
- 文档站点新增双语首页与设计博客，补充搜索和索引信号，并将 Sphinx API
  引用纳入仓库检查。

## 修复

- 比较与 correlation 证据现在绑定到报告实际使用的精确周期或滞后期。
- 没有覆盖率 sidecar 时不再声称存在覆盖率；归因 extraction 失败也不会隐藏仍可
  读取且可对账的行。
- Certified roll-up 键、时间发生项身份和 forecast 周期边界在持久化与重新
  加载过程中得到保留。

## 文档

- 新增 unified 时间语义规范，覆盖周期日历、时间集合、work
  schedule、粒度、范围与对齐。
- 更新中英文分析流程，说明 certified 时间选择、对齐、工作日
  比较和语义-粒度 forecasting。

## 安装

```bash
pip install marivo
```

请为计划使用的数据源安装对应后端扩展。Marivo 0.4.2 要求 Python 3.12 或更高版本。
