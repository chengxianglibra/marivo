Marivo 0.4.3 让固定 schema 的 semantic model 可以连接参数化 JSON API，为 event
elapsed-time analysis 加入受治理的 cohort axis，并让面向 agent 的 analysis failure
提供更可执行的修复路径。

## 重点

- `md.json(...)` 现在支持从嵌套响应中选取 record array、固定与运行时绑定的 query
  parameter、JSON `POST` body，以及用 `md.source_param(...)` 声明的参数值。Physical
  schema 仍须显式定义，并在 semantic loading 前完成校验。
- `Session.source_bindings(...)` 在一次动态 analysis scope 内提供必需的非敏感 API 参数，
  无需改变 `observe(...)` 等 operator 的签名。Inspection 也可以通过
  `inspection.sample(..., source_params=...)` 显式提供同一组参数。
- DuckDB connection 只会在声明的 `http_scope` 内附加来自环境变量的 bearer token 或
  custom header，使凭证留在 project metadata 之外，并避免发送到无关 URL。
- `session.events.time_to_event(...)` 支持受治理的 subject `axes`，elapsed-time result
  可以保留确定性的 cohort-entry dimension，并同步进入 lineage、quality check 和持久化的
  analysis scope。

## 变更

- JSON API acquisition 支持带 query string 的 `GET` 与 JSON object `POST`，同时保持
  datasource inspection 和 analysis execution 的惰性边界。参数缺失或多余、wrapped-record
  path 无效、request shape 不支持时，都会通过类型化 guidance fail closed。
- Analysis help 现在会为所有在 runtime 强制单 metric 输入的 MetricFrame operator 一致地
  声明该约束。
- Evidence digest 与 store failure 现在包含类型化 repair action 和规范 help target，使
  blocking issue 能指向有效的下一步。
- Project README 与 documentation site 更新了双语导航、产品定位和 Marivo 品牌素材。

## 修复

- Derived-metric component comparison 与 attribution 在 temporal join 遇到 `NaT` 时不再
  crash；无法匹配的行会被丢弃，无法形成完整 decomposition 时返回类型化的
  `ComponentDecompositionError`。
- `time_to_event` 会拒绝与 journey 或 result 保留列冲突的 governed axis，并在持久化
  metadata 中校验 axis 唯一性。
- Metric selection 的 evidence repair 现在解析到公开的 `MetricFrame.metric` help surface，
  不再指向无效的内部 target。

## 文档

- 扩展 semantic-layer guide 与 datasource specification，补充 wrapped JSON、参数化 request、
  scoped authentication、inspection 和 analysis 的完整示例。
- 进一步说明 retrieval-oriented knowledge base 可以补充，但不能替代可执行的 semantic
  contract。

## 安装

```bash
pip install marivo
```

请为计划使用的 datasource 安装对应 backend extra。Marivo 0.4.3 要求 Python 3.12 或更高版本。
