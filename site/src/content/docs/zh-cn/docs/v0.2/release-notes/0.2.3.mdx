Marivo 0.2.3 是 v0.2 系列的补丁版本发布。这个版本继续收紧面向智能体的
语义与分析契约，并增加运行侧发布能力。它改进 Trino 聚合兼容性，
让语义帮助与目录范围更明确，并为多层驱动因素分析增加稳定的
归因物化。

## 重点

- 增加 `marivo --version`，CLI 环境可以直接报告已安装的 package version。
- 增加 Marivo static 产物 publishing 流程使用的内部 S3 发布 uploader。
- 实现 composite 归因物化，支持需要稳定 multi-tier 驱动因素
  输出的分析 workflows。
- 围绕类型化范围、显式领域引用与分位数 naming 收紧语义
  目录和帮助契约。
- 从公共分析路径移除旧的报告发布接口。

## 变更

- 分析意图参数现在统一使用 `time_scope` 与 `slice_by`，不再沿用旧的
  `timescope` 与 `where` 命名。
- 语义折叠帮助现在统一使用分位数术语，不再混用分位数与
  分位数名称。
- 目录 list 范围现在要求类型化字符串范围对象，不再接受宽松的
  裸-字符串输入。
- 分析证据 suites 按领域与 per-tier 覆盖率重新组织，便于解读
  release 检查。

## 修复

- Trino-backed 语义 aggregates 现在支持分位数表达式。
- 采样比率归因现在可以在归因路径中工作。
- 分析帮助 aliases 现在会解析到当前公共名称。
- 语义编写现在会一致拒绝 `domain=` 的裸 strings。

## 文档

- 增加归因 composite 物化设计说明。
- 更新分析设计与技能指引，以匹配当前归因、publishing 和
  参数契约。
- 刷新语义层文档中关于类型化引用、显式帮助输出与分位数
  folding 的说明。

## 破坏性变更

- 公共分析报告发布接口已移除；产物 publishing 现在通过更窄的
  static publishing 路径执行。
- 分析 callers 应使用 `time_scope` 与 `slice_by`；旧的 `timescope` 与 `where`
  不再是文档化契约。
- 语义目录与编写辅助函数要求类型化范围/领域引用，不再接受
  裸 strings。

## 安装

```bash
pip install marivo
```

按数据源选择对应后端扩展：

```bash
pip install "marivo[duckdb]"
pip install "marivo[mysql]"
pip install "marivo[trino]"
pip install "marivo[postgres]"
pip install "marivo[clickhouse]"
pip install "marivo[all]"
```

Marivo 0.2.3 需要 Python 3.12 或更高版本。
