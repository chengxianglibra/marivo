这里记录 Marivo 背后的设计思考。它们不是接口手册，也不追逐一次演示中的效果，而是讨论一个
更长久的问题：怎样让 Agent 在获得分析自主性的同时，仍然尊重业务语义、计算边界与证据。

## 已发布

### [为什么数据分析 Agent 需要 Harness，而不只是生成 SQL](/zh-cn/blog/why-data-analysis-agents-need-a-harness/)

如果分析不只是生成一段能执行的 SQL，那么语义、分析状态、证据和接口分别应该承担什么责任？
这篇综述介绍 Marivo 试图解决的问题，以及整套设计背后的分工。

## 这个系列还会讨论

- 语义层如何把业务含义变成 Agent 可以依赖的代码契约；
- 类型化分析语言为什么约束分析动作，而不替 Agent 规定推理流程；
- 分析会话如何把一次回答变成可以恢复和继续的调查；
- 证据引擎如何记录事实，同时克制地停在判断之前；
- 面向 Agent 的结果对象、错误、实时帮助与接口分层。

这些文章会随着 Marivo 的演进继续补充。涉及具体接口时，以当前版本的
[正式文档](/zh-cn/latest/)和运行环境中的 `marivo.help(...)` 为准。
