## 1. 范围与当前盘点

本轮重写当前开发线 `latest` 的人类使用指南，两种语言作为同一交付维护：

- 英文根目录：`site/src/content/docs/docs/latest/`，URL 前缀 `/docs/latest/`。
- 中文根目录：`site/src/content/docs/zh-cn/docs/latest/`，URL 前缀 `/zh-cn/docs/latest/`。
- 两种语言目前各有 **22 篇使用文档**，下文逐页映射覆盖全部 44 个文件。
- 每种语言另有 1 篇贡献指南和 40 篇发布说明，正文均保留。
- 历史版本 `v0.1` 至 `v0.5`、博客、产品首页、API 参考和 packaged skills 不重写。
- 必要的导航、版本入口、链接和文档示例测试调整属于后续实施配套工作。

当前使用文档存在的组织问题：

1. 入口页主要说明工作流，缺少充分的产品介绍和任务化能力导览。
2. 首次 Agent 分析很快进入对象和执行规则，未完整展示人的准备、提问、确认与审阅。
3. `concepts/analysis-workflow.mdx` 同时承担会话、观察、筛选、群体、统计和执行说明。
4. `concepts/evidence.mdx` 混合结果恢复、审计解释和存储实现细节。
5. 时间与群体、比较与变化调查分别共用长篇页面，读者难以按当前任务定位。
6. 若干示例依赖另一页的变量或额外数据；必须明确前置条件和可复现起点。

这是一轮内容与教学结构重写，不进行产品功能改造。发现能力缺口时记录实际限制，
不得用虚构接口、隐含准备工作或未经验证的产品承诺补齐教程。

## 2. 目标阅读路径与组织决策

采用 7 个栏目、**30 篇主要使用页面 / 60 个双语文件**。
新增篇幅用于拆开不同任务、补齐产品介绍与结果审阅，不新增逐 API 的说明页面。
迁移承接页不计入 30 篇，不进入主导航。

| 读者 | 主路径 | 完成标志 |
| --- | --- | --- |
| 初次了解 Marivo | P01 产品介绍 → P02 能力导览 → P04 选择项目 | 知道用途、准备条件和适合自己的入口 |
| 使用已有项目的 Agent 用户 | P03 安装核验 → P04 已有项目 → P05 首次 Agent 分析 → P08 审阅回答 | 提出问题，确认口径，检查一份有结果依据的回答 |
| 没有生产数据、想直接试用的人 | P03 → P06 本地 Python 教程 | 在独立目录计算并保存确定性结果 |
| 直接使用 Python 的分析者 | P06 → 按需 P14–P20 | 从基础观察进入筛选、比较、时间、统计和结果复用 |
| 准备团队业务模型的人 | P04 新项目 → P09 接入 → P10 指标 → 按需 P11/P13 → P12 检查 | 得到可加载、口径明确并经过适当验证的模型 |

P05 使用已有可用模型，也提供进入本地演示项目的路径；演示准备由人运行命令或交给
Agent 执行，业务读者不必先学会编写 P06 的所有 Python 代码。
P07、P08 是可反复查询的协作指南，首次体验不要求事先逐页读完。
概念页按需阅读，不是开始使用的强制课程。

导航规则：

- 主导航按下节目录顺序呈现；开始使用展开，其余任务组可折叠。
- 一个主要页面在主导航中只出现一次；跨任务通过正文链接连接。
- 保留版本切换；发布说明、贡献指南、Python API 参考放在独立的次要导航中。
- 英文和中文使用同一结构，标题和导航标签自然本地化。
- 不为每个目录额外建立空洞的索引页；栏目由侧边栏分组，P02 提供跨任务导览。

## 4. 逐篇写作任务

每个 P 编号代表一个双语交付单元。下列“内容”是写作提纲，“验收”是读者应达到的结果，
不是已完成的验证。示例 D0–D4 在第 6 节定义；来源 S0–S6 在第 7 节定义。

### 认识产品

#### P01 · `index.mdx` · 认识 Marivo / What is Marivo?

- **读者与目标**：首次访问者；能用自己的话说明 Marivo 的用途并选择下一步。无前置要求。
- **内容**：业务分析中口径不一致、过程难复用、结论难检查的问题；Marivo 的角色；一份输入与结果的简短示意；人与 Agent 的职责；适用条件；Agent、Python、建模三个入口。
- **成果与边界**：读者知道需要数据与业务定义，以及 Marivo 不自动确认业务含义或因果。不给完整术语表，不列底层模块。来源 S0；示意引用 D0 的业务问题。

#### P02 · `capabilities.mdx` · Marivo 能做什么 / What can you do with Marivo?

- **读者与目标**：评估用途或寻找任务入口的人；把自己的问题对应到可用能力。前置仅 P01 的定位。
- **内容**：接入与检查、指标复用、观察与分组、比较与调查、时间分析、统计、结果复用与依据检查。每项按“问题 → 输入 → 结果示意 → 使用条件 → 操作指南”展开。
- **成果与边界**：每项能力都有具体例子和目标页；数据源连接与分析方法支持分别说明。D0–D4，来源 S0–S5；不宣传通用预测、自动因果分析或任意后端执行。

### 开始使用

#### P03 · `start/installation.mdx` · 安装与环境检查 / Install and check your environment

- **读者与目标**：所有实际使用者；得到能运行对应教程的环境。
- **内容**：版本选择；与 `latest` 匹配的明确安装路径；Python 与依赖条件；本地 DuckDB；其他驱动入口；平台命令差异；验证解释器、包来源与版本；可选初始化与安装脚本。
- **成果与边界**：从空目录到环境检查成功，无须凭据或生产数据。开发线与发布包路径明确分开，详细部署留给 P27。来源 S6；执行前固定版本/源码修订。

#### P04 · `start/project.mdx` · 选择或准备项目 / Choose or prepare a project

- **读者与目标**：准备开始任务的人；确定使用哪个项目及缺少什么。前置 P03 或已有可用环境。
- **内容**：已有模型、新业务项目、本地演示三条分支；项目目录和凭据的最低准备；如何确认已有指标适用；新项目需要人提供的业务规则；Agent 与 Python 下一步。
- **成果与边界**：每条分支到一个明确的可执行入口。解释 `init` 的可选性，不重复安装教程或承担完整建模。D0 演示准备入口，来源 S0/S1/S6。

#### P05 · `start/agent.mdx` · 用 Agent 完成首次分析 / Your first analysis with an agent

- **读者与目标**：有可用项目的 Agent 用户；走通准备、提问、必要确认、回答与审阅。
- **内容**：Agent 使用同一项目和解释器、发现技能的已验证方式；确认示例指标；提出收入变化问题；展示一次会改变口径的确认；回答中的关键数值、范围和限制；如何继续。
- **成果与边界**：业务读者无需写 Python 即能完成这条路径。使用 D0 已准备的项目；构造对话明确标为示意，数值来自真实演示；不泛称所有 Agent 自动兼容。来源 S0/S5/S6。

#### P06 · `start/python.mdx` · 用 Python 完成首次分析 / Your first analysis with Python

- **读者与目标**：会基本 Python 的新用户；从独立目录得到可保存、可解释的结果。前置 P03。
- **内容**：完整 D0 数据准备；声明数据源和收入指标；加载；按月和地区观察；比较；解释数值；保存；在新进程读取。每个文件有路径、命令和必要说明。
- **成果与边界**：不借用私有数据或上一聊天状态；运行真实页面代码，核对 1,000、800、-200 等结果。它是基础示例唯一完整所有者，不塞入复杂建模。来源 S1/S2/S3/S5。

### 与 Agent 协作

#### P07 · `agent/ask-question.mdx` · 提出有用的业务问题 / Ask a useful business question

- **读者与目标**：已有项目的业务用户；把关注点说清楚而无需指定算子。
- **内容**：从业务决策出发；知道哪些信息就提供哪些；指标、对象、时间、基准、输出诉求；模糊问题如何变得可分析；需要确认与可以逐步澄清的选择。
- **成果与边界**：有可改写的提问示例和缺失信息处理方式，不要求填写固定分析表单。D0/D1；解释首次体验已有最小提问即可，不造成 P05 与本页循环依赖。来源 S0/S2。

#### P08 · `agent/review-results.mdx` · 审阅回答与继续追问 / Review results and follow up

- **读者与目标**：收到分析回答的人；判断回答支持了什么，决定下一步。前置 P05 或已有结果。
- **内容**：一份带批注的示例回答；核对口径、时期、比较方向、关键数值、覆盖和缺失；区分观察、计算分解与原因假设；请求补充证据；选择复用历史结果或重新查询。
- **成果与边界**：能发现一个范围不一致或因果过度推断的例子，给出有意义的追问。D0/D1；不要求业务用户读取存储结构或内部审计字段。来源 S3/S5。

### 准备业务模型

#### P09 · `modeling/connect-data.mdx` · 接入并了解数据 / Connect and explore your data

- **读者与目标**：模型准备者；连接数据并获取建模所需的物理事实。前置 P03/P04。
- **内容**：本地 DuckDB 完整路径；远程数据库的最小连接配方；环境变量凭据与缓存控制；表、文件、HTTP/JSON 来源选择；查看结构与有界样本；连接测试；SQL 逃生口适用范围。
- **成果与边界**：D0 本地路径必跑，其他配方分别标明可执行前提；明确参数化 JSON、预览和数值分析支持不同。高级宿主凭据注入链接 P27/API，不在这里展开框架接口。来源 S1。

#### P10 · `modeling/define-metrics.mdx` · 定义可复用的业务指标 / Define reusable business metrics

- **读者与目标**：会 Python 的模型作者；将确认的业务口径变成可复用指标。前置 P09 或现成来源。
- **内容**：先写指标含义与排除范围；实体键、维度、时间字段、度量；捕获与解析依赖；定义收入、客单价等表达式；单位、可加性、空值；命名发布与业务说明；加载后取得指标。
- **成果与边界**：D0 的最小模型可运行，D1 的比率有独立预期值；介绍声明语法限制对作者的影响。多实体归属由 P11 负责，不复述退休 DSL 的迁移清单。来源 S2。

#### P11 · `modeling/relationships.mdx` · 连接实体与处理多重归属 / Connect entities and handle multiple memberships

- **读者与目标**：多表模型作者；按客户属性或多标签分析且不误算贡献。前置 P10。
- **内容**：D1 订单与客户；关系方向、键和基数；跨实体取属性；一条记录多种归属时的业务选择；集合筛选与分配的区别；重复连接、未匹配与缺失分类的实际影响。
- **成果与边界**：至少一个正常多表例子和一个可能重复计数的反例，明确各自预期总额。保留必要的 membership 用法，不展开编译器连接规则。来源 S2/S3。

#### P12 · `modeling/validate-model.mdx` · 检查模型与数据 / Validate your model and data

- **读者与目标**：交付或修改模型的人；选择与当前问题匹配的检查。前置 P10，按需 P11/P13。
- **内容**：加载发现定义问题；readiness 检查依赖；preview 读取指定范围；source health 检查实际来源与显式数据预期；成功与失败示例；修复后运行目标分析。
- **成果与边界**：使用 D0/D1 的一个可修复错误展示完整闭环；区分业务确认、静态检查和实际数据检查。时间认证操作链接 P13；不把所有检查规定为每次分析必跑。来源 S2。

#### P13 · `modeling/calendars.mdx` · 定义业务日历与活动期间 / Define business calendars and event periods

- **读者与目标**：有业务日历需求的模型作者；准备可用于实际分析的日历与期间。前置 P10/P12。
- **内容**：何时用自然日历、何时定义业务日历；D2 周期表和活动期间；时间身份与边界；完整范围认证；失败或截断处理；节假日分类、工作日字段及覆盖检查。
- **成果与边界**：提供全部来源数据并验证一例成功、一例缺失范围；产物交给 P18 使用。明确普通工作日字段不自动获得完整日历保证，节日同名不自动配对。来源 S2/S4。

### 开展分析

#### P14 · `analysis/observe.mdx` · 查看指标与明细 / Observe metrics and inspect records

- **读者与目标**：Python 分析者；从业务问题构造基础观察并读懂输出。前置 P06。
- **内容**：选择模型中的指标；总量与分组；明确时间范围；按实体身份读取明细；计算与查看返回结果；保存或进入后续分析；什么时候需要重新读取来源。

#### P15 · `analysis/select-groups.mdx` · 选择分析对象与分组 / Select populations and groups
