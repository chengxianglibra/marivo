## Physical evidence and decisions

- Correlation: all five reader accounts executed Pearson and Spearman positive cases. The independent nonlinear numeric oracle is in the shared numeric tests; duplicate-identity and constant-input source rejection were exercised on SQLite, not separately on each remote reader. PostgreSQL and Trino use native correlation; SQLite, MySQL and ClickHouse use centered-moment SQL. SQLite's recorded source submissions include `validation_batch` and `primary` SELECT roles, and its published frame has no `entity_identity` column. The other live backend tests assert primary execution but do not retain submitted SQL or roles.
- Expanded attribution: SQLite, PostgreSQL, Trino and ClickHouse executed hidden-axis zero-delta cases for both additive `revenue` and component-mix `mean_amount`, plus a hand-calculated two-window additive case. Fixture amounts give `a: -10`, `b: +40`, overall delta `30`; these assertions run against reader-submitted SQL, not a local recomputation of raw Entity rows. SQLite source SQL carries exact fixed-width `0/1` masks and the execution owner strictly converts them to Arrow boolean lists before storage. PostgreSQL source SQL uses `LEFT JOIN` plus right-only `RIGHT JOIN` and `UNION ALL`, preserving NULL equality and duplicate rows without a non-hashable `FULL JOIN` predicate; a NULL-axis case passed. Trino's presence validation now compares two non-null booleans, avoiding the compiler's malformed `IS NOT DISTINCT FROM ... <> ...` SQL. ClickHouse and Trino non-Entity publication summarizes the complete published rows; the DuckDB-only `struct_pack(... := ...)` source-summary SQL is reserved for private Entity state.
- Actual SQL submission is observed by the action's `Submission` recorder in `DatasetRuntime.statistics.submissions`; SQLite correlation now asserts source SQL text, roles and successful state. Other positive backend tests require `primary_queries > 0`, which does not itself archive SQL text. The execution paths submit validation SQL before primary SQL and stream only the result rows through `_batches`. No source `CREATE`, temporary table, upload, or raw Entity handoff is introduced. SQLite malformed-mask and empty-batch tests verify strict decoding; its non-finite source test confirms no artifact publication after validation failure. A SQLite injection after source validation checks failure cleanup without publication; this does not establish the same fault path on all five readers.
- MySQL mask compilation and strict Arrow decoding were observed in isolated live zero and nonzero runs, but those run artifacts and SQL are not retained as reproducible tests in this tree. A combined methods/runtime run killed the 768 MiB MySQL container during the nonzero validation SQL (`OOMKilled=true`, exit 137). Subsequent fixture errors were caused by the stopped server. After leaving this admission closed, the combined MySQL group passed. The static rejection now gives the observed resource-limit reason before source I/O; this is a rejected cell, not general admission.
- Top-K with one selected axis value and an Other row preserved the hand-calculated total contribution `30` on SQLite, PostgreSQL and ClickHouse. ClickHouse returned Boolean array members as integer `0/1`; its streaming adapter now strictly decodes those bits and rejects other values. Trino's live Top-K query generated 175 stages against a 150-stage server limit. The read-only contract does not permit temporary materialization, so this exact shape now rejects before source SQL submission. Complete untruncated Trino attribution remains open.
- Candidate and driver source preparations still require `table_statement`, unsupported by the five remote adapters. They remain rejected before source I/O.
- Entity sampling was removed from DuckDB and the public Analysis surface by a later user decision. Historical sampling tests in the verification paragraph below describe the earlier acceptance run, not current support.
