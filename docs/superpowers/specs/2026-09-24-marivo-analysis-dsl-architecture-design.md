## 1. 架构目标与实现边界

实现架构需要落实五项基础：

1. 有后端无关语义的基础能力，使 DSL 算子通过有限组合实现，明确输入、输出、状态及拒绝条件。
2. 可检查的执行计划，在来源后端、Python 表格计算和 Python 数值方法之间选择已准入的实现。
3. 统一的数据交换与部件契约，使源查询结果、pandas 输入和持久化结果具有一致解释。
4. pandas 本地物化续算、冷恢复、输入分类和原子发布，复用当前 Runtime 与 Store；明确混合输入的拒绝边界。
5. 可复核的扩展代价：新增算子、来源适配器和数值方法分别要修改哪些拥有者，承担哪些验证义务。

首轮交付范围由 MVP 文档限定，包括有限内核及其契约测试、源端 Ibis 适配、pandas 执行适配、一个真实数值方法适配、
交换与恢复实现、端到端方法切片和验收记录。它们属于产品实现基础，不是一次性脚本或
独立分析库。公开 API 切换与发布另行决定，内部候选也须按生产类型、所有权和生命周期规则实现。

## 2. 实现原则

语义不变量约束结果含义；技术选择规定本目标架构的实现路线；阶段限制界定首轮准入。
技术选择和阶段限制不是代数定理，后续变更仍须保持语义不变量并重新完成对应验收。

| 类别 | 原则 | 必须落实的约束 |
| --- | --- | --- |
| 语义不变量 | 语义与计算位置分离 | 量定义、域、Cell、方法状态及前提只有一个语义拥有者；Ibis、pandas、NumPy 是该契约的实现方式 |
| 语义不变量 | 源端下推按能力准入 | 仅向所选来源下推后端实际支持、语义保持的阶段；Ibis 能编译不等于满足类型、数值和检查契约 |
| 语义不变量 | 所有边界有同一数据契约 | 显式键、Cell 标签、量与域绑定、方法状态和证据随数据传递；不以裸 DataFrame、隐含 index 或 SQL NULL 代替完整输入 |
| 语义不变量 | 当前来源与固定输入分开 | 含现场来源依赖的 Lazy 图不自动复用历史 Artifact；显式 Materialized 输入不得重算替代；纯固定输入的精确复用按 §5.2 判定 |
| 语义不变量 | 惰性、不可变、原子发布 | 构造期零业务来源 I/O；一次执行共享显式节点实现；输入不可变，必要检查全部满足后才提交可读 Artifact |
| 技术选择 | 基础能力组合形成 DSL | where/compare/rollup 等复用明确的内部能力；不按业务案例或结果家族复制同一检查，也不先建设通用证明搜索或万能回调系统 |
| 技术选择 | SQL 生成完全委托 Ibis | Marivo 将 DSL 转为 Ibis 表达式或 pandas/NumPy 调用；不建设 SQL 生成器，不用手写 SQL、方言模板或生成后补丁补齐分析能力 |
| 技术选择 | 物化数据统一 pandas 路径 | Artifact 经现有受控读取得到 pandas 主表与部件；本地关系计算使用 pandas，数值方法使用获准库，不导入 DuckDB，不回源重建 |
| 技术选择 | 放置确定、分批语义明确 | 执行前按能力和输入位置选定阶段；明确算法需要逐批、完整组或完整输入，不静默改引擎或近似 |
| 技术选择 | 基础架构必须有扩展证据 | 记录新增方法和适配器的实际改动、重复语义判断与运行成本；不用类数或固定案例跑通代替复用证明 |
| 阶段限制 | 首轮限制输入及执行路线 | 拒绝显式物化与现场来源混合；全局本地方法使用完整必要输入，不实现自动 spill；范围由 MVP 文档限定 |

按需下钻属于[MVP 第 4 节](2026-09-24-marivo-analysis-dsl-mvp-validation-plan.md#4-分析场景与独立预期)的使用策略；对应的实现要求是表达式可增量构造、输入绑定明确、新观察
与保留结果续算可区分。既不预读所有未来维度，也不把来源变化后的新观察称为旧快照下钻。

## 3. 基础能力与规则推导

### 3.1 有限语义内核

下面是内部职责，不增加同名公共 API。每项由封闭的有类型输入描述，输出可推导的域、量、
Cell 政策和 RequiredParts；不能用 Any、任意字典或用户回调绕过准入。

| 能力 | 输入与输出责任 | 初始消费者 |
| --- | --- | --- |
| 绑定与投影 | 绑定来源/Artifact、字段角色、成员、时间、路径与量定义；只要求实际依赖列，投影不得删除后续必需部件 | members、read、observe |
| 域映射与对应 | 子域包含、单值属性映射、精确键配对、完整坐标元组并集、身份直接像；分别规定唯一性、覆盖与多重性 | group_by、compare、members、多根 observe |
| Cell 与逐行计算 | 标签检查、全定义 is_defined、受限谓词组合、差值/比率等注册取值规则；计算失败与数据状态分开 | where、compare、组件 finish |
| 当前行构建状态 | 按明确行单位和消费政策生成 sum/count/mean 状态，固定输入域与量定义 | summarize |
| 原状态归约 | 检查目标映射、贡献许可和方法版本；按方法合并状态并 finish，保留空目标组 | observe、rollup |
| 部件运输 | 限制或转换映射、组件状态、覆盖事实和依赖；为输出推导真实可用的后续操作 | where、compare、summarize、rollup |

例如 compare 分解为绑定相容检查、精确键对应、逐行差值与端点部件运输；where 分解为
谓词准入与求值、子域构造和部件限制。summarize 与 rollup 共用归约执行设施，但前者先
从当前值生成新统计状态，后者消费原量状态，不能因为都含 sum/count 就混淆。

扩展数值方法单独注册自己的输入、算法、输出定义和状态，复用配对、Cell、资源生命周期与交换边界；
不把任意 NumPy 函数包装成通用代数算子。理论 §6.7 的有限规则与 DSL 扩展分别记账；
条件规律不自动证明所有 Python 或数据库实现正确。

### 3.2 少量共同构造，各自有明确输出推导

基础能力及其消费者见 §3.1。match、replay、分配和抽样等领域构造另有独立身份、顺序、覆盖或概率条件，不能只靠通用归约获得准入。

每条规则统一描述：

```text
InputSignatures + Parameters
  -> OutputSignature
   + Pre + RequiredParts
   + PartTransform + Post + Transport
   + Eval
```

不要求一个文件集中所有判断，也不要求通用证明搜索。
业务操作可复用共同规则；其领域前提仍由唯一拥有者定义。
这些字段沿用理论 §6.1 的单一规则模板；数值政策属于量定义和具体方法，必须与 Eval 一起
落实，不能由后端默认值补全。每个扩展同样要给出完整规则与局部保持义务。

#### 3.2.1 有限核心的采用与方法扩展

理论 §6.7 固定有限域、精确有理数、严格值政策与两类部件，用于给出可检查的小规格。
本设计采用其域、量、贡献与状态区分；公开 DSL 的更大范围按下表逐项说明独立条件。

| 理论规则 | 目标 DSL 的对应切片 | 超出有限核心时的独立义务 |
| --- | --- | --- |
| Input / Observe | 固定 Artifact 输入；完整目标域上简单 sum/mean 指标的观察 | Ibis 规范图、count(*)、多根指标、比率、状态时点和时间坐标分别定义贡献与 Cell 政策，不能只满足同单位 |
| Select | Defined 数值与同单位阈值比较后 where | 分类/布尔谓词、is_defined 等状态谓词及全机会域 cohort 使用[接口设计第 6 节](2026-09-24-marivo-semantic-analysis-dsl-interface-design.md#6-比较与成员选择)的封闭政策；不能以未知被排除冒充完整判断 |
| Project / Pull | 有身份的单量视图和获准路径取值 | 核心 Pull 一律移除聚合状态；DSL 若隐藏字段而保留私有状态，须另证原量、贡献、范围与所有权绑定仍有效，尤其不把非单射取值认作贡献互斥 |
| Diff | 同一固定成员域、简单 Observed 量的完整时间绝对差 | RelativeChange、UnionKeys、CohortContrast、PeriodChange、复合指标及嵌套 Difference 按接口设计 §6.1 分别定义相容性、端点状态与部件；不从最小 Diff 推导额外续算 |
| RowReduce | 对 Defined 当前值等行权重 sum/mean；已知所有值 Defined 时的计数 | count()、count_defined() 的定义域不同；加权、distinct、分位数及 Duration 等方法保留自己的单位、状态及输入政策 |
| StateRollup | sum/count/mean 的真实状态沿全定义分组映射合并，贡献互斥 | 复合组件、重叠去重、分配、时间折叠及更多私有部件须按对应方法证明贡献许可与状态保持 |
| Subjects | 保留主体映射上的存在像，对应 where 后 members | 带角色的 Journey/Interval 映射、其他量词和覆盖语义由领域方法明确；不从主体去重恢复实例重数 |

理论的精确数值模型不是 Python Number 或某后端的执行承诺。int/float/Decimal、Duration
编码、舍入、溢出和近似方法须各自满足数值契约；浮点结果相近不构成语义等价。
输入量或方法未落入上述直接采用切片时，不能只引用 T1：须先给出该扩展的具体规则，
再验证组合前提。这里不新增通用映射、证明或任意 schema 构造器。

#### 3.2.2 R8 的评分与连续区间边界（2026-10-02 修订）

[接口设计 §8.4.1](2026-09-24-marivo-semantic-analysis-dsl-interface-design.md#841-从指标变化定位可继续分析的坐标)
是 C14.a 的唯一语义 owner。目标从五种 discover 候选操作收敛为两个独立方法；本节规定
实现归属，不另写一份公式、阈值默认值或候选排名策略。相关/预测的方法边界保持独立。

| 规则 | 输入与输出 | 必需部件与保持义务 |
| --- | --- | --- |
| Deviation | 一个 NumericRelation、闭合 method、显式分类分区 → 同域 DeviationResult | 输入量与原实例身份、拟合域/分区、各 Cell 状态计数、有效 n、中心/尺度及分支、数值政策与方法版本；observed/reference/deviation/score 固定视图 |
| Runs | 保留完整时间网格的 NumericRelation、显式 BoundPredicate → TimeRunResult 新区间域 | 原网格及每格映射、条件全部输入、true/false/unavailable 与原因、最大段起止、终止依据、区间→格映射及已有 SubjectBinding；不从排序后的剩余行重建邻接 |

Deviation 对时间行和 Entity 行使用同一方法语义；两者只有域和获准续算不同，不建立
point/entity 专用编译器、Candidate 类型或两份数值实现。拟合只读明确输入中的有效值，
计数和非定义状态仍覆盖整个输入域。where/rank/limit 不下推穿过拟合边界改变基准；后续
视图携带原拟合域绑定。score 的数值单位/来源不同于业务 Metric，不能运输原量聚合状态。

Runs 直接消费业务量或 score，不依赖 DeviationResult 家族。时间顺序来自已有网格，
非时间坐标决定序列分区；完整网格与逐格条件状态是方法必需输入，不是展示附件。普通
where 的严格消费者不可代替 runs 的 unavailable 分类。不能优化为先过滤 true 再分段，
不能把物理批次尾当作区间尾。批量实现必须保留跨批次的格邻接与未闭合段状态。

两方法都进入既有 typed graph、method registry、Runtime 和 Store 7：来源路线在执行前
选择 Ibis 准备→本地完整计算，固定路线消费已验收 Artifact；不新增 discover executor、
SQL 模板、source-after-local 或失败后换路。方法定义只有一个 owner；若以后增加源端
评分实现，须对同一方法版本、Cell/数值政策和整域结果逐形状验等后注册物理资格。

执行身份包含精确输入、量定义、分区或条件依赖、网格、方法版本和数值政策；派生选择保留
拟合/分段的原始绑定。恢复校验主表与必要 parts 的完整键、覆盖、身份和 receipt，离线
续算不重新拟合、不重新分段、不回源；显式对已有数值结果再次调用 deviation/runs 才是
新的分析节点。缺失部件须结构化拒绝并指向可重建的源表达式，不能暗中重建。

结果契约只披露现有部件允许的 where、具名视图、rank/table 和真实 Subject 投影；运行
事实与 Evidence 走统一发布事务。分数和条件命中本身不发布“原因已确认”的 Findings，
show/contract 不生成推荐计划。业务判断与下一步选择归 agent；ontology 不参与求值选路。

旧五个入口及 Candidate 私有图、codec、Help 在新消费者接通后退出；共享数值/归因 helper
按真实剩余调用方归属。driver_axes 不成为 attribute 之上的另一条执行链；rolling 和集中度
新方法不因旧复合方法存在而进入内核。这里不预先登记尚无方法契约的扩展或兼容读取器。

### 3.3 一条完整推导比“所有结果都能组合”更有意义

`客户收入 → 差值 → 负值筛选 → members → 九月收入 → 均值` 的推导：

1. 两次观察共享一个固定 Customer 成员输入，各自按指标变量、贡献归属角色和窗口产生 Observed，保留完整目标域、Customer 身份和真实指标状态。
2. compare 按同一时间比较设计检验完整且单射的共同身份键，读取两侧 Defined 值，产生 Difference，保留相容的主体映射；Difference 不因此获得原指标的上卷状态。
3. where 限制为负值子域；它不再覆盖原 Customer 域。
4. members 取已选实例的主体集合像，产生新成员域；本例 Customer 身份与恒等主体映射经筛选仍唯一，直接投影即可。原量不进入成员身份。
5. observe 显式引入九月贡献读取。这是新的查询依赖，不是前序结果偷偷回源。
6. summarize 将这些 Customer 行作为新贡献，产生 RowStatistic；不保留可恢复名单的承诺。

最后一步之后再要求按均值恢复具体客户，因缺少 SubjectMap 拒绝。
若用户保留了前面的单位级输入，可以显式使用它，不能声称摘要在任何额外信息下都不可选人。
无订单客户在完整 sum 观察中仍占一行且值为零；只有一侧实际客户行域不完整才是缺键。
若下降域为空，最后的全局 mean 仍在 Singleton 上输出 Undefined(empty_mean) 和有效空状态。

members 的 lowering 遵循[接口设计 §5.1、§6.2](2026-09-24-marivo-semantic-analysis-dsl-interface-design.md)：
Entity 根域投影完整声明主键，版本化根域先解析明确版本，不默认 distinct 或全源唯一性预检。
Subjects 沿非单射主体映射取集合像时必须消除重复主体，来源实现使用 Ibis distinct 或等价
集合像表达式；固定输入使用同义本地实现。已有依据的单射或恒等映射可省略去重，筛选保留
该依据。编译器依据规则推导决定实现，不根据样本碰巧无重复作出判断；输出契约不暴露算法
开关。集合像去重不能掩盖已观察到的输入身份违约，也不能取消消费契约要求的检查。

### 3.4 信息、事实与能力同时变化

能力由当前签名、部件和规则推导，不由家族名赋予永久标签。
筛选保留唯一键但失去父域覆盖；归约产生 Group 唯一键和新统计状态，却可能丢失主体映射。
投影可以隐藏字段而保留必要私有状态；显式删除部件则同步删除相应续算承诺。

AnalysisRelation 不能用一个 `is_complete/is_valid/is_additive` 汇总这些不同事实。
同样，`supports_rollup=True` 无法表达“哪一个量、哪一种粗化、哪一组保留状态”获准。

### 3.5 等价层次与局部替换

沿用理论 §9.2：数值相等只比较指定坐标上的已定义数值；语义等价还要保持域、量定义、
范围、Cell 与相关前提；K 续算等价再要求变换前声明的合法续算及其结果保持。
不比较原始 AST、证据记录文本或文件布局，也不以相同展示值归并 Artifact/selector 身份。

每项内部重排须记录固定输入、采用规律、前提、直接比较层次及其升级证明。
只在两侧表达式均由已定义的 DSL 方法构成时讨论替换，不新增通用等价判定或优化器要求。

| 规律 | 在本设计中可用的结论 | 替换前额外核对 |
| --- | --- | --- |
| L1 选择组合 | 共同原域上全定义的纯谓词得到同一子域 | 不能从两次 where 分别成功推出合取可执行；量定义、状态政策、部件限制及后续操作须保持 |
| L7 取值合成 | 同一固定量的取值函数相同 | 角色路径、范围与每类部件运输须一致；值重复不产生新的贡献许可 |
| L8 分层归约 | 中间保留状态时，两级与直接合并的状态相同 | 原方法、贡献并、最终目标组域及 finish 政策相同；后续所需部件不得被一条路径删掉 |
| L9 按组限制 | 固定 G' 后，限制组结果与限制 g⁻¹(G') 的原状态得到相同状态 | 两侧使用同一 G' 并保留空组；原状态、权重、参照和数值政策不变；量定义与 K 的保持分别证明 |

例如保留“华东”整组时，L9 允许比较该组在两条状态归约路径上的结果；不允许把汇总后的
“收入超过百万”换成“订单金额超过百万”。若 G' 依赖汇总值，仍须先求出或合法取得同一 G'。
也不能在筛选后重新归一化权重、缩小固定分母，或以实际有贡献的组替换显式目标域。
RowStatistic 记录输入域，状态相等仍不足以识别不同问题定义；只有方法明确证明同一量的
解释和后续部件均保持，才可升级为相应语义或 K 等价。

where 与贡献层 slice 的位置和含义仍分别保留。将固定状态上的 L9 进一步用于来源下推，
须另证值状态检查、拒绝行为、实际输入绑定和范围均保持；本设计不提供无条件下推许可。
两个结果都拒绝原定续算，不能用作该续算能力已保持的证据。

### 3.6 构造、检查义务与证据

Logical 构造检查类型、字段所有权、定义兼容性、可用部件，并登记可履行的检查义务。
不知道两侧键集合是否相同，可以在实际配对中检查；缺少主体映射则不能登记一次检查
假装未来可以恢复名单。

执行前提有三种依据：获准的来源声明、已完成且绑定本次范围的检查、封闭规则推导。
尚未执行的检查不是证据。依赖来源声明推导出的结果，经过物化也不会升级成来源已实测。
来源身份声明不变成自动全表审计；但已经发现的矛盾不能用另一份声明覆盖。

分别报告“语义上有定义”“本次可准入”“后端支持并执行成功”。
没有默认后端回退、自动近似、丢弃失败行或物理来源变化重试。

## 4. 方法注册与执行计划

### 4.1 方法契约与执行实现注册

输入衔接沿用[接口设计 §3.4](2026-09-24-marivo-semantic-analysis-dsl-interface-design.md#34-metric带贡献语义的可复用计算图)的 Metric 规范图和
[§3.7](2026-09-24-marivo-semantic-analysis-dsl-interface-design.md#37-语义层与-analysis-只通过-ref-衔接)的 Ref/定义环境 Γ 绑定。
装饰器 Metric 的单位、可加性及业务规则由作者通过接口声明；semantic 校验和绑定声明，
不分析函数体结构来推导规则或隐藏组件。受限语法、绑定与 Ibis 类型检查继续执行。
已有显式组件 builder 从构造参数形成规范图，注册方法据此确定状态；
semantic 拥有声明、组件图及值政策，Session 固定解析后的定义；执行适配器消费该产物，
不分别从 Ibis 或 pandas 数据猜测量定义和组件身份。作者声明是受信前提，不是实测或证明；
Artifact 保留声明版本及依据。声明缺失、已知矛盾、政策无法履行或必需状态缺失时拒绝，
不能以解析函数体补齐，也不能从 non_additive body 的展示值恢复比率组件。

显式 `ms.ratio/linear/aggregate` 的推导规则归 semantic 方法契约所有，依据见
[接口设计 §3.4.1](2026-09-24-marivo-semantic-analysis-dsl-interface-design.md#341-显式-builder-推导组合规则)。
注册方法消费有类型的构造参数和输入契约，产出单位、条件化归约规则、RequiredParts 及
未履行义务；没有规则时明确不支持，不让执行适配器根据 Ibis 操作或 pandas dtype 补推断。
声明输入与推导输出保留不同的依据来源，版本进入定义身份；输入为装饰器 Metric 时止于其
声明和保留部件。已知单位冲突在构造期拒绝，实际分区/覆盖等条件进入获准执行检查。
SQL 可编译、单次值正确或状态 schema 同形，均不能替代这些前提。

在现有 method/operator registry 上扩展，不再建平行注册中心。分开维护：

| 所有者 | 必须定义 |
| --- | --- |
| 语义方法契约 | 方法身份与版本、输入/输出种类、定义/单位/域条件、Cell 和空输入政策、状态 schema、必需部件、检查义务与合法续算 |
| 执行实现注册 | 方法与版本、来源后端或本地实现、支持的类型/输入形态、如何实现必要检查、数值政策、分批能力及资源生命周期 |
| 算子构造 | 将公开参数规范化并组合基础能力，纯检查已知前提，登记可履行的数据义务，推导输出 |
| 执行适配器 | 消费已绑定计划，构造 Ibis 或执行 pandas/NumPy 方法，返回符合交换契约的数据和已履行义务；不生成或改写 SQL |

参数采用各方法的封闭变体；不创建同时包含所有算子可选字段的通用配置类。后端别名、
临时表规则或 pandas dtype 不进入量定义。量定义保留影响数值含义的规则；分位数输入
只声明 q 和精确性要求，`count_distinct` 声明去重对象，不声明来源函数或 sketch 算法。
选中的实现、版本、参数及其精确性保证进入执行计划与结果证据。同一数值要求可以有多个
经过验证的实现，但未验证的组合不注册为支持。

`count_distinct`、median 和 percentile 首次接入只承诺在目标粒度直接观察。其方法注册
不声明可上卷状态，`StateRollup` 和需要成员关系或分布的归因均拒绝；不能把后端返回的
标量或函数名视为可合并状态。更粗粒度的同一量须在该目标域重新观察，而不是合并细粒度值。

### 4.2 复用现有图与运行服务

```text
Analysis DSL
  → 绑定及基础能力组合（扩展现有 typed logical nodes）
  → 能力准入与阶段放置
      ├─ SourceStage：Marivo 构造 Ibis 表达式 → Ibis 编译 SQL → 所选来源后端
      ├─ ArtifactReadStage：受控存储读取 → pandas
      ├─ LocalTableStage：pandas 关系计算与状态归约
      └─ LocalNumericStage：pandas/NumPy/SciPy 数值方法
  → 结果与部件校验 → 现有 Runtime 原子发布
```

阶段是现有 placement/执行结构的职责描述，不要求创建同名新类或第二套 AST。执行计划
记录各阶段输入角色、依赖、方法版本、放置理由、需读列/部件、检查位置和资源所有权。
计划先按 §5.1 分类整个执行根的传递数据依赖；混合输入在数据读取前拒绝。来源输出进入
本次 Python 数值阶段仍属同一次来源求值，不因中间暂存而变成显式历史 Artifact 输入。
一个 execute 可以包含多个查询和本地阶段；同一显式节点在本次运行中只建立一份实现，
不能复制子查询后声称共享输入，也不承诺不同来源共享事务快照。

### 4.3 lowering 的职责边界

本方案中的 lowering 仅指 Marivo 分析语义到执行表达的转换。它必须知道贡献路径、目标域、
组件状态及值政策，例如将 AOV rollup 转成分别合并收入和订单数、检查分母、再取比值的
Ibis 表达式或 pandas 状态归约。Ibis 不负责推导这些业务与分析含义。

| 转换层次 | 所有者与实现 |
| --- | --- |
| DSL → 已绑定的基础能力组合 | Marivo 语义内核；推导域、量、部件与义务 |
| 基础能力 → Ibis 表达式或 pandas/NumPy 调用 | Marivo 执行适配；按已准入契约构造计算 |
| Ibis 表达式 → 数据库 SQL 方言 | Ibis；负责 SQL 语法、别名、子查询与后端函数映射 |

量的精确性要求由 Marivo 在放置和准入时检查；Ibis 只把已选择的 `quantile`、
`approx_quantile` 等表达式映射为后端 SQL，不决定用户是否允许近似，也不证明后端结果
满足精确插值或误差契约。无法证明时保持不准入，不根据编译成功或运行失败切换精度。

本 DSL 的分析查询及数据校验查询均遵守这一边界。不拼接 SELECT/JOIN/GROUP BY，不把
手写查询片段塞进 Ibis 的原始 SQL 入口，也不在生成后用字符串或 SQL AST 补丁修正方言。
已有基础设施可以记录、传输和执行 Ibis 生成的 SQL，但不修改其计算含义；必要资源管理
使用后端/驱动 API，不在分析算子里另建方言模板。迁入本切片的已有方法若依赖手写分析 SQL，
必须改用 Ibis、注册 Python 实现或保持不准入，不能把旧路径当作例外。

无法通过所选后端上已准入的 Ibis 实现完成时，只有在数据准备可由 Ibis 表达、Python
方法已注册、语义和输入前提均满足时，才选择源端准备后本地计算；否则明确拒绝。不能为
支持某个 DSL 方法临时生成 SQL，也不将数据库执行失败解释为启用 pandas 的信号。
测试 fixture、独立 SQL oracle 与仅供追溯的 SQL 文本不属于产品执行实现，不能进入分析
求值链。本原则不要求本次文档修订顺带迁移全部旧生产方法。

## 5. 输入、执行身份与放置

### 5.1 历史缓存、显式物化输入与准入

首轮启用的输入组合由[MVP 第 2.2 节](2026-09-24-marivo-analysis-dsl-mvp-validation-plan.md#22-后端和范围边界)限定；本节定义分类、拒绝和修复的实现契约。
持久化记录的存在不等于本次请求使用旧数据。分类只沿当前执行根的实际传递数据依赖进行；
Artifact 的来源 lineage、日志中的旧执行记录和未被表达式引用的历史结果不属于现场查询。
Materialized 节点是固定输入边界，不沿其历史逻辑图重新展开来源。

| 本次输入 | 处理契约 |
| --- | --- |
| Lazy 来源表达式，可能已有对应历史 Artifact | 不自动复用历史缓存；按本次来源绑定重新编译求值，尽量形成完整源端计划，必要时进入已注册 Python 阶段 |
| 显式 Materialized 输入及其纯本地派生 | 保持指定数据、成员和状态，经 pandas 读取与续算；不重算来源、不导入 DuckDB |
| 同一执行根同时依赖显式 Materialized 数据和现场来源读取 | 构造或纯计划阶段可确定时立即结构化拒绝，在来源连接和 Artifact 数据读取前终止 |

例如下面的 july_values 和 saved_july 有不同的输入承诺：

```python
july_values = customers.observe(Revenue, during=july_scope, via=Buyer)
august_values = customers.observe(Revenue, during=august_scope, via=Buyer)
saved_july = july_values.execute()

fresh_change = august_values.compare(july_values)
mixed_change = august_values.compare(saved_july)
```

此例的 customers、july_values、august_values 均为 Lazy，两个 scope 分别为七月、八月窗口。
第一条 compare 重新求值 July；即使已存在 saved_july，也不自动替换。第二条明确使用
已保存的 July，属于首版拒绝的混合图。execute 不把原 july_values 对象原地变成 Materialized，
拒绝也不能把 saved_july 悄悄替换回其历史表达式。相同 AST 或量定义不足以证明输入等价。

已物化名单 selected_customers 再调用 read/observe，同样引入“固定成员 + 新来源”，
首版拒绝；名单来自尚未执行的 Lazy 选择时，可以随整个来源图求值，[MVP 的 J2](2026-09-24-marivo-analysis-dsl-mvp-validation-plan.md#4-分析场景与独立预期)因此仍在范围内。
即使物化数据很小，或其来源和现场查询都在同一个 DuckDB，也不豁免该边界。

错误区分两个由用户明确选择的修复：若接受当前来源重新确定值或成员，使用 Lazy 表达式
重建分析；若必须保留旧输入且独立新端点可以单独求得，先执行新端点，再以两份 Materialized
输入做获准的 pandas 运算。compare 仍须验证两端共同域、输入绑定和精确键要求，不能
仅凭分别调用 execute 就保证可比较。该修复不自动解决固定名单再观察的来源范围问题，
也不制造跨次来源快照。无法等价拆分时明确说明首版不支持，不建议重算
旧名单作为保持原问题的修复。

来源→Python 数值计算不属于上述混合输入：它消费本次执行产生的中间数据，仍须满足
§6 的交换和资源生命周期契约。运行内共享节点实现、内部暂存与历史缓存复用分别记账。
未来若支持显式物化输入和现场查询混合，应独立定义放置、搬运、成员限制和资源所有权规则；
当前不实现成本优化器、缓存等价证明或自动混合路线，不提供占位开关。

### 5.2 定义身份、求值身份与持久化

复用 Runtime/Store 包括调整新切片的执行键协议，不能只绕过历史缓存查找。当前
[execution_key.py](../../../marivo/analysis/materialization/execution_key.py) 从定义指纹生成执行键，
[dataset_execution.py](../../../marivo/analysis/materialization/dataset_execution.py) 在准入前
命中该键即恢复结果；[store.py](../../../marivo/analysis/materialization/store.py) 的准入和持久化均限制同一 Session、同一执行键只有一个
Artifact。这套键不能直接表达同一定义的多次现场来源求值。

| 身份 | 所有者与用途 | 不代表什么 |
| --- | --- | --- |
| 定义身份 | Core 固定定义环境、规范表达式、参数及显式输入绑定；未改变表达式和绑定时，重复 execute 不改变其定义指纹 | 不证明可变来源仍是同一批数据 |
| 显式节点身份 | Logical 图标识同一节点的共享关系；在一次求值内映射到唯一实现 | 不按同形定义合并独立构造的节点，也不跨次冻结来源 |
| 本次求值身份 | Runtime 在获准的新 Run 准入中分配，直接由该 Run 身份承载；绑定本次节点实现、检查和发布 | 不是量定义、主体键、来源事务快照或新的公开参数 |
| Artifact 身份 | Store 固定已提交 receipt、生产 Run、数据与部件；恢复使用具体 Artifact 引用 | 不指向同一定义的“最新结果”，不授权回放来源 |

先按 §5.1 分类实际数据依赖，再由新切片已注册的物化协议选择以下封闭执行键规则。
Session 仍是执行键的作用域；协议版本由现有 materialization owner 管理，不交给用户选择。

- **含现场来源依赖**：纯计划检查通过后，在现有 Session 写入保护及 Run 准入边界分配新的
  求值身份；执行键纳入协议版本、定义指纹和该求值身份。每次新的顶层 execute 都重新求值，
  不以定义指纹查找历史 Artifact 替代输入。整个图共用一次求值身份，中间阶段不另开 Run。
- **仅含固定 Artifact 输入的纯本地图**：保留现有精确复用政策，执行键由协议版本和包含
  确切输入 receipt、方法版本及绑定的定义指纹确定；同一 Session 的精确命中可直接恢复，
  不新建 Run。未命中才准入新的求值并发布，求值身份记录生产者而不改变固定输入执行键。
  禁止按相同显示值、成员数、来源 lineage 或最新 Artifact 替代确切输入。
- **首轮拒绝的混合图**：在 Run 准入及数据读取前拒绝，不分配一个新求值来绕过限制。

随机标识或运行时间不得塞进量定义以强行改变定义指纹。不同 Run 的产物也不因此自动
不可比较：两份 Materialized 端点仍按 compare 自己的共同域、输入绑定与精确键规则准入，
不能要求它们具有同一生产 Run。

Store 仍以 `(Session, execution_key)` 保持一次精确发布的唯一性；新的来源求值使用新键，
允许同一定义的多份 Artifact 并存。Run 准入、receipt 和发布使用同一已确定执行键，
恢复按 Artifact 引用找到原生产 Run，不重新分配来源求值身份。并发调用沿用现有 Session
写入保护和未完成 Run 检查：两个获准的来源求值有不同身份；固定输入的后续精确命中只恢复结果。

失败、取消或发布状态不确定时，保留原 Run、执行键和发布记录，按现有 reconcile/inspect/
abandon 契约处理；不自动生成新身份重放来源，不覆盖先前成功 Artifact。显式发起新的
来源 execute 仍需满足旧 Run 已妥善终结的准入条件，并获得新的求值身份。恢复已提交结果
和处理原发布状态不是新的求值。

该键协议仅接入获准的新 DSL 切片；尚未迁入的方法保留其 owning contract，不为本次候选
增加旧 Artifact 迁移或第二个 Store。实施前在 S0 接受执行键协议及所有者改动。首要验收是：
同一 Session、同一 Lazy 对象两次 execute 之间修改来源，定义指纹不变，两次成功发布的
Run、执行键和 Artifact 不同，两份结果均可断源精确恢复；纯固定输入的重复调用另验收
精确复用且不新建 Run。运行内节点共享按 §5.3 独立验证。

### 5.3 运行内共享

一次获准的新求值对同一个显式 Logical 节点建立唯一的本次实现绑定，所有消费者共享它。
纯固定输入的精确缓存命中按 §5.2 恢复原结果，不建立新的节点实现。
例如 jul 与 aug 引用同一个 customers 节点，完整分析执行时得到同一批客户；
同一个 aug 同时进入 share 的分子与 rollup 分母，也使用同一份 aug 实现。
编译器可下推、融合或采用必要的内部暂存，但必须保持这一可观察契约；这不要求逐节点执行
一条查询或逐节点发布 Artifact。语义上共享实现，不能仅把同一子查询文本复制到多个分支。
涉及选择、映射或归约的替换须满足 §3.5 的局部条件；L9 的状态相等本身不证明来源下推、
目标空组处理、检查履行与量定义都保持。

共享依据是显式节点身份，不是定义看起来相同：两次分别构造的 `session.members(Customer)`
不自动合并为一次读取。不需要增加按定义消重的优化器，也不保证客户、订单、地区等独立
来源读取处于同一个事务快照。运行内共享不能代替原有的覆盖、配对、数值与发布检查。

跨次冻结与 Materialized 的公开含义见接口设计第 9.1 节；混合输入按本章准入，不以保存历史表达式替代固定数据。

### 5.4 放置规则

按以下顺序决定，不建立未经验证的通用成本优化器：

1. 规范化方法、域、输入角色和必需部件；按 §5.1 区分 Lazy 来源依赖与显式物化依赖，
   排除来源型 Lazy 的历史缓存替换并拒绝首版不支持的混合图；纯固定输入按 §5.2 精确复用，
   确定哪些检查可以纯构造完成。
2. 根据来源位置、后端能力、类型及检查实现选择已注册路线。能生成 SQL 但不能保持消费
   政策的实现不准入；能否下推不能只查 Ibis 操作名称。Marivo 只构造 Ibis 表达式，
   不以自写 SQL 绕过 Ibis 或方法准入。
3. 纯来源且位于同一可执行来源域的关系阶段，优先 Ibis 下推；若有未支持方法，只允许采用
   已预先注册的“源端准备 + 本地执行”路线，并验证搬运及本地输入契约；两条路线均不
   可用时拒绝，不承诺所有 Ibis 不支持的计算都能自动转 pandas。
4. 一旦消费 Artifact，该输入经 pandas 读取；纯保留输入续算必须本地执行。不得扫描
   Artifact Parquet 为 Ibis 表，也不得通过临时表、VALUES 或上传重新送入 DuckDB/远端。
5. 数值方法可显式选择 Python 阶段，源端只完成对该方法合法的准备；后续结果继续在本地
   运算或发布，不为了恢复下推把本地结果再上传源端。

能力不足在数据执行前拒绝已知不支持项；源执行失败不得触发临时换引擎或拉全量数据重试。
如果数据相关准入在执行时失败，同样终止并保持原子发布边界。

| 计算 | MVP 的实现位置 | 关键准入 |
| --- | --- | --- |
| 来源筛选、属性绑定、受治理 join、坐标并集与分组 | Ibis → 已准入来源后端 | 路径、键、覆盖、类型与缺值检查可履行 |
| 来源上的 sum/count 状态与 ratio finish | Ibis → 来源后端 | 组件独立、空贡献有效、数值政策受支持 |
| Artifact 的 where/compare/group_by/summarize/rollup/members | pandas | 完整输入契约、必需状态；无源查询和无 DuckDB 连接 |
| Spearman 数值阶段 | 已准入 DuckDB/Ibis 来源路线，或来源准备后 Python NumPy/SciPy；纯固定输入走 pandas + NumPy/SciPy | 完整键配对、平均秩、方法缺值政策、完整输入与逐路线等价验证 |
| 语义判断、计划与发布 | Python 控制逻辑 | 唯一规则拥有者；不被算作“SQL 下推能力” |

同一语义方法的 Ibis 与 pandas 实现共享契约与测试向量，执行代码可以不同。需要双实现的
仅是本轮实际走两条路线的方法，不预先给全 DSL 各实现两套。

## 6. 数据交换、资源生命周期与恢复

### 6.1 一个规范契约，多种受控载体

传递单位是“数据 + 语义签名 + 必需部件”，不能只有一个 DataFrame。复用并扩展现有
row/row-set contract、primary/parts 和 receipt，不建设第二份独立元数据系统。

| 内容 | 规范 |
| --- | --- |
| 身份与坐标 | 显式有类型键列、键角色和域绑定；不能用 pandas index、行号或字符串拼接键代替身份 |
| 值状态 | 值与 Defined/Null/Undefined/Unknown 标签及原因分别编码；非 Defined payload 不参加普通算术；缺行另属域状态 |
| 量签名 | 量定义与版本、单位、时间范围、贡献归属角色、实际输入绑定和数值政策 |
| 状态与映射 | 每个部件有角色、schema/方法版本、所属量和实例键；明确键基数与覆盖，不能仅按物理行位置拼接 |
| 依据与义务 | 来源声明、已履行检查、推导依赖分别保存；阶段未完成的义务不能变成结果证据 |
| 数值与类型 | 固定列类型、可空性、精度、时区及溢出政策；禁止隐式 float 转换、非有限数掩盖错误或 object 列猜类型 |
| 生命周期 | 运行内实现标识、Artifact receipt 和资源所有权；未提交中间数据不能冒充可恢复 Artifact |

来源查询与 Parquet 读取共用固定 schema 的受控 RecordBatch 流作为物理交换边界，
pandas 是本地表格计算入口。RecordBatch 表示一个批次，不要求整个结果放进一个批次。

```text
Ibis plan -> admitted source adapter ----+
                                        +-> schema + RecordBatch stream -> pandas
Parquet -> receipt-checked decode -------+
```

复用现有 [BatchStream](../../../marivo/analysis/materialization/execution.py) 的 `schema`、
`Iterator[RecordBatch]` 和 `close()` 协议。来源和存储读取分别负责取得与释放底层资源，
不新增平行流类型或公开数据传输 API。统一边界须保持以下约束：

- 流创建后即可取得确定 schema，不能依靠第一行猜类型；空结果仍携带 schema。
  接入现有要求首批携带 schema 的消费者时，显式提供同 schema 的空批次。
  所有批次的字段、顺序和物理类型符合已绑定 schema；变化须拒绝，不能随批次重新推断。
- `RecordBatchReader` 可以由既有适配器包装；它本身不代替来源游标、事务、文件及取消的
  所有权。消费作用域在正常耗尽、提前停止和异常时均关闭流并释放拥有的资源。
  关闭不等于远端查询已确认终止，也不等于尚未完成的完整性检查已通过。
- Ibis 原生批次接口和受控驱动游标都可以产生符合相同契约的 RecordBatch；统一 Arrow
  输出不要求把已准入的专用来源传输替换为 Ibis reader。两者的分析 SQL 都遵守 §4.3。
  每条来源路线仍单独证明类型、分批和资源生命周期，不由返回类型自动获得后端资格。
- 创建来源 reader 可能立即提交查询，例如 [Ibis 的 `to_pyarrow_batches()`](https://ibis-project.org/reference/expression-generic#to_pyarrow_batches)；打开来源流
  属于获准的执行阶段，不能放进 Logical 构造或纯计划阶段并以“尚未迭代”为由声称无 I/O。

Arrow schema 负责物理编码；量定义、域、部件和依据继续由现有 Marivo 契约及 receipt
拥有，不能只存进 Arrow metadata。Arrow null bitmap 也不能区分 Null、Undefined 和
Unknown，必须与显式 Cell 标签及原因一同解释。同进程交换直接传递批次对象，不为统一
格式额外要求 IPC 序列化或中间 Parquet 落盘；Arrow 转换层不引入 DuckDB 执行。

Defined 的 payload 必须非空且符合声明类型；非 Defined 的 payload 采用规范空表示，
具体原因按所属方法的封闭编码保存。标签与 payload 不一致、非空键缺失或未知 schema
版本是输入完整性错误，不能由转换器猜测修复。数值有限性由方法进一步检查。
所有阶段错误沿现有结构化错误层级给出 expected、received 和具体修复；执行失败本身
不能被转换成一批 Unknown 值而继续发布。

### 6.2 读取、转换与写回

Artifact 读取顺序为：解析固定 receipt 和所需部件 → 受控 Parquet 解码为固定 schema 的
RecordBatch 流 → 按方法所需粒度转换为 pandas 主表/部件 → 检查部件对应与消费前提 →
本地执行。复用当前完整性检查，不能直接 pd.read_parquet(path) 绕过 receipt、所有权和
校验。文件行数或内容摘要等检查可能在流耗尽时才完成；允许边读边准备，但必要检查全部
完成前不发布结果，提前关闭不得把未完成校验记作通过。

Arrow 到 pandas 优先采用 [`to_pandas(types_mapper=pd.ArrowDtype)`](https://pandas.pydata.org/docs/user_guide/pyarrow.html)，复用现有
[转换所有者](../../../marivo/analysis/materialization/storage.py)并补齐新切片类型契约；
确需 nullable dtype 或身份、Duration 等专门表示时，使用明确的转换规则。不得把可空
int64 隐式转成 float，或丢失时区、时间单位及 Decimal 精度。编码可往返某类型不代表
数值方法已准入该类型；首轮方法范围仍以 MVP 为准。

Arrow 到 pandas 不承诺全程零拷贝。ArrowDtype 可以复用适合的 Arrow 存储，但具体
pandas 操作、类型转换和 NumPy 数值核可能分配新内存。数值方法仅在完成标签检查和
显式类型准入后取得 NumPy 数组，并保留数组位置到键的映射；输出重新绑定显式键。

pandas/NumPy 执行适配必须显式处理：

- groupby 的 Null 键、未出现分类、排序和空目标组；merge 的唯一性、缺键和两侧同名字段。
- sum/mean 默认 skipna、布尔 NA、整数溢出、浮点非有限值和 Decimal 转换。
- 非 Defined 值的状态掩码、恒真/恒假子条件不能豁免的消费前提、统计方法特有的缺值政策。
- 输入主表与私有状态不可原地修改；共享输入不能因 pandas 视图或数组写入被污染。

本地结果先通过方法输出与部件检查，再转换为确切 Arrow schema，经既有 Parquet Store
原子发布。持久化结果应保留约定 K；不能只存主值，或在恢复时靠 Catalog/来源补齐状态。

### 6.3 分批和内存使用

每个本地实现声明自己属于逐批行变换、可合并状态归约，还是需要完整组/完整输入。
分批边界不能改变分组、精确配对或秩次。Spearman 的全局秩不得逐批独立计算；不能宣称
RecordBatch 输入自动意味着整个算法可流式。首版全局本地方法采用完整必要输入，
不实现自动 spill 到 DuckDB。

逐批行变换可按批转换和消费；可合并归约跨批保留方法状态。需要完整输入的方法
收集批次、形成 Arrow Table 后统一转换为 pandas；Table 保留分块列，不要求先合成一个
巨大 RecordBatch，也不逐批扩展同一 DataFrame 反复 concat。这里的收集消耗完整输入内存，
批次行数既不是解码字节上限，也不是整个算法的工作区上限。来源驱动自身是否真正分批读取
另行验证，不能由适配器最终切出的批次数反推。

本切片不新增按输入行数、解码字节或工作区内存设定限额的 Runtime 本地资源政策，
也不以数据量或容量估算作为方法准入条件。分批、内存使用和复制开销保留实际观测；
读取或计算失败仍按既有异常与原子发布契约处理，关闭流并释放已拥有的资源，
不自动截断输入、改近似算法或回退到其他引擎。

### 6.4 原子发布与冷恢复

Artifact 原子保存签名、实际域绑定、Cell 状态、必要部件、数值政策和依据依赖。
冷恢复必须保留预先承诺的续算集合 K；“恢复前后显示值一样”不足以通过。
例如承诺上卷 AOV，就必须保留组件状态；承诺迁移统计，就必须保留规范轨迹。
恢复后两边都拒绝原定操作，也不能当作该能力已保持。

数学规律、具体方法的局部保持、后端实现和 codec 的履约、有限运行测试分别记账。
理论 §6.7 的局部论证只覆盖所选数学规则，不能作为更广 DSL 或数值实现已经正确的证据。
浮点容差用于执行验收，不用于归并量身份或签发支持集相等证明。
