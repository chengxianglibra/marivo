# Marivo 分析组合的语义与代数契约

Date: 2026-09-23

Updated: 2026-09-24；补齐有限核心子语言、具体值状态政策与局部替换条件，增加按目标组限制的规律。

Status: proposed v0.5；项目设计提案，包含条件规律、推论及证明，不代表实现完成或已获机器形式化验证。

配套文档：[语义层与 Analysis DSL 目标设计](2026-09-24-marivo-semantic-analysis-dsl-interface-design.md)。
本文定义分析组合的语义对象与运算含义；目标设计负责业务对象与公开语言。
本文不替代已接受的 API/Runtime 契约，也不代表目标设计已经实施。

本文借用成熟的集合、函数、关系运算、聚合代数与程序正确性思想，为 Marivo 定义组合契约。
它不是某套公认“统计分析代数”的转述，不声明符合一个统一的数据理论标准，也不主张新的数学发现。
具体类型、规则模板、证据协议与续算契约是项目设计；已有数学方法与项目定义的对应见第 1.2 节，
参考文献及采用范围见第 14 节。文中的“理论”指这些定义下的条件模型，不代表完整的统计推断体系。

## 1. 目标与组织主线

### 1.1 组合目标

分析会改变分析单位、构造群体、比较条件、分解变化、匹配事件和研究状态历史。
本文在关系运算之上设计语义类型和条件契约，以共同构造规则组织这些能力：

> 在有类型的实例域上定义量，通过明确的对应关系取得这些量，再做逐实例派生和沿映射归约。

| 层次 | 核心对象 | 负责回答 |
| --- | --- | --- |
| 实例域与对应关系 | 身份类型、实际域、目标域、映射及关系实例 | 分析谁；哪些实例互相对应 |
| 分析结果的值模型 | 量的定义、实际取值、保留部件与关系签名 | 结果意味着什么；还保留哪些续算依据 |
| 核心构造 | 域操作、沿映射取值、逐实例派生、沿映射归约 | 如何推导输出意义与后续组合 |
| 条件保持与执行 | 前提、部件、证据运输、准入及实现支持 | 何时成立；本次能否执行并发布 |

事件匹配、状态演化、抽样设计和贡献分配方法提供各自有明确含义的输入或扩展规则。
共同代数消费它们的规范结果，不接管这些领域判断。闭包发生在一族有类型的值上；
各运算可以是部分定义的，不要求所有对象都成为 Metric 或拥有相同方法。

系统化的标准是：一个新业务操作能指出它复用了哪些构造、增加了什么独立语义及成立条件。
本文不声称给出了数学上最小或完备的生成元，也不要求按理论层次新增公共类。
规则是否减少、总体成本是否下降，仍须通过对应实现范围的同等功能对照检验。

结论按证明责任组织：L1–L9 给出基础条件规律，C1–C4 提炼信息、映射、归约与覆盖的推论，
T1 给出组合保持定理模式。数学命题的证明、具体算子/codec 满足前提的证明与实际运行验证
分别记录，不能相互替代。索引与适用边界见第 9.4、9.5、12 节。

阅读时可先沿第 4–6 节理解域、量、保留状态与运算；第 6.7 节将选定范围落实成有限小规格，
第 9 节说明其相关规律和替换条件。第 3、7、8 节说明业务解释及独立扩展；第 10–12 节说明
信息、表示和执行如何保持这些含义。保留部件和相关假设在数学层就有作用，具体编码和检查后讲。

### 1.2 概念来源与项目定义

“有数学依据”“使用已有统计方法”“符合外部标准”是不同主张。下表区分直接使用的成熟概念、
对它们的项目改造，以及本文自行定义的契约。引用提供概念来源，不为整套设计及实现背书。

| 本文概念 | 来源及采用程度 | 项目定义或适用边界 |
| --- | --- | --- |
| 集合、函数、复合、直接像、单射 | 基础集合与函数定义；第 4、9 节直接使用并给出所需证明 | 实例身份、业务角色及哪些映射可准入由 Marivo 规定；不由函数存在自动推出 |
| 关系、选择、投影、配对 | 关系模型与关系运算，见 R1；本文在其上扩展 | 本文的字段投影保持实例身份和行域，不能直接等同于经典集合关系中可能合并相同元组的投影 |
| 无序状态合并、沿分组归约 | 交换幺半群的结合/单位/交换律；可分解聚合及均值 sum/count 见 R2 | lift/merge/finish 的具体语义绑定、贡献许可与保留部件协议由本文规定；数值执行需另证 |
| 均值、比例、加权均值、差值 | 基础描述统计与代数 | 给出指定有限域上的量，不自动成为对总体参数的估计或显著性结论 |
| 线性 contrast | 统计学中系数和为零的均值线性组合，见 R4 | 第 8.2 节将其形式应用于语义兼容的量；一般线性组合另称 linear combination，不附带 ANOVA 等模型 |
| 固定参考权重标准化 | 直接标准化的加权形式，见 R5 | 本文要求目标量、分层、权重单位与缺失政策明确，不推广到任意非线性统计量 |
| 未知成员的比率界 | 有限集合计数得到的最坏情形上下界；第 8.5、9.5 节直接证明 | 是指定成员域的确定性边界，不是置信区间或生存分析估计量 |
| 前置/后置条件与组合证明 | 受程序正确性和 Hoare 式推理启发，见 R3 | 第 6、12 节是项目规则及条件证明模式，没有建立完整的形式化逻辑或验证实现可靠性 |
| Entity、Dimension、Measure、Metric、Event、StateModel | 沿用 Marivo 的领域定义与拥有者 | 吸收通用建模词汇，但精确角色不是一套通用统计学或外部标准定义 |
| SRel 签名、A 值分解、量定义项 | 本文项目定义，使用类型环境、关系与谓词等已有记号 | 字段划分及组合方式由本文设计，不能当成既有标准类型体系 |
| Cell 四分支、部件和证据运输、K 续算等价 | 本文项目定义 | 分别是值状态、信息保留与续算观察的契约；不是现成四值逻辑、统计充分性或通用证据标准 |

L1–L9、C1–C4、T1 是本文内部编号，不是已有文献的统一命名。
其中集合/函数性质、状态合并与加权均值恒等式是基础数学在本文定义下的应用；
L6/T1 则依赖自定义的表示、续算和局部规则义务。不主张这些结论具有数学原创性。
新增加或借用术语时，必须说明来源、精确定义与改造之处，不能仅用形式化记号暗示其已有共识。

### 1.3 已定义的统计计算与未建立的模型

本文具体定义了有限域上的描述统计、固定参考权重标准化、零和线性比较和未知成员的确定性界。
这些方法的计算含义与附加条件可以独立检查；它们没有共同构成一个统计推断模型。

当前仅为抽样、bootstrap、总体估计、归因分配及因果识别说明组合边界，未给出其完整方法。
本文也没有从状态转移推出马尔可夫模型，或从相对窗口与留存推出生存分析模型。
抽样记录和随机种子不能代替概率机制；多次运行结果不能直接解释为置信区间；
差分、配对和贡献守恒不能单独识别因果效应。

若未来某个方法需要统计推断，应由该方法明确：目标总体、统计单位与估计目标；
抽样或数据生成机制及依赖结构；估计量、误差与区间的定义及有效条件；
相关的缺失、删失或因果识别假设。非参数方法或基于抽样设计的推断也需给出自身前提，
不要求所有方法强行采用参数分布族。这些是未来具体方法的说明义务。

语义上有定义、本次可准入与执行成功是三个不同判断，见第 11 节。

## 3. 语义定义环境 Γ

Γ 是有版本的业务定义系统，不是数据本身，也不包含本次分析自动选择的人群或窗口。

### 3.1 身份、变量与关系

Entity 给出业务身份类型，例如 `Id[Customer]`、`Id[Order]`。
二者即使底层均为整数，也不能互换。Entity 身份与物理行坐标不同：
快照坐标、有效期起点等可以区分历史行，却不因此成为新的客户身份。

Dimension、Measure、TimeDimension 都定义变量，但具有不同的合法使用角色：

$$
\operatorname{Channel}:\operatorname{Id}[Order]\to ChannelCode
$$

$$
\operatorname{Amount}:\operatorname{Id}[Order]\to Money[CNY]
$$

$$
\operatorname{Region}:\operatorname{Id}[Customer]\times Instant\to RegionCode
$$

这里的箭头描述业务意义；实际数据中的空值、未知和未定义状态由第 5 节表达。
数值分桶可以产生维度，持续时间可以成为统计变量，转换必须有显式定义。

Relationship 给出带角色、基数与时间条件的实例对应关系：

$$
BuyerOf\subseteq Id[Order]\times Id[Customer]
$$

关系存在不等于贡献可复制。订单关联两个标签，不自动授权把同一笔收入作为两笔收入相加。
贡献分配属于计算定义；关系事实本身不决定分配规则。

### 3.2 Metric、Event 与 StateModel

Metric 在此表示业务指标，不是度量空间中的距离函数。
它是可复用的计算定义：包含贡献类型、组件图、筛选、聚合状态、单位、空值与空集规则。
Metric 的计算根不等于分析单位。收入可以由订单贡献，在客户、渠道或总体单位上观察。
复合指标可以有多个贡献根，但每个组件必须有明确的范围映射。

Event 定义具有 occurrence 身份、参与者角色与发生时间的事件类型；观察到的 occurrences
是求值结果。StateModel 定义规范状态与合法转移，例如部分函数：

$$
\delta:S\times Event\rightharpoonup S
$$

事件解码、初始依据、同刻事件处理、重放窗口和观察覆盖另有明确所有者。
一个 StateModel 声明不能证明事件源完整。
上述转移描述没有定义转移概率，不因此构成马尔可夫模型。

## 4. 实例域与有类型对应关系

### 4.1 行实例、实际域与目标域

U 可以是 Customer、Customer × Week、PaymentOccurrence、Subject × Journey、
Subject × Interval、Region × Channel 或 Singleton。
`D ⊆ U` 不意味着 D 是这个类型的所有业务成员，更不意味着 D 自动等于 Ω。

例如目标人群为 `{u1,u2}`，只有 u1 有一笔 100 元订单。
从订单产生的分组域只有 `{u1}`；以完整人群为成员域、且完整无贡献收入定义为零时，
观察结果是 `{u1:100,u2:0}`。两者的客户均值分别为 100 与 50。
这不是给 NULL 补零可以解决的问题，而是目标域与实际行域的区别。

域描述 d 记录成员选择及输入绑定；`realize(d,ρ)=D` 给出它的一次实现。相同成员定义的两次读取
可以得到不同 D。域的身份也不能仅由行数、字段名或 Entity 名称确定。
每个量另有自己的观察范围；同一行域上的两个量可以分别代表七月和八月，不能共用
一个隐含的全局时间范围覆盖两者。

### 4.2 重复与抽取实例

数学关系值中的一个行实例只对应一行。源数据若违反已声明的键约束，不通过自动生成
额外行号把违约解释为合法新实例。

有业务含义的重复必须使用新的实例单位。例如有放回抽样使用
`Replicate × Draw`，并映射到原 Subject；同一主体被抽中两次是两个抽取实例。
SQL 的 bag 表示不能未经解释地替代这些身份规则。

### 4.3 映射与对应实例

映射 `r:K→D` 在其声明域上单值且全定义。部分对应必须先明确实际定义域，
或采用有缺失侧契约的封闭变体，不能把没有对应行等同于字段 NULL。

| 结构 | 映射形态 | 必须保留的含义 |
| --- | --- | --- |
| 子域 | `i:D'→D`，包含映射 | 选择位置、谓词、父域与未知处理 |
| 分组 | `g:D→G` | 分组坐标、目标组域及空组规则 |
| 主体 | `s:Journey→Subject` | 获准的角色、单值性；多旅程可映射到同一主体 |
| 配对 | `D₁ ← K → D₂` | 两侧角色、键与基数、完整性、缺失侧政策 |
| 多值导航 | `D₁ ← Edge → D₂` | 每个关系实例的身份；不自动保留贡献重数 |
| 贡献归属 | `Output ← Assignment → Fact` | 组件、事实身份、分配角色与必要权重 |
| 参照映射 | `r:D→Reference` | 每行对应的固定参照；参照输入不随展示筛选变化 |

同一事实可对应多个 Assignment；合法的重叠、去重或分配由计量方法决定。
不能因为建立了新关系实例身份，就把同一收入的重复累计解释为新的收入贡献。
权重也具有角色：分配权重、统计权重和抽样权重不能自动互换。

精确配对需要 K 完整覆盖设计要求的两侧实例，并满足规定基数；仅证明每个已有 k
恰好找到两行，不能证明没有漏掉其他应配对实例。交集、outer 与补零是另有含义的方法。

### 4.4 域的构造与合成

相容域可做并、交、差；输出仍需同一身份与范围解释。对带量的关系做集合组合时，
还必须处理同键量值冲突，不能仅由成员并集决定。分组输出域须明确选择 `image(g)`
或另有依据的目标域 G；后者的空组是否产出零值由归约方法和覆盖条件共同决定。

可合成的映射 `r:K→D`、`s:L→K` 给出 `r∘s:L→D`。
函数能合成只证明实例对应成立；业务角色、贡献重数和量的兼容性仍须按注册规则判断。
这些结构统一导航、配对、分组和选人的描述，不提供万能 join 或任意源查询授权。

## 5. 分析结果的值模型

第 4 节确定行代表谁、哪些实例互相对应；本节定义这些行上的量及完整分析结果，
作为第 6 节各算子共同消费和产出的对象。
需要分清三个问题：量意味着什么，当前实际取到了什么值，结果还保留哪些续算依据。
先定义这些组成部分，再用语义签名和关系值把它们组织起来；归约算法在第 6.5 节定义。

### 5.1 量的定义：一个值回答什么问题

量的定义说明物理值类型、单位、业务或计算含义、分析角色、观察范围、方法及数值政策。
这些定义由字段模式 Σ 拥有。同为 CNY 不表示 Revenue 与 Profit 是同一个量；
同为比例也不表示份额、渗透率和转化率可互换。
“允许比较”“允许求和”“允许总体上卷”“可以作因果解释”是分别需要判断的条件。

典型的计算定义项包括：

```text
Observed(metric, population, window, grouping)
Difference(current, baseline, comparison_design)
RelativeChange(current, baseline, comparison_design)
RowStatistic(method, input_variable, input_unit, domain, weighting)
Contribution(target, basis, decomposition_rule)
CompletedDuration(pattern, steps, matching_rule, selected_domain)
```

这些定义项属于本项目，可由分析产生，无须注册成 Catalog Metric。
例如“指定月份、按客户观察的订单均额”与“这些客户订单均额的等权平均”具有不同定义，
即使它们物理上都是一个数值字段。

对 Σ 中的每个量 q，实际取值记为 `x_q:D→Cell[T_q]`，其中 T_q 是该量声明的值类型。
Σ 说明含义，x 承载本次值；后文固定关系上的 `q(u)` 是 `x_q(u)` 的简写。
相同定义在不同实际输入下可以得到不同值，不能把定义本身当成一次已求得的结果。

### 5.2 单元格取值：有值、缺值、无定义与未知

每个字段值属于本文定义的带标签数据类型：

```text
Cell[T] = Defined[T] | Null[Reason] | Undefined[Reason] | Unknown[Reason]
```

- Defined(0) 是已定义的零值。
- Null 表示来源缺值等已知的缺失形态。
- Undefined 表示计算无定义，例如零分母或空集合均值。
- Unknown 表示信息不足，例如观察覆盖不足以判断行为是否发生。

这四个分支不是四个逻辑真值，也不等同于 SQL 三值逻辑；本文没有据此定义四值逻辑的
联结词、真值表或格结构。缺少一行属于成员域问题，不能自动等同于任何一个 Cell。
SQL NULL 如何进入这些状态由拥有者规定，不能仅从物理 NULL 猜测业务原因。
运算必须定义各状态的传播、拒绝或显式排除规则；没有通用的“缺失都补零”规则。

### 5.3 续算依据：贡献与保留部件

当前关系的行不一定是量的底层贡献。一行客户 AOV 代表一个 Customer，
但其计算可能由 100 个 Order 贡献。对量 q 的第 j 个计算组件，设贡献类型为 F_j，
输出实例 u 对应的贡献为 `B[q,j,u]`：带贡献身份、角色及必要权重的有限集合或 bag。
它不等于当前行域 D，可由第 4 节的 Assignment 对应关系解释。
各组件保留自己的贡献根和分配规则，不要求压成一个共同物理行表。

贡献 B 解释计算含义，保留部件 P 则是结果实际携带的续算依据；二者不能等同。
P 可以包含聚合状态、主体映射或轨迹，聚合状态只是其中一类。
保存 sum/count 不表示保存了全部订单 ID，也不保证能恢复原始订单。
贡献互斥、单值映射等条件仍按第 11 节使用获准声明、构造推导或必要检查。

Π 规定保留哪些部件及其角色，P 实现这些要求。聚合状态必须绑定对应量、贡献定义、
范围和状态版本；相同的物理 `(sum,count)` 结构不代表相同统计量。
不是每个量都有可合并状态，也不是每个结果都保留主体映射；缺少必要部件就不具备相应续算能力。

| 计算 | 典型保留状态 | 不足以继续合并的信息 |
| --- | --- | --- |
| Sum | 和、有效性及必要支持信息 | 不能只凭和证明贡献未重复 |
| Mean | sum、非空 count 与缺失规则 | 只有 mean |
| Ratio | 分子与分母各自的状态 | 只有 ratio |
| Weighted mean | 加权分子、权重和、配对有效性 | 未绑定到实例的权重列表 |
| Exact distinct | 与去重定义一致的精确成员状态 | 各分组的 distinct count |
| Exact quantile | 足够的精确分布状态 | 各分组的 quantile |

只有确实需要精确成员状态的方法才要求保存对应成员部件，贡献集合本身不是必须存储的对象。
上表说明保存什么，能否合并仍取决于第 6.5 节的方法条件。
这里状态“充分”只表示足以支持指定计算及续算；统计学的“充分统计量”相对于
具体概率模型和参数定义，不能仅凭可合并或结果可恢复就宣称具有统计充分性。

### 5.4 语义关系值：组织域、量、部件与条件

将以上组成部分与第 4 节的实例域放在一起，得到本文的项目定义：

$$
\tau=\operatorname{SRel}_{\Gamma}[U,d,\Sigma;\Pi,\Phi],\qquad
A=(D,x,P,E,\alpha)
$$

τ 是用于输出推导的语义签名，A 是满足相应条件时具有该签名的实际关系值。
两者分别说明“承诺什么”和“本次承载什么”：

| 组成 | 签名中的定义或承诺 | 实际值中的内容 |
| --- | --- | --- |
| 实例域 | U 定义坐标身份，d 定义成员域及其输入绑定 | D 是本次实际成员域 |
| 量 | Σ 定义字段、含义、类型、单位、范围及政策 | x 给出每个量在 D 上的 Cell 值 |
| 保留部件 | Π 定义部件角色及绑定要求 | P 是实际保留的状态、映射或轨迹等 |
| 成立条件 | Φ 是有前提的条件命题 | E 记录可用的声明依据、已完成检查及推导，不是命题的真值表 |

α 另记录所有权、实际输入与执行实现绑定，继续遵守既有 Session/Store 契约；
它不再次定义 Σ、d 已拥有的量含义和范围。Φ 的承诺不意味着所有事实已被检查，
E 也不包含待完成检查；条件推导与执行准入分别见第 6、11 节。

SRel 及其参数划分是项目契约，不要求把域成员编码进 Python 静态类型，
也不要求实现一个含大量可选字段的对象。该结构的作用是让算子明确输入含义、
所需部件和输出承诺，而非把所有分析结果变成同一种公共类。

### 5.5 贯穿示例：客户 AOV 的值与状态

固定一个观察窗口，客户 A 有 100 笔 1 元订单，客户 B 有 1 笔 100 元订单。
假定订单贡献完整、互斥且数值有效，关系的行单位为 Customer，实际域为 `{A,B}`：

| 行实例 | 量的定义（Σ） | 当前取值（x） | 对应订单贡献（B） | 实际保留状态（P） |
| --- | --- | --- | --- | --- |
| 客户 A | 同一窗口内的客户订单均额 | Defined(1 CNY) | 100 笔 1 元订单 | sum=100 CNY，count=100 |
| 客户 B | 同一窗口内的客户订单均额 | Defined(100 CNY) | 1 笔 100 元订单 | sum=100 CNY，count=1 |

订单贡献这一列解释数学含义，不要求结果保存订单明细。
当前值支持“客户 AOV 的等客户权重均值”，结果为 50.5 CNY，产生新的 RowStatistic；
保留的订单状态支持“这些客户的总体订单均额”，结果为 200/101 CNY，保持原订单均额定义。
只保留 x 而删掉 sum/count 后，前一种统计仍可能获准，后一种上卷则缺少必要部件。
两个答案都合法，但回答不同问题；保留更多状态不能替用户选择分析问题。
两条规则的共同计算机制及区别在第 6.5.3 节定义。

## 6. 核心构造与输出推导

### 6.1 统一规则形态

每个注册规则 O 有明确输入签名、参数及输出推导，使用以下项目定义的共同模板：

```text
InputSignatures + Parameters
  -> OutputSignature
   + Pre + RequiredParts
   + PartTransform + Post + Transport
   + Eval
```

`OutputSignature` 推导 U、d、Σ、Π、Φ；`PartTransform` 指明保留、新建或移除哪些部件及映射。
`Post` 是正确求值后的承诺，`Transport` 指明可运输的证据及仍相关的假设依赖。
`Eval` 给出数学含义；具体后端实现与准入政策由各自所有者负责。每项都是版本化的封闭规则，
不接受任意回调、任意证明程序或未约束的 metadata。

构造判断写成 `Γ;H;E ⊢ e : τ ▷ W`：表达式具有条件输出签名 τ，同时携带带输入绑定的义务 W。
规则先检查结构、字段所有权、参数角色和必需部件，再推导输出。可获准的延迟数据检查
进入 W；尚未履行的义务不能充当已成立事实。父节点可依赖子节点成功后保证的 Post，
但执行必须保证相关子义务在依赖它的计算或发布前完成。
只有强制义务履行且依据符合拥有者政策后，才可发布 A:τ；计划中的 Post/Transport
不能提前写入 E。这种发布仍以获准的 H 为条件，不把 H 的真实成立冒充已验证事实。

缺少主体映射等信息不能登记为一次检查后继续；只有拥有明确检查路径的命题才能延迟。
执行准入还需第 11 节的依据政策和实现支持，类型推导本身不证明来源正确或后端可执行。

### 6.2 域限制与字段投影

选择产生 `D'={u∈D:p(u)=true}`，但如何处理 unknown 谓词由该方法定义。
一种方法可以明确选择已知为真的行；它不能因此声称所有其他成员都为假。
需要完整成员判断的 cohort 操作可能必须拒绝仍有未知成员的输入。

投影只删除变量，不改变实例单位。若删除主体映射，后续主体选择失去依据；
若删除 mean 的 count，后续状态上卷失去依据。可读的数值相同不代表两者等价。
这里的身份保持投影是本契约的定义，不能直接套用经典关系投影可能消除相同元组的行数语义。

选择推导 `d'=Select(d,p)` 与包含映射 `D'→D`；U 不变，量按该域限制，
与当前行绑定的部件同步限制或按角色失效。原始观察范围仍保留，不能把展示筛选改写为重算来源。
投影保持 U、d，只裁剪 Σ 与按规则确定的 Π；字段不可见不必然意味着私有状态被删除，
但被明确删除的状态不得继续计入能力。两者都须给出后置命题与信息变化。

### 6.3 沿映射取值

给定获准的 `r:K→D` 和量 `q:D→Cell[T]`：

$$
r^*q(k)=q(r(k))
$$

输出行单位和域来自 K，量的单位及原始定义保留，并记录其在 K 上的取值映射与角色。
Π 只按已注册的部件映射规则保留。非单射 r 会多次取得同一输入值，不能因此声称贡献互斥。
配对先由领域设计构造 `D₁ ← K → D₂`，再分别取值；参照值使用独立绑定的 Reference 输入。
映射失配必须遵循原方法的拒绝/缺失侧契约，不静默变成 inner join。

### 6.4 逐实例派生

同一 K 上的量经过有类型规则 f 得到 `q'(k)=f(q₁(k),...,qₙ(k))`。
输出保持 K 的单位和域；Σ 增加含输入角色、范围、方法、单位与值状态政策的定义项。
例如 Difference 保留有序的 current/baseline 和比较设计；同为 CNY 不足以使任意两量可比较。
派生值不自动获得输入指标的 fold 状态、主体信息或归因资格；Π 的变化必须单独推导。

### 6.5 沿映射归约

本节定义怎样从多个输入得到分组结果。第 5 节的值与保留部件是输入，
归约方法决定消费哪些内容、如何合并及输出量意味着什么。

#### 6.5.1 无序可合并状态

对于一个声明可合并的计算 μ，设状态空间 M、单位状态 0_M、合并运算 ⊕、
贡献提升函数 lift 和结果函数 finish：

$$
S_\mu(B)=\bigoplus_{b\in B}lift_\mu(b),\qquad
\mu(B)=finish_\mu(S_\mu(B))
$$

这里的 B 是无序有限集合或 bag，因此 ⊕ 在可达状态上须满足结合、单位及交换律，
使状态不依赖枚举顺序。若只保证最终结果置换不变，须另证相关保留状态及续算也等价。
仅支持顺序合并的方法接收显式序列，使用第 7 节的 ordered fold；不能直接套用本式。
finish 可以是部分定义的，例如 count=0 时均值无定义。
空集、NULL、精度、溢出和数值顺序都是具体方法的契约。

均值保留 sum/count 后再合并是已有的可分解聚合方法，见 R2。
相同贡献重复进入两个集合时，普通 Sum 合并不代表总体收入。
Exact distinct 的集合并可以有意消除重叠；分配权重也可能使重叠贡献合法。
这些许可由对应方法证明，不能使用统一的 `additive=True` 代替。

#### 6.5.2 按目标组计算

给定有限实际域 D、有限目标组域 G、`g:D→G` 与获准的无序方法 m，对每个目标组 k：

$$
R_{g,m}(z)(k)=finish_m\!\left(\bigoplus_{u\in D:g(u)=k}lift_m(z(u))\right)
$$

g 的目标域决定哪些组应存在；空纤维、未知值和权重由 m 处理，不能只按有贡献的组产出。
输出单位为 Group，d 绑定目标组域，Σ 由 m 的定义规则产生；Π 只包含明确保留的新状态及映射。
主体存在量词也可沿主体映射归约，但必须使用其布尔真值、量化域与覆盖契约。

#### 6.5.3 当前行统计与原量上卷

相同的 `lift → merge → finish` 机制可以服务两种分析问题，必须用两条封闭规则区分：

| 规则 | 输入 z 及 lift | 合并及结果定义 |
| --- | --- | --- |
| 当前行统计 | 将 `(u,q(u),w(u))` 提升为新的统计状态 | 合并新状态，输出新的 RowStatistic；当前 u 是贡献身份 |
| 原量上卷 | 输入已有 `S_mu(B[q,j,u])`，lift 为状态恒等映射 | 合并原 μ 状态，保持原量含义；另需贡献覆盖和重叠许可 |

当前行统计对每个组使用新的观测集合：

$$
\{(u,q(u),w(u)):u\in D,\ g(u)=k\}
$$

统计定义记录 U、D、权重及缺失处理；原量上卷则保持原 μ 的贡献单位和计算含义。
第 5.5 节例子中，等客户权重均值的新状态是 `(101,2)`，订单状态合并是 `(200,101)`。
相同物理状态结构不能决定应采用哪条规则。共享计算机制不能自动选取贡献单位、权重或分析问题，
也不要求合并两个公开操作。

### 6.6 输出与信息变化的最小推导表

| 构造 | 输出单位与域 | 输出量的定义 | 部件与后置条件 |
| --- | --- | --- | --- |
| 限制 | 原 U、选中子域 | 原量在子域上的限制 | 按角色限制 P；保留键唯一，产生子域关系，不保留父域覆盖 |
| 投影 | 原 U、原 d | 保留字段原定义 | 明确保留/移除的部件，不从已删信息推导能力 |
| 沿映射取值 | K 的单位及域 | 原量加映射角色 | 保留获准映射；多值取用不推出贡献互斥 |
| 逐实例派生 | 原 K | 由封闭 f 构造新定义项 | 产生方法后置条件，不自动继承原 fold 权威 |
| 当前行归约 | Group、目标组域 | 新 RowStatistic，绑定原行域和权重 | 新统计状态；除非显式保留，否则失去原实例映射 |
| 状态归约 | Group、目标组域 | 原 μ 在粗域上的量 | 合并原状态；必须满足方法的贡献条件 |

该表是规则模板，不是全部输入均获准的能力矩阵。第 6.7 节填齐一个有限子语言；
其他具体方法仍需给出自己的 Pre、Π 变换和数值政策。

例如两侧客户收入的 difference 规则：输入各自的 `Customer,d_current/d_baseline,Observed`
签名；要求同一指标、获准时间比较设计、完整同键配对与已定义值，缺键检查可按政策进入 W。
输出仍以 Customer 为单位，d 为绑定两侧输入的配对域，Σ 为有序
`Difference(q_current,q_baseline,c)`。只有两侧主体映射在配对坐标上相容时才保留该映射，
不合并原指标状态。于是输出可进入获准的负值筛选与主体像；若随后归约成 Singleton 并移除
主体映射，继续选人就因 RequiredParts 缺失而拒绝。完整推导同时解释了成功组合与拒绝边界。

### 6.7 有限核心子语言

本节给出一套可逐项求值和检查的小规格，覆盖有限数值观察、完整时间比较、筛选、主体提取、
当前行统计与状态上卷。下列名称是数学表达式记号，不是新增公共 API，也不代表目标 DSL
已实现这些操作。本节的严格政策只是一个选定子语言，不覆盖全文所有领域方法。

#### 6.7.1 范围、输入与定义项

固定 Γ、输入绑定 ρ 和假设 H；所有域有限，数值使用带单位的精确有理数，不包含 NaN 或无穷。
数值输入仍使用 Cell，键与映射坐标则必须具有明确的业务身份类型。本节允许的表达式为：

```text
e ::= Input(A)
    | Observe(m, F, v, a, Omega, t)
    | Select(e, p) | Project(e, Q, J) | Pull(e, r)
    | Diff(e_current, q_current, e_baseline, q_baseline, c)
    | RowReduce(e, q, g, G, mu) | StateRollup(e, q, g, G)
    | Subjects(e)
```

`Input(A)` 引入满足第 5 节签名的固定值，不执行来源查询。它可含非 Defined 单元格，
是否可被消费由下列规则决定。输入量的定义限于本节的 Observed、Difference、RowStatistic
及其限制、取值映射和上卷解释；其他定义项不能仅因数值类型相同而进入本子语言。
叶节点的有效性是明确前提，不由后续推导反向证明。

本节仅有两类可选保留部件：单值主体映射 `s:D→Id[E]`，以及绑定量定义、方法版本、
贡献单位和范围的聚合状态 `S_q:D→M_mu`。没有保存贡献明细的要求；贡献覆盖和互斥可作为
适用范围明确的 H，或来自构造证明及允许的检查。只有状态数值不能证明这些贡献条件。
有效输入还要求每行状态真实实现其绑定贡献：`S_q(u)=S_mu(B[q,u])`，且对应展示值为
`x_q(u)=finish_mu(S_q(u))`。这属于数学输入有效性，不能仅由状态结构与版本匹配推出；
它不新增源全表预检。缺少状态的量不受此等式约束，也不因此获得状态上卷能力。

`m` 是 Γ 中固定的简单指标定义：贡献身份类型、数值变量、单位、时间角色、筛选定义及
本节的一种 μ，均有固定版本。`F,v,a,Omega,t` 是显式输入：F 为该时间范围与目标人群下的
完整贡献域，`v:F→Cell[Q[unit]]`，`a:F→Omega` 为全定义单值归属，Omega 为目标成员域。
F 的身份类型必须是 m 的贡献类型，v 必须是 m 声明的那个变量在 F 上的实际取值；
a 必须使用该观察中明确绑定的贡献归属角色，并与 Γ 中相应关系事实一致。单位相同不能
替换变量或归属角色。输入承诺 F 恰好覆盖按 m 的筛选、t 与 Omega 所要求的贡献；
Observed 定义同时绑定该归属角色。关系事实与数值来自固定 ρ，完整性依据仍服从第 11 节。
多根复合指标、分配权重、重叠贡献和其他缺失政策不属于这个 Observe。

新量仅由下列定义规则产生；输入角色、参数及实际依赖全部记录：

| 构造 | 新量或量的解释 |
| --- | --- |
| Observe | `Observed(m, Omega, t, identity_grouping)`，贡献单位为 m 的事实类型 |
| Diff | `Difference(q_current, q_baseline, c)`，保留有序两侧定义 |
| RowReduce | `RowStatistic(mu, q, U, D, g, G, equal_weight, strict)`，当前行是新贡献 |
| Select / Pull | 保留原量定义和观察范围，另记录包含映射或取值映射 |
| StateRollup | 同一 q、μ 及贡献定义在粗组上的解释，记录 g 和 G，不生成新的当前行统计 |

#### 6.7.2 三个归约方法与值状态政策

对已定义值 `Defined(z)`，三个 μ 的数学定义如下；元组合并逐分量相加：

| μ | 状态 M、单位状态 | lift(Defined(z)) | finish | 输出单位 |
| --- | --- | --- | --- | --- |
| sum | Q、0 | z | `Defined(S)` | 输入数值单位 |
| count | N、0 | 1 | `Defined(N)` | 本次贡献实例的计数单位 |
| mean | Q × N、(0,0) | (z,1) | N>0 时 `Defined(S/N)`；N=0 时 `Undefined(empty_mean)` | 输入数值单位 |

mean 的可达状态满足 N=0 时 S=0。这三个状态空间在可达状态上满足无序合并规律。
本节 count 统计被消费的已定义数值实例；它不实现忽略 NULL 的 count，也不定义 count(*)。
当前行 count 的计数单位为 U，原状态 count 的计数单位保持原贡献类型，不能互换。

| 操作 | Defined 输入 | Null / Undefined / Unknown 输入或其他失败 |
| --- | --- | --- |
| Select 的数值比较 | 同单位精确比较，得到 true 或 false | 被谓词引用的任一单元格非 Defined 即拒绝整次选择；不按 false 排除 |
| Diff | 两侧已定义且满足比较设计时相减 | 任一参与值非 Defined 即拒绝；缺一侧按配对失败处理，不制造 Cell |
| Observe / RowReduce | 每个参与数值都 lift 后合并 | 任一参与值非 Defined 即拒绝；不静默删行或补零 |
| StateRollup | 消费完整且绑定正确的状态 | 缺状态、状态结构或绑定失效即拒绝；不通过展示值重建状态 |
| Project / Pull / Subjects | 按各自结构规则操作 | 不对保留或搬运的 Cell 做数值运算；非 Defined 值不会因此变成 Defined |

`Select` 的谓词语法限于同单位数值比较 `q < b`、`q <= b`、`q = b` 及它们的 and/or/not，
b 为固定的同单位有理常量。所有被引用字段在整个输入域上均须 Defined，布尔组合不靠短路
避开该前提；谓词不读取分组结果、总体统计或隐藏来源。空域上前提真，选择仍为空域。

空贡献纤维使用单位状态，所以 sum/count 输出 Defined(0)，mean 输出 Undefined(empty_mean)。
这要求 Observe 的完整贡献前提成立；覆盖不足的观察不进入该规则，不能用空集恒等元抹掉未知。
空域上的全局统计仍需显式 `G={Singleton}` 才产生一行；若 G 为空则不产生结果行。
mean 的 Undefined 展示值可伴随有效的 (0,0) 状态保留：StateRollup 可消费该状态，
RowReduce 则消费展示值并按上表拒绝。底层缺值造成的未知贡献不属于这种空状态。

#### 6.7.3 域、映射与完整时间配对

域参数仅取固定输入域、Select 子域、显式有限目标组域、下述配对域或主体像。
映射仅取显式输入中的有角色映射、恒等/包含映射、配对投影及其类型匹配的复合；
另允许到 Singleton 的唯一映射，表示对整个当前域做一次统计。
g 必须是其中一个全定义 `D→G` 映射。输入映射的角色与坐标类型由 Γ 或其产生规则给出，
本节不开放任意 Python 回调。缺坐标、角色不匹配或多值映射均拒绝。

精确配对给定同一身份类型 Id[E] 上的键 `k_i:D_i→Id[E]`，两侧键均单射且键像相等：

$$
K=\{(u,v)\in D_1\times D_2:k_1(u)=k_2(v)\},\quad
\ell:K\to D_1,\quad r:K\to D_2.
$$

条件等价于两个投影对整个 D1、D2 分别为双射；两域可同时为空。键相等使用同一业务
身份的相等，不进行字符串化或不同 Entity 间的强制转换。重复键、缺侧或不同键像均拒绝，
不得缩成键交集；如需比较预选子域，必须先显式 Select 再按本规则检验两个实际域。
K 的客户坐标可通过共同键规范地标识，但仍记录到两个实际输入的投影。

本节 c 仅允许时间比较：两量的定义均为 Observed，只允许 Project/Select/Pull 的解释包装，
不含 Difference、RowStatistic 或 StateRollup。两量使用同一 m、同一固定目标成员输入、同一身份分组和 μ，
单位、筛选、时间角色及值政策相同；有意不同的只有声明的 current/baseline 窗口。
贡献归属角色也必须相同，不能把购买者收入与收款者收入作为同一指标的时间端点。
之后的 Select/Pull 不能改变这些原定义，实际输出仍须满足上述完整配对。窗口各自的
事实输入可以不同，不要求共同源快照，也不能把两个独立读取的目标成员定义当作同一固定输入。
其他比较设计、嵌套 Difference 比较与跨方法比较留给各自扩展规则；同单位不构成准入。

#### 6.7.4 逐规则的输出与信息变化

下表与前述方法、配对条件共同给出各规则的 Pre/Eval/Post。字段必须属于指定输入，
参数必须具有对应角色；未满足的前提按第 11 节拒绝或转成有明确检查路径的义务。

| 规则 | 求值与输出域/量 | 必需部件与输出部件 |
| --- | --- | --- |
| Input | 原 D、Σ、x | 原 P 及固定输入绑定；前提是输入满足声明签名 |
| Observe | 对每个 u∈Omega 合并 a⁻¹(u) 的 lift(v)，再 finish；输出域恰为 Omega | 输出 S_q；Omega 是主体域时输出其恒等主体映射；不输出原事实明细映射 |
| Select | D'={u∈D:p(u)=true}；所有字段按 D' 限制，量定义不变 | s、S_q 按 D' 限制并重绑当前载体域；每行原贡献不变；不保留对父目标域的完整覆盖 |
| Project | Q 为保留字段的有序子序列；D 不变，只保留 x_Q | J 明确选择保留的部件；本子语言要求状态所属 q∈Q，主体映射可独立保留；其余部件删除 |
| Pull | r:K→D；所有字段取 x_q∘r，输出域 K | 主体映射若存在则变为 s∘r；本子语言一律移除聚合状态，不从重复取值推导互斥贡献 |
| Diff | 按 6.7.3 构造 K 并取两侧值；输出仅有 Difference，其值为 current−baseline | 不继承两侧聚合状态；两侧主体映射都存在、身份类型一致且在 K 上相等时保留共同映射，否则不保留 |
| RowReduce | 对每个 k∈G 合并 g⁻¹(k) 内当前 q 值的 lift，再 finish；输出域恰为 G | 输出新的 S_q'，绑定新的 RowStatistic 与当前行贡献；移除原主体映射和其他状态 |
| StateRollup | 对每个 k∈G 合并 g⁻¹(k) 内已有 S_q，再以原 μ finish；输出域恰为 G | 必须有绑定正确的 S_q；输出合并后的同方法状态；移除主体映射和其他状态 |
| Subjects | 必须有 s:D→Id[E]；输出域 image_s(D)，Σ 为空 | 输出主体恒等映射；不保留原量、状态、实例重数或锚点 |

StateRollup 在本子语言另要求：被合并的各行原贡献两两互斥；每个输出组的贡献定义恰为
对应纤维中原贡献的并，不补入任何新事实。RowStatistic 状态以不同的当前行身份满足此条件，
Observe 状态由单值 a 的互斥纤维满足此条件，Select 不改变单行贡献。带重叠或分配权重的
其他输入不进入本规则。只保留 mean 的展示值时，无法履行 RequiredParts，不能延迟成数据检查。

每个输出的 Φ 只承诺表中给出的域、量、映射及状态事实和可由它们推出的命题。
本节统一的 Transport 是保留仍被输出含义或条件依赖的输入依据，并增加本规则的推导记录；
不升级来源假设，不为已删除部件保留能力承诺。α 继续绑定全部实际消费的输入及所有权。
这补齐了各行共同的依据规则，不声称 H 被实际扫描验证。图中未消费的新来源必须显式成为新输入。

#### 6.7.5 局部保持与一条完整推导

各规则的局部保持可直接由有限域定义检查：Select/Project/Pull 是明确的限制或函数复合，
因此保留表中声明的值与全定义映射；完整配对的双射保证 Diff 每个坐标恰有一对值。
Observe/RowReduce 的互斥纤维逐一覆盖所声明贡献，lift/merge/finish 因而给出定义的量和状态；
StateRollup 在互斥前提下由 L2 得到同一贡献并的状态。Subjects 的成员当且仅当存在输入原像，
且其恒等映射全定义。部件依表限制、新建或删除，故没有依赖已删部件的新承诺。
Transport 只沿这些构造保留依赖，局部结论仍以输入和 H 成立为条件。
这给出本节数学规则的局部保持论证，具体实现与 codec 仍有第 12 节的独立义务。

例如固定客户域 Omega={A,B}，m 为上述 sum 收入指标；七月完整订单贡献按客户归约为
`{A:100,B:50}`，八月为 `{A:60,B:70}`。值均已定义，两个观察输入共享同一个固定 Omega。

1. Observe 输出同单位的两个 Observed 量、各自 sum 状态和客户恒等映射；窗口分别绑定七月、八月。
2. Diff 以客户身份完整配对，输出 `{A:-40,B:20}` 和共同客户映射；不保留订单收入状态。
3. Select 使用 `difference < 0`，输出域 `{A}`、值 -40 与受限客户映射；原两个月范围不变。
4. RowReduce 取 mean，g 映射到显式 Singleton，输出 `Defined(-40)` 和新状态 `(-40,1)`。
   定义为下降客户的等客户权重收入变化均值，贡献身份是第 3 步的客户实例，不是订单。
5. 第 3 步也可沿 Subjects 得到 `{A}` 后显式观察九月；第 4 步已移除主体映射，不能恢复该名单。

若八月观察先经 Select 仅保留 A，第 2 步因键像不等拒绝；B 只是八月没有订单时，
完整 Observe 应保留 B 并给出收入零值。任一参与收入为 Unknown 时 Diff 拒绝；投影明确删掉状态后 StateRollup
拒绝。若第 3 步选择为空，第 4 步仍因显式 Singleton 产生 `Undefined(empty_mean)` 和 (0,0)；
它可以继续合并状态，但不能作为已定义数值继续比较。第 5.5 节的 AOV 例子进一步区分
RowReduce 与 StateRollup：前者产生新的客户统计，后者消费已有订单状态；不得按显示值互换。

## 7. 顺序、随机与领域扩展

这些扩展使用同一签名和条件模板，但提供共同关系构造不能自行决定的业务语义。

### 7.1 有序扫描

ordered fold 消费显式序列 `(x₁,...,xₙ)`、初始状态和转移规则；它的合并不要求交换。
分段结果必须保留跨边界继续扫描所需的信息，不能把无序分组归约当作事件重放。

扫描顺序必须有业务依据，或证明所有允许顺序给出同样的相关结果。
稳定的事件 ID 排序只证明可重复，不证明其先后符合业务意义。

结果可以同时包含最终状态、占用区间、转移轨迹和违规事实。
只保留连续状态区间，会丢失某些自循环、零长度转移及事件身份；
后续转移统计必须消费足够的 canonical 轨迹，不能重新匹配或重放补信息。

### 7.2 抽样

抽样设计构造 `Replicate × Draw` 域及到原实例的映射，并显式绑定随机性 ξ。

抽取实例保留到原主体的映射。抽样权重、贡献分配权重和统计等权是不同角色。
配对样本和聚类样本需要保持对应结构；重复主体不能被普通身份去重抹掉。
抽样产生样本值，不自动产生总体估计量；估计方法及其假设属于后续明确定义。
本节只规定抽取实例的表示与依赖，不指定抽样概率律或任何估计量的抽样分布。

### 7.3 领域构造器与分配方法

Event matching 负责 occurrence 到旅程的匹配、完成状态及 duration 定义；StateModel 的执行
负责规范轨迹和区间。共同代数可对已获准结果取值、筛选或归约，不能通过这些操作重新匹配、
解码或重放以补足丢失信息。

归因分配方法、统计估计和因果识别也各有所有者。它们可接入输入/输出签名和状态协议，
但其业务前提与方法正确性不会由通用配对、算术或结果守恒自动证明。

## 8. 业务操作的派生

本节把业务操作写成共同构造的组合，不代表现有 Marivo 已支持所有组合。
每个操作都须同时给出派生式与额外语义条件；拥有者仍负责那些条件。

| 业务操作 | 共同构造 | 独立语义条件 |
| --- | --- | --- |
| observe | 贡献对应 → 沿输出映射归约（含 finish） | 指标定义、目标域、时间范围和空贡献规则 |
| compare | 构造配对域 → 两侧取值 → Difference | 比较设计、方向、完整配对与缺失侧政策 |
| summarize | 当前行 lift → 沿分组映射归约 | 当前行单位、权重及缺失规则 |
| rollup | 原 μ 状态 → 沿粗化映射合并 → finish | 状态充分、贡献覆盖及重叠许可 |
| cohort | 实例谓词 → 沿主体映射量化 → 成员域 | 量词、量化域、真值和覆盖 |
| share | 固定参照映射 → 逐实例比值 | 相容计量、支持包含、分母和分区解释 |
| standardize | 参考权重配对 → 乘积 → 指定归约 | 统计单位、分层覆盖和固定目标 |
| attribute | target/basis 配对 → 注册分配方法 | 分配规则及充分状态；不能由普通求和代替 |

### 8.1 observe、cohort 与 summarize

observe 使用明确的目标域 Ω，把各指标组件的贡献映射到分析实例，再计算状态与观察值。
目标人群、贡献事实域、时间窗口、输出分组是不同对象。无贡献的成员是否产生零值，
由指标空集规则与覆盖条件决定，不由事实表恰好有没有行决定。

cohort 先在指定实例域上判断条件，再按明确量词归约到主体。
例如四周中至少三周活跃：已知三周活跃时，第四周未知也不影响条件为真；
已知两周活跃、一周不活跃、另一周未知时，成员真值仍未知。
这是谓词的逻辑性质，不意味着可以绕过现有来源完整性准入。

主体提取是 cohort 构造的受限形式。若 `s:D→Subject` 获准，
`image_s(D)` 为至少有一个选中实例的主体集合。它丢失原实例重数和锚点；
“每次满足”或“没有发生”另需量化域与覆盖条件，不能将未解决的主体真值静默压成排除。

summarize 对当前实例的值统计，在新量定义中记录被归约的实例单位和权重，输出域由分组决定。
它与原 Metric 上卷的区别由第 6.5.3 节定义，不以 API 名称相似与否决定。

### 8.2 compare、linear combination 与 contrast

配对设计 a 定义输出坐标 K 及到两侧行实例的映射。精确配对要求每个 k 恰好对应两侧各一行。
交集比较、完整 outer 比较和补零比较是不同方法，不能由执行器自动互换。

两侧键集合相等可以来自同一不可变域和保持域的构造，也可以在实际配对时检查缺失侧。
同一 Entity 名称、相同的行数、相同 Population 定义但两次独立读取，都不是充分证明。

比较还需要一个声明意图的设计 c，规定哪些条件有意不同、哪些条件必须相同。
时间对比、群组对比、同主体前后配对不能只用“字段名相同”决定。
绝对差记为 `Difference(x,y,c)`，固定有序方向；相对差另有分母与零值政策。

compare 是有比较设计的配对与变量派生。对语义兼容、已对齐的量 q_i，
固定无量纲系数 a_i 定义 linear combination（线性组合）：

$$
C=\sum_i a_iq_i
$$

只有系数满足 `Σa_i=0` 时，本文才将该零和比较称为 contrast。
统计学中的均值 contrast 使用这一约束，见 R4；应用到其他语义兼容量是本文的项目级推广，
不自动继承均值估计的方差公式、检验或置信区间。单位相同仍不足以保证量可比较。
例如系数 `(1,-2,1)` 的 `Aug-2×Jul+Jun` 是零和比较；
系数 `(1/2,1/2)` 的两期平均是线性组合，但不是 contrast。

系数、方向、条件角色及输入定义必须保留。线性式可描述
`(Aug-Jul)-(Jul-Jun)`，无须创造一个不可组合的 DeltaOfDelta 家族；
化简为上述三项形式还须满足第 9.1 节对共享 July 输入与数值重排的条件。
得到双重差分数值不代表已经满足因果识别或统计推断条件。

### 8.3 share、penetration 与 standardize

share 至少需要证明：分子是指定分母支持范围内的部分，计量定义兼容，参照映射唯一。
计量必须是同一个可加总量，或是注册分配方法给出的可加侧项；不能把分组转化率除以
总体转化率就称为份额。非加指标需要先明确合法的组成/分配定义，普通比值属于另一种量。
如果声称所有部分构成总体，还需证明完整分区或明确分配规则。
分母为零时份额无定义，不能自动填零。
只有非负贡献且分母为正等条件成立时，才能承诺份额在 [0,1]；有符号净值比不能借用该解释。
分母绑定独立参照输入，不随着展示筛选或 Top-K 改变。

penetration 对身份集合定义：

$$
penetration(B,\Omega)=\frac{|B\cap\Omega|}{|\Omega|}
$$

Ω 非空且成员含义完整时成立；重叠类别的渗透率之和可以超过一。
抽样总体估计不是这个简单集合比值，需另有估计定义。

standardize 对分层量使用固定参考权重：

$$
q_t^{std}=\sum_k w_k^{ref}q_{t,k},\qquad w_k^{ref}\ge0,\quad\sum_k w_k^{ref}=1
$$

这是直接标准化的加权形式，年龄标准化是典型应用，见 R5；不是本文发明的新统计方法。
所有正权重分层都必须有获准的量值；缺失后静默重归一化会改变目标。
权重的统计单位必须匹配目标量，例如访问转化率以参考访问构成为权重。
这一方法适用于其声明的加权量，不自动使分位数或任意非线性统计可如此合并。
结果是固定构成下的量，不是实际总体观察，也不是自动消除了干扰的真实效应。

### 8.4 attribute 与 reconcile

归因值操作需要显式三元组：

$$
attribute(target,basis,rule)
$$

target 固定被解释的量，basis 提供充分分解依据，rule 定义分配方法。
可加分区变化可以按各部分差值分解；比率需要对应组件和明确的分解方法。
贡献求和回到目标只是必要的数值核对，还需来源范围、方法和贡献关系成立。

reconcile 可以返回含 residual、coverage 和判断状态的诊断关系。
它使检查结果可继续分析，但 residual=0 本身不是完整性证明，也不赋予新的读源权限。

### 8.5 相对观察与留存

相对观察单位通常是 `Subject × Anchor`。时间窗口相对具体锚点定义；
168 小时与七个本地日历日不是同一规则。多锚点窗口重叠时，贡献共享或独占必须显式规定。

留存先固定目标实例域 Ω，再判定每个成员的行为命题。
对“七天内至少回来一次”，已出现的行为可以提前判真；尚未观察满且没有行为则可能未知。
若已知真、已知假、未知分别为 K+、K-、K?，三者完整划分非空 Ω，则：

$$
\frac{|K+|}{|\Omega|}\le retention(\Omega)\le
\frac{|K+|+|K?|}{|\Omega|}
$$

这只是由未知成员形成的确定性界，不是置信区间。
例如 100 人中已知真 25、已知假 5、未知 70，范围为 [25%,95%]。
只对完整窗口的 10 人计算 5/10=50%，回答的是另一个成员域的问题。
多锚点的实例留存与主体留存也必须分别定义，不能无条件按 Subject 去重。
上述界的可达性及有效信息增加时的单调收缩由 C4 证明。

### 8.6 跨家族旅程检验

`Metric → Delta → Population → Metric` 可展开为：观察量、配对、逐实例差值、
限制负变化域、沿主体映射取存在像，再以该成员域构造显式新观察。
新观察有新来源依赖；前面的值操作不从 lineage 隐式回源。

`Delta → Difference` 复用配对和派生规则，保留嵌套定义、方向及每个端点实现，
不需要 DeltaOfDelta 家族。实现能否归并相同端点，还要满足第 9 节的绑定与数值条件。

Event 规范结果中，u1 两个完成旅程为 10、30 秒，u2 一个为 100 秒。
当前旅程均值为 `140/3`；错误地改为先按主体均值再等主体平均会得到 `60`。
先筛选 `duration > 15` 再取主体像得到 `{u1,u2}`；`duration > 5` 选中三旅程，
主体像仍为两人。这同时检验逐实例计算、非单射映射与存在量词去重。
主体等权统计在此用于区分语义。

## 9. 表达式、等价与条件规律

### 9.1 表达式及显式绑定

`Expr[τ]` 是产生 τ 类型值的计算定义，`A:τ` 是已经得到的关系值。
业务 Metric 只是一种可复用定义，不是所有 Expr 或所有值的统称。

给定 Γ、实际输入绑定 ρ 和必要随机性 ξ，求值记为：

$$
\llbracket e\rrbracket_{\Gamma,\rho,\xi}\rightharpoonup A
$$

ρ 可以包含来自不同读取时点的输入实现；这个记号不承诺共同源快照。
固定定义不意味着重复执行看到相同数据。只有显式固定的输入值才可以直接用于
物化可替换性等式；本文不要求物理来源版本探测、共享事务或变化重试。

值操作只能消费输入值及显式参数；所需新数据必须成为表达式的显式依赖。
lineage 用于说明来源，不是查询原始来源的能力授权。
表达式重写还必须保持分析目标、固定参照和求值范围，不能只验证最终列名相同。

良构表达式由注册来源/保留值、核心构造及已注册扩展有限组合而成。
各节点按第 6 节推导条件签名和义务；类型匹配、域映射、量的角色、必需部件不能仅由列名代替。
表达式可以共享显式输入节点；把相同逻辑定义写两遍不保证复用同一次读取实现。

例如 `(Aug-Jul₁)-(Jul₂-Jun)` 的两个 July 项即使定义相同，也可能来自不同实现。
只有绑定同一个固定 July 值、量的角色相容且数值规律允许时，才可合并系数为
`Aug-2×Jul+Jun`。语义相容、输入身份相同与允许数值重排是三个不同条件。
本文不要求新增共同子表达式优化、源版本探测或自动重写。

### 9.2 三种等价与身份

以下三个比较层次由本文为分析组合定义；K 续算等价借用“按允许观察比较结果”的思路，
但其观察范围、部件和准入条件均是本项目契约，不声称是一套现成的数据库或统计等价标准。

| 关系 | 比较内容 | 不足以推出 |
| --- | --- | --- |
| 数值相等 `=_num` | 明确坐标和字段上的已定义数值 | 量的业务定义、域覆盖或贡献关系相同 |
| 语义等价 `≃_sem` | 单位、域、量的定义/范围/数值政策、值及其状态、相关前提等价 | 全部保留部件或任意未来续算相同 |
| K 续算等价 `≃_K` | 语义等价成立，预先声明的合法续算 K 及其结果观察均保持 | 未纳入 K 的能力、相同物理输入身份 |

语义等价允许由明确规律识别不同构造，不比较原始 AST、证据推导路径、检查时间戳或文件布局。
它仍保留相关假设及有效证据的作用，不能把依赖源声明的结果改写成已扫描验证的结果。
输入 Artifact/部件身份、Session 所有权及 selector 绑定仍按原契约检查，不由语义等价替代。

K 是变换或物化前声明的、带明确参数与观察契约的续算集合，可包含有限操作链。
只对语义等价且 K 中各续算均具备所需部件并获准的 A、B 定义 `A≃_K B`，
并要求在各自前提成立时，对应的成功求值结果语义等价。
K 不能事后取两边剩余能力的交集；两边都缺少主体映射而都拒绝选人，不构成选人能力的保持。
需要保持的拒绝行为另列负例，比对拒绝类别与修复含义，不要求错误文本字节相同。
此关系不承诺外部 I/O、资源或环境故障一致；那些行为仍由执行契约及独立检查负责。

数值容差是具体执行验收关系，通常不具传递性，不定义语义等价，也不能用于归并身份。
只做显示值比较不能验证 `≃_K`；反之保留某组 K 不要求保存全部原始信息。

#### 9.2.1 有限规则的局部可替换性

第 6.7 节选定的子语言只使用明确列出的定义项、值状态政策和部件变换。
在该范围内，两个不同构造的含义可以由本节的具名规律及其前提识别；不要求原始 AST 相同，
也不提供任意量定义的语义等价判定。L7–L9 描述共同数学模型中的规律，只有两侧均可由
第 6.7 节允许的表达式构成时，才成为该子语言内的替换候选。例如任意地区键选择及其原像
限制未被该子语言的数值谓词普遍覆盖，L9 不据此新增组键选择构造器。
每次将 `e` 替换为 `e'`，须明确以下内容：

1. 两侧固定的 Γ、显式输入绑定及参数；采用的规律、成立前提和原始比较层次。
2. 输出单位与域的对应、量定义及观察范围、值状态和相关假设如何保持。
   函数或状态相等只有完成这些核对后才能用于语义等价。
3. 替换前声明的续算 K；逐个列出其所需部件、绑定及准入条件在两侧如何保留，
   并按所用规则证明成功结果语义等价。字段、Artifact 与 Session 的绑定仍须合法。

下表列出四条核心规律能够支持的比较及升级义务；它不是所有后续操作的自动重写表。

| 规律 | 直接得到 | 升级为语义等价所需内容 | 升级为 K 续算等价所需内容 |
| --- | --- | --- | --- |
| L1 选择组合 | 满足 L1 条件时的语义等价 | 两侧把谓词作用于同一固定输入，合取不改变未知政策、量定义和观察范围 | 每个部件的连续限制与一次限制一致；按相同角色保留或失效，并支持原定 K |
| L7 取值合成 | Cell 值函数相等 | 复合映射保留同一业务角色链、量定义、原始范围及相关前提，不能只保留复合函数的物理键 | 部件运输沿两步与复合路径一致；非单射取值不新增贡献互斥性或状态上卷许可 |
| L8 分层归约 | 原方法状态相等 | 比较同一原量、贡献及最终目标组域；量定义将同一贡献沿 `h∘g` 的归约识别为分层归约；采用同一 finish 与值状态政策 | 中间保留完整状态，最终按相同角色保留部件及假设；不以当前行均值替换原状态，不恢复已丢失的细域映射 |
| L9 按目标组限制 | 限定组域上的状态相等 | 方法的定义规则明确识别同一组内贡献的限制，保留原观察范围、组身份及固定参照；不得仅因状态相同便删除量定义中的输入域差别 | 限制与归约两条路径保留原定 K 所需的相同部件、条件及输入绑定，空组及其后续处理也相同 |

L8、L9 的量定义识别须由所用方法明确给出；尚未给出时，只使用其状态等式。
例如两种 RowStatistic 定义记录了不同输入域时，需要证明该方法在每个保留组上使用相同
观测实例、权重和范围，并明确这种限制如何保留问题含义，不能以最终状态相等代替此项证明。

一个已能直接核对的局部例子是 L1 后接 Subjects：两种选择得到同一域 D'；
保留的主体映射均为原映射在 D' 上的限制，所以两侧主体像相同，且不增加或恢复主体映射。
若后接同一获准 RowReduce，固定其目标组域、分组映射及统计方法，两侧向 lift 提供同一批
实例和值，产生同一新统计定义、状态和结果。这两个推导都要求后续规则原本有定义且部件齐全。

在第 6.7 节的严格 Select 下，p、q 必须在同一个原始输入域上均满足 Defined 前提。
两次顺序选择各自成功不足以证明这一点：内层 q 可能先删除 p 所引用字段为 Null 的行，
使外层 p 可以执行，而合取在原域上会拒绝。本子语言仅在上述共同前提成立时应用 L1。

更长的 K 可以逐节点重复上述核对；每个新增后续规则仍需自己的保持论证。
本节没有证明全部注册操作的任意上下文替换定理。数值相等不足以开始该论证；
两侧同样拒绝也不保持原定成功续算，拒绝类别与修复含义按第 9.2 节另作负例验证。

### 9.3 有界批量求值

scan_slices、sensitivity 与 bootstrap 可以共享受控的表达式批量求值结构：

$$
evaluate\_each(e,\{\theta_1,\ldots,\theta_n\})
$$

每个 θ 明确可变参数、固定依赖以及重采样作用域。
切片不能把固定总体分母一起缩小；重采样时固定参考权重与每次重估权重是不同估计目标。
失败场景必须保留状态，不能静默删掉后用剩余结果计算不确定性。
随机种子本身不够，还需绑定抽样算法、单位、配对/聚类结构与抽取实例身份。

批量结果仍可成为类型化关系，但“执行同一程序很多次”没有自动提供显著性、因果性或模型正确性。
本节没有选择 bootstrap 估计方法、区间构造或有效性假设；批量求值结构本身不能提供这些方法。

### 9.4 条件规律

以下规律在明确条件下成立；每条标明比较对象，不能把数值或状态相等直接升级为 K 续算等价。
这些编号属于本文件；基础规律的数学内容及项目定义的条件定理模式应按第 1.2 节区分。

| 编号 | 结论与比较对象 | 直接用途 |
| --- | --- | --- |
| L1 | 选择组合的语义等价 | 在规定谓词条件下合并选择 |
| L2 | 互斥贡献分解后的状态相等 | 分区计算后合并原状态 |
| L3 | 完整配对域上差分与求和的数值恒等式 | 交换先求差和先求和的顺序 |
| L4 | 主体像保持并集，比较成员集合 | 分批提取主体后求并集 |
| L5 | 有序扫描分段后的转移状态相等 | 携带充分状态分段继续 |
| L6 | 正确 codec 下的 K 续算等价 | 固定输入物化及冷恢复 |
| L7 | 沿合成映射取值的函数相等 | 多步坐标取值的组合 |
| L8 | 两级与直接归约的状态相等 | 保留状态的分层上卷 |
| L9 | 按目标组限制前后的状态相等 | 保留整组贡献的限制与归约交换 |

L1–L5、L7–L9 的证明依赖下列数学定义和局部条件；它们不声称具体后端已满足这些条件。
L6 是表示保持的条件定理模式，须逐 codec、方法和续算集合证明其前提。
第 12 节的 T1 同样不自动完成各算子的局部证明。本文未进行机器形式化验证；
有限样例或性质测试提供实现证据，不能代替普遍命题的证明。

#### L1 选择组合

同一输入上，纯、全定义且语义不变的布尔谓词 p、q 满足：

$$
\sigma_p(\sigma_q(A))\simeq_{sem}\sigma_{p\land q}(A)
$$

证明要点：两边均保留恰好同时满足 p 与 q 的实例，量的定义和观察范围一致。
两次推导与一次推导的记录可不同，但相关假设不变；若声称 K 续算等价，还须逐角色验证
部件限制后支持相同 K。本式不自动授权执行器进行重写。
若谓词含未定义计算、隐藏求值副作用或不同 unknown 政策，不能直接使用这条等式。
它不允许把对汇总结果的选择移动到原始贡献上；按目标组限制的状态规律另见 L9。

#### L2 状态分解与合并

对方法允许的互斥贡献分解，且满足第 6.5.1 节的无序可合并状态条件：

$$
S_\mu(B_1\uplus B_2)=S_\mu(B_1)\oplus S_\mu(B_2)
$$

证明要点：展开 lift 后按结合与交换律重新分组，单位状态处理空分解。
有重叠时要应用去重/分配方法自己的定理，不能冒充互斥分解。
该式是指定无序状态空间中的相等，不是关系值的无条件等价，也不允许任意展示值再次求和或求均值。

#### L3 差分与当前行求和

同一有限完整配对域 K，所有值已定义，使用精确算术时：

$$
\sum_{k\in K}(x_k-y_k)=_{num}\sum_{k\in K}x_k-\sum_{k\in K}y_k
$$

这里的 K 是配对坐标域，不是续算集合。证明要点：有限加法的分配与结合。
把该恒等式解释为总体指标变化，还需额外证明
各行确实构成总体的可加分区。纯数值恒等式不能提供这个业务证明。

#### L4 存在量词主体像与并集

两个相容实例集合使用相同映射 s，则：

$$
image_s(D_1\cup D_2)=image_s(D_1)\cup image_s(D_2)
$$

证明要点：主体属于左侧，当且仅当它有原像在 D1 或 D2 中，也就当且仅当它属于右侧。
该等号比较主体成员集合，不声称保留原实例的量和重数。主体像一般不保持交集：
两个不同旅程都属于同一用户时，旅程交集可为空，
两侧主体像的交集却非空。因此不能随意交换“先提取主体”和“先做集合运算”。

#### L5 有序折叠

在相关转移均有定义、状态足以继续扫描时：

$$
fold(s_0,x\cdot y)=fold(fold(s_0,x),y)
$$

证明要点：对 y 的长度归纳。空序列不改变状态；每追加一个事件，两侧都从同一前缀状态
应用同一转移规则，因而结果相同。
该等号比较指定转移状态；它不提供交换律。若输出还包括历史，
摘要状态和输出组合必须保留跨段边界所需信息。
只验证最终状态相同，不足以证明转移次数、违规事实和区间历史等价。

#### L6 物化可替换性

设 K 是写入前声明的获准续算，令 `A'=read(write(A))`。固定全部显式输入、方法版本、
数值政策及必要随机性，并满足以下局部前提：

1. codec 正确保留当前域、量、值状态和相关依据，使 A 与 A' 语义等价；不只校验文件可读。
2. K 所需的每个部件均按量、贡献定义、范围和版本恢复，所有权及字段绑定按既有恢复契约建立。
3. K 中每个方法只消费声明的输入/部件；其准入与输出保持于上述内容的正确恢复，
   不依赖无语义作用的物理布局，也不隐式读取新的来源。对操作链，逐节点满足同一要求。

则：

$$
A\simeq_K read(write(A))
$$

**证明：**第一项给出起点的语义等价。第二、三项保证每个获准续算在恢复后仍具有相同
计算依据、成立条件和结果含义；对有限操作链逐节点应用这一局部保持，得到对应结果语义等价。
结合第 9.2 节的定义即得结论。第三项需要各方法的实际保持证明，不能仅从部件名称齐全推断。

必须先证明恢复后仍支持整个 K，再比较每个续算结果，不能删掉恢复后失败的操作再称等价。
没有保存 count 的 mean 不具备 mean 上卷的这一保证；定义相同但重新读取可变来源也不属于本式。
等价不要求序列化字节或证据路径相同，也不允许恢复时把来源假设升级为检查结论。
仅为 K 保留充分信息，不代表支持任意未来问题。

#### L7 沿映射取值的合成

对获准的全定义映射 `r:K→D`、`s:L→K` 和同一固定输入量 q：

$$
s^*(r^*q)=(r\circ s)^*q
$$

两边在每个 l 上都取 `q(r(s(l)))`；该等号先比较值函数。
升级为语义等价需保留映射业务角色与原量范围；升级为 K 续算等价还需相同部件变换。
它不证明重复取值后的贡献互斥，也不允许自动改成另一种配对设计。

#### L8 两级无序状态归约

给定有限域 D、G、G'，全定义 `g:D→G`、`h:G→G'` 和可达状态上的交换幺半群 M，定义
`Merge_g(s)(k)=⊕_{u:g(u)=k}s(u)`，目标空组使用单位状态，则：

$$
Merge_h(Merge_g(s))=Merge_{h\circ g}(s)
$$

证明要点：每个输入状态沿函数恰好进入一个最终组，结合与交换只改变分组次序。
该式要求中间保留状态而非 finish 后的展示值，且不改变贡献分配、权重或缺失政策。
它不把先求组均值再等组平均变成总体均值；原 μ 上卷仍需满足自身的贡献合并条件。

#### L9 按目标组限制与状态归约

固定有限实际域 D、有限目标组域 G、全定义分组映射 `g:D→G`，以及同一输入状态函数
`s:D→M`。M 使用第 6.5.1 节的无序可合并状态，目标空组以单位状态 `0_M` 合并。
选定同一个组集合 `G'⊆G`，定义其原像及限制映射：

$$
D'=g^{-1}(G'),\qquad g'=g|_{D'}:D'\to G'
$$

则有状态函数相等：

$$
\left.\operatorname{Merge}_g(s)\right|_{G'}
=\operatorname{Merge}_{g'}\left(\left.s\right|_{D'}\right)
$$

**证明：**对任意 `k∈G'`，`{u∈D:g(u)=k}={u∈D':g'(u)=k}`，
因此两侧合并完全相同的一批输入状态。空纤维两侧都返回 `0_M`；若 G' 为空，
两侧同为其上的空状态函数。目标域必须都是 G'，不能在一侧改用 `image(g')` 删除空组。

将此式用于分析归约时，还须满足以下绑定与方法条件：

- s 来自同一次固定输入，贡献身份、分配和重叠许可不变。若 `s(u)=lift_m(z(u))`，
  右侧限制同一个 z、lift 及其显式参数；不得随 D' 重估权重、重新归一化或重新读取来源。
- 组集合与分组映射在两侧相同；不能把作用于组的条件换成作用于单条贡献值的另一条件。
  若 G' 依赖已求得的组值，恒等式只比较固定该 G' 后的状态，不授权跳过确定 G' 的计算。
- 使用同一状态版本、合并与数值政策。若继续 finish，也须使用同一方法、固定参照、
  空组及值状态政策；空状态相同不意味着所有方法都产生 Defined 值，例如空组 mean 无定义。

例如“按地区汇总后保留华东”和“保留映射到华东的全部贡献后按同一地区域归约”具有相同状态。
“保留收入超过 100 万的地区”不能改成“先保留金额超过 100 万的订单”：后者通常删除
这些地区内的其他贡献，已不满足 `D'=g^{-1}(G')`。

本式不比较完整关系值，不更改原始观察范围或固定总体参照。仅有状态相等时，不能用于
改变 RowStatistic 的问题定义、把展示筛选改写为来源重算，或宣称保留任意主体与续算能力；
这些升级按第 9.2.1 节逐项证明。若原方法要求的部件、值状态、映射或贡献条件不满足，
仍须按其契约拒绝，不能因两条路径可能得到同一个显示值而豁免。
实现中的浮点或近似合并另遵守下述数值边界。

#### 数值执行边界

实数上的结合律不授权任意重排浮点计算。每个数值方法需要声明精度、舍入、溢出、
近似与允许误差。数值容差不能用于判断主体身份、集合覆盖或定义相等。
数学等价和某执行器的数值一致性是分别需要验证的命题。

### 9.5 明确推论及其证明

以下命题把已有定义和反例中的一般结论单独提出。每条给出量化范围、证明和分析含义；
它们不授权新增公开操作，也不替代具体领域扩展的独立定义。

#### C1 摘要信息丢失后的不可恢复性

固定允许输入集合 X，设确定性摘要 `F:X→S`，目标 `T:X→Y`。F 明确表示续算被允许消费的
摘要内容；所有额外参数固定，不允许额外输入或通过来源身份查表回源。
如果存在 `A,B∈X` 满足：

$$
F(A)=F(B),\qquad T(A)\ne T(B)
$$

则不存在只消费摘要的确定性 `G:S→Y`，使得对所有 X 都有 `T=G∘F`。
若目标是部分定义的，须将“是否有定义”一并视为目标观察，或先限制到共同定义域。

**证明：**若 G 存在，`F(A)=F(B)` 必须推出 `G(F(A))=G(F(B))`，
因而 `T(A)=T(B)`，与前提矛盾。

例如 `A={u1:0,u2:100}`、`B={u1:100,u2:0}`，去身份的分布、总和及均值相同，
但 `value>50` 的主体分别为 u2 与 u1。F 只保留这些汇总量而没有主体—值映射时，
无法精确恢复这个主体选择。这里相同的是所声明的摘要内容，不要求两个完整 Artifact
的物理身份相同；不把唯一 provenance ID 当作未声明外部查表的能力。

**推论：**声称摘要足以回答 T，至少要证明 T 在每个相同摘要的输入类上保持一致。
一对上述冲突输入就足以否定普遍可恢复性。保留额外映射或显式增加输入会改变 F，
需要重新判断；缺少反例也不证明已有可执行算法或获准方法。
这是确定性函数分解的限制，不是概率模型下的充分统计量定理，也未使用熵或互信息。

#### C2 主体像与交集普遍交换的充要条件

固定全定义映射 `s:D→Subject`。以下命题等价：

$$
s\text{ 为单射}
\quad\Longleftrightarrow\quad
\forall A,B\subseteq D,\quad s(A\cap B)=s(A)\cap s(B)
$$

**证明：**`s(A∩B)⊆s(A)∩s(B)` 总成立。若 s 单射，右侧同一个主体在 A、B 中的原像
必为同一实例，故也属于左侧。反之，若存在 `a≠b` 且 `s(a)=s(b)`，取 `A={a}`、`B={b}`，
左侧为空而右侧非空，否定对所有子集的交换性。

**推论：**一人多旅程时，“分别满足两个条件的主体交集”可能由该人的不同旅程贡献，
不能改写为“有同一旅程同时满足两个条件的主体”。非单射映射下，某一对集合仍可能恰好相等，
但不能据此推出一般交换律。此处量化所有数学子集，不要求库能构造任意子集，
也不新增主体集合运算或自动重写规则；L4 的并集规律仍然成立。

#### C3 等组均值与总体均值的相等判据

设 `m≥1` 个有限、获准的互斥贡献组具有同一计算定义和缺失政策，组有效计数 `n_i>0`，
组均值 `a_i` 已定义且有限。使用精确算术，定义：

$$
\bar a=\frac1m\sum_i a_i,\qquad
\bar n=\frac1m\sum_i n_i,\qquad
a_{pool}=\frac{\sum_i n_i a_i}{\sum_i n_i}
$$

若称 `a_pool` 为指定总体均值，还需各组完整覆盖该总体的获准贡献。则：

$$
a_{pool}-\bar a
=\frac{\sum_i(n_i-\bar n)(a_i-\bar a)}{\sum_i n_i}
$$

**证明：**展开分子，并使用 `Σn_i=m n̄`、`Σa_i=m ā`，得到
`Σn_i a_i-ā Σn_i`；除以正的 `Σn_i` 即得。

因此两种均值相等，当且仅当上式分子为零。等组规模是充分条件，但不是必要条件：
`a=(1,2,3)`、`n=(1,2,1)` 时，两种均值均为 2。第 5.5 节的 AOV 例子则给出不同结果。

**推论：**展示值碰巧相等不使等组统计与原状态上卷语义等价，不能据此替换定义或权重。
计数为零的组不满足本命题前提，不能静默删除以套用公式；组均值无定义、来源重叠或
缺失政策不同也需先按所属方法处理。浮点实现另按数值政策验证，不把容差相等当作该充要条件。

#### C4 未知成员界的可达性与单调收缩

固定有限非空目标域 Ω、行为定义和窗口，可靠的已知真、已知假、未知集合
`K+、K-、K?` 完整划分 Ω。设真实但可能尚未知的成员判断为布尔值，则第 8.5 节的界满足：

$$
L=\frac{|K+|}{|\Omega|}\le retention(\Omega)\le
U=\frac{|K+|+|K?|}{|\Omega|}
$$

**证明及最紧性：**真实为真的成员至少包括 K+，至多包括 `K+∪K?`。
若没有其他约束限制未知成员的可能取值，将其全部置假达到 L，全部置真达到 U，
所以两端是可达到的最紧上下界。若有额外约束，以上界仍安全，但未必最紧。
有限人群的可行比率是离散点，不声称区间内每个实数都可达到。

一次有效信息补充将未知中的互斥子集 P 判真、N 判假，已有确定判断不变，则：

$$
L'=L+\frac{|P|}{|\Omega|},\qquad
U'=U-\frac{|N|}{|\Omega|},\qquad
U'-L'=\frac{|K?| - |P| - |N|}{|\Omega|}
$$

**证明：**分别将新计数代入 L、U；未知真转入分子下界，未知假从上界候选中移除。
因此下界不降、上界不升，宽度始终等于未知成员占比。

**推论：**在固定问题下，可靠信息增加只能缩小这类不确定范围。改换人群、行为定义或窗口，
以及撤销旧判断的数据纠错，不属于此前提。该界不是置信区间，也不绕过来源覆盖准入。

## 10. 信息与证据如何随操作变化

| 变化 | 可以保留/推出 | 不能默认保留 |
| --- | --- | --- |
| 行选择 | 唯一键、单值映射、相对输入的子域关系 | 对原目标域的完整覆盖 |
| 变量投影 | 行域和保留字段的含义 | 依赖已删除部件的上卷或主体恢复能力 |
| 单值导航 | 在声明前提下的行单位 | 未声明多值路径的贡献唯一性 |
| 多值展开 | 新复合实例身份 | 原事实贡献互斥、原行数与权重 |
| 精确配对 | 已证实的坐标对应、有序两侧范围 | 两侧贡献互斥、相同来源实现或因果可比性 |
| 当前行归约 | 新 Group 键、新统计定义和当前行统计状态 | 原主体映射、原指标 fold 状态的同一性 |
| 状态上卷 | 合法合并后的原量含义 | 已丢失细粒度成员的可恢复性 |
| 主体像 | Subject 集合身份 | 原实例数量、锚点与量值 |

反例：完整分项为 `-100,+30,-30`，目标为 `-100`。
只保留第一项后，数值仍与目标相等，但分区完整性已经失效。
这说明“残差为零”和“对应贡献集合完整”是两个命题。

推导原则是：输入证据只能通过注册规则运输。未知条件不能因对象换了家族而消失，
假设也不能因序列化后恢复就变成检查结果。

对原输入信息的保留与新统计事实的产生要分别描述。归约可以构造新的 Group 唯一键、
统计量和状态，同时失去原 Subject 映射；不能把它概括为所有事实或所有能力只增或只减。
`RequiredParts` 是续算必要条件之一，具备部件仍须满足定义相容、所有权及方法前提。
能力应由当前签名、部件与注册规则推导，不能给整个家族附一个永久有效的能力标签。

## 11. 前提、证据与执行准入

### 11.1 三种不同的成立

1. **语义上有定义**：给定真实满足前提的输入，该运算有确定含义。
2. **本次可准入**：前提有被允许的依据，或能交给具体执行检查；并不代表来源假设被扫描验证。
3. **本次执行成功**：所选实现支持该调用，必要检查和计算成功，结果按契约发布。

后端不支持某方法，不改变方法的数学含义；数据检查失败，不代表所有同类型输入都无定义。
反过来，执行器算出了一个数字，也不证明它回答了声明的分析问题。

### 11.2 信任来源声明

现行 Marivo 把源行唯一性作为由 K 与版本坐标确定的作者假设，不进行自动全表证明。
参见 [Entity 契约](../../specs/semantic/semantic-object-model.md)。本理论保留这一边界。

设 H 包含某个来源的唯一性声明。基于它构造的推导表示：

$$
\Gamma;H\vdash UniqueKey(A)
$$

其含义是在这些前提下可以使用该性质，不是本次执行已验证源中每一行。
若真实来源违反 H，理论不保证仍然得到正确业务结果；系统也不承诺发现所有违约。
它仍必须拒绝已经观察到、且违反本次消费契约的错误，不能静默去重或取第一行修补成功。

### 11.3 事实、证据与检查义务

事实是关于明确输入及范围的命题，例如 `UniqueKey(A)` 或 `KeySetEqual(A, B)`。
声明了一个命题不等于已经证明它。证据说明系统凭什么使用该命题；检查义务说明具体操作
还必须完成什么工作。三者不合并成五种互斥的事实状态，也不存在通用可信度等级。

| 证据形式 | 必需含义 |
| --- | --- |
| 声明依据 | 现有所有者允许信任的具名声明、定义版本、适用输入与范围；对应 H 中的前提 |
| 检查记录 | 已完成检查的方法及版本、实际输入绑定、范围和结果；只有通过的记录能够支持命题 |
| 推导记录 | 封闭规则及版本、所得命题、输入绑定和所依赖的证据；保留相关假设依赖 |

同一命题可以有多份证据，例如来源声明与针对固定 Artifact 的唯一性检查同时存在。
证据缺失就是没有可用依据，不另设一种事实状态；它既不表示命题为假，也不等于值单元格的
`Unknown`。第 5.2 节的值状态保持独立。

推导可以依赖声明或检查，也可以依靠构造保证。例如筛选保留键唯一性的推导仍依赖输入的
唯一性声明，不能把声明变成全表检查记录；group-by 的输出键唯一性可由构造保证，却不能
反向证明原始订单没有重复。检查也不永远有效：单个分区、旧 Artifact 或抽样数据的记录，
不证明当前全表性质。证据的适用性取决于命题、输入绑定和范围，不取决于标签排序。

检查义务归属于具体操作调用的执行计划，记录待满足命题、输入绑定、检查方法与履行位置。
安排了检查不构成证据；检查实际通过后才产生相应记录，失败则按该操作契约拒绝发布。
检查方法不能证明的命题不会因为加入计划就变得可解决。

本系统自己的 selector、所有权、表达式类型及 codec 结构由本系统负责检查。
这不需要扫描整张业务表。源字段类型通常从声明/schema 与实际解码获得，
不因为需要类型正确性就额外读取所有源值。

### 11.4 具体调用的准入

对每个 Pre，准入按该操作拥有者的政策判断：已有证据是否足够；若不足，是否有已获准、
能在实际消费或发布前履行的检查路径；两者都没有则拒绝。后两种情况可能同样缺少证据，
区别在于有无可执行的检查义务，不需要给事实增加状态。
这三种处理结果属于本次调用，不是所有算子共用的事实可信度枚举。
已有证据足够也不能取消本次消费契约明定的检查，已发现的矛盾不能用另一份声明覆盖。
源声明不自动变成全表预检；无法满足某方法的必要条件时拒绝该方法，不拖累所有其他操作。
既有关系 fanout、成员、对齐和输出校验仍由其所有者执行，不能以信任来源为由全部取消。

例如两侧键集合相等，可以由共同不可变域及保持域的规则推导，也可以安排实际配对检查；
summary 丢失主体映射后却不能靠安排一次检查恢复名单，缺少必要部件就拒绝选人。
具体实现只需要有限命题、证据形式和注册规则，不要求通用证明搜索、证据评分或独立任务调度器。

## 12. 条件保持与组合验证

### 12.1 T1 条件组合保持

下面给出项目契约下的条件定理及归纳证明；具体算子满足局部前提的证明仍是独立义务。
证明采用局部正确性支持组合正确性的常见程序推理思路，参见 R3；
本文没有据此完成一个形式化类型系统的可靠性证明，也没有证明统计推断方法有效。

**局部保持义务：**对每个注册算子 O，若输入满足条件签名及 Pre，必需部件具备且 Eval 按定义正确执行，
则结果满足 OutputSignature 与 Post，PartTransform 实际履行声明的部件变化；
Transport 不凭空增加事实，也不删除仍相关的假设依赖。

**定理 T1：**对按第 6、9 节规则构成的有限、良构表达式 e，固定 Γ、实际输入绑定 ρ 及必要
随机性 ξ；若所有被使用的假设 H（来源及方法）在各自绑定和范围内真实成立，
必要检查在消费依赖前按契约成功履行，
各节点满足局部保持义务，且按各自规定的数学 Eval 成功求值，那么结果满足声明的输出契约。
这里的成功不等于后端仅未报错；将定理用于实际执行，还需证明实现遵循相应 Eval 与数值契约。

**证明：**对表达式结构归纳。叶节点由实际成立的来源契约或正确保留值获得其签名和命题。
假设所有子节点已经保持契约；良构规则保证父节点正确绑定这些输出及显式参数，
在 H 真实成立及推导可靠的前提下，必要检查与获准依据保证其 Pre，保留部件满足 RequiredParts。
应用父节点局部保持义务，
得到 OutputSignature、Post 及 PartTransform；Transport 同时保留相关假设依赖。
于是该父节点也保持契约。有限次归纳到根即得结论；共享输入的有限无环图按依赖顺序同理。

**推论：**仅由已证明规则组成的新业务表达式，可以复用各规则的局部保持证明，
但仍需证明新组合的输入绑定、前置条件匹配和部件充分性。新增语义规则需要新的局部证明。
这减少重复证明的范围，不证明实现代码更少，也不从几个组合样例推出所有组合均已正确。

该命题不保证：真实来源一定满足声明、任意关系谓词都可判定、所有后端都有实现、
所有程序都会成功、数值无误差，或分析结论具有统计/因果解释。

为了使准入可实现，具体内核必须限制命题语法和推导规则。
“假设一个万能定理证明器判断任意 χ”不属于本设计。

### 12.2 数学证明、实现义务与验证证据

| 层次 | 已陈述的结论 | 具体交付仍需提供 |
| --- | --- | --- |
| 数学模型 | L1–L5、L7–L9 与 C1–C4 的条件结论及证明 | 明确实际方法采用哪个模型、哪些前提和哪个比较层次 |
| 核心规则 | 第 6.7 节有限子语言的具体规则与局部保持论证 | 扩展方法自己的完整规则和局部证明；不能仅凭共同模板准入 |
| 局部实现 | 第 6 节数学规则及各条件签名 | 证明具体实现遵循相应 Pre/Eval/Post、部件和证据运输；数值方法单独验证 |
| 表示与组合 | L6 与 T1 的条件定理模式 | 具体 codec/续算的表示保持、各节点局部义务及组合前提 |
| 运行证据 | 固定输入 oracle、性质检查、真实执行及冷恢复 | 记录覆盖范围、失败与未验证项；有限测试不代替一般证明 |

每个实现规则至少给出一个完整推导样例和一个缺前提/缺部件的拒绝样例；检查包括输出签名、
域映射、定义项和状态变化，不能仅核对数值。对共享输入的有限表达式图可按依赖顺序进行同样论证；
不通过把逻辑定义重复求值来假装固定输入共享。

验收分为四类：类型与义务推导、获准规律的固定输入对照、K 续算保持、独立拒绝边界。
每条规律都明确数值/状态/集合/语义/续算的比较层次，浮点检查遵守方法数值政策。
这些是本理论及具体已选方法的证明义务；未定义的扩展方法仍需独立给出规则与证明。

## 13. 必须保留的反例

| 反例 | 被否定的错误推论 |
| --- | --- |
| 两组均值相同但 count 不同 | 展示值足以支持均值上卷 |
| 用户 AOV 均值 50.5，总体 AOV 200/101 | 同一单位的归约可以自动采用底层权重 |
| 无订单客户不出现在事实分组中 | 实例类型 Customer 自动代表完整客户域 |
| -100/+30/-30 筛掉抵消项仍核对为 -100 | 数值守恒证明完整分区 |
| u1=0/u2=100 与 u1=100/u2=0 具有相同分布 | 聚合分布足以恢复高消费主体 |
| 同时刻 activate/deactivate 的两个排序终态不同 | 稳定排序等于业务顺序 |
| Active 自循环发生次数不同，占用区间可以相同 | 占用区间足以恢复全部转移轨迹 |
| 两组旅程不相交但来自同一用户 | 主体像保持集合交集 |
| 已返回但窗口未完成的成员进入分子，却不进分母 | 有了覆盖计数就自然有唯一留存率 |
| 两侧都有 N 行但键集合不同 | 行数相同证明完整配对 |
| group-by 输出唯一但原订单重复累计 | 输出键唯一证明来源唯一及指标正确 |
| 固定输入物化续算与重新读取可变来源不同 | 相同逻辑定义保证相同数据实现 |
| 无序贡献上用非交换拼接得到 ab 或 ba | 集合/bag 自动拥有业务顺序 |
| 两次筛选与一次合取筛选的推导路径不同 | 语义等价要求证据记录字面相同 |
| 恢复丢失 count 后两边都拒绝上卷 | 同时拒绝就证明原定 K 的能力保持 |
| 同定义的 Jul₁ 与 Jul₂ 来自不同读取 | 可以直接将两个端点合并为 2×Jul |
| 一人两旅程、另一人一旅程 | 旅程统计自动等于等主体统计 |
| 组均值 1/2/3、计数 1/2/1，两种均值均为 2 | 数值相等证明等组与总体统计语义相同，或要求计数必须相等 |
| 改换目标人群后留存界变宽 | 固定 Ω 下的信息单调性也覆盖问题定义改变 |
| 空目标组没有贡献行，筛选后被 group-by 省略 | L9 允许把显式目标组域替换为实际分组像 |
| 选定地区后重算总体分母或归一化权重 | 限制归约状态等于按新总体重新计算状态 |
| 空 mean 保留 (0,0)，展示值为 Undefined | 展示值不可参与严格算术就表示原状态不能合并 |

这些反例应成为实现回归与理论修订的约束，不能通过缩窄测试数据使其消失。
