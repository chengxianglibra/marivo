## Direct Native Refactor Boundary

The user authorizes source checks and subsequent native calculations to read
independent source versions. Check evidence proves only its own query, not facts
acquired later. One logical Run/result identity does not promise one physical
scan or source revision. Qualified pure-native plans keep dependencies as closed
Ibis expressions and query checks, required parts and the terminal primary
directly, without capturing intermediate Arrow tables merely to stage them back
as literal or temporary source relations.
Independent checks may still produce temporary Arrow validation results; the
refactor removes intermediate stage capture/restaging, not check-result reads.

`marivo/analysis/materialization/graph_source_execution.py`. Final Arrow primary

## Measurement Boundaries

- Setup and oracle reads are outside execution. Fixed source capture has its own
  observations and timing, separate from the fixed kernel.
- Timings include observer overhead. Nested phase durations are inclusive and
  must not be added together.
- Arrow nbytes is decoded exchange data, not wire bytes. Wire bytes and separate
  server/Python/native memory are unobserved.
- Sampled RSS, process lifetime RSS peak and visible unique buffer ranges are
  distinct. The visible range union is a lower bound, not an exact simultaneous
  residence upper bound. Shared views are deduplicated by address overlap.
- PyArrow Cython `to_pylist`/`to_numpy` bypass CPython profiling; their call/copy
  totals remain unobserved. Actual Arrow/pandas/NumPy transitions have sharing
